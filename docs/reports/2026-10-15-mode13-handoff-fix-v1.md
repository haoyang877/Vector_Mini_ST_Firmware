# Mode 13 观测器交接失锁修复 v1

日期：2026-10-15；分支：codex/ovp-36v；基线：v0.6.0。
执行依据：[修复计划](../plans/2026-10-15-mode13-handoff-fix-v1.md)。

后续40 μs预算优化与最终板内镜像见[补充报告](2026-10-15-fast-irq-40us-v1.md)；
本文保留前序修复阶段的测量结果。

## 结论与范围

主要根因是快中断超时：模式13交接阶段仍按50 μs积分，实际ADC处理间隔已变为100 μs，
使电压、电流及观测器时间尺度不一致，出现速度估计下跌、反向和故障13。
优化执行预算后，补充轮档锁速反馈约5 ms滤波，多次完成闭环交接、LUT采集及原残差验收；最终普通镜像也通过固件内部验收。

本轮为架空、无阻尼轮电机，21极对、6 mΩ；沿用已确认的3 A、30 rad/s停止边界。
原速度PI Kp=0.06、Ki=0.6已保留。模型R=2.144 Ω与用户mode17单相测量约2.2 Ω相差约2.5%，
本轮未修改R、L、磁链、编码器方向、残差容差或保护阈值。

本报告覆盖轮档。阻尼档有离线回归，尚未实机验收；LUT残差是相对本机观测器的内部一致性，
不等于经过外部角度基准计量的绝对精度。

## 根因证据

170 MHz下，每拍50 μs预算为8500个CPU周期。临时DWT统计覆盖ADC IRQ主体：

| 阶段 | 基线平均/最大耗时 | 基线超50 μs拍数 | 修复后普通RTT平均/最大耗时 | 修复后超50 μs拍数 |
| --- | --- | --- | --- | --- |
| ALIGN | 46.808 / 57.094 μs | 1600 / 15999 | 38.919 / 43.059 μs | 0 / 15999 |
| OPEN_LOOP | 48.015 / 58.535 μs | 4000 / 40007 | 40.229 / 44.347 μs | 0 / 40007 |
| SPEED_LOCK | 48.422 / 58.888 μs | 3404 / 34023 | 40.516 / 44.041 μs | 0 / 4000 |
| HANDOFF | 52.701 / 62.459 μs | 2001 / 2001 | 44.487 / 47.994 μs | 0 / 2001 |

基线交接每拍均超过预算，测得最大相邻入口间隔约100 μs；ADC处理后的JEOS清除会合并期间新到事件，
无法把漏掉的一次采样补回来。观测器仍使用固定Current_Ts=50 μs，时间错误直接进入磁链积分及角速度计算。
交接前每10拍一次的重负载也导致漏拍，主要与慢拍任务、热更新及RTT任务重合有关。

独立证据来自旧记录的热更新计数：每20次快中断更新一次，按主机时间反推，
ALIGN/OPEN_LOOP/SPEED_LOCK中位频率分别为18.180/18.198/18.084 kHz，HANDOFF为10.087 kHz。
前者吻合20 kHz÷1.1，后者吻合每拍超时后的10 kHz。该计数与DWT相互印证，不能归因于RTT单独丢帧。
热积分同样依赖固定时间尺度，漏拍也会低估实际经过的热积累时间。

离线简化电机模型只将交接物理周期由50改为100 μs、保留算法50 μs，
即可复现磁链幅值塌陷和观测速度反向；正确周期可正常交接。
该模型使用假设惯量，仅验证因果机制，不用于预测此电机的精确瞬态。

修复后HANDOFF最长47.994 μs、相邻入口最长约50.059 μs，消除了本次持续失锁的触发条件。
普通RTT诊断试验的CLOSED_LOOP汇总仍有1/108838拍超过50 μs，最长57.724 μs、间隔100 μs；
补充`normal_stage_trial`定位到VERIFY_CW→STOP_DECEL（28→29）提交1024点LUT并释放采样缓冲的那一拍：
9656周期，即56.8 μs，mode仍为13、三相输出仍使能。随后仅出现一次100 μs间隔，未继续失锁或报错，
补测也完成标定及停机。该残余单拍超限已定位；本次不扩展LUT提交生命周期设计，
不能宣称全流程零丢拍或全部模式均完成最坏时序证明。最终无诊断镜像另有功能复测，不能据此代替全模式最坏时序证明。

## 修复内容

- `foc_sensorless.c`、`foc_calibration.c`、`motor_thermal.c`、`motor_thermal_control.c`
  沿用工程已有的O3、时间优先策略，正常/HIL工程同步。
- 只读启动档位在IDLE入口校验一次；NULL、可变电机模型、限流及保护继续逐拍检查。
- 热逻辑在已完成有限值检查后用直接比较代替通用min/max调用；去除同一快拍重复的热限流发布，
  统一在命令处理后的保护入口发布。热方程及阈值保持。
- 2 kHz RTT与编码器慢拍、1 kHz热更新错开半周期；单一快中断写入通道使用
  `SEGGER_RTT_WriteSkipNoLock`，空间不足整帧丢弃，保持非阻塞及原通道布局。
  按本工程RTT库约定，以返回0判定丢帧，成功返回1。
- 在CubeMX `USER CODE`区启用Flash顺序取指预取，缩短快环执行时间。
- 轮档锁速反馈滤波系数由1改为0.01，20 kHz下约5 ms，避免速度纹波反复清除锁定计时。
  速度误差容差仍为25%，连续锁定时间仍为0.20 s，交接时间仍为0.10 s。

## 最终普通固件与保存核验

正常与HIL构建均0错误、0警告。没有临时DWT数组或诊断宏；普通RTT保留手工10路布局。
普通APP原始二进制92484字节，相对v0.6.0的90692增加1792字节；8字节填充后92488，
位于98304字节APP区内，余5816字节。静态RAM=456+27480=27936字节，与基线一致。
HIL APP原始94300字节，填充后94304；HIL仅构建，未下载或上机验收。
镜像、日志、哈希见`final_firmware/manifest.json`和本轮`summary.json`。

最终普通镜像`final_mode13`用原PI完成LUT残差验收：8381点，峰13计数=0.071411°，
RMS=sqrt(142394/8381)×360/65536=0.022642°，无固件故障。
不过自动保存期间主机监测读到74.75 rad/s，记录保留ABORTED，不能把它改称完全无异常通过。
异常时mode9、Iq/Id指令均为0；普通STOP及关相已确认。
源码保存路径关闭全局中断，约35 ms主机间隔内角度增加0.587 rad，之后恢复采样却按固定8 ms速度窗口计算，
0.587/0.008≈73.4 rad/s，与尖峰相符；这支持保存采样间断造成速度估计失真，
不能将该数直接解释为真实瞬时轴速。随后6次读数确认静止，才继续mode15。
这是独立的保存期间测速时基问题，本轮没有忽略运行时的速度停止边界或修改保护。

mode15完成，标定电流请求3 A、临时运行上限2.7 A，实际相/dq电流监测不超过3 A。
保存后电零位12484、标志3（LUT和电零位有效，机械零位未标定）。
第一次参数差异检查只允许零位/标志字节，因此因额外的offset2150报FAILED；
后续用ELF确认它属于`InterfaceParam.current_limit`（offset2148起4字节），
正是前次mode13自动保存的临时3 A恢复成原6 A，并非无关参数污染。
原始FAILED记录保留，独立`final_verification/result.json`完成全部差异、镜像及复位回读核验。

复位读回：运行限流6 A、标定电流3 A、速度PI 0.06/0.6、无阻尼档、R/L/磁链原值，热配置不变且已启用。
0.2 A Id检查反馈均值0.20146 A，位置跨度0.02197°，仅证明该低电流对齐工作点。
最终ModeNow=0、ErrorNow=0，CCER=0x1000（三相使能掩码0x555为0），相引脚高阻已核验。
Loader代码和参数区下载时保留；最终参数备份、试验曲线和校验记录均在本轮outputs目录。
