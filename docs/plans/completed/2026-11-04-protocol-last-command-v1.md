# 最近一条协议命令的全局观测 v1

前台在已有解析和权限检查通过后发布一份有类型的命令值快照，供 Keil Watch 观察。
电机、设备查询、参数、标定和 APP 侧 Loader 命令共用同一全局符号。业务返回值不参与筛选。
快照不持有帧、栈或队列内存的指针。线路字节、业务调用、调度和 Loader 票据行为作为对照基准。

基线及验证位于 `outputs/protocol-last-command/`。验收覆盖跨类型覆盖、非法请求保留前值、
载荷生命周期、行为对照、PR 检查和三个 Keil APP 的构建及符号。回退仅恢复本次相关片段。

## 结果

三个 APP 的链接映射均有 `g_protocol_command` 全局符号，大小为 48 B。
上电时命令号为零。App 前台按对应命令的参数类型发布字段；启动或目标可观测模式，
查询、参数、标定和 APP 的 56/57 会覆盖旧值。无效报文和越权请求在写入前被拒绝。
快照是观察数据，多条命令可能在一次 Watch 刷新之间先后到达。

真实 RX 队列测试覆盖跨类型覆盖、载荷寿命、权限和坏 CRC。
128,592 组请求的业务调用与线上输出前后一致，真实电机业务与状态回归输出也一致。
完整 PR 检查通过。三个 Keil 工程全量构建均为 0 错误、0 警告，每个工程 RAM 增加 48 B，
AT32 APP、STM32 APP 和 STM32 LoaderApp 的 Flash 分别增加 736、608 和 600 B。
验证基于离线测试和本次构建的 AXF，未在目标板上测量时序。
证据见 `outputs/protocol-last-command/summary.json` 和 `outputs/runs/protocol-last-command-20261104/summary.json`。
