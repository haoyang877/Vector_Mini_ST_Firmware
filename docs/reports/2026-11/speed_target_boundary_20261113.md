# 30 rad/s目标边界修复与实测

2026-11-13，固件冻结`f9f87718`，配套GUI清单`34ff494c`，分支`the-system-refactor`。
交付APP v1.8.3、Loader v2.3.4和CAN-Link-Test v1.8.3。

用户原始帧中，参数1回读30000 mrad/s，Type116目标也是30000，板端却返回11/0。
原因是APP用`30000 * 0.001f`得到30.000001907348633，而参数服务除以1000得到
精确30.0；严格上限检查因此拒绝。只将速度目标改为`/ 1000.0f`，不提高上限，
不添加容差，也不下调用户发送值。其他字段、控制PI、参数ABI和线路载荷保持。

原生真实协议适配测试增加±30及±0.001的边界，旧实现断言失败，修复后通过。
ARM反汇编确认速度字段使用`VDIV.F32`，除数1000.0，未被编译器替换回乘近似倒数。
当前干净清单提交的Release档通过，236项Python、原生测试、架构/接口/格式及六个
Keil目标通过，六目标零错误零警告。摘要：
`outputs/runs/speed-boundary-v1.8.3-20261113/summary.json`。

首次连接时SWD身份与原节点6不一致且CAN无应答，未写入；用户检查连接后，重新
核对原UID、节点和固件，备份后完成升级。原16 KiB参数、标定和身份逐字节保留，
重启版本回读及十次状态查询通过。

| 实测项目 | 结果 |
| --- | --- |
| 0→+30→0→−30→0 rad/s | 五次目标均受理，131次反馈，零超时 |
