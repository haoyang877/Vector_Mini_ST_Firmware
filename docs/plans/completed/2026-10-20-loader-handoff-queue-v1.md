# Loader 交接发送队列修复 v1

日期：2026-10-20。基线：`fdc58d11`，分支：`codex/system-refactor`。

## 问题与目标

同板 CAN0 实测：Loader 驻留时下载、校验、激活与 APP 持久确认通过；从 APP 发起升级时，
主机收到 READY 后设备仍留在 APP。硬件断点确认组合层收到失败的发送票据，尚未写入进入邮箱。

队列的 `head` 是下次入队位置，`tail` 是下次出队位置。交接旁记录反向使用这两个字段，
导致成功入队被误判失败；排队超时删除及跟踪发送的读取位置也反向。

## 修改边界

只修正交接回复的入队位置捕获、出队位置关联和超时移除。既有线协议、参数 ABI、Flash 布局、
超时长度与电机控制行为不变。APP 配套版本递增为 v1.4.2；Loader 保持 v2.0.0。
不放宽关相、真实 TX 完成或事务身份复核。

## 验收与回退

1. 使用真实队列和链路的原生测试覆盖 READY 物理发送完成才回调、旧票据不能触发交接、
   回绕队列中 READY 位于普通回复之后，以及排队超时只删除对应 READY 并保持其他回复顺序。
2. 完整 release 检查；重新构建配套包，记录源码、哈希及 Flash/RAM 用量。
3. 独占用户指定探针与 CAN0：保存并核对原始 Flash；受控安装配套镜像；完成
   APP→Loader→CAN 下载→校验→激活→APP 持久确认。全过程不发送电机使能，结束后恢复
   原始程序、参数和身份区，逐字节核对。
4. 若新镜像或关相校验失败，停止试验；受控回退使用本轮原始备份。软件回退至基线时，
   保留本次失败证据，不把旧版本称为已通过 APP 交接。
