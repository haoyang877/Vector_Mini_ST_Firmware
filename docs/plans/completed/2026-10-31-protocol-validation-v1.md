# 通信协议实机验证 v1

用户要求测试当前新代码的通信协议。沿用已下载的AT32F456 Commissioning镜像、节点1及CAN FD 1M/5M链路，
目标为YQ-5708（8:1）。本轮不修改固件，不复位或重新烧录，保留上轮RAM中的LUT和电零位。

## 场景与验收

1. 重新核对GET_INFO身份、GET_CAPS能力、APP状态及数字关相；记录当前RAM标定基线。
2. 1000次只读请求，每次核对帧CRC、地址、类型、序号、长度和字段；单次超时100ms，P99不高于20ms。
3. 执行非法帧、字段、采集边界、重复/冲突/旧序号检查；拒绝后设备仍能查询，不能启动或改变标定。
4. 核对普通停止/禁能/清错响应、116拒绝及124关联反馈、已移除参数和任务的明确拒绝。
5. 零Id/零Iq短时运行，验证普通STOP、私有KEEPALIVE、租约丢失关相及适配器关闭重开后不自动恢复。
   动力上限不超过用户已确认的3A和50rad/s；本轮进一步收紧至0.5A、5rad/s、0.1rad累计行程、4s时限、200ms租约。
   任一失败立即停止后续启相并保留真实失败，不自动清错重试。
6. 最终确认数字关相、故障0、LUT及电零位与本轮基线一致；保存逐帧日志、逐项结果和报告。

## 边界

适配器软件关闭重开不等于物理拔线、电磁干扰或CAN错误注入。
Commissioning私有租约不代表普通APP具备通信失联保护；当前GET_CAPS通用看门狗为0。
普通启动带载能力、Loader升级/复位、Flash写入和实时反馈有效性不在本轮通过声明中。
公共108/124测量字段当前按协议为无效哨兵，只验证编码与关联，不当作实时波形。

## 证据与回退

原始证据位于`outputs/protocol-validation-20261031/`。沿用现有台架客户端和CRC编解码器，
批次脚本放在输出目录；没有固件行为或ABI修改。异常先STOP并复核关相，保留RAM和失败日志。
文档更新执行quick检查；硬件结果以本批次日志为准，不沿用历史输出作为本次证明。
