# yg_protocol CMD 功能契约 v0.1（评审稿）

日期：2026-09-23。状态：**功能设计，尚非已批准的线上 ABI，不授权接入电机功率输出**。编号以[CMD ID 核对表 v0.1](yg_protocol_cmd_id_review_v0_1.md)的 28 个 Type 为准；公司[《消息类型定义》](https://wcnxj7iyqdkp.feishu.cn/wiki/DXV4wohO0ioGbskmFAFct8wFngd)目前只有 `0 TEST` 具名。其余编号、具体 payload 和回复字段均为项目候选，必须先登记、评审，再实施。正常控制模式及初拟字节布局见[简化电调协议 v0.1](yg_protocol_simplified_motor_v0_1.md)。

## 1. 所有命令共用的执行规则

- 应用帧始终是公司 `16B 头 + payload + 2B CRC16`，`type:u16` 位于头偏移 6～7，使用小端；CAN FD 29 位 ID 只做优先级/寻址。实时控制必须单帧，公司 payload 最多 46B。项目 CAN FD 候选位时序是仲裁 1 Mbit/s、数据 5 Mbit/s、BRS。
- 主控为 `0x02`，五个电机节点为 `0x03～0x07`。改变电机、参数、标定或升级状态的请求只接受授权主控；只读查询也要检查目标节点和来源策略。广播仅供明确允许的命令使用。任何 malformed/CRC 错误帧不得进入业务执行。广播 193 不回五条普通 ACK，以每轴 125 反馈确认执行。
- 除主动上报的 124/125 外，每条按需请求均有**同 Type、同 `seq_id`、源/目的互换**的业务回复，包括被拒绝的请求。公司帧 flags 中 ACK/请求/回复位的原文有歧义，定版时须统一；不能把 CAN 硬件 ACK 当业务回复。`seq_id` 由主控递增，重试沿用原值，最多 5 次、单次最长等待 1 s 是当前系统约束，不是实时控制周期。接收端对可重试的有副作用请求做有界去重，并返回原处理结果；复位后的序号/去重边界需另定版。
- 业务结果至少区分 **REJECTED / ACCEPTED / APPLIED**。`ACCEPTED` 只表示校验通过并入队；`APPLIED` 表示控制所有者或非易失写入已确认。位置到位、标定成功、整机重启成功分别由反馈或状态查询判定。错误回复应给出可诊断原因，不把失败伪装为成功。不可识别的 Type 返回不支持，不声明为 GET_CAPS 能力。
- 所有模式、位置、电流、参数和时间值先做长度、保留位、范围、运行状态和源节点校验，再交给唯一业务所有者；协议层不得直接写 PWM、HAL 寄存器或 Flash。故障及本地硬件保护优先于网络命令。电机复位后的默认输出为失能，不恢复旧目标。状态字段必须标明测量有效性；`Iq` 是 q 轴电流，不是已经标定的机械扭矩。

| `3 GET_DEVICE_STATUS` | APP/Loader 及升级期间的低频查询。 | 给出设备运行角色、启动/升级状态、错误及可用性；不代替电机测量。 | 指明处于 APP、Loader、校验中、待激活或失败等状态。格式和 Loader 数据来源待冻结；当前未注册。 |

## 3. 电机控制与单轴反馈（101、107、108、110、116、124）

| Type / 命令 | 允许场景与请求 | 驱动器必须完成的功能 | 回复、反馈和拒绝条件 |
| --- | --- | --- | --- |
| `101 SET_ENABLE` | `enable=1/0`。正常启动只发一次使能；正常退出用失能。候选请求为 `enable:u8 + 3B 保留零`。 | `1`：检查故障、母线、电机状态、转速及低侧制动许可后，由功率所有者进入 mode 5：PWM/驱动使能，三相**上管关、下管全开**。`0`：撤销控制目标，进入 mode 0，关闭 PWM/栅极输出并确认。重复相同请求幂等。 | 只有物理动作已验证才回 APPLIED；无法安全低侧制动、保护未就绪、输出关闭验证失败都报错并保持/进入安全状态。mode 5 不是三相悬空，转动时可能产生制动力矩和环流，允许转速/持续时间/退出条件需硬件评审。旧 `111 MOTOR_DISABLE` 在此命令实施时退役。 |
| `107 CLEAR_FAULT` | 故障源已解除且输出失能时请求；可带待清除故障掩码。 | 让故障所有者清除可复位的锁存位，重新检查实时故障输入；不自动使能或恢复旧目标。 | 回复已清与仍存在的故障；活跃过流、过温或驱动器故障不得被“清除成功”掩盖。掩码和结果格式待冻结。 |
| `108 GET_MOTOR_STATE` | 按需读取完整快照，不能作为 1 kHz 轮询替代。简化版拟用空请求。 | 在同一采样边界获取设备状态、电机状态、故障码、mode、位置、速度、`Iq`、母线电压/电流、温度及各量有效标志。温度源要明确是 MCU/功率级/绕组之一。 | 返回一致的快照及采样时刻/代次；无效传感器标无效而非填 0 冒充测量。当前路由的请求含 `session_id/request_id`、回复格式不同，迁移属于 ABI 变更；拟议新格式尚未冻结。 |
| `110 MOTOR_STOP` | 紧急或故障停止请求；要能在普通控制排队时优先处理。 | 交给本地停止/功率安全路径，撤销目标并执行明确的停止策略；重复 STOP 幂等。若需要先受控减速，须定义截止时间与失败时的强制失能。 | 仅排队时回 ACCEPTED；**输出关断经验证**后才回 APPLIED/最终成功。无法证明关断是硬失败，不能自动重启试验。当前有路由但停止服务未绑定，现状不能宣称已可停机。 |
| `116 SET_CONTROL` | 电机已使能且无禁止控制的故障；一帧同时给 mode 和该模式目标。候选 20B：mode/flags/reserved、`position_mrad:i32`、`speed_mrad_s:i32`、`iq_mA:i32`、`v_q_mV:i32`。 | 校验模式 1 电流、2 速度、3 绝对位置、4 MIT、5 低侧制动、6 q 轴电压；未用字段和保留位必须为 0；检查单位、限位、传感器、母线和当前状态。交给控制所有者在监督周期切换/应用；首次进入位置模式以**当前位置**初始化保持参考，再运行至目标。后续同模式目标不重复初始化。不得隐式使能，也不得直接写 PWM。 | 可先回 ACCEPTED，实际应用由 124 的 `applied_seq` 证明；拒绝越限/过期/无效模式且保持原安全状态。mode 4 的 Kp/Kd 来源和算法未定，不能接成现有阻抗模式的同义词；mode 6 是 q 轴电压 mV，不是开环电压。mode 0 用 101 失能，不由 116 表达。 |
| `124 MOTOR_FEEDBACK` | 电机主动周期发送；不需要主机请求或逐帧 ACK。单轴默认控制/反馈目标为 200 Hz，是否升至 1 kHz 以总线预算和硬件验证为准。 | 从同一快照编码位置、速度、`Iq`、已应用控制 `seq_id`、mode/状态和故障摘要；不得用“已收到序号”冒充“已应用序号”。建议 payload 12B，前 8B 为 `position:i32 + speed:i16 + iq:i16`，后 4B 为 `applied_seq:u16 + state_mode:u8 + fault_summary:u8`。 | 主机据 `applied_seq` 判断 116 已进控制周期，再据位置误差判断到位。丢帧通过公司头发送流 `seq_id` 观察；发送拥塞不能阻塞本地控制。当前只有 8B 编码、尚无周期发送；12B 是待评审 ABI。 |

`116` 的首版模式 1/2/3/5/6 有明确目标字段，但这不表示模式 4 已可用；`GET_CAPS` 应逐项报告。`101 enable=1` 进入低侧短接可能对旋转电机立即施加制动，安全边界未验证前不能通过通信开放该动作。

## 4. 参数与标定（120～123、160～163）

参数 ID、标定 `task_kind` 是 payload 中的子键，不再各占一个 Type。所有写入和执行请求必须校验参数表版本、单位、范围及电机状态；未知键返回不支持。

| Type / 命令 | 允许场景与请求 | 驱动器必须完成的功能 | 回复及失败语义 |
| --- | --- | --- | --- |
| `120 READ_PARAM` | 给出参数 ID，可读运行值或已保存值；包括明确登记的标定参数。 | 从参数所有者读取类型、缩放、值和修订号；对敏感/不可读参数按权限拒绝。 | 返回准确单位/修订号，未知 ID 报错。当前内层服务只有少数 ID，不能承诺全部标定量已可读。 |
| `121 WRITE_PARAM` | 给参数 ID、值和期望修订号；只修改运行态。需按参数的在线/失能策略准入。 | 校验类型、量程、交叉约束和版本冲突，原子地交给参数所有者应用；不自动写 Flash。 | 回复已应用值与新修订号；验证失败保持旧值，修订号冲突明确返回。安全相关参数原则上要求失能；逐项策略随参数表冻结。 |
| `122 SAVE_PARAM` | 主控明确请求持久化，电机失能且电源条件满足。 | 把运行态参数通过受控存储路径写入非易失介质并读回/校验提交结果；不得在 1 kHz 控制时隙阻塞。 | 可先 ACCEPTED，只有提交验证完成才报最终成功；失败时运行值与持久值分别说明。用户未要求增加通用掉电事务保护，仍需报告写入失败。 |
| `123 GET_PARAM_SCHEMA` | **条件保留**：主机确需动态发现参数表时才注册。 | 分页返回实际参数 ID、类型、单位、比例、范围、读写和应用策略。 | 页码/版本稳定，未知页报错；若主机使用版本化静态参数表，可不实现，也不得在 GET_CAPS 中声明。 |
| `160 CALIBRATION_START` | 电机处于该 `task_kind` 允许的安全状态；请求含标定类型及该类型参数。 | 验证互斥、资源和电机/传感器条件，创建一个有界异步任务 token，交标定所有者执行。任何可能驱动电机的任务须有独立安全准入，不能由命令隐式使能。 | 回复 token 与已受理状态；不把“开始”当“标定完成”。未知类型、故障、忙或条件不满足时拒绝，不留下半启动任务。 |
| `161 CALIBRATION_STATUS` | 用 token 查询，不改变任务。 | 返回阶段、进度、最终成功/失败、故障与结果可用性；复位后无效 token 明确报告。 | 进度只作诊断，不代替最终完成状态；失败要保留可读错误。 |
| `162 CALIBRATION_ABORT` | 用 token 中止可取消任务；紧急停止优先级高于此命令。 | 请求任务退出并把功率状态恢复至该任务定义的安全状态；重复中止幂等。 | 仅在任务确已结束、输出安全状态经验证后报告完成；不可取消阶段或验证失败明确报错。 |
| `163 CALIBRATION_RESULT` | **条件保留**：结果大到无法用 120 的参数 ID 表达时才实现；按 token/页读取。 | 分页返回带版本、单位与完整性标记的只读结果；简单标定系数通过 120 读取即可。 | 未完成、过期 token 和无效页报错；不因读取结果而自动保存参数。 |

## 5. 升级（50～56）

升级是应用层业务，`BEGIN/WRITE/...` 与 CAN FD 链路解耦；今后换成 485、以太网或其他承载时保持相同业务语义。公司外层 CRC 只校验**单帧**，不能替代镜像级完整性/真实性检查。每个 Type 的请求和业务回复仍使用统一公司帧；超过单帧容量的数据按适配层分片或缩小块，块 ACK 只能在存储确认后发出。升级期间不得使能电机。

| Type / 命令 | 允许场景与请求 | 设备必须完成的功能 | 回复及恢复语义 |
| --- | --- | --- | --- |
| `50 UPDATE_BEGIN` | 电机失能；提供产品/硬件目标、镜像版本、总长度、摘要及签名/真实性元信息。 | 校验目标兼容、容量、权限和安全状态，建立唯一有界升级上下文，确定可写分区及最大块长；不覆盖正在运行的镜像。 | 回复上下文标识、最大块长和可继续的 offset；不支持签名方案或目标不符须拒绝。镜像鉴权策略、双区布局和 Flash 能力尚须在 Loader 设计中冻结。 |
| `51 UPDATE_WRITE` | 已 BEGIN；提供上下文、offset、块长度和数据。 | 校验范围、顺序/重试一致性及块校验，写入目标分区并验证提交；同 offset、同数据的重试幂等，不同内容冲突拒绝。 | 返回**已持久确认**的 next_offset，不以 CAN 收到为成功；Flash 错误保留可查询状态。分片时业务 WRITE 只执行一次。 |
| `52 UPDATE_FINISH` | 全部块已确认。 | 检查长度连续性与整镜像摘要/签名、产品匹配；仅将镜像标记为“已验证”，不在校验途中重启。 | 可先 ACCEPTED，最终结果由回复或 53 查询；校验失败绝不可激活。 |
| `53 UPDATE_STATUS` | 升级中、复位后或激活后均可只读查询。 | 返回阶段、next_offset、已验证/待激活、错误及启动结果；支持主机断线后恢复判断。 | 明确区分“收到块”“已落盘”“整包已验证”“已启动新镜像”；无上下文返回空闲/无会话。 |
| `54 UPDATE_ACTIVATE` | 仅对已验证且与当前硬件兼容的镜像；电机失能。 | 记录激活意图，给主机可观察的受理结果，然后受控切换/重启；启动后通过 1/3/53 判断新版本和回退结果。 | 发送前不能宣称重启已成功；若激活前校验状态丢失或输出未关闭则拒绝。启动确认/回退策略须在 Loader/APP 契约中冻结。 |
| `55 UPDATE_ABORT` | 未激活的升级上下文；可重复。 | 停止后续写入并清理未完成上下文，不影响当前运行镜像。 | 回复安全终态；若已激活不能谎称撤销。 |
| `56 ENTER_BOOT` | **条件保留**：仅 APP/Loader 架构需要显式跳转时启用；电机失能。 | 验证 Loader 可用及输出已关闭，回复后受控跳转。 | 主机通过 3/1 识别 Loader；如果 54 或复位路径已经满足流程，就不注册 56。 |

## 6. 五轴同步（180、193、125）

目标为**至少五轴、每轴 1 kHz 位置控制及每轴 1 kHz 状态反馈**，并非当前固件已达到的保证。单路 1M/5M CAN FD 的旧估算约占周期 84%；必须重新核算最终帧 DLC、仲裁/位填充、错误重传和诊断流量，并在整机测截止时间、相位与抖动。用户给出的最大周期抖动容许值 10 ms 不应误当作 1 kHz 同步精度；具体时钟误差和连续丢周期阈值还需冻结。

| Type / 命令 | 允许场景与请求 | 驱动器必须完成的功能 | 执行证据与失败动作 |
| --- | --- | --- | --- |
| `180 TIME_SYNC` | 主控低频发送同步信息；单播请求要求业务回复，若最终采用广播则只能由独立状态反馈报告同步质量。 | 维护本地单调时间到主控时间的有界映射，并报告同步质量/时钟代次；不能把时间校正直接写入控制目标。 | 单播回复用同 Type/序号；具体时间戳往返算法、单位和误差上限待定。失同步时 193 必须被安全拒绝或降级，不能假称微秒同步。 |
| `193 GROUP_POSITION` | 主控每 1 ms 广播**一条**至少五轴的位置目标；请求含组周期/执行时刻、轴身份及各自 `position_mrad`，必须单帧。 | 各节点只取自己的槽位，检查授权源、组配置、时间质量、执行期限、模式/使能及范围；在指定控制周期应用。不得隐式使能、替其他轴执行或把旧帧当新周期。 | 广播不逐轴回普通业务 ACK；拒绝原因及实际应用的组周期通过各轴 125 报告。缺帧/过期后的保持、减速或失能策略应在控制安全契约中明确，不凭 10 ms 容许抖动自由保持。最终字节布局需在 46B payload 内证明装得下。 |
| `125 GROUP_FEEDBACK` | **每个轴每 1 ms 主动发一帧**，无逐帧 ACK。 | 使用同一控制采样边界反馈组周期/已应用序号、实际位置/速度/`Iq`、mode/状态和故障摘要；保持足够紧凑，为五轴总线预算留余量。 | 主控按每轴已应用周期判断同步，不把“收到了 193”当“已执行”；丢帧由各轴发送流序号识别。原方案曾建议 14B，字段与缩放尚未冻结。 |

## 7. 最少业务流程与定版条件
