# 本次启动身份来源实现 v1

日期：2026-10-08。状态：独立源码与离线实现完成，待 ROOT 内存契约审查及工程接线。
完整基线：`7f44bd083902081b00d1761648c158c34350d098`。

## 目标和不变范围

为 APP Type3 状态及新增运行／标定线路提供真实的非零 u64 本次启动身份。
身份先持久提交和读回再发布，同次启动固定不变；失败和耗尽不猜值、不回绕。
不是 Loader nonce、UID、生产 SN、参数修订号或电机任务代际。

保持 layout5 总分区、RAW schema12 的4304B记录、身份页格式、控制数学、模式、Watch、
保护和开发入口。两页所有权见[记录与兼容契约](../../protocols/boot_epoch_record_v1.md)。
保留页不擦，未知非空不迁移；不恢复旧 dual 参数 journal。

## 实际调用与修改

- 组合层在 MotorAxis_Init 关相完成后、board_hw_start 与通信启动前调用 BootEpoch_Init。
- platform/api 给出稳定只读身份和失败结果；STM32 port 扫描、分配、确认，BSP限定写域。
- Type3 状态适配器使用 provider 的完整身份；镜像阶段仍来自 BootHw，不混用计数与确认。
- 参数写域限定 RAW 前三页，所有现用记录调用仍在范围内。
- 新线路在H协议边界拒绝零或不匹配epoch；不加入底层start_permitted/start_blockers，
  保留本地RequestEnable、旧117、单项维护和开发Watch的既有健康与输出限制。
- 原 Keil工程不改；新增源清单交 ROOT 在最终候选统一接线和构建。

## 离线验收

仅编译生产 provider 和相关生产体，Flash存储由内存模型替代。
覆盖同次启动稳定、跨重启单调、页满轮换、每条记录写入边界和撕裂、擦除中断、
读回失败、未知尾部、坏CRC、计数缺口／重复／跨页冲突、最大计数和写域拒绝。
确认已经发布的身份不会重用；不完整记录可使后续启动不可用，不冒险修复。
状态源验证完整64位和有效位，不用截断GET_INFO计数补造。

本工作树PR检查通过；布局检查只证明路径和include有效，不证明新增源已被工程链接。
新增boot_epoch_stm32g4.c需加入普通APP与LoaderApp的Platform组，API与BSP头已有include路径。
最终release、工程链接和容量由ROOT统一执行。
原始产物放 outputs；报告记完整base/head、所测输入和代价，不能报告实机PASS。

## 风险和回退

ECCD走现有NMI死循环，仅能保证在已关相、通信未开始时不发布身份或启动功率；
不表示故障可在线诊断。未知／撕裂数据需要受控维修，维修策略尚未实现。
不能擦计数回到1；全片擦除、回退到可覆盖该区的旧固件或未知外部写入会破坏身份连续性。
源码回退用本项独立提交revert；已发布计数不得随代码回退清除，旧镜像再装须另审写域。
完整16KiB或整片历史备份也会回滚epoch；恢复与保留验收须分RAW、身份和计数页，
正常计数增长不算标定破坏。硬件抗回滚、安全维修及分域恢复工具均尚未实现。
本轮禁止任何探针、CAN SDK、真实Flash写入、复位和运动。
