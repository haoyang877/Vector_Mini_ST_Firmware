# 参数紧凑存储与旧版迁移 v1

更新：2026-10-29。当前开发只接受 schema14；物理分区仍为 layout 6。

## 改了什么

参数仍只保存一份。删除不再使用的齿槽补偿表后，记录从 4,352 字节缩至
2,288 字节，减少 2,064 字节。一次参数保存由擦除三页改为两页，每页 2 KiB。
Flash 的 14 KiB 用户参数区和 2 KiB 身份页地址都不改变；节省的页暂不划给 APP。

APP 的维护工作区还用于编码器采样，因此本次参数缩小不等于 APP 静态 RAM 同量下降。
不会新增备份记录，也不会缩小编码器标定表。

## 存储格式

| 内容 | schema12 | schema13 | schema14 |
| --- | ---: | ---: | ---: |
| 整条记录长度 | 4,304 B | 4,352 B | 2,288 B |
| 基础配置、编码器标定、轴配置 | 前 2,240 B | 前 2,240 B | 前 2,240 B |
| 退役齿槽表 | 占 2,064 B、忽略 | 占 2,064 B、忽略 | 删除 |
| 热保护与速度前馈 | 使用默认值 | 末尾 48 B | 末尾 48 B |

基础字段位置不变：CAN ID 在记录开头；配置确认在字节 2136；整条 CRC 在字节 2140；
格式版本在字节 2160；识别字在字节 2164。所有字段均为小端，CRC 沿用原算法，
覆盖对应版本的整条记录并跳过 CRC 自身四个字节。
[黄金向量](parameter_schema14_vectors.json)固定新长度、版本字节和 CRC。
旧格式向量继续保留，不随新版本改写。

参数 ABI 更新为 `0x000E08F0`，用于 APP、Loader、上位机的配套核对。
这个字段表示协议兼容关系，不是用户参数。跨 ABI 首次安装需通过受控 SWD 安装新配套包，
不能用旧 Loader 强行接收新 APP。后续同一配套版本可正常通过 CAN FD 升级。

## 启动读取策略

APP启动只读取 2,288 字节的 schema14 记录并校验整条 CRC；不读取旧版长度或转换旧格式，也不在启动时写 Flash。
schema12/13 和其他非当前版本按不支持处理，使用未确认默认配置，不保留旧记录的电机参数或标定。
截断、CRC 损坏和不合法的当前记录也不能获得有效配置资格。

Loader 独立识别节点的旧行为不在本次两个APP工程范围；它对旧版本的识别不代表APP能够装载旧参数。
完整参数 CRC 与业务范围由 APP 检查。

## 历史离线工具

以下工具为历史数据处理保留，不是当前新设备开发或启动时兼容流程，也不表示旧设备受到支持。

`tools/build/migrate_parameters.py` 接收完整 16 KiB 参数快照、它的 SHA256 和新输出路径。
它保留有效编码器零位、方向、标定位和线性化表，保留 CAN ID、模型及配置，
但清除配置确认位，要求在设备上核对后重新确认。输入、身份页以及新记录以外的字节保持不变。

```text
uv run python tools/build/migrate_parameters.py --input outputs/参数快照.bin \
  --source-sha256 已核对的快照哈希 --output outputs/迁移后参数.bin
```

schema10 还必须指定 `--legacy-layout vector-mini-schema10-delivery-v1`，表示已经核对
该快照来自已盘点的旧交付布局。哈希保证输入文件没有换掉，不能证明旧布局或历史标定正确。
工具会检查节点、模型、偏置、整定值、标定位、轴记录及旧扩展的 CRC；无法确认时拒绝转换。
`--node` 仅用于操作者明确改变地址。电流偏置不会代替 APP 本次上电重新采样。

原 `prepare_calibration_reset.py` 保持“清零位、清表、清标定位”的用途，输出也更新为
schema14。两条命令均只生成文件和变更报告，不连接硬件、不写板。

## 掉电、恢复和回滚

参数仍为单份，保存途中掉电可能使 CRC 失效。重启后 APP 进入未确认的默认配置，
不能假定旧标定会自动回来；应从已核对快照恢复或重新配置与标定。
身份页不参与普通参数擦写。普通固件升级不会写入这两个区域。

新记录只占前两页；旧版第三页可能残留历史字节，读取 schema14 时忽略。
工具也保留记录外字节，避免覆盖未盘点数据。因此“可重新分配”不等于“已自动擦空”。
若回滚旧 APP，须同时恢复它能够识别的旧参数快照，不能把新记录伪装成旧格式。
