# CAN FD 精简通信流程与 1 kHz 多轴同步位置控制建议

日期：2026-09-09。状态：建议稿修订 2；最低 5 轴，控制目标和每轴状态反馈均为 1 kHz。未替换当前 1.2.3 命令表或固件。

本方案保留公司 16 B 帧头 + payload + CRC16 2 B、29 位扩展 ID、5 Mbit/s 数据、BRS=1。现行仲裁为 500 kbit/s；为满足本轮双向 1 kHz 要求，建议评估 1 Mbit/s 仲裁及双路 CAN FD，尚未作为已确认硬件配置。用户已确认至少支持 5 轴。协议单帧容量按最多 8 轴设计，第一阶段必须以至少 5 轴同时运行验收；最终最大轴数与允许同步误差仍待明确。≤50 µs 仅为首轮讨论目标，不是已确认或已验证指标。

## 1 建议结论

采用“启动时配置，运行时广播一条组位置目标，各轴按未来时刻执行”的流程。主机每 1 ms 发送一条含全部轴位置的公司报文，驱动器提前缓存，并在同步时钟指定时刻把目标交给本地位置控制。位置闭环、电流环在驱动器本地运行。

用户确认的第一阶段最低要求：至少 5 轴同时运行，组位置目标 1 kHz，每轴状态反馈也为 1 kHz。心跳仍为 1 Hz，连续时钟同步初始按 50 Hz 评估。驱动器本地闭环持续运行；主机可以每周期获得反馈，但主机闭环仍需单独计入采样、传输、计算及目标提前量，不能把 1 kHz 通信频率等同于机械系统带宽。推荐评估双路 CAN FD、每路仲裁 1 Mbit/s / 数据 5 Mbit/s，五轴按 3+2 分配；单路 1 Mbit/s / 5 Mbit/s 为余量有限的候选方案。

CAN FD 的 64 B 是整个数据区，公司固定开销占 18 B，因此实际可用 payload≤46 B。[Bosch CAN FD 概述](https://www.bosch-semiconductors.com/products/ip-modules/can-protocols/can-fd/)说明 CAN FD 使用更长数据区及帧内变速；不能据数据段 5 Mbit/s 直接推导所有节点的最高闭环频率。

## 2 精简的是运行流程

保留三个业务类别：

| 类别 | 运行方式 | 建议 |
| --- | --- | --- |
| 配置/管理 | 单播、请求应答、按需 | 模式、限制、组映射、能力与任务参数在运行前确定，不在每个周期重复发送 |
| 实时目标 | 广播、单帧、无逐轴业务 ACK | 每 1 ms 一条全轴位置目标，带组身份、周期序号和执行时刻 |
| 反馈/事件 | 周期反馈错开 + 故障立即报告 | 每轴 1 kHz；附执行周期与状态；心跳 1 Hz；查询不刷新控制看门狗 |

此前统一目标、任务、状态查询的建议仍可使主消息从 65→49；新同步流命令及能力扩展尚未登记，最终数量需合并清单后重算，不能新增功能后继续声称只有 49 项。不要把所有操作塞进一个万能 command(op,blob) 后声称状态机和测试分支已经减少。

主机软件可提供 prepare_group()、start_stream()、send_positions()、stop_group() 四个接口；这些是有明确步骤的 API 编排，不能在设备端用一个收到即使能的报文绕过控制权和安全准备。

## 3 正常流程

1. **发现与检查**：逐轴 GET_INFO/GET_CAPS，核对 boot_id、节点唯一性、位置单位、组最大轴数、最小周期、硬件时间戳与时钟/位置环相位同步能力。
2. **准备设备**：逐轴申请控制权，未使能时设置位置模式、运动限制与允许误差。组期间不混用普通 SET_POSITION、标量 SET_TARGET 和同步组位置流。
3. **配置组**：逐轴单播相同组配置，冻结 group_tag、节点顺序、各自 axis_index、周期 1000 µs、反馈周期 1000 µs 与采样/发送相位、时间域、初始序号、队列深度及欠载策略。配置成功必须应答；每个节点确认自己的 UID/地址/boot_id 和控制者身份。
4. **建立同步**：校准逻辑时钟并验证误差上界；驱动器位置环执行相位也必须对齐。误差或时钟质量不达标拒绝进入同步流。
5. **预装与使能**：每轴预装当前位置附近的安全初始目标，显式使能并保持位置；主机确认全部轴状态符合要求。组配置和时钟报文本身不使能电机。
6. **启动位置流**：选择共同 T0，并提前发送执行时刻为 T0、T0+1 ms…的目标。初始 lookahead 可按 2 ms 评估，缓存容量可按 4～8 点评估；最终值取决于最坏端到端时延和资源验收。
7. **稳定运行**：所有轴按同一执行时标插值/更新；按分配时隙回传同周期快照和已应用序号。无每周期逐轴 ACK、ENABLE、SET_MODE 或参数写入。
8. **停止/退出**：组取消和本地故障采用明确停止策略，必要时发送现有 MOTOR_STOP；停止后清空未执行队列、撤销流状态，再允许换组/模式。故障不能靠继续发送旧目标掩盖。

2 ms lookahead 是固定管线延迟，并不把更新频率降为 500 Hz。主机如果要按反馈进行全局闭环设计，必须把这个延迟和 1 kHz 反馈的采样、回传延迟一起纳入控制器设计。

## 4 一条广播装下全部轴目标

建议新增 SET_GROUP_POSITION，候选 type=193（0x00C1），仅供评审，未注册。沿用 Priority=2、PGN=EF00；主机 02 广播时 CAN ID=0x08EFFF02，header.dst=FF，flags=0，不分片、不请求逐轴 ACK。当前协议的广播允许列表需显式增加该命令，不能直接使用现有固件解析器。

| payload 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0～3 | group_tag | u32 | 本次已授权并冻结的组身份；同一有效生命周期不复用 |
| 4～5 | cycle_seq | u16 | 应用层执行周期序号，每 1 ms 递增；与公司头帧序号分开 |
| 6 | axis_count | u8 | 必须与已确认组配置一致 |
| 7 | flags | u8 | 首版固定 0，不承载使能/切模式 |
| 8～11 | execute_at_us_low32 | u32 | 同步时间域中的未来执行时刻低 32 位 |
| 12～ | position[N] | i32[N] | 按冻结的节点列表排列，各轴只取自己的位置目标 |

单帧条件为 12+4N≤46，所以最多 **8 轴/帧**。5 轴 payload=32 B，公司报文=50 B，FD 数据区=64 B；8 轴 payload=44 B，公司报文=62 B，也为一个 64 B FD 帧。9 轴已超限，须拆组/总线或另行设计有共同提交时刻的多帧协议，不能使用现有实时分片。

位置暂保留当前 0.001 rad 单位。1 kHz 不会自动提高位置分辨率；若低速精密跟随需要更细编码，可评审另一个显式 schema，例如 µrad，同时重新核对 i32 多圈范围。未协商前不得更换倍率。

各节点的组配置必须绑定当前合法控制会话、发送源、boot_id、节点清单和唯一索引；同一个普通 group_id 不能替代控制权。组身份是防误投递字段，不是密码学认证。主机或任一轴复位后需重建组，旧队列和旧组身份不得继续执行。

cycle_seq 用模 65536 的半区间规则判新旧，但同时要求执行时刻严格递增、位于很短的许可未来窗口、与配置的 T0+k×1000 µs 一致。重复相同序号/内容幂等；同序号不同内容拒绝，旧序号不延长可执行时间。低 32 位时间每约 71.6 分钟回绕，必须结合本地 u64 同步时间和远小于 2^31 µs 的窗口恢复，不能直接用普通有符号大小比较。队列不得覆盖尚未执行的最近点；此处需要有界 FIFO/环形缓存，不再使用旧“只保留最新目标”的队列规则。

## 5 多轴同步需要什么

必须区分三个时刻：报文发出、设备收到、控制目标实际参与位置环计算。普通按到达时刻更新目标，即使同一广播同时接收，仍会因 ISR、队列和位置环相位差而不同步。[CiA SYNC 机制](https://www.can-cia.org/can-knowledge/sync-protocol)可作为周期关联思想的参考，但本方案继续使用公司的帧格式，不切换成 CANopen。

推荐采用：**共同时间域 + 接收缓存 + 定时插值 + 控制周期相位同步**。不建议每 1 ms 再额外发送 PREPARE、逐轴 ACK、COMMIT；配置准备在启动时完成，每条组目标本身携带共同未来执行时刻。

主机发送队列前的软件时间戳包含排队延迟，不能独自支撑数十微秒级保证。建议评审 CAN FD 硬件 TX/RX 事件时间戳，统一到同一种物理事件（例如 SOF）；通过时钟信标与后续发送实际时间戳的 FOLLOW_UP 形成两步同步，并用本地时钟伺服估计偏移和频率漂移。总线传播、时间戳映射与 MCU 数字延迟需测量并计入上界，不能假设为零。具体控制器的时间戳计数单位、回绕、FD/BRS 下行为和外部时间基准映射须在 HAL Port 验证。

初步按 50 Hz 两步同步评估，每 20 ms 两条 32 B FD 报文；是否足够取决于实际晶振漂移和同步误差预算，不是硬件已验证值。运行中只允许有界平滑校正，时钟不能倒退、不能阶跃导致已缓存目标提前/重复生效。离散目标 k 的执行时刻和既有队列必须保持单调。

当前协议 CLOCK_EXCHANGE/ADJUST 只允许未使能时进行探测/更新，并限制时钟有效期；现有 SYNC_ARM/COMMIT 只定义缓存轨迹共同启动。这些不能直接当作长期 1 kHz 同步流使用，需要新增运行中频率/相位伺服和能力声明，不能只改命令周期。

[CiA 高精度驱动同步论文](https://www.can-cia.org/fileadmin/cia/documents/proceedings/2002_rostan.pdf)指出，总线 SYNC 报文会被正在发送的帧延迟，通信同步并不自动等于驱动控制周期同步，可通过本地同步控制器降低抖动。文献中的硬件测量结果不能当作本板已能实现的精度。

跨轴目标生效误差应按时钟残差、定时派发、位置环采样/计算相位、PWM 提交等项建立预算。若每轴相对共同时间的误差界为 E_i，则任意两轴误差界不超过 E_i+E_j。要承诺两轴≤50 µs，应给每轴各误差来源分配合计≤25 µs 的预算，并实测。

本工程静态代码可见 20 kHz 快环、2 kHz 级联位置环配置。独立 2 kHz 环的相位差可接近一个 500 µs 周期；即使仅等下一个独立 20 kHz 快环，也有最多近 50 µs 的量化等待，尚未加时钟/ISR 误差。因此不能仅凭“FOC 20 kHz”承诺≤50 µs，更不能直接承诺≤10 µs。必须统一位置环/快环的应用相位或提供经验证的定时执行能力；硬件具体实现留在 motor_hw/time_hw 的 Port，不能从协议代码直接调整定时器寄存器。

严格≤10 µs 应作为独立验收目标。仅 CAN FD 下可评估硬件时间戳、分布式时钟伺服和相位对齐，但若实际硬件无法达到，就必须降低指标或经用户同意调整硬件；本方案不默认增加外部同步线。

## 6 每轴 1 kHz 状态反馈与总线容量

### 精简为每轴一个 32 B FD 帧

候选 type=125 MOTION_FEEDBACK_SYNC 修订为 14 B payload，完整公司报文恰好为 16+14+2=32 B，DLC=13，无填充。CAN ID 的源地址标识电机；使用优先级 3，单播到主机。flags=0，不分片、不请求业务 ACK。

| 位置 | 字段 | 大小/含义 |
| --- | --- | --- |
| 公司头 seq_id | applied_cycle_seq | u16；本次采样时实际参与控制的目标周期 |
| payload 0～3 | group_tag | u32；完整保留本次授权组身份 |
| payload 4 | state_mode | u8；高 4 位模式、低 4 位设备状态 |
| payload 5 | fault_summary | u8；故障摘要 |
| payload 6～9 | position | i32；0.001 rad |
| payload 10～11 | speed | i16；0.001 rad/s |
| payload 12～13 | iq | i16；mA |

这里省掉的是 payload 内重复的执行序号。**仅候选 125 明确定义公司头 seq_id 为 applied_cycle_seq**；原 124 的头序号仍是反馈发送流序号，不能混用。公司头布局及 CRC 覆盖不变，但这一新增消息的序号语义必须登记，并通过能力/schema 协商；当前通用解析器不能默认所有报告序号都独立递增。不要再向此 payload 加 2 B 字段，否则完整长度将变为 34 B，物理 FD 数据区会跳到 48 B。

fault_summary：bit0 过流、bit1 过压、bit2 欠压、bit3 过温、bit4 传感器故障、bit5 通信/同步故障、bit6 软件停止锁定、bit7 其他故障，可同时置位。摘要非完整故障码，母线电压、温度、完整故障等通过低频状态查询/事件获得；本轮 1 kHz 状态包括上表全部字段。i16 无效码/溢出沿用当前定义，不允许回绕。

运行时以 125 替代 124 的周期发送，不同时发送两份。每个共同周期 k 在约定采样相位 T0+k×1000 µs+phi_sample 获取同一份位置、速度、Iq 和状态快照；phi_sample 是全组配置并经控制路径验证的固定相位。头 seq 回显该时刻实际使用的周期 k。主机按 group_tag、源轴和周期对齐，不能用接收时刻当作采样时刻。固定相位不等于目标已经产生机械响应。

准备阶段没有有效应用周期时不发送伪造的 125，用管理状态报告。目标缺失、无法保持固定采样/应用关系或同步失效时立即报告故障/退出流，不把重复的旧周期当成新周期反馈。主机对每轴每周期设置接收截止时间，缺失即标记该周期数据无效；不使用上一周期数据冒充当前反馈。过期反馈不无限积压补发，硬件 TX 队列的过期帧也须能取消或有确定的排空上界。

### 以实际帧字段建立工程估算

上一版的 220/260/300 µs 是预分配调度槽，160% 是基于旧 48 B 反馈和这些槽的预算，不能当成物理测量。本修订以压缩后的 32 B 反馈重新计算。

字段与填充依据：[Linux CAN 帧长度定义](https://raw.githubusercontent.com/torvalds/linux/master/include/linux/can/length.h)。从其 ISO CAN FD 扩展帧字段推导下列**无错误、error-active 状态的保守工程模型**：SOF 至 BRS 为 36 个原始位，BRS 后 ESI+DLC 为 5 位；20～64 B 数据区使用 CRC21，其 CRC 字段含计数/固定填充共 33 位（含定界符），ACK+EOF 为 9 位，帧间隔为 3 位。动态填充分段使用 ceil(n/4) 预留边界影响，BRS 和 CRC 定界符整个按较慢的仲裁速率计入，以免低估变速边界。

```text
B_nominal = 36 + ceil(36/4) + 1 + 9 + 3 = 58
B_data(N) = (5+8N) + ceil((5+8N)/4) + 32
T(N) = 58/R_nominal + B_data(N)/5,000,000
```

N 是物理 FD 数据区字节数，包含公司头、业务、公司 CRC 和填充。模型包含正常 CAN CRC、填充、ACK、EOF 和帧间隔，不含错误帧/重传、背景帧阻塞、软件延迟、额外空闲、error-passive suspend；也不是对特定报文可达到最坏模式的证明。仍需用实际位时序、报文字节和总线分析仪验证。

| 物理数据区 | 仲裁 500 kbit/s / 数据 5 Mbit/s | 仲裁 1 Mbit/s / 数据 5 Mbit/s |
| --- | ---: | ---: |
| 32 B 反馈 | 187.8 µs | 129.8 µs |
| 48 B 心跳/扩展状态 | 219.8 µs | 161.8 µs |
| 64 B 组目标 | 251.8 µs | 193.8 µs |

五轴每 1 ms 一帧组目标加五帧反馈，即 6000 帧/s。以下占比只计周期目标和反馈：

| 总线方案 | 最忙一路每周期估算 | 周期占比 | 结论 |
| --- | ---: | ---: | --- |
| 单路 500 kbit/s / 5 Mbit/s，5 轴 | 1190.8 µs | 119.08% | 不能按本模型保证 1 ms 截止时间 |
| 单路 1 Mbit/s / 5 Mbit/s，5 轴 | 842.8 µs | 84.28% | 可作为候选，但余量小，不能直接承诺硬实时 |
| 双路 500 kbit/s / 5 Mbit/s，3+2 轴 | 815.2 / 627.4 µs | 81.52% / 62.74% | 最忙一路仍偏高 |
| 双路 1 Mbit/s / 5 Mbit/s，3+2 轴 | 583.2 / 453.4 µs | 58.32% / 45.34% | 推荐评估的五轴配置 |
| 双路 1 Mbit/s / 5 Mbit/s，4+4 轴 | 各 713.0 µs | 各 71.30% | 八轴扩展候选，需单独验收，不满足 60% 预算 |

双路方案保守地在两路各发同一份完整 64 B 全轴组目标，不靠拆分缩短控制帧来获得这些数字。每轴只连接分配给它的一路，不重复上报；双路是分担负载，并非容错冗余。主机须有两个可并行发送/接收的 CAN FD 控制器，并支持同一主时钟时间域。不得以一个串行接口轮流切换两路代替。

按每路两帧 32 B 时钟报文×50 Hz、每轴一帧 48 B 心跳×1 Hz，双路 1 Mbit/s 五轴方案约为 59.67% / 46.67% 平均模型占用；单路 1 Mbit/s 约 85.66%。平均占用不代替逐周期截止时间证明，时钟 FOLLOW_UP 产生时间、故障事件、正常与最坏重传均需做响应时间分析。≤60% 是本项目建议预算，不是 CAN FD 标准的硬性限制。1 kHz 运行期间暂停固件升级和大块诊断流量。

### 每 1 ms 的采样与调度

所有轴按共同周期更新目标并在固定相位采样；每轴在**同一个 1 ms 周期内**分配不同发送相位，上报该周期快照。不能再把五轴分散到五个 1 ms 周期发送，那会使每轴降回 200 Hz。

推荐双路 1 Mbit/s 五轴示意：每路为完整组目标预留 200 µs，为每个反馈预留 135 µs，再放时钟/事件及空闲余量；三轴一路周期业务预留 605 µs，二轴一路 470 µs。这是调度槽建议，包含的最坏排队、应用采样相位和软件就绪时间尚须验证；不是已经实现的 TDMA。主机广播的是未来执行目标，当前周期执行不等待这个发送槽结束。

两路目标可以在不同总线时刻送达，只要都在各自截止前到达且携带同一 group_tag、cycle_seq、execute_at，驱动器就按共同未来时刻执行。跨总线时钟误差必须计入轴间同步预算。CAN 帧不可中途抢占，后台发送必须做截止时间准入；重传不能无限挤占下一周期。全组反馈回齐后主机若再计算下一目标，需把计算耗时和 lookahead 纳入固定管线设计，不能要求未收到的数据影响已经发出的目标。

**当前建议调整的是仲裁速率和总线拓扑，数据段仍为用户指定的 5 Mbit/s。** 1 Mbit/s 是否可用取决于控制器、收发器、线长/支线、时钟及位时序；具体 prescaler、segment、SJW 和 TDC 保持 UNKNOWN，不能猜测。本轮没有修改 BSP、硬件配置或公司已登记速率。

## 7 缺包、超时与安全边界

- 收到未来目标只入队，不能立刻改 PWM 或位置参考。超过执行截止时间的目标丢弃，不能“补执行”。
- 组目标缺失或插值下一个必要点不足时，在预先定义的截止处触发欠载处理，进入明确的受控停止/功率禁止策略；不能依靠原 50 ms 看门狗继续盲走，也不做无限外推。具体最大容忍周期与停止参数需要机械风险和制动能力确定，标为配置/待验收。
- 合法远期目标不能把失联容忍时间无限向后延长；同时限制未来窗口、接收新鲜度和可执行队列连续性。重复包、普通心跳和查询不刷新同步流的新目标新鲜度。
- 如果某轴位置/速度/加速度/跟随误差越界，它报告故障并进入本地保护；不能各轴独立限幅后继续宣称轨迹仍同步。组协调者应中止其他轴。
- 广播的 CAN 硬件 ACK 不证明所有轴应用层都接受。一轴 CRC 校验、缓冲或本地状态失败时，可能其他轴已经执行；本协议无法在任意网络故障下保证“所有轴全执行或全不执行”。反馈只提供事后检测，严格安全联动还需要系统级风险设计。

## 8 固件开发顺序与验收

1. 先完成公司 CAN FD codec、队列、广播过滤及选定拓扑的硬件通信验收；重点验证候选 1 Mbit/s / 5 Mbit/s 及主机双控制器能力，维持 MCU/Vendor 与协议分层。
2. 在单轴实现带执行时刻的有界目标缓存和流式位置插值，不先做多轴。CSP 路径使用主机给出的连续设定值，不在每 1 ms 收到新点时重新启动独立点到点梯形轨迹。
3. 在两轴实现时钟与位置环执行相位同步，测量实际“目标进入位置控制”和 PWM 应用时刻；不能只观察 CAN RX 中断。
4. 扩展到至少五轴同时运行，作为最低验收规模；固定目标、反馈和同步发送相位；记录延迟、抖动、执行周期、缓存水位、队列满、CRC 错误和 bus-off。
5. 故障注入：缺点、迟到、重复、乱序、时间/序号回绕、时钟失效、单轴复位、主机复位和背景流量；证明不会晚到补执行或旧组复活。
6. 在 PRODUCT/FACTORY/DEBUG 的相应构建上测量 FOC WCET、位置环 WCET、ISR 嵌套和 PWM 更新截止时间。协议 ISR 只收包与发布事件，解码/业务不直接修改 FOC 全局变量。

主机必须有稳定的实时调度源。普通桌面定时器或非实时 Linux 线程的偶然 1 ms 唤醒不能作为硬实时保证；可评估实时 MCU 主站或经调度、驱动、接口延迟验证的实时 Linux。缓冲可吸收有界抖动，不能掩盖持续计算迟到。

建议验收指标分别记录：设定值周期和每轴反馈周期均为 1000 µs、每周期全组反馈接收截止时间、轴间实际生效误差、固定管线延迟、每轴反馈周期、最大连续缺点、长期漂移、位置跟随误差。所有硬件参数与允许误差在确认前保持 UNKNOWN/TODO，不把本轮计算或编码校验当成实机通过。

当前仓库参考：Bsp/hw_conf.h 定义快环 20 kHz 与 CASCADE_POSITION_LOOP_FREQ=2000；Core/Src/stm32g4xx_it.c 的 ADC 回调进入 FOC20kHzIRQHandler；Foc/position_cascade.c 有本地点到点轨迹生成逻辑。这说明已有本地控制路径，但不证明已实现上述同步流或确定性通信。

参考编码和工程预算见 canfd_1khz_sync_proposal_vectors.json，可由 tools/canfd_sync_budget_reference.py 复现。已校验新反馈的 14 B 业务长度、32 B 物理长度、头部执行序号及两种实现交叉校验的公司 CRC；时序为模型计算，未做实机验证。当前 1.2.3 命令表及固件均未改动；其旧 200 Hz 默认档位不代表本建议最新的双向 1 kHz 要求。
