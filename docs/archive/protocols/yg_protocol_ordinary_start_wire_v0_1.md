# 普通速度启动通信候选 v0.1

日期：2026-09-30。状态：**台架候选 ABI，非公司消息类型表定版，未做整机验收**。
本文件描述基于 `83f39c6` 与运行所有者 `0c8e9fac` 的离线实现；
`0x0065 SET_ENABLE(enable=1)` 仍保留 mode 5 三相下管导通语义，不用作普通启动；
`0x0074 SET_CONTROL` 仍只更新已经 RUNNING 的同模式目标。

## 线路字段

使用现行公司统一应用帧：16 B 头、payload、2 B CRC16，小端，单帧不分片。
29 位 CAN FD 扩展 ID 的 PF 为 `0xEF`，其余字段表示优先级和源/目标节点；
CMD ID 在应用头偏移 6～7。BRS 位时序为仲裁 1 Mbit/s、数据 5 Mbit/s。
主站节点 `0x02`，目标是设备当前实际 Node ID。请求 flags=`0x20`，
重试 flags=`0x24`，回复 flags=`0x10`，回复复用原 CMD ID 和 seq。

| CMD ID | 方向 | payload | 规则 |
| --- | --- | --- | --- |
| `0x0075 START_CONTROL` | 主站→电机 | `mode:u8, reserved[3]=0`，共 4 B | 仅单播主站；本候选仅 mode=2（速度零目标） |
| `0x0075 START_CONTROL` | 电机→主站 | `result:u16 LE, detail:u16 LE`，共 4 B | 同源/序号身份的进展；首次受理不表示启相完成 |

长度错返回 result=3；保留字节非零返回 4；非主站返回 7；其他 mode 返回 2。
运行所有者受理后，首次结果为 1（PENDING）；原身份重试查询到 STARTED 回 0，
但这是该身份的历史完成结果，不证明电机当前仍在运行。故障返回 17，忙返回 6，
状态不允许返回 5。陈旧身份返回 result=4/detail=`0x0101`，
`0x0102` 是所有者保留的同序号不同请求映射；当前仅 mode=2 且保留字节必须为零，
因此合法 4 B 线路请求不会触发该冲突。状态守卫拒绝返回 5/`0x0105`。
具体状态机诊断不得从 result=1 推断为已应用控制目标。

## 消息流与 STOP 顺序

```text
主站发送 0x0075(mode=2, seq=N)
→ 统一帧/CRC/地址检查 → 通信适配器 → 唯一运行所有者按源+序号受理
→ 回复 0x0075(result=1) → 2 kHz 监督拍确认启动条件和 RUNNING
→ 主站以原身份重试 0x0075，完成时取得 result=0，并查询 0x006C 状态
→ 发送 0x0074(mode=2, speed_mrad_s=目标) → 收 0x0074 回复和关联 0x007C
→ 发送 0x006E STOP 或 0x0065(enable=0) → 确认输出禁止
```

`0x0075` 去重归运行所有者，独立于 `0x0074` 的目标历史。
每个通过校验的 STOP/失能请求即使停机服务已 PENDING/CONFIRMED，
也将原 `source_node+sequence` 交给所有者推进 STOP 屏障；旧序号 STOP 仍执行安全停机，
但不回退屏障。这样 STOP 先到、旧 START 后到时，旧启动不能启相。
停机服务的 token 可复用，result=0 仍只表示数字输出关断获得所有者确认。
CRC/地址无法可靠验证或未知 CMD ID 时，不保证业务回复。

序号与去重记录只在当前 APP 运行期内有效；没有跨复位防重放保证。
主站超时上限 1 s，最多 5 次重试，重试保留源、目标、CMD ID、seq 和 payload，
仅增加 retry 位并重新计算 CRC。当前 `GET_CAPS.supported_modes=0` 不宣布量产可用能力；
本候选只能在明确台架构建与测试场景下使用，不能让主机自动回退到 `0x0065` 制动。

## 兼容与验收边界

旧固件没有 `0x0075` 路由；新主机须通过目标构建和现场确认选择此候选 ABI，
不能假设旧固件会回复 result=2。公司 CMD ID 登记、产品能力发现、跨复位身份和
功率级行为仍待产品定版。离线测试覆盖正常帧、拒绝、重试字节、STOP 后旧帧、
STOP 身份穿透 PENDING/CONFIRMED；实机安全、速度闭环和时序由独立台架记录证明。
