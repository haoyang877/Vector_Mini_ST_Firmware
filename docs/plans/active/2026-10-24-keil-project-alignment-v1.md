# 双板 Keil 工程对齐 v1

日期：2026-10-24。用户要求以旧工程为模板统一新板工程树和公共编译配置，仅保留必要的硬件差异；本轮不烧录。

## 边界与基线

旧板 `YG_ESC_APP.uvprojx` 作为只读模板，保持其源文件、选项及镜像不变。
整理新板完整 APP 的 Off、Commissioning 两个工程，不改独立外设台架。
不修改公共 APP、中间层、BSP API、算法、电机参数、协议或 Flash 分区。
保留新板芯片/SDK、启动文件、内存及散装文件、设备包、目标配置预包含和关相/限时策略。
不把旧板自动下载设置复制到新板，不改变本地用户调试选项。

基线保存于 `outputs/keil-project-alignment-20261024/`：源文件哈希、原工程、三个目标重新构建的 AXF/HEX/MAP、对象文件及日志。
不得将早先 HIL 时序结论直接用于编译选项改变后的新镜像。

## 实施

1. 新板沿用 `00_App`、`10_Motor`、`20_Parameters`、`30_Communication`、`40_Platform`、`50_Shared`、`90_Vendor`。
2. 公共文件保持旧板的分组及相对顺序；新板启动、采集和限时诊断归平台，RTT 归第三方。
3. 复制公共 C/汇编编译设置及公共源文件的单文件设置，列明必要例外。
   基线证实旧板为 ARMCC 5.06、新板为 ARMClang 6.16；新板一起切回旧板工具链。
   预包含使用 ARMCC 的 `--preinclude`，继续保留目标配置选择。
   只修改新板平台的工具链兼容写法：三处文件的布局断言改用 C99 typedef，
   临界区调用地址使用 ARMCC 内建，温度诊断发布使用 ARMCC 屏障内建；
   主机/Clang 分支保持原内建，无公共算法或接口改动。
   同时显式标注诊断对象的零初始化属性，沿用原UNINIT地址；散装文件匹配ARMCC段名。
   平台温度禁用分支改为条件编译，窗口零状态使用枚举值，均保持原行为。
4. 增加离线结构检查，约束分组、公共文件选项和目标配置，不触碰硬件。
5. 重建三个目标，对比映像与资源；发生变化必须解释来源，不能宣称字节等价。
6. 完成 release 检查；脏工作树用独立冻结副本验收，不修改原分支或丢弃本地工作。
7. 打开整理后的新板工程供用户查看，不进入调试或下载。

## 验收与回退

旧板 HEX 应逐字节一致；公共 C 实现及 17 个 BSP API 哈希不变。
新板按“仅分组”和“公共编译设置”分阶段比较，记录代码、数据、布局的变化。
若公共设置不能满足新板构建或有依据的必要时序条件，只允许范围明确、可检验的硬件例外。
双板离线检查与构建须零错误、零警告；新板新镜像的实机时序仍需后续单独验收。
回退只恢复本轮两个工程及新增测试/文档，不触及用户其他修改或已有数据。

## 结果

工程与公共编译配置对齐完成，旧板工程未修改。新板Off/Commissioning均使用
ARMCC 5.06 update 7、C99以及旧板的逐文件优化；所有公共组的文件、顺序与选项一致。
新板平台兼容改动涉及7个C文件，合计只调整声明、编译期分支和编译器原语；
公共APP/Motor/Parameters/Communication及17个BSP API共145个文件哈希全部不变。

完整release在独立干净冻结副本通过，提交标识
`83dfb9966cff656b4a7a9736670ad3482d7c9c21`；原工作分支未提交、未清理用户修改。
102项Python单元、14项集成、36组原生测试及格式、架构、接口、文档、hygiene、
旧板构建和发布清单全部通过；其中功率启动回归覆盖29968个官方HAL案例。

ARMCC试编译发现的平台扩展及段名差异已修复；温度禁用后的测试夹具改用相同编译期分支，
启用、未校准、已校准及无效参数覆盖仍全部保留。没有放宽门禁或保护。
