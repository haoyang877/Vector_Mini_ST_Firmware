# 维护工具视觉改版 v3

## 目标、基线与范围

用户确认上一版原生控件布局不够美观；重新组织四页界面，采用侧边导航、浅色工作区、
连接卡片、分步骤任务卡、清晰主操作及折叠日志。仅使用已有Tk/ttk，不增加GUI依赖。
基线为四页EXE归档`outputs/loader_flasher_exe_20261014_v3/`及其源码快照。

## 保持行为

MCU、参数ABI、CAN协议、升级客户端、J-Link烧录/快照后端、文件预检及UID准入不变。
所有按钮使用原回调，连接选择改变后仍撤销绑定；忙时输入互斥，关闭窗口不能中断任务。
默认启动、预览、离线验证不访问设备；本轮仅界面调整，不烧录或启动电机。

## 验收及证据

检查四个页面默认、已读取样本、错误及忙状态的布局，窄窗口下主要按钮可见、表格可滚动。
验证导航和日志展开不触发硬件，未绑定时两种写入按钮禁用，忙时控件锁定。
原维护后端及Loader离线回归通过，记录后端源码哈希与基线一致。
冻结EXE完成有效HEX、坏HEX拒绝、四页启动及截图检查；EXE和源码哈希归档outputs。
旧基线没有统一quick/pr/release入口，使用现有离线/native验证及Ruff，注明工具链限制。

## 回退

保留上一版EXE及源码快照，不修改已有下载包；回退只需使用旧EXE，不改变MCU固件或参数。

## 内置厂商库

用户追加要求取消两个DLL选择入口；将当前64位J-Link及ControlCANFD库原样打包到单文件EXE。
构建显式接收两个来源文件，验证PE架构，记录哈希及厂商说明；不把工作站路径写入仓库。
运行优先从PyInstaller资源目录自动加载；离线检查验证哈希、加载及必要导出，不调用打开设备接口。
不自动安装内核USB驱动、不更新探针固件。换电脑时设备USB驱动仍需安装，用户不再选择DLL。
J-Link随包保留原厂商许可文本及官方DLL分发说明链接，不包含其他SDK工具。
