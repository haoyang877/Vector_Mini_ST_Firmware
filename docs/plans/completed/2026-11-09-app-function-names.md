# 合并电机状态机和整理 APP 函数命名

基线 `a6a0bb7f`。依 STYLE.md 核对 APP 生产代码的函数名，优先处理把请求写成已执行动作、把协议转换写成数据名、或省略操作对象的私有函数。合并生命周期与五态实现，集中处理实际事件的条件、输出动作和主状态切换，移除仅转交同一事件的私有函数。保留已有公共接口、协议编号和硬件行为。测试文件按实际依赖更新，测试用 RTT 文件不在范围内。

核对 ADC、外环、监督和前台的调用时机，验证 30 种状态事件组合、启停、标定、故障、清错、双实例和抢占。更新工程输入和现行文档，执行 PR 和三目标 Keil 构建。回退本提交可恢复原文件布局和私有符号。

## 结果

- 已移除 `motor_lifecycle.c`。[状态机](../../../firmware/app/motor_state_machine.c) 的 `transition_motor_state` 是初始化之后唯一写主状态的函数。公开接口和 CAN 编号保持兼容，控制目标仍直接写入，未改变 ADC 或 Flash 策略。
- 两块板的 30 种状态事件组合均通过。对基线和当前实现输入相同的宿主测试，每板 567 条状态、PWM、故障、会话及控制参考记录逐字节相同。其余六个 APP 编译单元核对了重命名后的 C 标记，见 `outputs/merged-state/trace-comparison.json`。
- 三个 Keil 生产镜像均为零错误零警告。G431、AT32F456、G431 LoaderApp 的静态数据 RAM 均未增加，ROM 分别增加 16、136、8 字节。AT32F456 的纯迁移查询仍链接到 SRAM，镜像哈希见 `outputs/merged-state/images.json`。
- PR 检查中 45 组原生测试和 21 项集成测试通过。单元测试 124 项中有两项基线失败，分别涉及 RTT 固定哈希和历史文档诊断。104 项文档诊断与基线完全相同，整仓 PR 仍为 FAIL。结果见 `outputs/runs/20261109-merged-state/summary.json`。未上板测量 ADC 时序。
