# 通信实现可读性整理 v1

## 目标与边界

保留三个实现文件和一个头文件。入口按初始化、收包、前台处理、发包排列；
电机和设备命令按业务分组。删除内部通用 service/context 转换，回复长度和数据使用短名称，
线路结果使用具名常量；保留真实业务回调边界和显式编解码。

不改变报文字节、命令权限、错误优先级、控制/标定回调及发送顺序。
保留单生产者队列的内存屏障、每轮 8 帧预算、116/124 成对空间预留、
升级 READY 精确帧确认和 100 ms 截止。共享编解码与 Loader 线路契约不变。

## 基线、验收与回退

基线副本与哈希在 `outputs/protocol-readability/baseline/`；整理前核心、链路和
电机黄金向量测试通过。当前 AT32 工程已由工作区更新为三个正确的通信源文件。

验收使用既有黄金向量、错误及权限用例、拥塞/升级发送回归、PR 检查和三个 APP 的
Keil 编译，比较 Flash/RAM；不连接硬件，不以编译代替硬件时序验收。
只改通信实现和直接依赖的测试、说明；回退从基线逐文件恢复，不重置整个工作区。

## 结果

已完成，仍为三个 `.c` 和一个 `.h`，没有增加目录或运行时层级。

- 三个文件顶部统一为初始化、绑定和分发入口，后面按命令组织编解码及处理。
- 私有命令直接访问所属文件状态，删除通用 `void *context` 转换和重复请求外层校验。
  电机、标定、Loader 所有者的真实回调边界继续保留。
- APP 回复统一为 `ProtocolResponse { length, data }`，线路结果用 `ProtocolCode` 命名；
  删除共享头中无人再使用的 service 包装和重复四字节编码函数。
- 设备查询与 Loader 交接分组，APP 确认单独处理；唯一协议说明补充代码阅读入口。

同一探针对整理前后各输入 128,592 组请求，对比实际 CAN 帧、业务调用和值以及队列余量，
结果逐项一致；包含 19 类命令、3 类来源、4 种标志、0～46 字节长度和 12 种载荷。
既有黄金向量、拥塞不重执行、停机及升级精确发送/超时回归全部通过。
探针、前后输出和哈希见 `outputs/protocol-readability/comparison.json`。

最终 PR 检查全部通过：`outputs/runs/protocol-readability-final-20261103/summary.json`。
首次完整检查仅发现基线中 AT32 工程的 motor/device 源文件顺序与其他 APP 不一致；
已统一为 protocol、motor、device，定向 12 项检查及最终完整 PR 均通过。

三个 APP 前后 Keil 全量重编译均为 0 错误、0 警告：
