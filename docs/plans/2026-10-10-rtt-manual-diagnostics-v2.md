# 手工 RTT 通道顺序 v2

## 目标和边界

用户要求删除当前 10 路诊断档的 Vd，增加位置环速度参考并整理顺序。
基线是当前 `codex/ovp-36v` 组合工作区；保留 MCU 温度、PI 分离、软件版本等
其他任务及个人配置改动。不下载、不进行运动测试。

## 决策和不变量

复用最近一次外环只读快照的 `speed_command`，表示含误差校正且限幅后的
实际速度 PI 输入；不用 `trajectory_speed_reference` 或外部 `speedRef` 代替。
顺序为位置目标/反馈、速度参考/控制反馈/PLL、Iq参考/反馈、Id、摩擦前馈、Vq。
mode 3 外或快照无效时速度参考和摩擦前馈清零，速度反馈沿用原回退逻辑。

保持 10 路 int16、20 B/帧、2 kHz、单位、饱和、非阻塞及丢帧计数逻辑；
不改变控制输出、参数、标定、故障处理、CAN 或 Flash ABI。
此顺序是 RTT 语义 ABI 变更：新建 v2 黄金向量和文档，同步现有 Scope；
保留 v1 文档/向量作为历史解码依据。帧内无版本字段，必须匹配镜像和 Scope。

## 验收、证据和回滚

离线运行实际诊断编码器，验证索引/单位/名称、实际速度指令与轨迹速度的区别、
停机及无效快照清零、Vd 不参与诊断、饱和/NaN、分频及丢帧；回归旧标定档。
运行本树 Python 回归、工程检查及普通 Keil 构建；证据归档
`outputs/rtt_manual_diagnostics_v2_20261010/summary.json`，固定镜像及源文件哈希。
历史 worktree 无新版 verify/format/lint 工具，不声明现代 PR/release profile 通过。
HIL 沿用用户不处理的边界；实时开销和实机显示尚未测量。

回滚本次诊断分支、Scope、测试及文档，使用 v1 镜像对应 Scope；其他改动不撤销。

  构建期间固件输入哈希未变，镜像/AXF/映射已固定到本轮证据目录并记录 SHA256。
