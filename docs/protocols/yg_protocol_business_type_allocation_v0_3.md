# yg_protocol 业务 Type 分配提案 v0.3

日期：2026-09-23。状态：**项目候选，尚未经公司消息类型表登记或整机验证**。本文用于新协议业务重构和评审，不表示表中功能已由固件实现。新业务接入前应先冻结该条目的 payload、回复、状态/权限规则与黄金向量。

## 1. 分配依据和命名空间

公司原文已经规定统一 16 B 应用头、2 B CRC16、小端字节序，并将十进制 `0～99` 留给通用消息、`100～199` 留给电机消息；电机具体条目和升级编号在已读飞书表格中尚为空白。本文在这两个段内提出项目登记值。`200～299` 属于感知段，本项目不占用；`300` 及以上没有得到分段授权，也不自行占用。

`type` 是公司应用头偏移 6 的 **u16 业务消息类型**，不是 29 位 CAN ID、PF、Node ID、参数 ID、控制模式、标定子类型或业务结果码。CAN ID 保持 `priority | R=0 | DP=0 | PF=0xEF | dst | src`；Node ID 按公司表，主控 RV1126B 为 `0x02`，五个电机为 `0x03～0x07`。回复保持相同 `type`、相同请求 `seq_id`，交换 src/dst 并设置 RESPONSE 位；失败也回复业务结果。广播周期业务的执行回执规则见第 5 节。

当前项目承载只采用 CAN FD：29 位扩展帧、BRS、仲裁 1 Mbit/s、数据 5 Mbit/s。单帧公司 payload 上限为 46 B；实时目标、停止和周期反馈禁止分片。类型编号与物理链路解耦，今后增加其他链路时仍使用同一 `type` 与 payload 契约。

状态栏：**R**＝当前固件已注册路由；**D**＝仅注册描述符或定义常量，尚不发送；**P**＝本文提案，代码未注册；**X**＝明确退役、不得按历史含义发送。R 只说明路由可达，不表示电机业务已经实现。

## 3. 电机业务：100～199

### 3.1 控制、状态与参数

| Type（十进制 / 十六进制） | 名称 | 方向与回复 | 状态 | 规则 |
| --- | --- | --- | --- | --- |

| 102～105 | 退役：旧 DISABLE / SET_IQ / SET_SPEED / SET_POSITION | — | X | 旧候选独立目标并入 116；旧 DISABLE 迁到 111 |

## 4. 合并与历史冲突处置

| 历史候选或当前实现 | 本提案 | 原因 |
| --- | --- | --- |
| 历史 100 STOP、102 DISABLE | 保留当前实现 110 STOP、111 DISABLE；100/102 退役 | 避免已经注册的 110/111 再改号；不允许同义双入口 |
| 历史 110 READ_PARAM、111 WRITE_PARAM | 改为 120/121；保存 122 | 110/111 已被当前固件使用，不能一号两义 |
| 历史 103 SET_IQ、104 SET_SPEED、105 SET_POSITION | 合并为 116 SET_TARGET，`target_kind` 指定物理量 | 消除三个同构周期路由；保留模式/单位的严格校验 |
| 历史 131/132 阻抗目标 | 走 116 SET_TARGET；130 仅配置阻抗参数 | 目标数据与模式校验共用一条业务路径 |
| 历史 160～165 CALIB、170～174 IDENT | 合并为 160～165 任务族，`task_kind` 选择任务 | 标定/辨识共享异步 token、进度、结果查询与应用流程 |
| 当前 108 GET_MOTOR_STATE、124 合并反馈、候选 125 同步反馈、193 组目标 | 保留编号 | 降低已实现和已有向量的迁移成本 |

历史 `motor_command_catalog.md`、`motor_protocol_v1.md` 的 500 kbit/s、200 Hz 和冲突编号只作为迁移资料。正式上线前应由公司消息类型表一次登记本提案，并将旧候选表明确标记为退役；不能让不同上位机分别按两套表发送。

## 5. 回复、时序与错误语义

1. **按需请求**：同 `type`、同头部 `seq_id` 回复，payload 带 `result`、`request_id` 或异步 `token`。超时上限暂为 1 s、重试最多 5 次；重试保留原业务 request_id 和序号，接收方去重，不重复写 Flash 或重复启动标定。
2. **周期单轴目标 116**：普通低频控制可逐条业务回复；进入 1 kHz 流模式时，成功应用由同轴 124/125 反馈中的已应用序号确认，拒绝需尽快返回同 type 错误。是否允许这种“反馈作为周期回执”的形式，必须和“每命令都回复”要求一起正式冻结；不能在 5 轴 1 kHz 情况下又额外要求每周期逐轴独立 OK 帧。
3. **广播组目标 193**：每轴 125 在对应采样周期回报实际应用的 group_tag/cycle_seq；未看到某轴该周期反馈就视为该轴未确认，不能把 CAN 硬件 ACK 当成五轴都执行。广播 110/184/192 也需要逐轴状态证据；故障情况下不保证原子“全轴执行”。
4. **设备主动上报 3/124/125/126**：本身不是请求，无逐帧业务 ACK；需要可靠读取时使用 108、162、185 或 194 查询。心跳与查询不刷新实时目标的新鲜度。
5. **CAN 优先级**：停止/故障最高；周期组目标与单轴目标其次；周期反馈随后；管理、参数、标定、升级最低。不同优先级不改变 `type`，只改变 CAN ID 的 priority 位。低优先级分片不得塞满硬件 FIFO 阻塞下一周期。
6. **结果与执行分离**：`OK` 可表示同步完成；`ACCEPTED + token` 仅表示任务受理，最终完成需读任务状态或反馈。参数保存、标定、升级和使能均不能把物理 ACK 当执行成功。

## 6. 落地顺序与冻结门槛

1. 在公司消息类型表申请上述区间和具体编号，先裁决 110/111 冲突、50～59 升级段、116/125/193 周期语义；冻结一份机器可读单一登记表。
2. 将 `firmware/communication/protocol` 的分散 `#define` 和 `yg_protocol_readonly_registry_init()` 描述符收敛到同一登记来源；未实现项不要加入运行注册表，`GET_CAPS` 不能声明尚未绑定的控制模式。
3. 按 STOP/DISABLE → 控制会话/模式/使能 → 116 目标与 124 反馈 → 参数 → 任务 → 193/125 同步 → Loader 升级的顺序接入；每一步编译并验证。
4. 每个新增线上 type 同步提交版本化 payload 文档、请求/回复及失败黄金向量、字节序/CRC 测试、主机镜像、超时/重试与兼容说明；ABI 改动必须显式升版。
5. 1 kHz 五轴必须用实物测得周期总线占用、端到端延迟、实际应用时刻、每轴反馈完整率和故障注入结果；不能用登记表或离线测试声称时序已经满足。
