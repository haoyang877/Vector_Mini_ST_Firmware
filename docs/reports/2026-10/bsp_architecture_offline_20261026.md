## 最终设计与实际变更

当前文件职责、依赖和运行顺序见[BSP架构总图](../../architecture/bsp_architecture_v1.md)。
平台只有BSP、板级config与原样SDK；共同功能由实际共用逻辑实现，MCU负责硬件操作，独立器件文件负责协议。
初始化覆盖当前使用的外设，应用只调用功能接口。UART与硬件版本采样没有绑定，明确保持未支持。

- AT32的时钟初始化和硬件启动准备合并到system_setup.c/.h；APP和五个台架共用，保留原先后顺序。
- BSP PWM只消费统一构建输入BSP_PWM_HARD_LOCK；普通/永久关相/限时模式和一次性窗口归应用。
  编译时检查模式与硬件锁一致，不再因头文件包含顺序得到不同的锁状态。
- 命令电流上限、标定电流上限、软件过流阈值移入app/config/current_sense_limits.h；数值不变。
  板配置只保留物理采样参数和资源信息，不用测量满量程自动放宽保护。
- SPI私有契约移入internal；删除无消费者的CAN健康查询、PWM配置宏和旧启动文件。
- 工程、测试和架构检查同步实际位置；PWM层禁止依赖应用策略头，没有扩充架构债务基线。
- 当前总图与逐文件职责一致；旧AT32过程笔记归档。公开接口本轮未改变：10个功能头、57个函数、9个ADC通道。

没有为目录对称制造空驱动、转发文件或运行时注册表。STM32继续使用原生成外设初始化；
AT32实际多消费者的启动、采样配置和Flash暂停恢复保留独立文件。

## 修订6实施对照

按BSP API v1修订6复核，10个功能头的57个函数与固件公开头一致；职责已接入实际实现。
不能把此结论扩展为全部硬件指标已经验收。2026-10-26复查还发现接口包执行说明、覆盖表残留
“未接入/待迁移”的历史表述，已同步当前实现状态，并显式补记零偏收尾的调度差异。

| 模块 | 实现落点 | 当前边界 |
| --- | --- | --- |
| 生命周期/应用事件 | 两板system.c及app/composition | 同一Init/Start与静态回调，未增加注册层 |
| 系统/看门狗 | 两板system.c；AT32 system_setup.c | 时间、临界区、UID、复位、看门狗由BSP拥有 |
| ADC | bsp_adc.c及两板sampling_backend.c | 九通道与分组有效位；相电流零偏应用收尾存在下述调度调整 |
| PWM | bsp_pwm.c及两板pwm_backend.c | 提交检查、真实输出状态及失败关断；物理波形/最坏时限待测 |
| 编码器 | bsp_encoder.c、devices、两板encoder_spi.c | 接口/器件协议/物理传输分开；TLE未读取安全字，不能宣称CRC通过 |
| LED | bsp_led.c及两板led.c | 统一闪烁/呼吸规则，保留各板真实输出方式 |
| CAN | bsp_can.c及两板can_backend.c | 帧/票据/终态、控制器/IRQ、应用协议分工 |
| UART | bsp_uart.c | 当前两板未绑定，明确返回NOT_SUPPORTED，未实现物理收发 |
| Flash | 两板flash.c | 固定存储区、事务关相与暂停/恢复；参数格式归应用 |
| BootHw | 两板boot实现 | 原交接行为与IsAvailable只读缓存，避免二次初始化 |

相电流零偏的差异不是接口缺失：Setter仍支持关相ISR提交，同缓存读取不增加采样序号。
但应用未沿用草案“满20k帧当拍完成”流程；它冻结满窗累计，由2kHz监督计算并提交，下一快拍使用。
这是为修复已观察到的快环超预算，保留原计算结果和保护范围；不能称为应用启动时序逐拍相同。
若“完成”指修订6的接口/职责落地和离线回归，则已完成；若包括原草案逐拍时序及全部物理验收，则尚不能称全部完成。
