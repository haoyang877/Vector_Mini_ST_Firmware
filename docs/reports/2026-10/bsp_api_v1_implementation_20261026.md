## 最终结构

平台仅保留BSP、板级config和原样SDK。公开功能契约、实际公共流程、MCU外设操作和器件协议分开。
统一入口为Bsp_Init → App_Init → Bsp_Start → App_Start → App_Process；删除AppPlatform转发链。
完整接口及目录见[统一接口](../../architecture/bsp_interfaces_v1.md)。

- 公共ADC拥有快帧、物理量、独立有效位、新鲜度和零偏；MCU拥有原码、触发、DMA及硬件错误。
- 公共编码器拥有采样/诊断事务；MT6835/TLE5012B仅解释器件协议，SPI层只做物理传输。
- 公共PWM拥有提交检查、输出状态和失败关断；一次性功率窗口移回应用。
- 公共CAN拥有票据、截止、终态和恢复节流；MCU只管理控制器、帧传输及IRQ。
- LED公共节拍与GPIO/DMA输出分开；UART无实际绑定，明确返回NOT_SUPPORTED。
- Flash独占实际擦写、回读、采样暂停恢复与硬件临界区；应用只保护业务保存会话。

删除或迁移21个旧BSP文件及应用装配转发头。未增加运行时驱动注册、函数表或第三套板型命名。
BootHw_IsAvailable只读缓存，避免应用再次初始化Loader交接状态。

## 行为与明确增强

保留正常控制数学顺序、三相采样过采样精度、保护阈值、编码器角度映射、协议帧及参数格式。
新增PWM非法占空比/提交过晚/部分启相失败的明确处理，CAN溢出报告及已完成票据保护。
AT32母线电流移至与相电流同触发的ADC2注入采样；原2kHz滤波和128样本零偏窗口仍在应用。
这不是单纯更名：同步母线采样及失败行为增强须单独取得实机证据。
TLE当前没有读取安全字，诊断明确crc_checked=false，不声称完成CRC保护。

## 正常供电后的问题与修正

用户确认上电后，母线读数恢复至约30.7V，身份、健康及参数查询均有回复。

这是正常供电后首次覆盖到的有效零偏完成路径，不能将其归为CAN链路故障。

修正版把20k拍原码累计及窗口冻结保留在快环，把均值计算、校验与发布放在2kHz监督中。
