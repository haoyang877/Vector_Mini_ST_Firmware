# 电机逐命令反馈契约 v0.2（评审稿）

日期：2026-09-23。状态：**按飞书反馈字段和用户逐命令反馈要求修订，线上字节 ABI 尚未冻结，固件未接入 `116/124`**。本文件修正[简化电调协议 v0.1](yg_protocol_simplified_motor_v0_1.md)与[CMD 功能契约 v0.1](yg_protocol_cmd_function_contract_v0_1.md)中“124 仅周期发送、12B 摘要”的提案；其他命令功能仍按上述文件评审。用户已确认：单轴控制使用全量反馈，五轴 1 kHz 使用精简反馈。

## 1. 原文与新增要求

[飞书《电调通信协议》“状态反馈”](https://wcnxj7iyqdkp.feishu.cn/wiki/M5KJwCZApilqfjk251XcktAPnxa)列出：当前 node ID、电机状态 `uint8`、故障码 `uint32`、控制模式 `uint8`、母线电压/电流 `int16`、参考/当前位置 `int32`、参考/当前速度 `int32`、参考/当前扭矩电流 `int16`、MCU/电机温度 `int16`、Vq/Vd 电压 `int16`。页面的状态名称为 boot、upgrading、init、selftest、cali、idel、run、stop、fault_now、fault_over；原文拼写 `idel` 保留为来源记录，正式枚举需校正。页面**没有**规定反馈 CMD ID、单位/比例、字节偏移、有效值表示或命令与反馈的关联规则；下述补充均为项目设计。

用户新增要求：**电机处于控制中时，主控每发送一条带控制参数的命令，驱动器就返回一条包含上述完整状态的电机反馈**。这个要求针对 `116 SET_CONTROL` 的每条合法到达请求，包括业务拒绝；不能只靠 200 Hz 定时反馈碰巧覆盖。五轴 `193 GROUP_POSITION` 每周期仍由每轴一条精简 125 确认，见第 5 节。

## 2. Type 与回复关系

```text
主控 -> 电机: 116 SET_CONTROL(seq=N, mode + 参数)
电机 -> 主控: 116 RESPONSE(seq=N, result/detail)        // 公司协议同 Type 业务 ACK
电机 -> 主控: 124 MOTOR_FEEDBACK(correlated_seq=N, ...) // 对此命令恰好一条完整反馈
```

公司统一帧规定业务 ACK 复用请求 `type` 与 `seq_id`，所以 **124 不能替代 116 的业务 ACK**。124 是带来源关联的独立反馈帧；公司头 `seq_id` 是 124 自身发送流序号，payload 中的 `correlated_seq` 才指向 `116.seq_id`。主控应分别记录“116 已受理/拒绝”和“124 已报告当前状态”，不能把 124 的位置值视作机械已到位。若实现后仍有空闲时周期上报 124，必须用独立标记区分周期样本与命令触发样本，防止误配；首版建议**只在每条 116 后触发 124**，避免同一数据被重复发送。

接收端处理同一 `seq_id` 重试时不得重复切换模式/写目标；必须重发原业务结果，并保证主机仍能取得相同命令对应的反馈。命令业务拒绝时 124 也返回当前安全状态，`result` 给拒绝原因，`correlated_seq=N`，已应用序号不前进。CRC/长度错误到无法可信读取头部的帧不生成反馈。**先为 116 ACK 与 124 反馈预留发送容量，再提交电机目标**；容量不足则以 116 BUSY 拒绝且不改变目标。反馈采样无法及时取得时，仍要返回带无效标志的状态/故障，不得发送上一次样本伪装为本次快照。控制目标真正进入控制周期后才把该命令标记为 APPLIED；若先回 ACCEPTED，124 必须区分“待应用”和“已应用”。

## 3. 单帧字段布局候选

以下是一个**候选** 45B payload：公司帧共 `16+45+2=63B`，CAN FD DLC 64B，最后 1B 填充为零。所有整数小端，显式逐字段编码，不依赖 C 结构体填充。`result` 与 `correlated_seq` 是项目为逐命令关联增加的字段；其余 16 项与飞书字段一一对应。Feishu 所说 node ID 是业务节点 ID，不把完整 29 位 CAN ID 当作 1B。

| 偏移 | 字段 | 类型 | 单位/含义（项目候选） |
| ---: | --- | --- | --- |
| 0 | result | u16 | 0=已应用，1=已受理待应用，其余为拒绝码；完整枚举待冻结 |
| 2 | correlated_seq | u16 | 触发此反馈的 116 请求序号 |
| 4 | fault_code | u32 | 完整故障位图；当前固件映射尚不完整 |
| 8 | reference_position_mrad | i32 | 参考位置，mrad |
| 12 | actual_position_mrad | i32 | 实测位置，mrad |
| 16 | reference_speed_mrad_s | i32 | 参考速度，mrad/s |
| 20 | actual_speed_mrad_s | i32 | 实测速度，mrad/s |
| 24 | valid_bits | u16 | 下方 12 个测量量各有一位，0 表示该量不可用 |
| 26 | bus_voltage_cV | i16 | 母线电压，0.01 V；采用 cV 是为覆盖超过 32.767 V 的母线 |
| 28 | bus_current_mA | i16 | 直流母线电流，mA |
| 30 | reference_iq_mA | i16 | 参考 q 轴电流，mA；不是 N·m |
| 32 | actual_iq_mA | i16 | 实测 q 轴电流，mA |
| 34 | mcu_temperature_centi_c | i16 | MCU 温度，0.01 °C；当前 `FOC.temp` 源需核对 |
| 36 | motor_temperature_centi_c | i16 | 电机温度，0.01 °C；本板若无传感器则无效 |
| 38 | v_q_mV | i16 | q 轴电压，mV |
| 40 | v_d_mV | i16 | d 轴电压，mV |
| 42 | node_id | u8 | 发送此快照的电机节点；必须与统一帧 `src_id` 一致 |
| 43 | motor_state | u8 | 飞书状态枚举，数值映射待冻结 |
| 44 | control_mode | u8 | 实际控制模式，不是本条请求中尚未应用的模式 |

`valid_bits` 的 bit 0～11 按上表从参考位置到 Vd 的 **12 个测量字段**依次对应，bit 12～15 必须为零。无效值先使用各字段最小整数作为哨兵且相应有效位为 0；若真实值超出缩放范围，不得饱和成另一个看似有效的值。状态、故障和 node ID 即使测量不可用也必须来自当前所有者。控制参数与实测量要从**同一个已发布快照**读取；尚未到下一个控制周期时反馈可以标记 ACCEPTED，但不能回填“已应用”。

离线编码器的黄金 payload 向量（45B）选用 `correlated_seq=0x1234`、node 3、mode 3、参考位置 1000 mrad、实际位置 -2000 mrad、电机温度无效；具体测试见 `tests/unit/yg_protocol_contract_test.c`：

```text
00 00 34 12 04 03 02 01 E8 03 00 00 30 F8 FF FF
B8 0B 00 00 60 F0 FF FF FF 0D 60 09 DC 05 50 FB
4C 04 E6 09 00 80 88 13 06 FF 03 06 03
```

飞书没有定义以上单位：位置/速度/电流沿用当前项目单位；母线电压采用 cV 避免 i16 mV 范围不足；Vq/Vd 的 i16 mV 仅覆盖 ±32.767 V，若本硬件可能超过此范围，必须改比例再冻结。电机温度尚无板级测量路径，不能把 MCU 温度复制到电机温度。当前 `MotorStatus` 没有 Vq/Vd 或电机温度，`yg_protocol_status_adapter` 的 `last_applied_sequence` 仍固定 0；这些都需先补数据来源和有效性，不能把新格式立即宣布可用。

## 4. 实施顺序与验收

1. 先冻结 124/116 的 Type 登记、飞书状态枚举数值、单位/比例、结果码与有效位，并补齐拒绝、无效温度、重试的帧级黄金向量；主机与固件同时切换版本。现有 8B 124 编码未周期发送，新 45B 纯编码器已取代它，但还没有运行路由。
2. 快速环发布同一时刻的参考/实际值与状态、故障、有效性；协议层只编码快照。对当前无法测得的电机温度回无效值，直到硬件路径验证。控制所有者提供实际应用序号，不由接收时刻猜测。
3. 接入 116 路由时，为每条有效到达的控制请求生成同 Type ACK 和**恰好一条**关联 124；发送队列拥塞时不允许“目标已执行、反馈丢失”。测试按顺序覆盖正常、越限拒绝、重复帧、反馈快照不可用、队列满与失能竞争。
4. 在整机上测 200 Hz 单轴往返和功率安全。五轴 1 kHz 的 Type193/125 路径另做 DLC、位填充、仲裁和错误重传预算；不把单轴全量 124 的通过结果直接推成五轴带宽保证。

本文件先给出可评审字段和程序流；**目前固件只有 45B 离线编码器，尚未有 116 控制路由，也未发送 124**，因此不能声称逐命令反馈已在设备上实现。

## 5. 五轴反馈范围（用户已确认）

五轴方案为每 1 ms 发送一条 193 组目标，每轴发一条紧凑 125；每轴 125 仍需逐周期回显已应用组周期、实际位置/速度/Iq、状态/故障摘要。约 84% 总线占用估算基于**短反馈**，还须以最终 DLC、位填充和错误重传实测确认。飞书全量状态通过低频 108 按需读取，或在单轴 116 后由 124 回报；五轴 1 kHz 不每周期发送 45B 的 124。
