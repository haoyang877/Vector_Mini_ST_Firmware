# 参数刷新响应优化

基线：abde33af，CAN-Link-Test v1.17.3，APP v1.8.12，工作树干净。
每次参数读取都会 spawn 新进程，打包程序重复启动和导入，逐项读取期间没有进度。

目标：参数读写使用单一后台线程，UI 不执行设备 I/O；保留其他任务进程隔离。
参数任务与其他任务仍互斥，SDK 在任务内打开并关闭。每项读取前响应停止，
逐项显示进度与总耗时。保留 UID、状态、修订号、只读权限和 Flash 回读检查，
不重试写入，不修改固件、ABI、波特率或参数默认值。

验收：模拟慢应答时 UI 心跳持续、重复任务拒绝、读取中取消、退出等待资源释放；
参数事务回归、PR 检查、生成 v1.17.4 EXE 与同一 APP 的整包。
离线测量线程与 spawn 启动延迟；未实测的设备延迟不能当作实际改善比例。
回退：撤销本次上位机修改，原 1.17.3 整包保留。

## 结果

实现参数专用线程、逐项进度、操作耗时及读取间取消；SDK 仍由单一任务持有。
Tk 测试确认模拟应答等待期间界面心跳继续，重复启动拒绝，停止后完成队列消费和释放。
322 项单元、22 项集成及全部原生回归通过，PR 全部通过：
`outputs/runs/parameter-refresh-20261114/summary.json`。
Tk 多窗口测试有销毁后的 ThemeChanged 提示，测试退出码为零。

5 次源码解释器对比：spawn 启动中位 174.16 ms，线程 0.1524 ms。
此数据只衡量后台任务启动，不包括设备通信，也不是打包 EXE 或实机总刷新耗时。
原始样本在 `outputs/parameter-refresh-benchmark.json`。

已构建 CAN-Link-Test v1.17.4，内置原 APP v1.8.12 / Loader v2.3.4。
本次不接触硬件；串口/USB设备实际耗时和用户现场体验待新包验证。
固件、参数 ABI、PI、标定表和相电阻流程均未改动。
