# AT32F456 硬件功能检测方案 v3

2026-11-12 · 设计及离线实施记录。方案起点为 `the-system-refactor@76e91dc3`，实现基线为 `36625947`。AT32F456 驱动板及电机通过“硬件功能检测”取得通信、关相采样和双向运动结果。当前线上字段和操作入口见[协议契约](../../protocols/README.md#at32f456-硬件功能检测-v2)。

## 检测结果与取数

通信执行后仅显示**正常 / 异常**。板端每项完成后也只给正常或异常。“未测”用于工况、行程或证据不足，“未装”用于设备预设明确无输出霍尔。这两种是执行状态。板端 RAM 保留本轮均值、RMS、极值、实测角度和时间，供复核某一项。现有运动保护故障仍走原通道。

| 项目 | 从代码中获取的信息 | 本次合格条件 |
| --- | --- | --- |
| **主控与 AT32 通信** | 主控对目标节点单播现有 `GET_INFO(1)`，按 CAN ID、源目的、命令、sequence、长度和两级 CRC 核对应答 | 收到匹配的有效应答即正常。建议每次等 50 ms，最多 3 次，均未收到则异常。其他轴/旧序号的应答不计。合法 BUSY 短应答能证明链路可达，开展板端检查仍须读到匹配的设备身份和 APP 能力。通信异常时由主控出结果，同轮尚未取得的板端项显示未测 |
| **Ia、Ib、Ic、母线电流** | 关相、轴静止，从已完成的同拍 ADC 取 PA0/1/2、PA4 原码。三相用 `BspAdc_ReadRawChannel` 已折算的 12 位等效 cnt，母线为独立 12 位单次采样 | 四路各自满足**去均值 RMS < 10 cnt**，且**均值与 2048 的绝对差 < 300 cnt**。也就是 1748 < 均值 < 2348。任一条件达到界值即该路异常。关相零电流判据只用于静态段 |
| **母线电压** | PA3 母线电压原码按板级分压换算成 V，保存实际窗口的最小/最大瞬时采样电压 | **27.0 V ≤ Vbus ≤ 29.0 V**，两端可取。只有窗口内最小值和最大值都在范围内才通过。驱动段也观察这一测试供电范围，越界则记录并结束本次驱动 |
| **电机 NTC** | 从原有 PA7 温度消费者取得新读数及时间戳。检查有效、有限，距最新样本 ≤30 ms | 在室温环境进行，允许的测试温度为 **0～60 °C**，两端可取。已知环境超界则停止本轮测试，板端未测项保持未测。若 NTC 读数超界且实际温度未知，显示实测温度及“工况不满足”，不进入驱动。在已确认室温时读数仍超界、无有效换算或持续不更新，温度项异常 |
| **电机端 MT6835，静止** | 取同一次 SPI2 DMA 的新 21 位机械角、芯片状态和 CRC。用原始机械角在跨零处展开，不用速度估计或低通输出 | 芯片有可信的有效在线应答，且静态窗口**峰峰跳动 < 0.01°**。峰峰值取整个窗口展开角的最大值减最小值。相等即超限 |
| **输出轴双线性霍尔，静止** | 从已发布的配对快拍取 ADC2 PA5/PA6 的 sin、cos，两路分别去掉各自的均值 | sin 和 cos 的 **RMS 分别 < 10 cnt**。任一路达到 10 cnt 就是霍尔静态项异常。先查有效轴预设的 `has_linear_hall`，装配未知显示未测 |
| **电机端角度，驱动中** | 带时间戳的电机轴独立实测角，应用既有安装方向。记录正、反两段轨迹及各自的净位移符号 | 两个驱动方向均能连续跟随，无不合理跳变或已确认实际转动时的卡住。两段角度的旋向均与实物相符 |
| **输出轴霍尔，驱动中** | 从同拍 sin/cos、该轴有效的校准参数计算独立霍尔角，带时间戳记录，同时保留两路原码的实际极值 | 正、反两段均连续、方向与实际输出轴相符。每一路分别满足 **95 ≤ 最小值 ≤ 最大值 ≤ 4000 cnt**。这是全段实测值的允许范围，有限行程按实际经过的角段检查，不要求触及两个边界或转满一圈 |

静态窗口拟取稳定后连续 **100 ms**，20 kHz 下为 2000 个新快拍。所有 RMS 用 `sqrt(Σ(x−均值)²/N)`。三相已归一化的原码保留小数，判定前不取整。缺采样时不重复使用缓存补齐窗口。NTC 按自己的慢采样时钟更新。现有启动零偏资格比应急宽窗更严，某路静态检查可以正常而运动启动受现有保护拒绝，此时动态项未测。[AT32 ADC 与换算](../../../firmware/platform/bsp/mcu/at32f456/adc.c) · [本次上电校零](../../../firmware/motor/sensing/motor_current.c) · [电压、NTC 与启动条件](../../../firmware/app/motor_state_machine.c)

### 取得可信的电机端静止角

现行 `Encoder_IsOnline` 只记录是否取得过首样本，控制环读角使用高 16 位。检测应在同一笔已完成 DMA 中取原始 21 位及 CRC，在固定窗中核对新帧和芯片状态。21 位每圈 2,097,152 cnt，因此峰峰跨度 58 cnt 约 0.009956°，59 cnt 约 0.010128°。以原码作严格比较，跨 0° 的小摆动按真实短距离计算。[现有读角入口](../../../firmware/motor/feedback/encoder_feedback.c) · [AT32 帧布局](../../../firmware/platform/bsp/mcu/at32f456/encoder_spi.c) · [MT6835 手册，角度、状态与 CRC](https://www.magntek.com.cn/upload/pdf/202407/MT6835_Rev.1.3.pdf#page=25)

如果整窗都是全零帧，全零角和状态也可能恰好产生零 CRC。此时可在关相、SPI 总线空闲时只读已登记且有可辨识预期值的配置，或在另一静止角重新取得可辨识的有效应答。无法证实在线时显示未测，暂缓驱动。超时/持续坏帧判电机端静态异常。若现有 DMA 等待使前台也停滞，由主控记录通信异常和板端报告未取得。[芯片寄存器表](https://www.magntek.com.cn/upload/pdf/202407/MT6835_Rev.1.3.pdf#page=31)

## 上电驱动怎样检查连续性与实际旋向

1. **建立机械参照。** 固定观察轴端和正向定义。工装方向信号或人员观察轴上标记，分别记录两段的真实旋向。有减速器时按已知传动方向把电机轴与输出轴统一到同一坐标，速度和位移按活动减速比折算。保留原始角增减与按安装方向修正后的符号。使用事先确定的安装方向，避免在检测中自动翻转符号掩盖安装反向。
2. **实际驱动两个方向。** 供电、温度、电流和必要反馈满足本轮工况及现有启相条件后，台架拟用已有的限流开环电流模式 10，让正、负电频分别驱动一小段，中途减速停稳。驱动电角由控制器生成，待测编码器和霍尔独立提供观测。117 启动、116 给限流/频率目标、现有租约续期、110 停机。按轴的极对数、减速比和已知起点选低速、短行程及最长时间。PITCH 等有限位轴按可用空间约束实际行程，工装监视实际位置，电频积分只能估算行程。失联、保护、超出工况、意外反转或到期均结束驱动，通信中断时由现有板端租约处理。确认关相后才结束会话。仅检查或读报告不会启相。[开环相位与电流控制](../../../firmware/motor/control/motor_control.c) · [轴装配与行程](../../guides/at32f456_five_axes.md) · [运动协议及租约](../../protocols/README.md)
3. **逐段判连续。** 用相邻新样本的最短有符号角差展开，再按时间检查。`|角差| ≤ 该轴本次测试速度上界 × 实际采样间隔 + 测量裕量`，各项取同轴单位。裕量使用该传感器实测静态角波动及量化分辨率，0.01° 仅用于电机端静止检查。工装确认转过了显著大于噪声的位移时，传感器也必须有相应的前进，持续卡值或中途反向超过裕量都判异常。正反段分开计算，不让往返位移互相抵消。样本缺失到无法可靠展开、未观察到实际运动等，动态项未测。
4. **逐段判同向。** 电机端比较实测电机角与真实电机旋向。装有霍尔时比较其独立角与真实输出旋向，再核对两条轨迹按安装方向和传动关系折算后同向。应读取 `linear_hall.val.angle_rad` 或 Type 126 的有效 `hall_position`。同一页的 `tracked_position` 含转子增量，用它与转子角互证会漏掉霍尔反向。仅有速度指令或两个传感器互相一致时，能记录相对方向，绝对物理同向仍未测。无霍尔的轴照常检查电机端。[独立霍尔角计算](../../../firmware/motor/feedback/linear_hall.c) · [采样发布与跟踪角](../../../firmware/app/motor_axis.c) · [传动方向与减速比](../../../firmware/motor/feedback/output_encoder.c)

## 一个入口和一帧结果

AT32 两个 APP 工程共用一份检测逻辑。板端在 `BspAdc_CompleteFast`、编码器 DMA 及 NTC 现有完成点保留同拍数据，快中断有界复制小块，前台累计统计并发布同一轮 RAM 报告。主控工具编排“通信 → 关相静态 → 驱动往返 → 停机”，对照工装/观察到的实际旋向后给出最终结果。没有完整收齐本轮证据时，界面保留已知异常，未完成项目显示未测。适配仅限 AT32F456。[AT32 应用入口](../../../projects/at32f456/application/main.c) · [运行与 BSP 边界](../../../ARCHITECTURE.md)

沿用拟议 Type 127，按 GET_CAPS bit19 探测支持。空请求只读本轮报告。启动采集建议用 8 B，P0=格式号 2、P1=启动采集 1、P2=模式（静态 1、含驱动 2）、P3=0、P4～7=预期上次序号。受理后建立新序号，重复请求复用原轮。含驱动模式在静态阶段后等待同一检测会话中显式受理的运动命令，按两段实际生效的异号目标划窗，续约与同目标重发不另开窗。旧 APP 或 Loader 能应答时仍显示通信正常，板端检测可显示不支持。建议成功回包使用下面的 21 B 载荷，`P` 从业务载荷 0 起算，多字节整数均为小端。[现行 CAN 帧与命令](../../protocols/README.md#can-frame)

| 载荷位置 | 内容 |
| --- | --- |
| P0～3 | 公共命令 result、detail，各 u16。用于本次查询能否完成 |
| P4 / P5 / P6～9 | 格式号 2、阶段、本次检测序号 u32。阶段为 0 未开始、1 静态、2 待驱动、3 驱动中、4 结束、5 中止 |
| P10 / P11 / P12 / P13 | Ia、Ib、Ic、母线电流的静态结果，各 1 B |
| P14 / P15 / P16 / P17 | 母线电压、NTC、MT6835 静态、霍尔静态，各 1 B |
| P18 / P19 | 电机端、霍尔的板端动态结果，各 1 B，涵盖实测连续性，霍尔还含原码范围。实际旋向由主控结合 P20 和机械参照判定 |
| P20 | 实测方向。bit1～0、3～2、5～4、7～6 依次对应电机去程、电机回程、霍尔去程、霍尔回程。每两位 0 无有效记录、1 正、2 负、3 有有效样本但无可辨位移。两轴均先正后负时此字节为 `0x99` |

P10～19 统一使用 `0 未测、1 正常、2 异常、3 未装`。“未装”只适用于已确认无霍尔的轴。主控保留已知异常，结合 P20 和机械参照判方向。确认轴在转而角度静止或反向即异常，两段均有足够证据且相符才正常。通信结论由主控本地生成，整板无应答也能显示异常。D16 起为业务载荷，D37～38 为 CRC16，D39～47 补零，整帧 48 B。日常界面只显示逐项结论，调试可用 Watch 读本轮 RAM，并用已有 108/126 读母线量、温度及有效输出角。

## 离线验收与实施顺序

实现基线已同步至 `the-system-refactor@36625947`。本轮接入两个 AT32 APP、CAN 工具和生产代码离线测试，并记录 Keil 构建及 PR 结果。业务 ABI 以协议入口和对应黄金向量为准。

- 校验电流四路独立判定、RMS 恰为 10 cnt、均值偏离恰为 300 cnt、母线电压 27/29 V 两侧、温度 0/60 °C 两侧及过期样本。
- 校验电机端原码 58/59 cnt、跨零静止和跨零旋转、合法零角与无证据全零帧，霍尔两路分别超噪声及各自极值 94/95/4000/4001 cnt。
- 回放带机械参照的双向轨迹、反向安装、错向、卡住、跳角、丢样、缺参照及无霍尔。验证旧节点/整板无应答和本轮结果逐字节解析。
- 本阶段在独立 worktree 交付计划和离线向量。实现时再接入 AT32 两个 APP 与主控入口，同步协议文档、黄金向量并做 PR 验证。真实带电转向、噪声及中断开销待对应台架核验，按约定在验证完成后合并。回退范围为新增的 AT32 采集/检测、主控编排与新命令。

本次 91 个离线设计向量通过，含阈值边界、跨零、双向实物参照、卡住、反向和 21 B 载荷解码。样本及参照由夹具生成，结果在 `outputs/hardware-check-compact-v3/summary.json`。现有 AT32 ADC/CAN 与协议链路原生测试也通过。quick 的 183 项 Python 单测仅文档卫生检查因基线的 120 处历史产物断链失败，21 项集成测试通过。本次变更的两个文档均未新增断链。

## 生产实现与验证

两套 AT32 APP 工程在板级入口绑定同一[检测模块](../../../projects/at32f456/application/hardware_check.c)。关相与动态采集共用单生产者队列，前台计算窗口和发布报告。两个轴角按各自时基展开，有效的传动方向标定参与相对旋向检查。上位机入口为 CAN FD 桌面工具的“硬件功能检测”或 [hardware_check 命令](../../../tools/bench/hardware_check.py)。无可辨位移且已确认实物转动时，主控将对应动态项判为异常。

本次只构建同一份 AT32F456 应用的两种目标。`ESC-APP-AT32F456-Standalone` 从应用自己的复位入口独立启动，`ESC-APP-AT32F456` 位于 Loader 后的 APP 分区。两者均通过 Keil 编译和链接，0 错误、0 警告。

- 生产 C 检测器通过精确边界、CRC/状态位、角度跨零、实物参照缺失、停滞/反转、传动方向、缺拍及停机代际注入。MT6835 驱动在全部 2,097,152 个角度上核对 DMA 数据。主控生成的真实 CAN 帧经过板端接收中断、检测器及发送队列后，由主控解析出本轮 Ia 异常。破坏 CRC 的启动帧被丢弃，同序号重发保持原采样窗口。
- 主控的 7 项离线测试覆盖通信超时、错节点/旧序号、Loader/旧 APP、双向驱动、失联停机及实物方向判定。桌面入口的默认关相模式及异常报告在 Tk 中验证。
- PR 运行 47 组原生检查和 21 项集成测试，均通过。190 项 Python 单测中，唯一失败为既有文档链接检查。与实现基线逐项比对，120 条缺失历史产物链接完全相同。格式、lint、工程布局、架构、接口和仓库卫生检查均通过。

真实板卡的模拟噪声、实际机械旋向及采集中断耗时留待指定台架实测。
