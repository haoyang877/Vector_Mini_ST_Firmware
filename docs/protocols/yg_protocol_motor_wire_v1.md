# yg_protocol 单轴电机线路契约 v1

日期：2026-09-24。状态：项目首批 Type 编号已由用户确认；公司《消息类型定义》表仍待同步登记。本文件固定离线可验证的线路字段，不代表功率级已验证或控制命令已开放。108 已按本版迁移为无会话查询。

## 统一帧

沿用公司统一帧：16B 头、payload、2B CRC16，小端。CRC8 覆盖头偏移 0～14（poly 0x9B、init 0）；CRC16 覆盖整个 16B 头及 payload（poly 0xBAAD、init 0xFFFF），均不反射。项目把 flags bit5 解释为请求业务回复、bit4 解释为业务回复；请求 `0x20`、回复 `0x10`，重试额外置 bit2。应用版本当前为 `0x01`。CAN FD 使用 29 位扩展 ID、BRS，仲裁 1 Mbit/s、数据 5 Mbit/s；控制消息禁止分片。

主控节点 `0x02`，电机节点 `0x03～0x07`。CAN ID 的 PF `0xEF` 只做寻址；业务 Type 仍在统一帧头偏移 6～7。所有按需命令由设备回复相同 Type、相同 seq、反向 src/dst。原文对 ACK bit5 和 CRC16 名称的文字冲突，以本文件的明确位/多项式及黄金向量作为本项目解释；公司原文勘误仍待同步。

## 单轴命令

| Type | 请求 payload | 回复 payload | 行为 |
| ---: | --- | --- | --- |
| 101 `SET_ENABLE` | 4B：`enable:u8` 为 0/1，余下 3B 必须为 0 | `result:u16, detail:u16` | 0 确认输出禁止；1 仅在硬件验证后进入 mode 5 三相低侧导通 |
| 108 `GET_MOTOR_STATE` | 空 | 45B：与 124 相同的全量状态布局 | 帧头 seq 对应查询；payload 的 `correlated_seq=0`；无新鲜样本时 `result=6` 且测量无效，非空请求 `result=3` |
| 110 `MOTOR_STOP` | 空 | 同上 | 停止请求；`result=0` 仅在功率输出禁止得到所有者确认后使用 |
| 116 `SET_CONTROL` | 20B：`mode:u8, flags=0:u8, reserved=0:u16, position_mrad:i32, speed_mrad_s:i32, iq_mA:i32, v_q_mV:i32` | 同上，另发一条关联的 124 | 模式和目标一同提交；不得隐式使能 |
| 124 `MOTOR_FEEDBACK` | 主动上报 45B，详见[全量反馈契约](yg_protocol_motor_feedback_v0_2.md) | 无 | 每条已通过帧校验的 116 恰好对应一条，拒绝时也报告当前安全状态 |

116 模式 1 仅用 Iq，2 仅用速度，3 仅用位置，4 用位置/速度/Iq，5 所有目标为零，6 仅用 q 轴电压；未使用字段必须为零。mode 0 使用 101 失能。mode 4 的 MIT 增益来源尚未确定，不应开放；mode 5 是低侧制动，不能用全桥关闭或普通 PWM 启动代替。mode 6 单位为 mV；功率限值由电机所有者检查。

线路结果码：0 已执行、1 已受理待应用、2 不支持、3 长度错误、4 字段错误（含过期序号）、5 状态不允许、6 忙、7 未授权源、8 内部失败、11 超范围、17 故障未解除。`detail` 为零或出错字段偏移。124 的 `result` 使用同一结果码；其 payload `correlated_seq` 指向 116，帧头 seq 是独立反馈流序号。108 的 `result` 也使用同一结果码，但 `correlated_seq` 恒为零。回复只说明业务状态；位置到位由实测位置判定。

当前应用状态投影按飞书顺序取 0 boot、2 init/starting、3 selftest、4 cali、5 idle、6 run、7 stop、8 fault_now、9 fault_over；1 upgrading 留给 Loader。mode 7/8 是当前标定状态的项目扩展，并非可由 116 请求的控制模式。没有电机温度或 Vq/Vd 的真实测量源时，124 对应有效位清零并发送整数最小值；不填造传感器数值。

## 黄金 CAN FD 向量

以下均从主控 2 发往电机 3，29 位 ID `0x08EF0302`；展示完整 CAN FD 数据区，末尾零是 DLC 填充，不参与应用 CRC。

101 `enable=1, seq=40`，DLC 24：

```text
5A A5 01 20 02 03 65 00 28 00 04 00 00 00 00 F3
01 00 00 00 31 BF 00 00
```

116 `mode=3, position=1000 mrad, seq=41`，DLC 48：

```text
5A A5 01 20 02 03 74 00 29 00 14 00 00 00 00 2D
03 00 00 00 E8 03 00 00 00 00 00 00 00 00 00 00
00 00 00 00 6B 82 00 00 00 00 00 00 00 00 00 00
```

黄金向量和字段拒绝检查位于 `tests/unit/yg_protocol_contract_test.c`。同 seq 重试必须避免重复应用目标；在 116/124 成对发送容量、序号去重和真实状态快照完成前，控制能力不得声明为可用。

108 空查询 `seq=42`，DLC 20：

```text
5A A5 01 20 02 03 6C 00 2A 00 00 00 00 00 00 FA
F5 DA 00 00
```

108 的正常回复复用 [124 的 45B 字段布局](yg_protocol_motor_feedback_v0_2.md)，但使用 108 回复帧头及查询 seq；电机温度和 Vq/Vd 当前没有真实测量源，保持无效哨兵。旧 108 会话前缀和 34B 状态体已删除；主机需按本版同步升级。测试固定空查询帧向量和 45B 状态 payload 向量。

## 迁移

旧 111 失能入口已退役；旧 108 的会话请求已删除，110 回复已改为 4B，主机须同步改版。首版不兼容旧线路格式。101/116 已有 CAN FD 路由；未完成安全使能时回复“不支持”，116 同时发一条关联 124。256 条序号历史支持单轴 200 Hz、1 s 内的同序号重传，旧于历史窗口的请求拒绝而不重复执行。124 已可从同一前台快照填充，但控制实际应用序号仍未接线；GET_CAPS 不声明控制能力。启动板级采样时钟时三相输出保持关闭，110/101 失能经停机所有者提交，软件确认取自三相六路输出使能位；真实栅极/相电压尚须台架验证。
