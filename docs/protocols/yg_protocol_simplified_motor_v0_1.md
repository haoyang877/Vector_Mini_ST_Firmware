# yg_protocol 简化电调协议 v0.1（设计提案）

日期：2026-09-23。状态：**依据飞书《电调通信协议》重拟，尚未成为线上 ABI，固件未实现本文控制命令**。本文件替代此前[业务 Type 分配 v0.3](yg_protocol_business_type_allocation_v0_3.md)和[电机 Payload v0.1](yg_protocol_motor_payload_design_v0_1.md)中的**电机启动/控制流程提案**；旧文件保留为历史方案，不作为新功能接线依据。**本文第 5 节的 12B/仅周期 124 反馈设想已由[逐命令反馈契约 v0.2](yg_protocol_motor_feedback_v0_2.md)替代。**

## 1. 原文、项目约束和边界

[飞书《电调通信协议》](https://wcnxj7iyqdkp.feishu.cn/wiki/M5KJwCZApilqfjk251XcktAPnxa)目前把正常电调控制归为两项：①使能/失能，且使能后默认进入页面称为“高阻态”的 mode 5；②设置控制模式**和**控制命令。其模式表定义 0 失能、1 电流、2 速度、3 绝对位置、4 MIT（位置/速度/电流指令）、5 页面所称高阻态。页面升级条目明确标注“由 AI 补充”，列出设备状态/信息、开始传输、传输中、完成和校验完成；不能把这些条目视为已批准的升级 ABI。页面**未给出业务 Type 数值、逐字节 payload、单位、回复格式和反馈格式**；本文件的这些内容均为项目建议，不能标成飞书原文。

用户补充的物理定义是：**mode 5 使能 PWM，三相下管全部导通**。为避免上下桥臂直通，进入该状态时三相上管必须关闭。它在通常电机驱动术语中属于低侧短接/制动，而非三相断开的电气高阻；[TI 驱动器资料](https://www.ti.com/lit/ds/symlink/mcf8329hs-q1.pdf)将“全部 MOSFET 关闭”的 Hi-Z 与“全部低侧 MOSFET 导通”的制动分别描述。TI 资料只说明术语和电流路径，**不证明本板硬件已经安全支持这个动作**。本文保留页面 mode 5 编号，并在实施中使用明确的 `LOW_SIDE_BRAKE` 物理语义；页面名称应同步修正。旋转电机进入 mode 5 可能产生制动力矩和环流，必须实测电流/温升并确定允许转速、持续时间及故障退出方式。

外层仍遵守[公司统一帧](company_protocol_source_readback.md)：`16B 头 + payload + 2B CRC16`、小端、CAN FD 29 位扩展 ID、单帧公司 payload≤46B。项目 CAN FD 位时序沿用仲裁 1 Mbit/s、数据 5 Mbit/s、BRS。主控按公司节点表为 `0x02`，电机为 `0x03～0x07`；项目旧记录的主控 `0x01` 仍须在部署配置中纠正。CAN ID 只负责优先级和寻址；业务 Type 位于公司头偏移 6～7。

本版取消拟议的 `ACQUIRE_CONTROL`、`RELEASE_CONTROL`、`session_id`、每命令 `request_id`、独立 `SET_MODE`、`MOTION_KEEPALIVE` 和单轴 `lease_ms`。唯一主控由节点 `0x02` 和部署配置约束；公司头 `seq_id:u16` 用于请求/回复关联和有界重试去重。新功能必须拒绝非授权源节点，不因没有会话字段而接受任意发送方。复位后的控制状态归于失能，旧目标不得恢复执行。此处取消的是额外业务握手，不取消故障、过流、失联等电机保护。

## 2. 最小业务命令

编号沿用已有项目候选，逐项核对与退役关系见[CMD ID 核对表 v0.1](yg_protocol_cmd_id_review_v0_1.md)。**公司消息类型表尚未登记**；正式编号可能调整。R 表示已有路由，P 表示仅提案，D 表示仅有编码/描述符。所有按需请求都需要同 Type、同 `seq_id`、反向 src/dst 的业务回复；设备主动周期上报没有逐帧 ACK。

| Type | 名称 | 状态 | 用途 |
| ---: | --- | --- | --- |
| 1 | GET_INFO | R | 设备版本、产品和启动代次；不进入每次控制流程 |
| 2 | GET_CAPS | R | 仅声明已实现的控制/反馈能力 |
| 101 | SET_ENABLE | P | `enable=1` 默认进入 mode 5 三相低侧导通；`enable=0` 进入 mode 0 失能 |
| 116 | SET_CONTROL | P | 一条消息同时选模式和设置该模式目标；不得隐式使能 |
| 108 | GET_MOTOR_STATE | R，但当前请求/回复格式不同 | 按需读取完整状态、故障和诊断量 |
| 124 | MOTOR_FEEDBACK | 已有 45B 离线编码器，尚未发送 | 单轴每条 116 后一条飞书字段全量反馈，见[反馈 v0.2](yg_protocol_motor_feedback_v0_2.md) |
| 110 | MOTOR_STOP | R，执行服务未绑定 | 故障/紧急停止入口；普通退出使用 101 失能 |
| 193 / 125 | GROUP_POSITION / GROUP_FEEDBACK | P | 五轴 1 kHz 同步目标与每轴 1 kHz 反馈的专用扩展 |

参数读取/写入、标定和升级仍是独立的低频业务；它们不参与启动位置控制的必经步骤。未实现的命令不加入运行路由或 GET_CAPS 能力位。现有 111 DISABLE 路由在实现 101 前应连同主机契约一起退役或明确重映射，不能同时存在两套失能含义；旧协议兼容不是本项目要求。

## 3. 模式和两个控制 Payload

所有目标整数按当前代码单位：位置 `i32 mrad`、速度 `i32 mrad/s`、q 轴电流 `i32 mA`。新增电压模式使用有符号 q 轴电压 `i32 mV`，可与当前固件 `Vq_Mode/vqRef`（内部单位 V）对应；它**不是**另一个需要角度/速度参数的开环电压模式。`Iq` 不是标定后的机械扭矩。页面未填写单位，本项目值须通过公司登记与主机黄金向量冻结。

| mode | 页面定义 | `SET_CONTROL` 中使用的字段 | 不使用字段 |
| ---: | --- | --- | --- |
| 0 | 失能，PWM 引脚全部失能 | 不用 `SET_CONTROL`；发送 `SET_ENABLE(enable=0)` | — |
| 1 | 电流/扭矩控制 | `iq_mA` | 位置、速度必须为 0 |
| 2 | 速度控制 | `speed_mrad_s` | 位置、Iq 必须为 0 |
| 3 | 绝对位置控制 | `position_mrad` | 速度、Iq 必须为 0 |
| 4 | MIT 控制 | 位置、速度、Iq | 页面对 Kp/Kd 没有定义；首版不能假定它们在帧里 |
| 5 | 页面称“高阻态”；用户定义为三相低侧全部导通的制动状态 | 所有目标都为 0 | 可能产生制动力矩，不能称电气高阻 |
| 6 | 项目新增：q 轴电压模式 | `v_q_mV` | 位置、速度、Iq 必须为 0 |

页面正文提到“电压”，但模式表未分配编号；用户确认首版需要，因此本提案申请 mode 6，并明确为 q 轴电压、单位 mV。若所需其实是 `Voltage_OpenLoop`，则缺少电角速度/相位等字段，必须另行设计，不能把它暗中解释为 mode 6。mode 4 也不能直接别名到当前固件 `Position_Impedance_Mode`，须先确认 MIT 算法及增益来源。

`101 SET_ENABLE` 请求 payload 固定 4B：偏移 0 `enable:u8`（0 或 1），偏移 1～3 `reserved=0`。驱动器受理 `enable=1` 后默认进入逻辑 mode 5：PWM/栅极驱动使能、三相上管关闭、三相下管导通；`enable=0` 必须切到 mode 0 并验证输出禁止后才回成功。具体 PWM 极性、死区、驱动器使能引脚和故障保护必须在本板硬件上验证，不能从协议字段直接操作寄存器。

从旋转状态进入 mode 5 前，应检查速度/电流和低侧制动允许条件；条件不满足时拒绝使能或执行已评审的受控减速，不能无条件合上三相下管。mode 6 的 `v_q_mV` 需按实时母线电压、功率级与产品限值校验，并要求编码器/电角度输入有效。

`116 SET_CONTROL` 请求 payload 固定 20B，完整公司帧为 38B，CAN FD 物理数据区仍为 48B：

| 偏移 | 字段 | 类型 | 规则 |
| ---: | --- | --- | --- |
| 0 | mode | u8 | 仅 1～6；mode 0 用 101 |
| 1 | flags | u8 | 首版必须为 0 |
| 2～3 | reserved | u16 | 必须为 0 |
| 4～7 | position_mrad | i32 | mode 3/4 使用 |
| 8～11 | speed_mrad_s | i32 | mode 2/4 使用 |
| 12～15 | iq_mA | i32 | mode 1/4 使用 |
| 16～19 | v_q_mV | i32 | mode 6 使用 |

请求的公司头置 ACK_REQUEST 位，回复同 Type/同 `seq_id` 并置 RESPONSE 位。首版统一回复 payload 为 `result:u16 + detail:u16`（4B）：0=已执行，1=已受理待应用，2=不支持，3=长度错误，4=字段错误，5=状态不允许，6=忙，7=非授权源，11=超范围，17=故障未解除。`detail` 首版为 0 或出错字段偏移。`result=1` 后必须从反馈确认目标实际进入控制周期；CAN 硬件 ACK 或回复到达都不表示机械到位。重传保持相同 `seq_id`，接收端在有限窗口内去重，不重复切模式或重置轨迹。

## 4. 正常位置控制：两条控制请求

```text
主控 0x02                              电机 0x03
   │ 101 SET_ENABLE(enable=1, seq=40)  │
   ├────────────────────────────────────>│ 校验故障/配置，进入 mode 5 低侧制动
   │<────────────────────────────────────┤ 同 type/seq 业务回复
   │ 116 SET_CONTROL(mode=3,           │
   │     position_mrad=1000, seq=41)    │
   ├────────────────────────────────────>│ 校验当前位置、限位和编码器；
   │                                     │ 从安全当前位置起步，交给位置环
   │<────────────────────────────────────┤ 同 type/seq 业务回复：OK 或 ACCEPTED
   │<─────────124 correlated_seq=41───────┤ 全量状态：参考/实际位置、速度、Iq 等飞书字段
   │ 101 SET_ENABLE(enable=0)           │
   ├────────────────────────────────────>│ 停止并禁止输出，确认后回复
```

这两条是**正常启动的控制请求数量**，不含各自回复和后续反馈。`SET_CONTROL(mode=3)` 从低侧制动进入位置模式时，必须先用当前位置建立初始保持参考，再将 1.000 rad 作为位置轨迹目标；不能直接把未检查的网络值写到 PWM 或 `MotorControl.posRef`。后续位置目标只需发送新的 116。单轴定点目标的保持/通信中断策略必须在开放远程使能前评审；不再为它增加通用会话或每目标租约字段。故障始终由本地保护路径停机。

例如 1.000 rad 的 116 payload 为 `03 00 00 00 E8 03 00 00 00 00 00 00 00 00 00 00 00 00 00 00`。主控到电机的普通管理 CAN ID 可为 `0x18EF0302`；实时目标建议优先级 2、CAN ID `0x08EF0302`。这只是候选字段示例，还不是可发给当前固件的黄金向量。

## 5. 反馈、同步和升级仍保持明确边界

当前 108 使用 8B 的 `session_id/request_id` 请求，成功回复为 12B 前缀加 34B 状态。简化版目标是 108 空 payload 查询；**124 已按[反馈 v0.2](yg_protocol_motor_feedback_v0_2.md)改为 45B 飞书全量字段候选**，每条 116 有同 Type 业务回复及一条关联 124。124 的公司头 `seq_id` 仍是反馈发送流序号，payload 的 `correlated_seq` 对应控制命令。该改动是线上 ABI 变更，必须同主机、黄金向量和测试一起实施；目前固件只有离线编码器，尚未发送 124。

五轴每轴 1 kHz 不能由每周期五条 116 加五条反馈直接推断可行。原[同步方案](canfd_1khz_sync_design_proposal.md)的单路 1M/5M 组目标＋五帧反馈估算已占约 84% 周期；本版保留一条 193 广播五轴未来位置和每轴一条 125 同步反馈，但不把先前提案的 180～194 全部管理命令当作启动必需项。节点顺序、时钟质量、缺包动作与物理同步误差仍需单独定版和实测。

升级沿用页面的顺序，把“传输中”“校验完成”视为状态而非各自新增一条命令。建议的最小通用业务为：1 GET_INFO/设备状态、UPDATE_BEGIN（镜像身份/长度/校验信息）、UPDATE_WRITE（offset+数据）、UPDATE_FINISH（整包校验）、UPDATE_STATUS（进度/最终结果）、必要时 UPDATE_ABORT。具体 Type、镜像签名、Flash 失败恢复和 Loader/APP 接口另行冻结；本文件不声称现有升级链路已可用。

## 6. 代码落点与评审门槛

现有 `yg_protocol_link.c` 只注册 1/2/108/110/111；`yg_protocol_motor_adapter.c` 对 ENABLE/SET_MODE/SET_TARGET 返回 UNSUPPORTED。`yg_protocol_status_adapter.c` 的已应用序号仍为 0。`ModeSwitch_Handle()` 目前的模式切换可能触发启动，且没有独立 mode 5 的三相低侧导通实现。因此不能仅添加 101/116 路由就对外宣称用户定义的使能态已经满足。

实施顺序：①冻结 mode 0/5 硬件行为、低侧制动安全边界、MIT 增益与 mode 6 电压范围、回复/序号规则；②提交 101/116/108/124 的版本化向量与主机镜像；③用现有电机状态机作为模式/功率唯一所有者，协议层只提交有界值对象；④单轴验证“mode 5 三相低侧导通且上侧关闭、制动电流/温升受控、位置目标从当前位置起步、禁用确实关闭输出”；⑤再接五轴同步和升级。每步按[新实施决策](../plans/active/2026-09-23-yg-protocol-simplification.md)验收，不在本轮改动固件或下载到设备。
