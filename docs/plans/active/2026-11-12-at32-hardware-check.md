# AT32F456 硬件功能检测方案与判定阈值 v2

2026-11-12 · 方案评审稿 · 已核对 `the-system-refactor@76e91dc3`。适用对象为主控、一台 AT32F456 驱动板及其电机。首要问题是主控能否按时收到目标板的有效应答。本文的 Type 127、能力位和检测阈值均为拟议设计，当前固件与上位机尚未实现该检测命令。首轮只做离线验证。

## 操作者怎样使用

在 CAN 工具提供一个“硬件功能检测”入口，选择目标节点、总线速率和“关相静态”或“关相静态＋手动转轴”。主控先探测目标，再按设备能力启动板端检测。Keil Watch 也可启动同一状态机并读取 RAM 报告，通信中断时仍可在板端排查。两个 AT32 APP 共用实现。A/B/C 独立判定，输出霍尔的 sin/cos 分别记录。

| 步骤 | 检测动作 | 操作者看到的结果 |
| --- | --- | --- |
| 0. 通信（优先） | 主控单播 GET_INFO 核对目标，读角色和 GET_CAPS。支持新服务且受理 START 时，紧接着发一组只读往返探测。旧 APP、Loader 或采样启动被拒也可单独测通信 | 目标节点/UID、往返成功数、丢应答、延迟、异常帧、服务是否可用。全板静默由主控直接出结果 |
| 1. 检查工况 | 板端采样只在 IDLE 或已实际关相的 FAULT 中受理。复核六路 PWM 均关闭、无待启相/标定。记录轴角色、会话代次、本次上电零偏资格 | 有效配置、装配项目、可执行项目。角色未知时将霍尔记为“待确认装配” |
| 2. 静置 | 保持轴静止，在约 0.5 s 的观察期内取得 3 个独立快窗，并记录 NTC 慢样本 | 各通道原码与工程量、零位、峰峰值、噪声、首个异常和重复次数 |
| 3. 手动转轴，可选 | 保持关相，在允许行程内单向慢转。观察 MT6835 跨零连续性及已装配霍尔的跟随。候选观察期 5 s | 实际覆盖的电机轴角、输出轴角、角差及未验证项目。未转动或行程不足时可保留静态结果 |
| 4. 锁存报告 | 每次报告带本次检测序号、窗口起止时刻和逐项结论。检测期间若启相、会话更换或出现维护写入，终止该次窗口 | 通过、异常、需复测、待验证、未装配；另外记录中止原因。一次供电异常可以与一次正常的编码器帧检查同时显示 |

“通过”要带范围，例如“相 B 关相零位通过”或“编码器手动跟随通过”。打开检测只观察采样，PWM、清故障、校准及 Flash 写入仍由原所有者控制。已锁存的启动零偏故障允许逐路排查原码，避免一条坏通道遮住其余通道。当前角色由预设声明，0x03 左轮、0x04 右轮、0x05 ROLL 无独立输出霍尔，0x06 PITCH 和 0x07 YAW 配双线性霍尔，产品预设减速比为 40∶1。[轴预设实现](../../../firmware/parameters/motor_axis_profile.c) · [五轴装配与行程](../../guides/at32f456_five_axes.md)

## 应急通信检查

| 检查 | 执行与候选判据 |
| --- | --- |
| 建立通信 | 主站 2 按选定节点和两段速率发扩展 CAN FD+BRS 单播。参数 `0x71` 默认 1 Mbit/s / 5 Mbit/s，现行 AT32 支持 12 种组合。记录适配器、通道和实际打开的速率。主机端打开/发送失败单独出码。只读探测不用写波特率或续运动租约。[AT32 速率与板级配置](../../hardware/at32f456_configuration_v1.md) |
| 确认应答者 | GET_INFO(1) page 0 请求为 12 B，成功回复 32 B，前 12 B 为 UID。验证扩展 ID、源目的、FD/BRS、响应 flags、命令、sequence、长度、两级 CRC、填充。发现阶段最多连续等 3 次，每次 50 ms。合法 BUSY 短回复证明目标有回包，记“服务忙”，继续独立评估链路。已绑定的 UID 不符立即报告身份异常。未绑定时只记录观察到的 UID［本轮后续须一致］。page 1 的 role 区分 APP/Loader，GET_CAPS(2) page 0 区分是否支持检测报告。可达的旧 APP 或 Loader 单独显示能力/角色。[现行设备查询](../../protocols/README.md#commands) |
| 定向往返 | 用同一 GET_INFO page 0 发 **20 笔、20 Hz、每笔时限 50 ms**，同时只挂一笔，应用层不重试。相邻探测序号递增并处理 u16 回绕。记录唯一按时回包数、超时数、首笔/最大/P95 往返时延和异常原因。只归集与本次探测关联的帧，其他节点、正常 124 主动反馈及其他业务流量排除。重复包只算一笔，超时包保留原序号，不能抵下一笔。ESI 与适配器错误帧分别计数。 |
| 主控判定 | 20/20 按时取得正确身份页且没有相关异常为“通过”。1～2 笔未获有效回复，或出现迟到、重复、错序、坏帧及服务忙，记“需复测”。**连续 3 笔无有效应答可提前结束，累计 ≥3/20 笔无有效应答判异常**。一个 CRC 错帧后同序号按时补到正确帧，记录一次完整往返及一项坏帧。已证实的主控总线关闭（Bus-off）、适配器失败、绑定 UID 错误优先单列。无有效回复时提示核对板卡供电、通道、两段速率和线束，保留原因待定位。 |
| 板端证据 | START 后首个约 1.1 s 窗口覆盖主控发出的 20 笔定向请求。记录本机接受的探测数、提交与完成发送数、Bus-off、错误被动、RX 溢出/丢队列、TEC/REC 首末值和窗口内上升。由原收发拥有者计数，按请求序号关联发送完成。读取状态不消费 FIFO、不清原有中断位。观察到有效请求、匹配的发送成功且无异常才给出板端通过。无探测流量或无法取得必要证据给“待验证”。提交发送、总线 ACK、主控收到匹配回复分别记账；最后一项只有主控能确认。[AT32 收发实现](../../../firmware/platform/bsp/mcu/at32f456/can.c) · [主机现有编解码](../../../host_app/upgrade_client.py) |

链路结果由主控独立留存，带上时间、节点、UID（若能读到）、两段速率、判据版本。板端结果附本次检测序号。通信中途丢失时保留已经取得的证据，把未读到的传感器结果标成“待验证”。通信检查的发送、接收与计时可以复用现有 CAN-Link-Test 工具，增加单节点应急入口。其现有 fixed 模式使用 108，该命令可能续上位机位置会话，本方案用只读身份查询。[只读收发与时延统计](../../../tools/bench/five_axis_can_stability.py) · [108 处理](../../../firmware/communication/yg_protocol.c)

## 六项传感器判据

**沿用**指现有源码中的判据或器件定义，使用时保留原来的工况。**候选**用于离线造例和首批台架筛查，越界先标“需复测”。**待定标**指需要实物参考才能给出精度结论。所有 ADC 数字以下均按等效 12 位 count 表示。

| 项目 | 沿用的判据及单位 | 建议增加的判断与排查 |
| --- | --- | --- |
| **A/B/C 相电流**，PA0/1/2 | 20 kHz 下，上电校零统计 2048 拍，约 102.4 ms。启动零偏资格按各相均值 **[1948, 2148] count**。ADC1 每相硬件累加 4 次，除以 4 后保留小数 | 关相应急筛查的独立窗口均值放宽到 **[1920, 2176] count**。每相去均值 RMS **≤3 count**、峰峰值 **≤16 count**、相对已发布上电零偏的均值残差 **≤4 count，约 40 mA**。工装通入已知正负电流才能核对增益、极性和相别 |
| **母线电流**，PA4 | ADC2 单次采样。2048 拍启动零偏资格仍用 **[1948, 2148] count**。每 count 约 **20.15 mA**，相电流约 **10.07 mA** | 关相应急均值 **[1920, 2176] count**，相同负载下相对已发布零偏的残差 **≤4 count，约 81 mA**。PA4 的 RMS 和峰峰值先记录，取多板基线后定限。用流过同一分流器的已知正负参考电流核对增益/极性，记录辅助负载 |
| **母线电压**，PA3 | 分压为 100 kΩ / 3.3 kΩ，标称 **25.226 mV/count**。启动准入要求滤波 Vbus 在 **[25.6, 33.8] V** 且瞬时 Vbus **<34.5 V**。分别报告采样、供应电压和准入状态 | 与端子万用表同步比对。候选误差 **≤max(0.30 V, 2% × 参考电压)**。29.00 V 标称约 1150 count。测得 24 V 且万用表也为 24 V 时，报告“供电低于启动窗口”；万用表约 29 V 而 ADC 贴地时，排查 PA3 分压、接地和 ADC 通道 |
| **电机 NTC**，PA7 | 10 kΩ @ 25 °C，B=3950 K，1 kΩ 下拉；升温时原码上升。监督每 **10 ms** 消费新结果，样本年龄 **>30 ms** 过期。板级已定义 **2 count** 轨边裕量和 **[−40, 150] °C** 换算诊断区。当前驱动只对 0 或 ≥4095 的原码返回 NaN，这些诊断常量尚未全部用于运行判定 | 拟按独立慢样本判断。连续 **3** 个新样本 **≤2** 或 **≥4093 count** 分别提示低轨（检查 NTC 开路/对地短接）或高轨（检查 NTC 短接/对 3.3 V 短接）。温区边界用于排查换算。热平衡后与参考温度计的误差候选 **≤3 °C**；绕组工作温限须取电机规格 |
| **电机端角度**，MT6835 / SPI2 | 已完成帧含 21 位角度、3 位状态、8 位 CRC。MSB 先入，多项式 **0x07**。仅从通过 CRC 的帧解读超速、弱磁、欠压，三种状态独立计数 | 静止峰峰角 **≤0.3°（电机轴）**。动态按环形差、实际时间及 0.3° 抖动裕量判断跳变。独立见证单向转过 **≥8°** 而编码器全程跨度仍 **≤0.2°**，提示疑似卡住。静止恒值或合法零角可正常。完整性仍要求 0 错帧，单个 CRC 错记录并复测，持续错帧定位 SPI/编码器链路 |
| **输出轴双线性霍尔**，PA5/6 | 现有标定原码极值 **[10, 4086] count**、完整扫圈时 sin 和 cos 各自半峰峰值 **≥800 count**。轴角色和减速比取活动配置 | 应急筛查逐路电平范围 **[8, 4088] count**，持续碰到 0/4095 单列。确认实际转满输出轴一圈才检查每路半幅 **≥750 count**。已校准且电机端参考健康，输出轴单向实转 **≥10°** 时局部跟随允许误差 **≤4°（输出轴）**。PITCH 装机用局部判据。缺标定、行程不足和未装配分别显示 |

## 故障类型、证据来源与反馈

### 现有代码已经能读到什么

- **通信和保护。** GET_INFO 能验证目标与主站之间完成了一次往返。现有 108/124 的业务载荷 P4～7 可读运行保护位，其中 bit6 是既有 CAN 断连，bit14 涵盖电流零偏等多种原因。两者都无法替代逐笔超时或逐通道的故障证据。[运行保护位](../../../firmware/app/app_protocol.c) · [报文格式](../../protocols/README.md#feedback)
- **模拟量、温度和输出角。** 108/124 的 P24～25 是有效位，P26～27 为母线电压，P28～29 为母线电流，P36～37 为电机 NTC 温度，有效性看 bit9。AT32 配置启用 PA7 电机 NTC，片内温度采样关闭。Type 126 已能读霍尔装配/有效标志、霍尔角、跟踪角、样本年龄及计数。三相逐路原码、NTC 轨边、MT6835 原帧/CRC 和霍尔原始 sin/cos 需通过本次拟加的采集与证据页取得。[AT32 采样开关](../../../firmware/config/board_config.h) · [温度与角度反馈实现](../../../firmware/app/motor_axis.c) · [现有反馈编码](../../../firmware/communication/yg_protocol.c)
- **现场定位。** 主控报目标无应答时先保存请求 ID、序号、实际两段速率及等待时长。能经 Watch 读取板端时，对同一探测窗口核对接受请求数、提交回复数和确认发送完成数。接收计数为零、收到了请求但回复未发出、回复已发出但主控未收齐分别指向不同排查环节。CAN 应用帧的 CRC8/CRC16 可从收到的字节复算。被控制器在物理链路层丢弃的报文只能从控制器错误状态、错误计数和缺应答旁证。

### 诊断项的状态

“硬件功能检测”有两份独立观测。主控知道哪一笔按时往返、哪一笔没有应答。AT32 知道本机 CAN 控制器的状态以及各个传感器实际给了什么数据。主控按节点、观测到的 UID 和本次检测序号拼成一份报告。板卡完全静默时，主控可以独立出具通信结论，板端各项显示“未取得本次报告”。上次成功的数据须标明上次的序号与时刻。

每个检查项有一个状态和一个可同时置多位的原因掩码。显示码为 `(组号 << 8) | (原因位序号 + 1)`，16 位十六进制，位序从 0 起算。例如 `0x0302` 是 B 相噪声 RMS 超限，对应 B 相原因字的 bit1。原因码表示观测到的现象，维修人员可据此检查对应路线。

| 状态值 | 含义与使用条件 |
| --- | --- |
| 0 未执行 | 本次还没有进入这个步骤，或因中止未获得该项证据 |
| 1 通过 | 本次所选范围有足够样本且满足判据。报告须注明关相静态、手转或参考比对 |
| 2 需复测 | 候选宽限超出、偶发错帧、重复/迟到等。记录窗口数或次数 |
| 3 异常 | 出现已定义的硬判据，例如 Bus-off、连续无应答、持续贴轨、确认后的停采或持续 CRC 错。供电越界标明“供电” |
| 4 待验证 | 缺校准、独立参考、运动行程或必要观测源。装配未知也在此处说明 |
| 5 未装配 | 已确认该轴没有此传感器，仅在配置有明确依据时使用 |

对已装配且已执行的项目，汇总优先级为异常、需复测、待验证、通过。同一项既触轨又缺参考时，两条原因都保留。静态模式只承诺静态筛查，未选择的精度/手转测试不阻止静态通过。原因在本次会话累计，重复读报告不清位。新一轮从新序号开始。现有 `MotorFault_Report` 和 108/124 中的运行保护位继续由运动保护所有者维护。[运行故障处理](../../../firmware/motor/protection/motor_fault.c) · [旧保护位映射](../../../firmware/app/app_protocol.c)

**判定需要几次观测。** 电流 RMS、峰峰值、均值残差和角度抖动属于候选宽限。任一有效窗越界记“需复测”，三个独立窗中至少两个越界再标明“重复超限”。电流/母线电压的持续贴轨候选为至少两个完整快窗的每个样本均 ≤2 或均 ≥4093 count。霍尔 [8, 4088] 外的单次读数先复测，同一路在至少两个完整窗持续处于同一侧则报异常。NTC 同侧连续三个新样本、同一芯片告警连续三个有效帧、连续三个 SPI 错帧或控制器 Bus-off，分别报告对应异常。硬过压按瞬时值独立记录。无激励的电流中点、静止零角和有限行程的小霍尔半幅都不足以判硬件损坏。

**外部参考的归属。** 电流工装、端子表、温度计和手转刻度由主控记录数值、单位、时刻及工况，与同一次报告/窗口配对。主控可以在相同的组和原因下追加“外部参考比对”结论，保留原板端状态和原字节。缺少这些条件时只交付已测的静态/相对项目。每条导出记录至少含来源、节点/UID、本次序号、检测范围、状态、原因、观测值、阈值及其版本、有效样本数、首次异常时间。旧 APP/Loader 能应答但缺少自检能力时显示“链路可达 / 设备不支持本项”。

## 怎样读取结果及其字节位置（拟议 ABI v1）

现行 Type 108/124 的 45 B 载荷中，P4～7 是运行保护位，P42～44 是节点、状态和模式。公司帧单帧最多 46 B 载荷。拟在 AT32 APP 使用独立 **Type 127 / 0x007F**，通过 GET_CAPS.features **bit19 / 0x00080000** 宣告。上述编号已在本次重构基线筛过占用，待实现时登记到现行协议及黄金向量。旧设备对未识别命令可能静默，应先查能力。现场只想知道通信好坏时，现有 GET_INFO 足以执行往返检查。[现行帧和命令表](../../protocols/README.md#can-frame) · [现行反馈编码](../../../firmware/communication/yg_protocol.c)

| 主控动作 | Type 127 请求 payload（小端，字节从 0 编号） | 应答 |
| --- | --- | --- |
| 读总览 | 空载荷，无副作用 | 下表 43 B。首次上电可读到 `run_id=0`、各项未执行 |
| 启动 | 8 B。`[0]版本=1 [1]操作=1 [2]模式 [3]保留=0 [4..7]上次读到的 run_id`。模式 1 关相静态、2 静态＋手转 | 仅主站 2 可启动。受理回 43 B，总览带新序号。相同来源、序号和参数的重发返回已受理的同一轮。检测忙或前置序号已过期，返回错误或重读提示 |
| 读单项证据 | 8 B。`[0]版本=1 [1]操作=2 [2]组号01～09 [3]保留=0 [4..7]本次 run_id` | 44 B 证据页，包括本组的原始量或统计量。run_id 过期返回 4 B 结果，避免读错轮次 |

**总览帧。** `P` 从业务载荷 0 开始，`D` 从 CAN 数据区 0 开始。所有多字节数手工按小端编解码，不依赖 C 结构体对齐。

每组固定三个字节 `[状态, 原因低字节, 原因高字节]`。例如 B 相同时发生 RMS 和峰峰值超限，P22～24 为 `02 06 00`，主控显示 `0x0302` 与 `0x0303`，状态为需复测。若此时 MT6835 连续错帧，P37～39 可同时为 `03 01 00`，显示 `0x0801`。主控超时 `0x0A01` 直接进入主控记录；板卡没有返回帧时不填造 D32～58。板端 Bus-off `0x0101` 可查 Keil Watch 的 RAM 快照，链路恢复后也可按同一 run_id 读回。

**单项证据页。** P0～3 为命令结果，P4～7 各为版本、组号、状态、数据有效位图（bit0～5），P8～11 为 run_id，P12～13 为原因掩码，P14～15 为有效样本数（上限 65535）。P16～19 为从本轮开始至首次异常的毫秒数，尚无异常为 `0xFFFFFFFF`。P20、24、28、32、36、40 起各放一个 i32，小端。无效槽位写 0 且清对应有效位，因而可以区分“实测为零”和“没有数据”。44 B 业务载荷可装入一帧 64 B 的 CAN FD 数据。主控负责同一时钟域的请求与应答记录，原生 RAM 快照保留各窗口的时刻和详情。

| 02～05 电流 | 均值、去均值 RMS、峰峰值、相对已发布零偏的有符号残差、最小值、最大值，单位均为 0.01 count。取首个越界的完整窗，均正常时取最后完整窗 |

## 采样和实现位置

- **调度。** 建议用一对 AT32 专用的 `firmware/app/at32f456_hardware_check.c/.h` 集中实现 `HardwareCheck_Start`、`HardwareCheck_CaptureFast`、`HardwareCheck_Process` 和 `HardwareCheck_ReadReport`。板级 main 只连接中断和主循环。CAN 与 Keil Watch 进入同一个采集状态机，前台编码器读一致的已发布报告。采集及判定只链入 AT32 的独立 APP 和 LoaderApp 两个工程。通用协议只负责按已注册能力路由和编解码，BSP 负责硬件快照。[AT32 应用入口](../../../projects/at32f456/application/main.c) · [架构职责](../../../ARCHITECTURE.md)
- **快窗。** 检测激活期间，每窗复制连续 **128 个已完成快拍**，20 kHz 下约 6.4 ms，附序号和实际时刻。三个窗口复用同一固定缓冲，前台归还读槽后才可重新采集。快中断只做有界复制，均值、RMS 和 CRC 在前台计算。手动阶段用带时间戳的降采样轨迹覆盖更长行程。标称快拍间隔 50 µs，候选以 **>75 µs** 标记间隔缺口。到 0.5 s 截止仍无三个连续有效窗，就报告覆盖不足。保留异常拍前后数据、原始峰值及缺口数。[快采样时序](../../architecture/at32f456_pwm_adc_driver.md)
- **传感器读数归属。** 在 MT6835 DMA 完成后、下一事务开始前取同一帧的角度、状态和 CRC；当前控制入口只返回角度。NTC 的原码、温度与时间戳由原有唯一消费者在同一次完成事件中发布。前台读取已封存数据，避免再次消费 ADC 标志或占用 SPI。若 DMA 硬卡在现有快中断的等待循环，前台也会停止运行；此类故障由调试端用独立时钟检查快拍进度和检测心跳，报告“采集停滞，待定位”。[MT6835 传输](../../../firmware/platform/bsp/mcu/at32f456/encoder_spi.c) · [温度监督入口](../../../firmware/app/motor_axis.c)
- **结果。** 每项保留适用性、实测值/单位、使用的阈值及版本、有效样本数、首次异常时刻与原因。电流窗口输出均值、去均值 RMS 和峰峰值；编码器输出错帧数、状态位、最大环形步长；霍尔输出两路极值、覆盖角和参考角差。没有外部参考时，绝对精度项标“待验证”。已装配而没有新样本须显示采集异常；已确认无霍尔的轴标“未装配”。

## 阈值怎样定版

1. **冻结工况和计算口径。** 随记录保存板卡修订、轴角色/型号、减速比、固件版本、供电、环境温度、是否关相、采样率和窗口长度。去均值 RMS 取 `sqrt(sum((x−mean)²)/N)`，峰峰值取 `max−min`。静止噪声在各自窗口内计算。首版候选规则为三个独立窗中至少两个超限提示“重复超限”；单次尖峰、任一 CRC 错和状态位均单独留痕。
2. **用独立参考验证误差。** PA3 与端子万用表在低、中、高三个稳定供电点对照。PA4 用同一电流路径，三相在专用工装以已知方向的电流依次验证 A/B、B/C、C/A 回路，记录零点、正负斜率及通道对应关系。NTC 用精密电阻箱和同位置参考温度计分别验证板端换算、传感器安装。以标称曲线造例，33 kΩ 约 120 count / 0.35 °C，10 kΩ 约 372 count / 25.0 °C，3.3 kΩ 约 952 count / 52.2 °C。机械绝对角精度使用独立角度量具。
3. **从误差预算和样本决定界限。** 电流、电压预算包含分流/分压电阻公差、放大器增益/偏置、ADC 参考与温漂；温度另计 R25、B 值公差和热平衡误差。按板卡修订、装配、冷热机和供电范围采集多台良品、多个独立上电窗口，并在另一批样本上核对误报和漏报。用已知断线、短接、固定中点、偏移和错帧样本检验检出能力。正常与故障分布重叠时，增加独立激励或保留“需复测”。
4. **处理临界值。** 有产品容差 `L` 和比对结果的测量不确定度 `U` 时，`|误差|+U ≤ L` 可判通过，`|误差|−U > L` 可判越限，中间区间复测。当前待补的是目标绝对精度、器件公差、仪表精度及批次实测。现有阈值引用其源码定义，新增候选值集中放在 AT32 检测模块，附单位、比较符、窗口和适用工况。阈值定版须记录样本范围、误报/漏报和生效版本。

本轮在独立工作树提交故障字典与读出设计。实现时先把字典、协议版本、兼容性和黄金字节向量登记到对应模块，接入本板采集、主控判定以及两个 AT32 工程，再做原生故障注入、工程编译和 PR 验证。实机结论随具体板卡、接线和测试记录单独出具。功能完成并按约定验证后再合并到重构分支。需要回退时可撤销能力注册、AT32 模块接线、主控入口及对应的新协议项。

离线证据在忽略目录 `outputs/hardware-check-communications-v2/`。主机实际编解码器与固件 C 端点通过内存 CAN 口收发 GET_INFO/GET_CAPS，截止时刻和坏帧由夹具注入。22 个链路判定场景、2 个现有端点路由/能力用例、2 个拟议总览和证据页字节向量共 26 项通过。现有 CAN 寄存器/收发、协议核心、链路、旧电机反馈与 AT32 的 12 种速率回归均通过。传感器的标称尺度与候选限值用于造例，实物绝对精度及现场误报率待测。独立工作树在修改前后均有 120 处历史产物的既有文档断链，quick 的文档卫生单测会报告这些记录。
