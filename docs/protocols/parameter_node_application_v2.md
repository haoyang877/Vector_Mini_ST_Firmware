# 设备地址与应用包络分离 v2

日期：2026-10-16。此版本修改装载策略，**不声明与旧地址派生行为等价**。
schema12、4304 B、CRC、参数 ABI 和16 KiB分区不变，不新增参数ID或自动迁移Flash。

## 独立来源

- 设备地址只取记录偏移0的`node_id`，须为1～254的有限精确整数；AXS角色不再覆盖它。
  APP与Loader读取同一字段。参数ID3仍只读，端点在启动时冻结，不新增在线换地址。
- 应用`speed_limit_rad_s`仍由偏移2152的独立字段和参数ID1表达，单位与读写权限不变。
  编译期应用包络为既有20 rad/s，不再按节点选择；有效AXS数值包络只进一步收窄。
- 首次默认运行限值仍为0.5 rev/s和6 A；非法速度（非有限、非正或超过20 rad/s）
  回低速默认，再受AXS收窄，不能回到20 rad/s作为默认运行值。
- 硬件感测/保护归platform，物理模型和校准电流归motor，运行限值/外环归application，
  node与个体零偏归device。模型、控制数学、物理保护门槛和标定字节不变。

## 兼容行为与部署例子

| 原始schema12字段 | 旧APP装载值 | v2装载值 |
| --- | --- | --- |
| node=3，无AXS，speed_limit=10 | node=3，运行上限π rad/s | node=3，运行上限10 rad/s |
| node=7，AXS1 roll范围±1 rad、速度0.7，speed_limit=20 | 角色覆盖为node=3，speed_limit=π | node=7，speed_limit=0.7 rad/s |
| node=7，无AXS，speed_limit=π | node=7，速度上限π | 两项保持 |
| 任意有效节点，无AXS，speed_limit=NaN/0/21 | 依节点回退到20或π | 回低速默认π，不改地址 |

表格只比较装载的`speed_limit_rad_s`，不是跳过其他门禁后的最终允许目标。
例如roll包络0.7的旧代码已经在控制目标入口另行收窄至0.7，新版没有取消这一限制。
无AXS的旧字段10不会被改写成更大值，但移除旧节点钳制后，有效速度上限确实可能增大。
这属于本批显式行为变化，不能写成“不提高旧运行上限”。不修改原始记录、不生成更高默认值、
不发速度目标；启动仍使用明确的零目标请求，改速必须另行给命令。

角色与显式node不一致的记录升级后会改变通信地址。例如roll的原始node=7过去APP用3、
Loader用7，现在两端都用7。部署前必须读取匹配记录并按显式node准备连接，不能把旧角色表
当作发现地址；回退旧APP又会恢复其旧映射。本批没有操作设备或回写参数。

独立生产身份页中的SN不变；参数记录的校准/LUT/CRC布局不变。
3.5等分数节点不再被APP截断，而是损坏配置回退。
Loader对空白区、node=0的既有救援策略保留，不将它当成APP可运行配置。
如果未来需要独立持久化第二个产品硬上限或在线切换应用profile，应另行定义版本化契约。

## 定向证据

[黄金向量](parameter_node_application_v2_vectors.json)固定node、速度、AXS的原字节与前后行为。
`zero_fill_crc32`由独立Python zlib针对其余字节全零的4304 B记录计算，用于固定偏移和CRC；
不是可直接上设备的完整生产配置。原生夹具把这些字段叠到合法配置上，执行真实装载逻辑，
核对输入不变、1～254节点两端一致、AXS只收窄、非法地址/速度拒绝及ID1独立更新。
