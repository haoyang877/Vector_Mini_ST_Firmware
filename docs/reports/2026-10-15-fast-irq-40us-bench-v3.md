## 当前结论

软件优化与本轮台架验证完成。最终汇编包装测量覆盖完整原 C 中断处理函数，
**171,320 拍中的最大值为 37.118 μs，达到或超过 40 μs 的拍数为 0**。
该窗口仍不包含硬件异常入栈/返回，也排除了临时包装和统计；
**严格的完整异常占用小于 40 μs 尚未直接测量证明**，不能将上述结果改称完整 IRQ 最坏时间。

同 r3 口径下，run 5 的主体峰值为 40.512 μs；八函数移入 CCM 后，run 8/9
主体峰值均为 **37.376 μs**，主体加计数尾段同拍峰值均为 **38.318 μs**。
十轮计时及一轮普通固件的 mode 13 均完成候选 LUT 提交、进入保存并返回停机，关相检查通过。

固定通道热计算展开已合入源码并通过离线等价回归。同一 r2 分段插桩口径下，
step 26 峰值拍的热采样/更新段从 5.141 μs 降至 4.765 μs，减少约 **0.376 μs**。
不能将不同插桩镜像之间的时间差全部归因于算法优化。

八函数 CCM 布局已采纳到生产共用 scatter，最终普通/HIL 工程均 0 错误、0 警告。
普通无插桩固件已下载，CCM 启动复制与别名回读通过；随后完成 mode 15，恢复原运行
限流 6 A、标定电流 3 A，保存并复位回读。最终 `mode=0`、`ErrorNow=0`、三相高阻，
标定标志为 3，电零位为 18,727 Q15；热配置保持原值。

## 台架与计时口径

本轮数据为无阻尼轮电机配置，21 极对，速度 PI 为 Kp=0.06、Ki=0.6。
试验边界是相电流及 dq 电流最高 3 A、机械速度最高 30 rad/s、每轮超时 18 s。
探针、芯片身份及实读参数保存在各轮 `result.json`，不写入版本管理文档。

- DWT 换算为 170 cycles/μs；目标周期 8,500 cycles，即 50 μs。
- `budget_steps[64][8]` 按进入 IRQ 时的标定阶段分桶，覆盖新增阶段 36、37。
  主体耗时为计时器首次读取到主体结束读取之间；首读前、末读后代码另有开销。
- `budget_tail` 的主体加尾段最大值来自同一拍，不是两个独立最大值相加。
  该字段也不是完整 IRQ 耗时。
- IRQ 入口间隔仅统计相邻两次均在 mode 13 的有效区间。进入 mode 9 后的 Flash 保存
  屏蔽中断时间不在连续控制区间内，不能据此宣称保存期间保持 20 kHz。
- r1 含状态桶与峰值统计，r2 进一步加入相位及四段计时，r3 精简统计尾段，
  r4 改测嵌套 FOC/无感/标定任务。它们的附加指令、镜像布局和计时边界不同。
  r3_ccm 以 r3 冻结副本为基线，仅改变 scatter 放置，供同口径后续比较。
- 分段计时包含测量边界开销；嵌套段不可直接相加。运行环境、启动相位和 Flash 布局
  也会影响最大值，单轮最大值不等于已穷尽全部最坏工况。

## 完整 C 处理函数边界复核

`asm_wrapper_r3` 从最终普通固件副本生成，将原 ADC C 函数只改名，并在汇编向量中
用两次 `CYCCNT` 读取包围调用。窗口包含调用跳转、原 C 序言、ADC 分发、快环、
原 C 尾声及正常返回；原控制路径不插入分段计时。
包装保存 `{r4-r6,lr}` 共 16 B，保持 8 字节栈对齐，最终恢复 `EXC_RETURN`；
原 ADC C 函数体及 HardFault 等异常函数逐字不变。源码、反汇编、向量与入口字节已独立复核。

`timing_run10_complete_c/result.json` 记录 171,320 拍，最大 6,310 cycles（37.118 μs），
`>=40 μs` 为 0；峰值位于减速 step 29。关键阶段如下。

| 阶段 | 完整 C 窗口峰值 |
|---|---:|
| 准备 step 0 | 21.924 μs |
| PWM 使能 step 36 | 30.059 μs |
| 开环/锁速/交接 step 23 | 37.071 μs |
| 闭环采集 step 26 | 37.106 μs |
| 关相后提交 step 37 | 31.076 μs |

有效入口间隔 171,318 个，范围 8,492～8,509 cycles，无超过 75 μs 的记录。
统计包装、硬件异常入栈/返回与其他尚未覆盖的最坏工况仍在本结果边界之外。
run 10 与 r3 的窗口及镜像不同，不能用两者峰值之差再声称新增软件收益。

## 热计算优化与剩余热点

`motor_thermal.c` 将三相累计和四路热更新的固定循环展开，以私有内联函数保留四路
相同的更新规则。删除数组中转及循环索引，不改变原除法、浮点表达式、阈值、
20 kHz 电流采样和 1 kHz 热更新；不跳过无效输入检查。

计算顺序仍为：按 A/B/C 检查并累计，全部有效才增加样本数；先算全部四个热输入，
再依次更新四路热量。失败时保留此前已完成的部分更新、坏通道写回与原最大值规则。
独立旧实现对照覆盖 100,180 个累计状态及 288,035 个热窗口，全状态逐位一致。
详见 `thermal_candidates/report.md` 和 `thermal_candidates/production_native/`。

ARMCC 的两函数代码节合计增加 176 B，以消除临时数组和动态循环开销。
同 r2 A/B 的 step 26 峰值拍中：热段 874→810 cycles，观测器保持 566 cycles，
编码器完成保持 482 cycles，外层 mode 13 任务 3,166→3,164 cycles。
整体 step 26 主体峰值减少约 0.365 μs，均值减少约 0.231 μs；这些指标不能混作一项收益。

该峰值拍的相位为热样本计数 19、编码器分频 8、速度 PI 计数 2、RTT 分频 4。
已避开编码器和速度 PI 的慢拍，剩余峰值不是它们恰好叠加导致；继续改相位不能替代
减少每拍实际工作量。r4 的嵌套计时用于定位 FOC/无感任务开销，不能拿其总时间直接
减去 r3 结果估计某项优化。

## CCM 布局与最终镜像

先在 `r3_ccm` 将 `FOC_Current`、`FOC_SetVoltageModulation` 及四个 PI 操作函数
放入 CCM，再在 `r3_ccm_thermal` 加入 `MotorThermal_Accumulate/Update`。
两轮实测确认收益后，八函数布局合入生产共用 `Vector_Mini_ST.sct`。
不修改控制公式、ABI、采样频率或保护逻辑；两项 `ScatterAssert` 约束数据与代码边界。

| 最终无插桩产物 | normal | HIL |
|---|---:|---:|
| Code | 90,744 B | 92,500 B |
| RO-data | 3,116 B | 3,124 B |
| RW/ZI 合计 | 27,984 B | 28,240 B |
| RW/ZI 结束地址（不含） | `0x20006D70` | `0x20006E70` |
| 栈 / C 库堆 | 3,072 / 512 B | 3,072 / 512 B |
| CCM 执行代码，含 veneer/对齐 | 1,960 B | 1,960 B |
| RAM 实际占用（RW/ZI + CCM） | 29,944 B | 30,200 B |
| 加 32 B 启动邮箱后占用 | 29,976 B | 30,232 B |
| 32 KiB 物理 RAM 剩余 | 2,792 B | 2,536 B |
| Flash 搬运源起点 | `0x0801A6F0` | `0x0801ADF4` |
| APP CRC32 | `3EB32179` | `E9D3EA1A` |

两版 CCM 执行区均为 `[0x10002000, 0x100027A8)`，对应别名
`[0x20007800, 0x20007FA8)`，代码分区剩 88 B。RW 分区上界为 `0x20007800`。
两版均为 0 错误、0 警告，无 `budget_*` 插桩符号。栈容量保持，表中剩余空间
不是运行栈高水位测量。固件自有 4 KiB 堆已计入 RW/ZI，与 512 B C 库堆不同。

对比加入本轮热展开和 CCM 前的 v2，normal 的 Code+RO 增加 380 B，
RW/ZI 不变，实际 RAM 因 CCM 代码副本增加 1,960 B。固定 APP BIN 仍为 98,304 B。

CCM 的原生地址与 SRAM 连续别名对应同一物理内存，不能把它当成额外 10 KiB。
普通 `RW+ZI` 统计没有计入 RO 代码的 RAM 副本，不能直接称为本候选总 RAM。

已独立读取两版 AXF 与搬运表：`Reset_Handler` 仍在 Flash，`__main` 经 scatterload
将 1,960 B 复制到 `0x10002000` 后才进入主程序；后续 ZI 清零不会覆盖 CCM 代码。
八个函数及必要跨区 veneer 均在分区限制内，普通固件实际启动后两个别名回读也通过。

AXF 仍只有 Boot record 48 B 和 APP 98,304 B 两个非空加载段。
CCM 的 Flash 副本仍位于 APP 区内，两版启动记录的 APP CRC 及记录自身 CRC 均独立
校验一致，Reset/SP 通过现有 Loader 范围约束。构建及 CCM 清单位于 `final_firmware_ccm/`。

实际执行依赖启动搬运；不能只向 RAM 下载片段后跳过复位来代替正常加载验证。
Flash 与 CCM 间新增 veneer 的代价已包含于实测。HIL 本轮仅完成构建及镜像检查，
未执行 HIL 台架；不能用其离线结果推断另一套工况的最坏时间。

67、66、68、69、65、70、68、69、66、67 帧，不能宣称遥测完全无丢帧。
