# CAN FD v1.8.2 中止提示和速度上限

2026-11-13；源码`bdaf5d6d`，`the-system-refactor`；固件仍为APP1.8.2 / Loader2.3.4。
现行用法见[CAN操作指南](../../guides/canfd_motor_operations.md)。

## 原中止原因

用户节点6两轮记录均为阶段5，八项静态正常、电机动态未测、Hall动态异常，随后
Type118返回5/0，通信零超时。关相后只读SWD保留的第二轮报告与用户记录一致；
Hall sin范围2529～3440、cos范围3473～4044 cnt。cos超过4000 cnt的现有上限，
触发板端中止；运动许可结束后拒绝续租。不是CAN超时，不能仅凭118拒绝判计数错误。

工具在驱动被拒绝时先查127、再STOP，仅当板端已中止且有异常项时优先显示
异常项；原始拒绝仍保留。若续租被拒绝时板端仍在驱动，保留续租错误，不用随后
STOP的结果倒推原因。新增两种顺序的离线回归；硬件检测也记录`frames.csv`。

同台架3 A、3 Hz、1500 ms复测完成第3轮：九项正常，电机方向通过，Hall动态仍异常，
无续租拒绝、无通信超时、实际关相。该轮Hall原码范围sin2578～3580、cos3450～3912，
未越界但趋势仍失败；提示修复不代表Hall根因修复，原4000 cnt和其他阈值均未改变。

## 速度上限

速度页新增速度上限，默认30电机轴rad/s，默认目标仍0；停机使能前通过121修改
参数1并120回读。普通操作只改RAM，不自动写Flash，不修改电流上限和PI增益。
固件包络仍生效；写入拒绝、应答丢失或读回不符均不启相、不重发。使能前失败显示
“未发送使能命令”，不再误报关相失败或不存在的反馈曲线。

本板原保存运行限值和AXS2轴包络都是4 rad/s，单写参数1不能越过包络。
按用户要求，先完整备份并仅将这两项改成30，重算基础、AXS2和OEN3绑定CRC。
16 KiB参数中仅20字节变化，全部位于速度值及CRC槽；所有标定表、零位、PI、
热参数、行程及电流限额保持原字节。整片除参数区之外完全不变，复位后回读有效。
此为当前台架一次性配置；GUI不自动修改其他设备的轴包络，越界仍由固件拒绝。

参数SHA-256：`9fd8b2e1c1c3d94397a8527414e8bf49d0662b2d55b6cc538aa9f55ea26f3082`；
整片SHA-256：`cfad6616f4b7b69cec0772cdcd9998bae6baf285fcd9669b6c106f04ef39203b`。

实机运行限值30→12→30写入/回读通过。12 rad/s上限的零速会话19笔反馈通过；
30 rad/s上限下0→+5→−5→0目标、131笔反馈、续租、STOP全部通过，零超时。
舍弃非零段前0.7秒后速度均值为+4.89317和−5.01650 rad/s。最终关相、CPU运行，
电流上限3 A，Id/Iq Kp0.609958529、Ki3226.220703未变；速度测试未再写Flash。
未进行30 rad/s目标满速、其他型号或长时运行验收；不能把5 rad/s通过写成全速度域通过。
