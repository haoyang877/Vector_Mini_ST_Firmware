# 配置与运行状态实体分离 v3

基线：`codex/system-refactor@8323514e`。用户要求四类配置与运行状态彻底分开，保留Keil Watch与核心功能。

## 目标

- 硬件固定配置保持编译期只读；独立 `MotorConfiguration` 单份持有电机、应用、设备配置及参数来源元数据。
- 设备内单份 `EncoderCalibration` 保存LUT/零位/方向；`EncoderState` 只保留采样、位置、速度与诊断。
- `MotorControlState` 不含配置实体或指针；算法显式接收只读配置及可写运行对象。
- 参数服务、运行所有者和校准提交分别维护其所属数据；不发布可写全局地址接口。
- 保留 `s_motor_state`、`s_rotor_encoder` 等Watch符号，新配置通过 `s_motor_configuration` 观察。

## 不变项

schema14记录及12/13兼容读取、所有线上字段/缩放、默认数值、算法运算顺序、保护阈值、
启动/停止/清错语义、维护时点、自动保存、热历史和参数revision规则均保持。
LUT验证后同拍提交与减速、坐标重建顺序保持，不将提交延到最终完成或复制第二份常驻表。
参数默认函数原有清vq运行副作用移到原调用方显式执行，不能悄悄丢失。
用户未提交文件、硬件和下载镜像不动。不得用运行内隐藏配置指针或兼容可写别名假装完成分离。

## 验收与回滚

先迁移类型和显式接口，再适配实际调用链及原有离线夹具。覆盖配置写入不修改运行目标、
运行算法不修改配置、标定和取消时点、三版记录黄金向量、默认值、状态与输出差分。
执行PR检查；必要时只做主工程编译，不发起硬件动作。以源码和当前证据收口，不宣称实机PASS。
拆分会改变RAM字段路径，文档必须说明使用匹配AXF；协议与Flash布局不变。
回滚本次源码提交即可回到基线，不修改设备Flash。完成后记录实际资源/时序验证范围，不能假称未测项通过。
