# MCU 温度替代外部温度输入 v2

## 目标与边界

用户确认外部温度传感器未接，要求用 MCU 温度替代。基线为 `bb38d388`，
保留参数表、Keil 用户配置等已有本地改动。本轮只改源码、文档并离线验证和
构建普通固件，不下载或启动电机；HIL 沿用用户此前不处理的范围。

## 实现与不变量

- ADC1 在 CubeMX USER CODE 区改用两个注入通道：MCU 温度、VREFINT；
  640.5 周期采样，42.5 MHz 下完整序列约 30.7 us，小于 50 us PWM 周期。
  仍由 TIM1 CH4 触发，不增加 ADC1 中断，不修改 ADC2 四通道、4× 过采样或电流环时序。
- 平台 API 只返回 ℃/NaN，不把 ADC 寄存器或厂商类型引入新的电机接口。
  1 kHz 监督任务换算，使用出厂 30/130 ℃ 双点校准和 VREFINT 电压补偿。
  校准温度按 ST DS12589 Rev 6 和新版 LL，绕过仓库旧 LL 的 110 ℃ 定义。
- `FOC.temp`、周期反馈和单项温度查询统一为 MCU 温度；保留 100 ℃ 过温阈值。
  无有效完整新序列或校准异常返回 NaN，周期反馈编码无效哨兵，不新增故障枚举。
- CAN 帧布局、缩放、扩展版本及 Flash ABI 不变。温度语义变化按来源 v2 记录；
  旧接收端能解码，但显示标签需改为 MCU 温度。MCU 温度不能替代绕组/MOS 保护。

## 验收、证据与回滚

离线执行实际 ADC1 初始化和平台换算函数：校准端点、中点、亚摄氏度精度、
VDDA 补偿、ADC/校准异常、无新序列、100 ℃ 阈值；回归 ADC2 配置和 CAN 金向量。
运行当前分支 Python 回归、工程布局检查和普通 Keil 全量构建，证据保存
`outputs/mcu_temperature_20261009/summary.json`，包含日志和固件哈希。

旧 worktree 无 `pyproject.toml`、STYLE.md、新版 verify/format/lint 入口，
使用当前可用工具，不宣称 PR/release profile 通过。未实测内部温度绝对精度、
最坏监督任务耗时或 ADC1 双通道采样稳定性；构建通过不代表设备已更新。

回滚本轮 ADC1 USER CODE、平台入口及温度调用和相应文档即可恢复外部 NTC，
不覆盖其他用户改动；保留全部证据。

## 离线结果

- 53 个 Python 单元检查、36 个集成检查、工程布局检查通过。
- MCU 温度原生检查通过，包含 ADC1 两通道初始化、30/130 ℃ 校准、参考电压
  补偿、无效/过期数据、亚摄氏度精度及 100 ℃ 保护边界。
- ADC2 4× 过采样、快中断分派和 CAN 状态 8 组原生检查通过。
  CAN 命令夹具补齐当前工作区位置速度 PI 分支的缺失声明，没有修改协议逻辑。
- 普通 Keil 全量构建 0 错误、0 警告；Code 82444、RO-data 5028、RW-data 428、
  ZI-data 27260 字节。最终构建前后固件输入哈希一致，镜像和日志已复制到本轮
  证据目录，避免共用构建目录被后续构建覆盖。
- 工作区同时存在另一项“速度模式/位置速度 PI 分离”改动；本轮保留该项及其他
  用户修改，以上最终镜像对应组合工作区，不把其体积变化全部归因于温度替换。
- 未连接探针、未下载、未运行电机；设备仍需下载新镜像后才会反馈 MCU 温度。
