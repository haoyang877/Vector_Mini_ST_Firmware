# 独立上位机升级依赖收口 v1

## 目标与基线

基线为 `codex/system-refactor` 的 `adf7b263`、上位机 v1.4.0。
独立包中的 `upgrade_client.py` 仍按仓库路径读取 shared 目标 JSON，而部署包未携带该文件。
因此 GUI 内嵌资源的检查通过，不代表独立升级进程可以运行。修复这一实际依赖缺口，
不增加页面、控制模式、协议或通用配置框架。

## 实施与不变项

- 使用 CMake 原生 install 安装 EXE、Qt 运行库、现有 Python 端口及只读目标契约。
- 构建目录及部署目录携带 `contracts/vector_mini_st_g431.json`，直接复制 shared 单一来源。
- 客户端优先读取同目录契约；源码运行保留 shared 路径兼容。缺失或损坏时报错，禁止打开 SDK。
- 固件、Loader、shared 文件内容、通信/参数 ABI、目标容量、控制数学与保护阈值全部不变。
- 默认仍断开；保留现有 UID、STOP、版本、限值与独占门禁，不自动连接、下载或运动。

## 验收、回退与证据

复用现有黄金包和 Loader 内存模型测试；新增一个隔离目录的客户端检查，覆盖没有仓库时
有效包通过、目标契约缺失时明确拒绝。构建并安装独立包，再从包内执行 inspect 和未连接预览。
按仓库约定执行离线 PR 检查；失败和未运行项如实记录，不扩展为硬件验收。

回退仅撤销本批源码提交；历史部署包、用户改动和硬件镜像不变。
新证据放 `outputs/coordination/host_portable_20261016/`，不以历史输出声明本轮 PASS。
