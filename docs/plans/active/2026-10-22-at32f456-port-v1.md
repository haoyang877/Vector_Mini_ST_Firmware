# AT32F456 最小改动适配计划 v1

日期：2026-10-22。状态：P0完成；P1基础目标、P2的ADC/CAN及P3的MT6835端口已落地；
PWM、温度和参数存储端口亦已补齐；完整APP、实板温度校准与P5输出轴反馈尚未完成。

## 1. 目标与已确认范围

在同一份重构代码上保留 STM32G431 旧板，增加 AT32F456CCU7 新板。
先完成单电机端反馈的移植：平台资源与外设、MT6835、电机配置及现有控制功能。
输出轴 sin/cos 反馈最后单独设计、单独实施，不能混入前面的纯硬件替换。

用户明确的改动边界：

- BSP 公共接口冻结：签名、类型、数据布局、单位、有效性、错误、时序和所有权不变。
  用户已明确允许将板级配置数据分离到各目标；公共头的配置归属可调整，接口契约不变。
- 中间功能层实现零修改：FOC、控制器、主状态机、参数功能、协议与命令语义保持。
- 上层最多改一到两个组装/目标打包文件，不改控制逻辑，也不增加第二个运行状态机。
- 新板差异留在平台实现、外设配置、启动/链接、构建及目标数据中。
- 不能靠伪造 ADC 计数、伪造传感器有效状态、假报关相成功或隐藏宏替换满足表面兼容。
- 本轮实施板级配置数据分离；本批及后续实施只做离线验证与明确的编译。
  不下载、复位设备、连接探针、上电试验或驱动电机。

母线沿用现有方案；新电机截图记录 14 极对和 8:1；机构空载、无抱闸、暂未定义产品行程。
不要求补霍尔型号与安装图后才开始平台移植，不把暂未定义行程解释为允许无限旋转。
已确认硬件与电机数据以[配置确认记录](../../hardware/r40_at32f456_configuration_v1.md)为准：
CAN固定1M/5M；PA3电压、PA4电流；星形线间R/L；2.5/7.5Arms，短时峰值30s；2500rpm为电机轴。

## 2. 基线、不变项与实际适配缺口

基线为 `the-system-refactor` 的 `29fc12ab545fe1a0f0c263c8f76862d1e82d893a`。
已有本地 `motor_profile_defaults.h`、Keil 工程/调试配置与 `.vscode` 内容原样保留。
输入为用户提供的 F456_base 工程、标准外设库、原理图、器件手册和电机参数图。
实施前记录当时源码、板级输入与生成器输入的哈希，不能只记录不包含本地修改的 HEAD。

旧板保持：四个 App 入口、20 kHz 快环/2 kHz 监督、控制数学、状态/故障、STOP 行为、
命令和参数 ABI、原有传感器及编译工具链、链接布局、默认构建目标。
两板分别产出镜像和证据；AT32 不能沿用 G431 的 MCU/布局/硬件身份或参数标定。
新增功能不恢复重构中已退役的模式、辨识或通信能力。

当前代码的适配性需要先判清：

| 能力 | 当前契约与限制 | 计划结论 |
| --- | --- | --- |
| PWM/启停 | duty 与功率使能分离，有全部关相状态读取接口 | 新增 AT32 实现，不改调用方 |
| 时钟/中断/临界区 | App 四入口及平台时间/临界区接口已存在 | AT32 映射执行上下文，不照搬基础工程 10 kHz 位置中断 |
| MT6835 样本 | encoder_sensor 已预留型号，输出单圈 65536 计数及状态 | 实现同名接口；不扩展样本类型或上层分辨率 |
| SPI | encoder_spi 仍是 TLE5012B 半双工 16 位事务契约 | MT6835 使用平台内部四线事务实现，不改变旧 SPI 接口语义 |
| ADC 数值域 | motor_sensing 规定 12 位 ADC 的四次和；新工程当前为单次序列 | 可在 AT32 采样配置中取得真实四次和；需核算新采样窗，不能把一次结果乘四冒充四次采样 |
| 电流/母线换算 | 原公共 API 内固定旧板配置，现已迁到独立目标数据 | 旧板等价性已核对；AT32 目标数据仍需按实板及限值定版 |
| 温度 | 外部轮询接口返回物理温度；公共头中另有 STM32 特定换算帮助函数 | AT32 在端口按自身标定规则返回同单位结果，不借用 STM32 出厂标定地址或伪造标定常数 |
| 新电机参数 | 默认模型仅有旧电机，部分模型参数对外只读 | 先梳理现有装载入口；不假定通过现有 CAN 就能写入新模型，不改旧电机默认值 |
| 目标身份 | app_startup 直接包含 G431 目标头 | 允许在上层一个组装文件选择正确目标描述，公共协议不变 |
| 输出轴反馈 | 当前控制和状态仍从转子对象取机械反馈 | 新功能，最后进行架构设计，不能直接替换转子对象的机械字段 |

## 3. 先解决板级配置的架构归属

当前 `firmware/platform/config/board_profile_defaults.h` 固定旧板增益 10、
分压 10 kΩ/1 kΩ，只支持 2/6 mΩ；`current_sense_profile.h` 又据此选择硬限值。
新板原理图为相线 4 mΩ、INA240A1，分压 100 kΩ/3.3 kΩ。
相关常量直接参与 `motor/foc/foc_sensing.c`、保护和参数校验。

因此，仅增加 AT32 寄存器驱动、保留上述所有公共头文件逐字不变，不能忠实完成这部分移植。
这与母线工作电压相同无关，是采样链路的板级配置入口问题。
新电机默认模型的选择也需区分“配置数据变化”和“功能实现变化”。

用户已确认：冻结函数、类型、单位、时序等契约，允许将板级配置数据分离到各目标。
本批将旧板输入及固定电流限值迁到 `firmware/platform/config/boards/vector_mini_st.h`，
公共头保留目标选择、默认中点和原有派生表达式。功能层继续使用同名配置，不改函数和数据类型。
新增纯配置层只能依赖自身，公共 API 只允许消费该层，不允许配置反向依赖功能或外设。
不使用隐式 include 路径遮蔽、include guard 注入或编译器宏覆盖既有数据。

本批不添加未定版的 AT32 采样限值或未知板型占位。下一阶段新增实际 AT32 目标时，
沿此入口提供真实板级数据，未知目标继续编译报错；完整新板驱动仍未完成。

### P1第一批：独立底层基础验证目标

新增[AT32平台](../../../firmware/platform/bsp/mcu/at32f456/README.md)，本批不改APP、功能层、
公共BSP接口或旧板实现。原始SDK依赖按字节导入third_party并记录清单，未导入示例main。
新增180MHz时钟、六路默认关相、PB12默认CS高电平、时间/临界区和功率启停端口；
新工程单独编译到`outputs/build/at32_foundation/`，不混入旧APP发布。

时钟方案：8MHz晶振，PLL 90/1/4，VCO720MHz；APB1/2为180MHz、APB3为45MHz。
手册第56页与第62页的VCO上界分别为1200/1000MHz，本方案位于两者共同范围内。
CAN的1M/5M可由PCLK1整数分频实现，收发和采样点补偿留在P2验证。
按手册15.4.3.2中央对齐周期为2*PR，故TMR1采用4500，不将单向计数的减一公式套用。
TMR6为179/499得到2kHz，SysTick为1ms。当前不启用ADC/DMA或派发控制快环。

本批启动目标只验证平台，尚未实现完整APP目标身份/参数布局、board_hw_start及其余BSP能力。
因此不将P1整阶段或新板适配标为完成。后续按P2、P3、P4补齐，输出轴仍留P5。
200ns死区为待实测配置，不作为运动准入或10A能力证据。
