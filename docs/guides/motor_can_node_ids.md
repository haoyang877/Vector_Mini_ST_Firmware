# 电机 CAN 节点 ID

文档版本：v1.1（2026-09-30 临时联调）

参数恢复时优先使用 Flash 中合法的整数 `node_id`（0～7），随后 CAN 初始化用该 ID 配置接收过滤器。存储值无效时才回退到轴身份映射。

| 电机类型 | 身份映射的回退 CAN 节点 ID | 原有关节类型存储编号 |
|---|---:|---:|
| wheel_left | 1 | 5 |
| wheel_right | 2 | 4 |
| roll | 3 | 1 |
| pitch | 4 | 2 |
| yaw | 5 | 3 |

映射源为 `firmware/services/parameters/motor_axis_profile.c` 中的 `MotorAxisProfile_CanNodeId()`。
CAN 节点 ID 与关节类型存储编号独立，AXS1/AXS2 的布局、版本及 CRC 算法保持不变。
AXS1 的 roll/pitch 记录同样适用；有效 AXS2 身份记录即使尚未配置运动参数，也能选择通信地址，且不会因此允许电机运行。

临时联调期间，有效的已存 `node_id` 优先于轴身份；例如 yaw 身份配合已存节点 3，重启后仍使用节点 3。恢复原轴绑定策略时需撤销这项优先级。
无效、非整数或超出 0～7 的已存节点号回退到有效轴身份映射；未知或损坏的身份记录回退到硬件默认节点 0。
本映射本身不写 Flash；后续正常参数保存会记录实际运行的节点 ID。
多机总线必须避免重复节点号；yaw 临时使用 3 时不能与默认同为 3 的 roll 同时接入。

现有协议使用 `标准帧标识符 = (节点 ID << 8) | 参数编号`，因此节点 1～5 分别对应
`0x100～0x1FF`、`0x200～0x2FF`、`0x300～0x3FF`、`0x400～0x4FF`、`0x500～0x5FF`。
这些节点编号不是完整 CAN 帧标识符。

安装新固件并重新启动后生效。当前硬件是否已安装新固件，应以烧录及读回记录为准。

新增[周期状态反馈](can_motor_status_stream.md)使用独立的低优先级 ID：
`0x7F0 + 节点 ID`，roll 为 `0x7F3`，pitch 为 `0x7F4`，数据长度 48 字节。
临时改号后按实际运行节点计算反馈 ID；yaw 若存为 3，也发送 `0x7F3`。
启停/帧率命令仍使用原参数 ID 规则，参数号 `0x64`，回复/查询号 `0x65`。
