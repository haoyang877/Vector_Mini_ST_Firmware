# 齿槽转矩标定（mode 6）

`Calib_Anticogging = 6` 使用编码器位置反馈，对一机械圈的 1024 个等角度位置进行正、反向静态定位和 Iq 采样。两次采样合成后去除整圈均值，得到等效齿槽补偿电流表。每点占 `int16_t` 两字节，表本体共 2048 字节；每点角度间隔为 0.3515625°。

本功能生成、校验、保存和读取标定表。2026-09-18 增加编码器力矩模式（mode 1）的运行补偿，默认关闭，开关不持久化。

## 模块归属

2026-09-19 完成解耦重构，运行行为、参数 ABI、CAN 协议与 RTT/J-Link 变量名保持不变；
同日将台架保护收敛为适配层内联的租约与测速判定，并把表记录从标定过程中拆出：

- `motor/identification/cogging_map.{c,h}`：表格式、身份签名、CRC 校验、跨圈查表与成表（纯数据，无硬件）。
- `motor/identification/cogging_calibration.{c,h}`：标定过程状态机（网格定位、稳定/采样窗口、双向遍历），不含表格式。
- `motor/foc/cogging_compensation.{c,h}`：运行补偿纯核心（准入、查表、200 ms 渐变、±1 A 钳位与遥测台账），不包含平台头。
- `motor/identification/foc_cogging_calibration.{c,h}`：唯一硬件适配层，保留全部 `FocCogging_*` 公共接口与既有全局符号；台架保护（约 10 行租约/测速判定）与力矩遥测帧内联于此。

全局变量的 RAM 地址随构建变化，J-Link 调试需使用配套 AXF；变量与字段名未变。


## 力矩模式运行补偿

仅在 `Current_Mode=1`、编码器反馈有效且关闭无感模式时叠加。使用有方向且线性化的机械角度，按低 6 位在相邻 1024 点之间线性插值，最后一点跨圈插值到第 0 点。

`Iq_total = clamp(Iq_command + blend × Iq_table, -current_limit, current_limit)`。

表值为保持该角度所需的电流，因此以原符号相加；不翻转编码器方向。查表值额外限制在 ±1 A，当前表实际范围约 -0.189…0.169 A。补偿开/关用 200 ms 渐入/渐出，总指令限幅；`MotorControl.iqRef` 保留用户原始指令，不会反复累加。速度、位置、无感和标定模式不使用此补偿。

CAN 0x26 写入大端 float32 `1.0` 开启、`0.0` 关闭，0x27 读取开关。启用仅接受 mode 0/1，前台先验证完整表 CRC、编码器签名、采样量程；运行时继续核对方向、电零位、极对数和表 CRC 字段，避免在 20 kHz 环重复计算整表 CRC。离开 mode 0/1 自动关闭，重启默认关闭。

J-Link 可写 `CoggingCompensation.request=0/1`，观察 `enabled/rejected/blend/table_a/applied_a/total_a`。`TorqueTelemetryState` 写 1 请求，等 2 后读取冻结的 36 字节 `TorqueTelemetry`，读完写 0；其中包含同一次电流环的角度、速度、原始指令、实际补偿、总指令和 Iq 反馈。RTT 原有八通道布局未改变，原始 Iq 指令与实际总指令应区分。

台架脚本另使用 RAM-only `TorqueGuard`：20 kHz 倒计时租约与速度上限。租约到期或测速超限时直接关闭 PWM 并回 mode 0；`trip=1/2` 分别表示租约与测速。此保护默认关闭，不是生产模式下自动存在的主机断连保护；测试电流包络由 `MotorControl.current_limit` 保证。测试结束恢复电流/速度配置并关闭补偿。

实现已通过主机回归、普通/HIL 编译和零 Iq 实机开关测试；小力矩运动 A/B 对比尚待台架交回，不能据零电流静止结果宣称降低了转速纹波。精确固件、脚本与记录见 `outputs/cogging_compensation_20260918/`，该版 RTT 地址 `0x200069ec`，普通/HIL RAM 为 32008/32272 字节。

## 电流编码

采用有符号 Q15 满量程归一化，**不是 1 mA/count**：

```text
Iq_A = iq_q15[i] * full_scale_a / 32768
iq_q15[i] = round(Iq_A / full_scale_a * 32768)
```

正端饱和为 `32767`，负端为 `-32768`。满量程取硬件 ADC 中点到单侧电源轨对应的理论电流：`1.65 V / (放大倍数 × 采样电阻)`。

| 采样电阻 | 增益 | full_scale_a | 1 count |
| --- | --- | --- | --- |
| 2 mΩ | 10 | 82.5 A | 约 2.518 mA |
| 6 mΩ | 10 | 27.5 A | 约 0.839 mA |

量程由 `current_sense_profile.h` 的 `CURRENT_SENSE_PROFILE_FULL_SCALE_A` 定义，并随每张表保存。此量程用于编码；可靠采样范围、运行限流和过流保护仍使用原来的独立配置。标定定位电流限制为 `min(1 A, calib_current, current_limit)`，不会把运行电流限制提升到满量程。

## 角度与标定流程

- 表索引 `i` 对应经过方向设置和线性化后的单圈编码器角度 `i × 2π/1024`，不依赖用户设置的机械零位。表值为保持该位置所需的有符号 Iq；将来作为补偿使用时，正值应增加正 Iq。
- 从当前位置之后的最近网格点开始，正向采 1024 点，再额外前进一格后反向采同样的 1024 点，以保证反向第一点也从相反方向靠近。
- 定位使用独立的位置 PI 和速度阻尼，参数为 Kp=60 A/rad、Ki=240 A/(rad·s)、Kd=0.12 A/(rad/s)，不改动保存的速度/位置环参数。目标位置以最大 0.1 rad/s、加减速度 2 rad/s² 移动，并受 `speed_limit` 约束；速度阻尼使用单个原始编码器码宽的迟滞位置跟踪、2 kHz 差分和约 90 Hz 低通，避免正常 16 点测速窗口的延迟引起静态摆动。
- 有效采样要求原始位置误差不超过 ±0.0219727°（1024 格间距的 1/16，4096 格间距的 1/4）、约 5 Hz 滤波后的速度不超过 0.01 rad/s、原连续速度不超过 0.15 rad/s，且没有电流饱和。浮点角度相减额外容许 1 µrad（0.0000573°）舍入余量，防止跨圈时恰好 4 个 Q15 计数被误拒绝，仍拒绝第 5 个计数。先累计 200 个合格稳定周期，再采 200 个合格电流周期，均为 2 kHz。每个 Iq 输入是全部 10 个 20 kHz 电流反馈的块平均。
- 稳定和采样窗口各允许最多 10 个孤立无效周期（有效覆盖率至少 200/210≈95.24%）；无效周期不计时、不贡献 Iq。连续 4 个无效周期（2 ms）、超过 10 个无效周期、原始误差超过两倍门限、原速度超过 0.15 rad/s 或电流饱和，均重新等待稳定。这样不会因一个编码器噪声点丢弃整个窗口，也不会使用超出位置门限的电流样本。每个目标由整数网格计算，避免跨圈浮点累加漂移。
- 两方向的保持电流取平均，再减去整圈均值，减小方向性摩擦和恒定偏置的影响；非恒定外部负载仍可能混入结果。仅稳定与有效采样的理论下限约 410 s，实际还包括逐点定位时间。
- 首点最长 10 s，其余单点最长 5 s，全程最长 1800 s；连续限流 200 ms、转速超过 1.5 rad/s、反馈无效、失去编码器标定、电压/温度异常均退出。失败或中止不发布半张表，原来的完整表保持可用。
- 正常完成后先关闭相位 PWM，再在前台计算整圈均值和 CRC，进入参数保存，最后回到 mode 0。Flash 写入或回读失败会报告失败，不会把保存失败报告为完成。

## 使用

需要先完成编码器线性化和电零位标定（标志位包含 `0x03`），电机停稳、编码器在线且速度估计就绪。模式只接收允许整圈转动的无边界轴配置（当前轮电机使用 `axis_profile.magic=0`），拒绝带行程约束的轴。编码器方向不会被修改。

从 mode 0 设置 `ModeNow=6`，或者用现有 CAN 模式命令切换到 6。设置 mode 0 可以中止。J-Link 可查看：

- `CoggingCalib.state/reason/index/direction_pass/points_done`：状态、原因、当前索引、方向和完成点数。
- `CoggingCalib.iq_q15`：标定中的暂存表，不是可用的最终表。
- `CoggingMap.iq_q15[1024]` 和 `CoggingMap.full_scale_a`：发布的完整表及量程。

CAN 新增只读参数，请求和回复均为 **4 字节大端 float32**，沿用现有标准帧地址 `(node << 8) | param_id`：

| ID | 请求载荷 | 回复 |
| --- | --- | --- |
| 0x68 | 0 | 状态：0 空闲、1 定位稳定、2 采样、3 换向定位、4 完成且保存成功、5 失败、6 待保存/保存中 |
| 0x69 | 0 | 原因：0 正常、1 取消、2 配置/采样无效、3 超时、4 持续限流、5 保护退出、6 保存失败 |
| 0x6A | 0 | 完成百分比（2048 次方向采样）；100% 不替代保存成功状态 |
| 0x6B | 整数索引 0…1023 | 该点原始 Q15 有符号整数值，以 float32 传输 |
| 0x6C | 0 | 表中满量程，单位 A |
| 0x6D | 0 | 完整表是否有效：0/1 |

无效表的点值、量程读取返回 float32 NaN；越界或非整数索引不回复。逐个发送索引请求并等待回复，避免现有单回复缓存被后续请求覆盖。建议停止后读取整张表。可先查询 0x6D，确认有效后读取 0x6C 和 1024 点。

## 力矩模式应用补偿

已实现编码器力矩模式（mode 1）的运行补偿，1024点按绝对线性化机械角度跨圈插值，再按保持电流的原符号加入用户Iq。用户原始`iqRef`不被改写。补偿表输出限制在±1 A内，总指令受运行电流限制；开关约200 ms渐变。默认关闭，开关只保存在RAM，重启后需重新启用。

CAN参数`0x26`写大端float32的0或1，`0x27`读当前启用状态；左轮node1对应帧ID`0x126/0x127`。可在停机时预先开启，也可在力矩模式中切换。CAN中断只排队请求，前台校验表CRC、量程、编码器身份和模式后启用。GET的1表示已启用，不表示渐变已经完成。

`CoggingCompensation`包含request、enabled、rejected、blend、table_a、applied_a、total_a。速度、位置、标定和无感模式不应用补偿。改变编码器方向、电零位、极对数或表身份时拒绝继续使用失配表；不通过翻转编码器方向调整补偿效果。

`TorqueTelemetryState`写1请求同一ISR采样，等于2时读取36字节`TorqueTelemetry`，读完写0。内容依次为uint32 tick及8个float：机械位置rad、速度rad/s、用户Iq、实际补偿Iq、总Iq指令、反馈Iq、母线电压、blend。原RTT仍为8通道，用户Iq通道不含补偿。

可选的`TorqueGuard`仅供有界测试，默认关闭。enabled=1时，lease_ticks按20 kHz倒计时，测试主机必须续租；租约到期trip1、超速trip2均停PWM并回mode0。测试电流包络由`MotorControl.current_limit`设置；它不是速度闭环，不能维持恒力矩空载电机的恒速。

已完成CAN运行中开关、零Iq验证、正反向小力矩OFF/ON对比及失联停机验证。当前证据证明功能生效，尚不能证明动态平滑度改善。实际结果、最终HEX/AXF和匹配RTT地址见[力矩补偿实机报告](../reports/2026-09/cogging_compensation_20260918.md)。下文精度标定镜像的地址仅适用于该历史镜像。

## 持久化与兼容性

参数 schema 从 10 升到 11，在原参数结构末尾追加 2064 字节 `CoggingMapRecord`：12 字节 magic/编码器签名/满量程、4 字节 CRC、2048 字节表。旧字段偏移保持不变，总参数长度为 4304 字节，使用参数区的前三个 2 KiB Flash 页。

schema 10 升级保留节点、速度与位置增益、电流限制和编码器标定，初始齿槽表无效。更早版本保留原来的迁移规则。CRC 验证失败、采样电阻配置改变、编码器方向/电零位/LUT 或极对数改变后，表不会被作为有效结果读取或重新保存。改变用户机械零位不改变表的物理索引。

## 验证范围

原生测试运行真实标定核心和 FOC 适配代码，覆盖双向 1024 点、首尾跨圈、正负满量程、两种电阻量程、均值去除、CRC、旧参数迁移、超时、限流、编码器离线、先停 PWM 再保存和保存失败。合成反馈用于验证状态机与数值，不代表实物电机已经验证定位参数或标定精度。

40 项 Python 单元测试、36 项集成测试和 14 组原生测试通过。普通版与 HIL 版均 0 errors、0 warnings；链接后的 RAM（包含预留栈和堆）分别为 31904 / 32160 字节，低于 32768 字节容量。参数 I/O 与既有 8192 字节编码器标定缓冲重叠时，14 KiB 堆回归仍有 1760 字节余量。

匹配的普通候选 HEX、AXF、map 和 scope 位于 `outputs/cogging_precision_20260917/firmware/`，摘要与校验值见 `outputs/cogging_precision_20260917/candidate.json`。本版 `_SEGGER_RTT=0x20006984`；使用对应 AXF/scope，不能沿用先前固件的 RAM 地址。APP 未进入 `0x0801c000` 开始的参数区。

实机调试日志、每次烧录前 Flash 备份和逐点遥测位于 `outputs/cogging_bench_20260917/`。验证对象为 node=1、2 mΩ、无阻尼器轮电机；保留用户当前的编码器方向和电零位。完整结果以该目录下各次 `report.json` 的成功及持久化校验字段为准，定位或保护退出不算标定完成。
