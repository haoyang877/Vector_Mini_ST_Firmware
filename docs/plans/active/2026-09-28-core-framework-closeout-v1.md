# 核心框架接线收口 v1

日期：2026-09-28。状态：派发实施，尚未验收。

## 目标与基线

以已提交版本 `9226df154c1f6bc8eef9ecdd2be920d5a7d0c847` 为共同基线，优先使当前
分层工程具备真实的生命周期条件、明确的受控启动契约和可供上位机接入的命令闭环。
不重新迁移目录，不整支移入旧框架，不把原型升级为全面验收项目。
当前工作区的自动电流探针及未跟踪 Keil 工程不属于基线；保留现场文件，不纳入交付。

不因 G1 尚未完成阻止 E 处理已有证据支持的独立条件。

## 不变项与实现原则

- 保留 schema11、现有算法数学、保护阈值、控制调度频率、Keil 配置和既有协议布局。
- 生命周期条件须说明来源、更新时机和所有者。没有真实依据的条件明确登记缺口，
  不以常量真伪造就绪，也不一律置假造成启动永久阻塞。
- 关相确认使用平台能力接口；业务层不得读取寄存器或引入 HAL。
- 区分通用启动条件与各模式条件，避免编码器未标定时连标定入口也被封死。
- STOP/FAULT 撤销待执行目标；CLEAR 不恢复旧目标、不自动启动；维护完成不得被旧结果冒认。
- 不新增泛化框架；优先现有信号、现有接口和局部明确实现。
- 不连接硬件、不烧录、不复位、不运动；此前通信台架结果只覆盖其记录的失能场景。

## 验收与证据

只新增或运行改动直接涉及的已有接线路径检查，复用输入匹配的现有证据；不补全模式矩阵、
不五工程构建、不重证原控制数学。代码交付遵循仓库格式、lint 和适用验证规则，
同一批最终输入统一运行，ROOT 不重复执行无新问题的套件。

E1 交付完整 base/head、改动清单、guards 来源表、实际运行/复用/未测三类结果和主要剩余缺口。
H1 交付明确的支持/未支持表及启动前置依赖，不把 ACK ACCEPTED 写为已应用或到位。
G1 交付带行号的具体意见；无具体问题不追加测试范围。

确认 ABI/参数布局、状态与故障语义、功率输出行为是否受影响；说明新增快慢环工作量及
资源变化。只在最终构建输入改变时做主工程 normal 编译，不将离线结果记为实机通过。
E1 的适用 PR 验证及文档包 quick 检查如遇现有失败，区分本次引入与已有问题并如实交付。

## 回退与集成

各工作包在隔离分支提交，未经 ROOT 审查不自动合入现场分支，不改其他工作树引用。
以整包撤回保持原接口及现有已支持能力；不得用 reset/clean 回退共享工作区。
集成前重新核对现场变动、文件归属和依赖顺序。新增行为未完成时继续返回明确的不支持结果，
不得借兼容入口绕过生命周期检查。
