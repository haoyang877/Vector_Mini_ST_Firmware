# 参数加载策略 v1：仅接受 schema 11

日期：2026-09-28。适用：`codex/capacity-fit` 的历史兼容清理。

## 行为变化

固件只加载 `magic_word == 0x454E4332` 且 `schema_version == 11` 的参数记录。
schema 4～10 的自动迁移、旧整定值换算、历史采样电阻推断和启动自动回写路径删除。
其他版本（包括未来版本）同样按不支持处理，不提供固件内迁移包装。

旧版本或无效识别字的记录会使运行配置回到编译期默认值，编码器标定标志清零，
既有线性化表和齿槽补偿表不作为有效标定加载。启动不会转换或改写 Flash 参数区。
要投入运行，须通过当前配置/标定流程建立有效参数并显式保存。

`Param_Download()` 改为无返回值的装载操作；原返回值仅表示“需要迁移回写”，现已
没有对应语义。唯一生产调用方 `load_parameters()` 不再执行迁移写入。

## 当前格式与边界

这是接受版本集合的收窄，不改变当前 schema 11 的存储布局或线上参数命令：

| 项目 | 值 |
| --- | --- |
| `InterfaceParam_TypeDef` | 4304 B |
| schema 字段偏移 | 2160 B |
| magic 字段偏移 | 2164 B |
| schema 黄金字节（小端） | `0b 00 00 00` |
| magic 黄金字节（小端） | `32 43 4e 45` |
| 参数分区 | 16 KiB |

当前版本的编码器标定、增益、节点限速、数值有效性检查和齿槽表 CRC/签名检查保留。
当前记录与编译目标的采样电阻不匹配时，电流域参数及补偿失效处理仍生效；它是
硬件配置约束，不是旧 schema 迁移。AXS1/AXS2 轴记录由独立模块管理，本批尚未调整。

## 验证

`tests/unit/native/test_wheel_speed_limits.py` 验证：

- 拒绝版本 0～10、12 和 `UINT32_MAX`，恢复默认值且不改动输入记录；
- 拒绝无效 magic，清除运行态标定和补偿表；
- 当前 schema 的长度、字段偏移和黄金字节保持；
- 当前标定/整定加载、节点速度上限、齿槽表往返及损坏/签名不匹配拒绝。

上述为离线检查，不代表旧设备已重新配置或新镜像已经烧录。
容量变化记录在 [容量适配计划](../plans/active/2026-09-28-capacity-fit-v1.md)。
