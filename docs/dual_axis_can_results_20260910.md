已完成全部六项运动用例，并监测 32 字节状态帧。保持、±1°、±5°同向/反向、0.1 Hz 正弦通过本轮门槛；0.2 Hz 正弦执行完成但跟随精度未达标。所有运动阶段均无驱动故障、反馈超时或 4 A 主机停止触发，结束均回读两轴 mode0、fault0。

运动阶段取得 5395 个用于轨迹分析的快照；包含各阶段静止预检和收尾，共记录 6139 个状态帧。原始命令、完整 CAN 帧和反馈数据均保留。

## 测试条件

- CAN0，roll=3、pitch=4，仲裁/数据 1 Mbps；目标指令和反馈均 20 Hz。两轴依次发指令，无硬件同步触发。
- 测试中心 roll −3.295899°，pitch +3.493652°；相对中心 ±5°，没有修改机械零位。
- 两轴位置 Kp/Kd=8/2，速度 Kp=0.5；roll Ki=1，pitch Ki=2。参数和标定 Flash 区全部保持不变。
- 运动测试临时位置速度上限 15°/s；结束恢复 45°/s。CAN 控制超时 500 ms，仅 RAM。
- 台阶：每段末 2 s 误差≤0.3°、速度≤1°/s、超调≤0.5°；正弦：动态段 RMSE≤1°、最大误差≤2°。

## 0.2 Hz 跟随误差分解

| 指标（仅正弦运动段） | Roll | Pitch |

| CAN目标－实际反馈 RMSE | 1.126° | 1.209° |
| CAN目标－规划参考 RMSE | 0.983° | 1.069° |
| 规划参考－实际反馈 RMSE | 0.264° | 0.287° |

0.2 Hz 时，规划参考本身相对目标已出现较大滞后；估计规划滞后 roll 约 0.245 s、pitch 约 0.230 s，实际反馈估计滞后约 0.250 s、0.230 s。这些是 20 Hz 样本拟合结果，不能按毫秒级精度理解。RMSE 各分量不能直接相加。
数据支持下一步优先检查连续目标下的轨迹重规划和参考相位滞后，再处理 pitch 的方向差异；本轮没有据此改动已保存增益。电流参考和反馈在已采样时刻接近，不能由 20 Hz 遥测排除采样之间的高频电流噪声。

## 本次解决的测试阻塞

1. 两轴原固件尚不支持新反馈，已下载同一修正版。全部程序字节核验通过，两轴 16 KiB 参数/标定区逐字节未变。
2. roll 遗留硬件断点 `FP_COMP0=0x48001FB5`，位于新 CAN 命令处理函数，收到查询触发 DEBUGEVT HardFault。保存现场、关闭输出、清除断点并复位后，普通查询恢复。
3. 修复 STM32G4 HAL Port 的队列空闲判断：实测 TX Queue 空时 TFFL 为 0，改为检查三个发送缓冲区 pending 位，避免状态帧一直被跳过。
4. USB-CAN single-shot 模式在周期反馈并发时出现查询丢失，改用正常发送，随后双轴全部运动/停机验证通过。此处改变的是台架主机发送策略。

修复后六组 C 模块/适配回归通过，普通/HIL 固件编译均 0 错误、0 警告；台架轨迹、保护和报告分析共 10 项 Python 检查通过。独立新增快环采样耗时尚未测量。
