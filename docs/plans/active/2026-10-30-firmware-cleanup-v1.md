# 固件工程残留清理 v1

## 目标与边界

清除本轮重构留下的失效工程引用、无消费者声明/实现、重复包含、过时导航和测试接线。
以当前工作树为行为基线，不恢复已经删除的功能，不改变协议和参数 ABI、控制计算、
状态迁移、保护策略、启停时序、板卡/电机选择或 Loader 独立产品边界。
厂商 SDK、CubeMX 生成区和忽略的实验数据保持原样。

## 基线与回退

开始时工作树已经包含大量未提交修改，不使用 git reset/checkout 覆盖这些修改。
清理前文件及 SHA256 保存于 outputs/firmware-cleanup-v1-20261030/before.zip、
before-files.json，原有差异与状态分别保存为 before-diff.patch、before-status.txt。
回退仅恢复本轮实际修改的文件，不解包覆盖其他并发修改。
离线基线使用 verify --profile pr，记录独立 run-id 和已有失败。

## 执行步骤

1. 修正四个 APP 工程和测试驱动的失效输入，核对所有 Keil 工程的源和包含目录。
2. 按生产、台架、共享产品和测试调用核对消费者，删除可证实无用途的残留；
   稳定协议/存储字段以及仍有真实使用的算法保留。
3. 统一当前源码导航和关键运行说明，历史报告不当作当前事实重写。
4. 对触及文件格式化，运行格式、lint、架构、接口、文档、离线测试与可用的构建检查。

## 验收与证据

无新增失效工程路径或反向依赖；保留协议编号、记录大小和布局、状态与故障语义。
比较清理前后离线结果，不通过删除有效用例掩盖失败。可构建目标记录资源/产物比较；
不能构建或基线已失败的项目如实记录，不声称二进制等价或实机验收。
本轮不烧录、不连接探针、不操作电机。结果、差异清单和剩余问题补记于本页及 outputs。
