# AT32完整APP标定与闭环接入 v1

## 目标与边界

以重构后的完整APP完成MT6835线性化、电零位、dq电流环和编码器速度闭环。
保留G431和新板App_Off；BSP函数、类型、单位、时序及共享控制算法不改。
输出轴sin/cos闭环不在本轮范围。普通验证不得自动接触硬件。

当前板上是此前验收的App_Off，故障0、IDLE，PA4偏置和CAN读取通过。
它具有不可运行时解除的编译期功率锁，不能直接用于运动验收。
临时MCU温度可选和临时热参数也仅允许关相目标，不能只删除功率锁后烧录。
用户已提出继续实机标定/闭环；本轮另行确认台架状态及限时验证目标的温度策略。

## 已定位的配置不匹配

新板没有定义阻尼环，采用无阻尼标定。旧配置电角启动目标315rad/s，机械稳态
15rad/s按21对极成立；YQ-5708为14对极，对应210rad/s，低于250rad/s观测器下限。
仅在型号配置选择处为YQ-5708选择30rad/s机械目标和420rad/s电角目标。
启动2A、稳态初始Iq0.5A、Id0.5A不扩展3A相电流边界；旧型号数值保持。
此项是待实机评估的候选，不等于已经实现可靠无感交接或标定成功。

## 实施顺序

1. 配置与离线验证：实际默认参数、14对极速度关系、标定准入及保护检查。
2. 独立完整APP限时目标：沿用同一App_Init/FastTick/SupervisorTick/Process、
   原标定任务与原状态机；功率窗口由平台限制，复位不自动运行。
   App_Off仍保持永久关相；不在中间层增加第二套运行状态机。
3. 增加平台侧只读2kHz诊断：三相电流、Id/Iq目标与反馈、vd/vq、原始/校正角、
   电角度、速度、状态/故障及帧序号；不写入已有控制所有者对象。
4. 实机先验证关相启动、实际配置、偏置、SPI状态和采样时间，再显式启动LUT。
   LUT覆盖和残差必须通过；不能将全零LUT伪装成已校准。
5. 电零位通过已有d轴预定位/平均流程取得，检查Id跟踪、Iq串扰和角度稳定；
   完成后独立核对保存结果及复位重载。没有可靠电零位不开始速度测试。
6. 在有效电角度下验证小电流目标阶跃，再以低速正/反目标检查速度跟踪；
   每段独立开始和停止，故障后不自动重试或提高电流。

### 时序调整及失败记录

原Flash执行候选在LUT启动出现约73.8us快环超时。独立scatter把运行热路径搬到SRAM；
随后候选在交接附近出现约51.0us/50.1us超时。没有提高50us保护阈值或降低20kHz频率。

已把CRM留在Flash并核对地址，强制关断GPIO后重新下载恢复。该失败候选不再使用。

MT6835的SPI由限时工程单独选择11.25MHz，其他目标仍5.625MHz；
两者都低于[厂家16MHz上限](https://www.magntek.com.cn/136/107)。帧格式、CRC、错误状态、
两段事务及40us整帧预算均保留。真实驱动离线的全部角度/CRC/状态/超时用例均通过。
关相8000帧记录无编码器错误，零电流峰值约0.037A。
