# AT32 RTT 曲线恢复 v1

## 目标与基线

AT32 ADC 向量直接执行轴快环，未经过通用应用回调。临时放在该回调中的
RTT 发送被链接器删除，通道虽初始化却没有样本；同时该依赖使 STM32 工程
和提取应用函数的离线夹具无法构建。

复位问题另由 ADC 向量遗漏快环计数造成。恢复计数后实机连续观察通过，
该行恢复到基线提交 `87d24143` 的既有实现，并非修改该提交的看门狗策略。

## 实施与边界

- APP 的 `app_rtt.c` 独占 RTT 缓冲、初始化与发送；AT32 入口调用 `RTT_Init()`，
  快环按采样、控制、健康计数、`RTT_Sampling()` 的固定次序调用。
- `app_rtt.c` 在同一快环末尾只读MotorAxis现有FOC和编码器对象；快照结构与组装均归RTT模块，
  内容为三相电流 A、电角度 rad、反馈转速 rad/s、q 轴电流 A。
- 通道 1 使用 `JScope_f4f4f4f4f4f4`，单帧 24 字节、20 kHz；单写者无锁，满时丢整帧。
  2026-11-04 晚按用户要求改为六路 int16（`JScope_i2i2i2i2i2i2`，单帧 12 字节），
  整数刻度与范围见文末“曲线使用”的通道表。
- 通用应用不依赖 RTT；CAN 协议、参数 ABI、控制参数及启动/故障策略不变。

## 验收与回退

验证真实向量在有效事件后更新计数并发送一次，不为缺失事件发送。
执行 release 检查、AT32 Keil 编译和样机 RTT 读取，确认波形通道、采样节拍及关相状态。
证据保存到 `outputs/at32-rtt-20261104/`，复位和标定证据另见对应日期目录。
回退本次 AT32 RTT 入口和快照接口即可关闭曲线；不得删去快环健康计数。

## 实测记录

台架为 AT32F456、5708 电机和 8:1 减速器；用户确认电机已固定、输出轴可自由转动。
复位修复后连续观测约 24 s，20 kHz 快环和 2 kHz 慢环计数持续增长。
诊断版本在 10 ms 停止喂狗的原因是快环计数遗漏，未禁用或放宽看门狗。

| 项目 | 本次结果 |
| --- | --- |
| CAN 通信 | 1000 次查询成功，平均 1.47 ms、P99 2.13 ms、最大 3.17 ms；非法启动字段按协议拒绝 |
| LUT 标定 | 6.33 s 完成，RAM 校正表更新，旧零位资格清除 |
| 电角零位 | 1.53 s 完成，有效位恢复 |
| 机械零位 | 0.10 s 内完成，位置反馈归零，有效位为 7 |
| 速度测试 | 未通过；0.5 rad/s 目标下出现 8.426 rad/s 反馈，已 STOP 并关相；用户要求停止排查此项 |
| RTT | 单次 5.01 s 读取 93089 帧，后续数据全部有限值；快环约 19.96 kHz，lksscope 已显示六路浮点曲线 |
| 离线回归 | 本次修改的 PR profile 全项通过；AT32 编译 0 错误、0 警告 |

标定未保存 Flash，下载前后完整参数区逐字节相同；重启使用原先的持久化标定。
测试期间先发现其他控制操作与测试并行，经用户暂停后重新执行通信与标定。
RTT 首次读取可能包含启动零偏尚未就绪的 NaN，后续批次确认六路有限；不将启动样本认作有效电流。
2026-11-04 晚改为六路 int16 后不再上行 NaN：启动未就绪样本换算为 0。

实机测试使用工作区构建，含用户尚未提交的 RTT 库及观察变量修改；同时以提交范围
单独检出编译和回归，避免把无关工作区变动混入提交。提交后执行 clean release profile，
结果保存于 `outputs/runs/at32-rtt-final-release/summary.json`，该文件实际状态为准。

## 曲线使用

先加载与样机匹配的 AXF，使工具找到 `_SEGGER_RTT`，再启动 J-Link 连接。
未载入符号时本次工具显示“已打开 [无]”，载入后显示“已打开 [RTT]”。
通道名编码当前为六路 int16（`JScope_i2i2i2i2i2i2`）；工具需按新名称重新发现通道，
时间轴频率设为 20000 Hz。RTT 不保证主机持续接收全部 20 kHz 样本，传输不足时允许丢整帧。

| 通道 | 字段 | 单位（整数刻度） | 范围 |
| --- | --- | --- | --- |
| data0 | A 相电流 | mA | ±32.767 A |
| data1 | B 相电流 | mA | ±32.767 A |
| data2 | C 相电流 | mA | ±32.767 A |
| data3 | 编码器电角度 | mrad | 0..6.283 rad |
| data4 | 编码器机械转速反馈 | 0.01 rad/s | ±327.67 rad/s |
| data5 | q 轴电流反馈 `current_dq_a.q` | mA | ±32.767 A |

用户随后明确第六路为 q 轴电流反馈；此表已按该选择更新，替换初次验证时暂用的转速目标。
随后按用户要求将RTT代码集中到APP层，保留原有采样、控制和计数调用顺序。
新增真实模块测试，检查六路数据次序及缓冲满时不重试；中断测试检查每个有效事件只调用一次RTT。
本次APP分拆与第六路变更的提交后检查另存于
`outputs/runs/at32-app-rtt-final-release/summary.json`；这次结构调整未重新下载样机。

电机保持关相时，电流近零、角度基本不变、转速近零属于正常结果。
