# Keil标定结果保存 v1

## 范围与实现

用户要求通过Keil Watch在标定后保存Flash。命令5同步保存当前schema14完整记录，
包含LUT和两类零位；保留现有字段、版本、CRC和CAN行为，不自动保存或重试。
新增MotorAxis_SaveCalibration作为参数所有者入口，复用启动记录的2288字节暂存区。
仅停机空闲、无待启相/停止、无故障、标定工作区释放、零偏完成、配置及标定标志有效时保存。
前台串行化保持快照稳定，BSP拥有实际关相复核、采样暂停、擦写和回读验证。
成功后重新起算APP健康观察窗口，必须再次看到快慢环进展后才能喂狗。
g_debug_result沿用0至5，新增6表示保存失败；命令5的0表示写入及回读完成。

## 必要缺陷修复

当前Param_Download用运行必需掩码0x03校验所有标志，错误拒绝既有机械零位位0x04。
改为允许三个已定义位0x07，仍拒绝未知位；不改变运行准入所需的ENC_CALIB_ALL。
新增实际导出/内存Flash/重新装载的往返测试，覆盖机械零位及未知位拒绝。

旧AT32实测2288字节保存屏蔽中断约57.8ms（2026-10-23-r40-app-commissioning-v1），
超过当前511重载的原窗口。仅在关相、前台且全屏蔽的Flash事务内，将已启动WDT的
重载暂改为4095，结束恢复原值；分频不变，等待期间不循环喂狗。进入或恢复失败返回IO错误并锁存。
未启动WDT时不配置或启动它，运行期间继续使用原重载。增加真实硬件寄存器模型与事务失败测试。

## 验收与回退

基线为keil-calibration-control-20261103；修改前文件备份至outputs/keil-calibration-save-20261103/。
验证无命令不写、保存一次、拒绝运行/标定/待请求/故障/未校零/坏配置、错误传播，
以及三类标定结果和CRC往返。运行完整PR、四个正式目标构建及资源检查。
不连接硬件，不烧录或实际擦写板上Flash。
回退时仅撤销命令5、保存入口与暂存区移动、标志校验及Flash专用WDT窗口和本轮测试文档。

## 完成结果（2026-11-03）

命令5及MotorAxis_SaveCalibration已接入，返回0表示当前完整记录已保存且核对一致，
6表示保存或看门狗窗口切换失败；结果写回后再清零命令。
所有原命令意义不变，失败不自动重试；默认上电不保存。
APP成功返回后重建双环健康观察窗口，BSP在Flash事务结束前恢复WDT原重载值。
未启动WDT的底层台架不被隐式启用WDT。

最终PR档通过：44组原生检查、140项单元、16项集成，以及格式、lint、布局、
架构、接口、文档和卫生检查。
证据：outputs/runs/keil-calibration-save-20261103-final-pr/summary.json。
专项覆盖真实schema14编码/CRC/解码往返、0x01至0x07标志、未知位拒绝、
保存前后故障/状态复核、Flash错误、WDT仅关相使用/忙等待不喂狗/恢复原值、事务失败锁存。

四个正式目标与五个AT32台架目标均0错误0警告；
