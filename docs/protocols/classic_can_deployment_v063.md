# v0.6.3 共线经典 CAN 部署与接收准入

## 部署选择

`shared/can_deployment.h` 定义 `VECTOR_CAN_CLASSIC_ONLY`，默认 **1**。
这是 APP 和 Loader 共用的编译选项，不保存到参数 Flash，不提供在线切换命令。
Keil 可在 C/C++ 的 Define 中设置 `VECTOR_CAN_CLASSIC_ONLY=0`，然后完整 Rebuild，
得到历史 FD 兼容版本。两种产物必须分别保存并标注部署选项；不能混装后宣称全生命周期经典 CAN。

| 行为 | 全经典＝1（默认） | FD 兼容＝0 |
|---|---|---|
| 普通请求 | 标准经典数据帧 | 标准经典或 FD 数据帧 |
| 回复 | 经典、BRS 关闭、最多 8 字节 | 跟随请求 FD/BRS 格式 |
| `0x64` 周期流配置 | 只接受 0，非零拒绝 | 保留 1/10～200 Hz |
| 状态流旧启用位 | Rate=0、Prepare=false，平台拒绝发送 | 按配置发送 48 字节 FD |
| UID `0x63` | 拒绝；不截断 16 字节回复 | 只接受 FD 请求 |
| BOOT `0x66` | 请求、交接状态机、复位邮箱三处拒绝 | 保留 `BOOT` 请求和 FD ACK |
| CRC `0x7C` | 4 字节 nonce 查询，8 字节经典回复 | 保留 nonce+CRC 回复 |
| Loader | 不初始化 CAN；接收/发送/完成查询均不成功 | 保留原 FD 维护协议 |

全经典模式在生成代码初始化之后、外设 Start 之前选择经典 FrameFormat。
改波特率时重新应用 FrameFormat、已提交的节点过滤器和通知，不会恢复成 FD。
直接短回复接口、前台重试、旧队列、状态流底层接口均受部署约束；不做隐式分片或截断。
FD 兼容版本保留现有线协议，参数格式版本仍为 2；软件版本查询为 `00060300`。

## 接收与通信保活

顺序是完整 ID/格式 → 明确白名单 → 精确载荷长度 → 解码 → 数值/业务验证 → 接受后发布 RX 镜像及喂狗。
本节点未知参数、源电机 `0x37D/37E/3FD/3FE`、只读字段伪写入、未实现的 `0x0C/26/27`、
错误长度、扩展/RTR 帧、经典 BRS、全经典部署下的 FD 请求都不刷新心跳，也不清 `CAN_DisConnect`。

查询统一使用 4 字节占位载荷，忽略其数值（包括 NaN）。电流写命令 `02/0E/10` 必须是 2 字节
有符号毫安；位置 `06` 是 4 字节有符号毫弧度；速度类沿用百分之一 rad/s（或 rad/s²）。
整数最小值保留为无效哨兵。其他写参数是 4 字节大端 float32，按原各参数范围检查。
模式、极对数、心跳、布尔开关等必须精确为允许的整数/枚举，不能截断小数。

白名单按实际实现逐项列出，不能按奇偶划分读写：`6B/6D` 为位置内速度 PI 写，`6C/6E` 为读；
`5A/5C/60/62/6A/6C/6E/7A/7C/8E` 都包含合法偶数查询。
业务拒绝（例如运行中修改停机配置、无有效摩擦候选、模式切换失败、位置目标越界）不喂狗。
电流/速度/位置目标先校验再申请模式，申请失败不写入目标。控制所有者的安全故障诊断仍可锁存。
已接受的普通查询即使回复槽忙仍可喂狗；UID/CRC 需成功占用回复槽才算接受。
部分原扩展写命令保留 `-1.0f` NAK，NAK 不等于接受，也不能喂狗。

断连状态下可先发送合法只读查询恢复链路，再申请运行；不先清故障以绕过运行准入。
看门狗启用模式、时间设置及 STOP 解除逻辑保持原实现。

## 最小通路查询

Roll node=3：标准经典数据帧，ID `0x309`，DLC=4，数据 `00 00 00 00`。
期望回复相同 ID、DLC=4、数据 `40 40 00 00`（float32 节点 3）。
版本查询 ID `0x36F`，相同占位数据，期望 `00 06 03 00`。
这只证明请求和回复通路，不证明电机可运行或三轴位置控制通过。
黄金向量见 `tests/vectors/classic_can_admission_v063.json`。

## Loader 生命周期及当前部署阻断项

原 FD Loader 无主动启动广播，但会在启动窗口/维护等待期间接受 FD 请求并回复 FD。
APP 不能覆盖自身执行之前的这段行为。新经典 Loader 保留原功率关断、APP 有效性检查、
启动等待和跳转逻辑；CAN 端口从初始化到无效 APP 恢复等待始终静默。
无效 APP 或有效维护邮箱导致停留时，不开放经典升级协议，需要本地恢复。

本次只构建和离线测试，没有更新设备。**板上原 Loader 未经更新与核验，仍是共线部署阻断项。**
最小后续工作是经独立授权，在物理隔离的维护环境安装同配置的经典 Loader 与 APP，
核对产物哈希；再在上电、复位、有效 APP 启动和无效 APP 回退场景检查总线没有 FD。
历史 FD 维护仅允许在确认兼容、与当前共线设备物理隔离的环境使用。
没有设计或宣称实现经典 CAN Loader，也没有实现 CANopen。

## 验收边界

离线测试使用真实 RX、业务分派、队列、看门狗和发送函数；控制/硬件边界用内存替身。
热配置还运行真实热控制器的业务拒绝及持久化回归。两种策略均测试，旧位置算法等价性单独回归。
Loader 经典构建的测试无需链接任何 HAL 函数；FD 构建另跑原维护回归。
这些证据不代表 J-Link 烧录、实际 CAN 收发、三轴联动或位置性能已完成。
