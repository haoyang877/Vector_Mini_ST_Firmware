# AT32F456 单板波特率实测与桌面工具集成

本次在一台连接 J-Link 和 USB-CAN 的板上验证已交付的 APP v0.7.1、Loader v2.3.1。固定源为 `9bf44955`，先核对芯片 UID、CAN 回报、当前运行速率、六路关相和 FLASH 双读备份。关相完成全程通信测试并保留可复原的原始镜像与标定。

总线上有其他在线节点。按本次授权，实机始终使用 1M/5M，只读 0x71 的 RAM 与 Flash 值，验证复位、APP 与 Loader 同速应答及两端寄存器。12 种组合保留离线验证。退出时恢复测试前现场状态并复核。只有本次实机验收通过才合并。重构工作树中已确认的工具基线为 CAN-Link-Test v1.6.0，界面沿用其现有工作进程、适配器设置和节点身份识别。

共线复位时记录到主站每 200 ms 轮询五轴。v2.3.1 在 8 次复位中有 2 次于 APP 镜像校验期间出现 CAN RX 溢出并驻留 Loader。补丁将 AT32 Loader 的硬件接收范围限定到本机与广播，继续保留溢出和 bus-off 救援逻辑。使用同一主站流量复验，交付配对版本为 APP v0.7.2、Loader v2.3.2。

## 单板验收结果

- 节点 6（PITCH）用 J-Link 备份完整 256 KiB Flash，分别核对芯片 UID、节点和六路关相。桌面工具在 CAN 通道 0 使用 1M/5M 扫描，再对选中的同一 UID 读取。
- 测试包为 APP v0.7.2 和 Loader v2.3.2。两者的 ACTIME 为 `0x2C2C0085`、FDTIME 为 `0x08080019`。参数 `0x71` 的 RAM 与 Flash 值均为 `0x03E81388`。本次只发参数读命令 120、123。
- 共线主站继续轮询五轴。24 次复位逐次核对 APP 版本、状态、两份参数和硬件位时序。独立复位后连续查询状态 100/100 次，均为停机、零故障。通过协议进入 Loader 后核对角色和版本，再复位返回 APP。
- J-Link 校验完成后恢复 Cortex-M 调试中断屏蔽，再按系统复位启动。桌面工作进程的身份和状态首答 11/11 次在 50 ms 内返回。读取波特率按钮已通过真实适配器验证。
- 测后恢复原 APP v0.6.2 和 Loader v2.2.0，整片逐字节与测试前备份一致，原始参数、身份和校准均已核对，1M/5M CAN 查询通过。其他电机未烧录。
- 其余 11 种组合仅做离线验证。AT32 Loader 的 12 档寄存器测试同时覆盖所有 256 个地址的本机和广播匹配规则。

最终整机 HEX 的 SHA-256 为 `ae937b8ae53c9469d14d1bed43a93c1fda00ba8299865179d76057c551bc0a14`。冻结的调试包使用源码 `54c67127`，详细构建清单随包交付。
