# APP 参数保存行为 v1

2026-10-16。本次只收紧保存流程，沿用 `mode = 9`（`Save_Param`）和既有参数区；不增加 CAN 操作码、参数字段或故障码。

## 保存流程与职责

1. 主循环调用 `ParameterPersistence_Poll()`。应用参数模块看到保存请求后，等待快环把 `ModeLast` 更新为 `Save_Param`。快环在更新前完成关相，避免 STOP、SAVE 连续到达时过早擦写。
2. 应用参数模块通过存储平台接口屏蔽中断并复查模式、六路输出关闭及引脚高阻，然后独占 2384 字节参数缓冲，生成完整快照。模块负责运行模式、停机与故障发布；BSP 只操作固定参数区字节，不持有应用参数或缓冲所有权。
3. 快照与 Flash 的 2384 字节完全相同时直接成功返回，不解锁、不擦除、不编程。
4. 数据有变化时，逐页擦除原参数区的第 56、57 页，再逐个编程 298 个双字。首次 HAL 失败立即终止，随后尝试重新锁定 Flash；全部编程成功后逐字节回读比较。
5. 所有返回路径恢复调用前的 PRIMASK，释放本次获得的缓冲所有权。忙调用不能释放别人的缓冲。运行期保存成功后回到停机；失败先关相，发布既有 `MotorParam_Error`，再回到停机，不自动重试。

相同数据跳过擦写以 `Param_Upload()` 生成的完整记录为准，包括 LUT、扩展记录和 CRC。该函数先清零整个结构，因此填充字节不会造成重复擦写。

代码入口：

| 层次 | 文件 | 职责 |
| --- | --- | --- |
| 应用 | `firmware/app/parameter_persistence.c/.h` | 独占缓冲、序列化调用、启动迁移、保存协调与结果诊断 |
| 平台契约 | `firmware/platform/api/parameter_storage_hw.h` | 固定大小原始记录读写及本次参数事务中断状态保存/恢复；不暴露 HAL 或参数结构 |
| STM32 BSP | `firmware/platform/stm32g4/bsp/flash.c` | 使用已有 `BOOT_PARAM_BASE` 地址，执行字节比较、擦写、校验及锁回 |

`Board_Init()` 保留 `flash_read_param()` 启动入口；`flash_write_param()`、`flash_get_last_save_result()` 也保留原名字和诊断值，声明归应用头文件所有。主循环仅调用 `ParameterPersistence_Poll()`，不再直接持有 `ModeLast` 或参数保存故障处理。存储 BSP 不再依赖 `foc_param.h`、运行模式或关相策略；魔数字归 `foc_param.h` 的记录契约所有。旧 `bsp/flash.h` 的板级页地址表已无调用者，随职责迁移删除。

## 如何观察结果

`flash_get_last_save_result()` 是只读本机诊断接口；调试器也可查看 `parameter_persistence.c` 中的 `last_save_result`。结果不保存在 Flash，复位后为 0。

| 值 | 结果 | 含义 |
| --- | --- | --- |
| 0 | `NOT_ATTEMPTED` | 本次启动尚未保存 |
| 1 | `WRITTEN` | 写入、回读和重新锁定均成功 |
| 2 | `UNCHANGED` | 完整记录相同，跳过擦写 |
| 3 | `BUSY` | 参数缓冲正由另一调用占用 |
| 4 | `OUTPUTS_ACTIVE` | 输出尚未完成关断，未擦写 |
| 5 | `UNLOCK_FAILED` | Flash 解锁失败 |
| 6 | `ERASE_FAILED` | 某页擦除失败 |
| 7 | `PROGRAM_FAILED` | 某个双字编程失败 |
| 8 | `VERIFY_FAILED` | 编程返回成功，但回读不一致 |
| 9 | `LOCK_FAILED` | 数据写入和回读成功，但重新锁定失败 |

只有 1、2 是成功。若擦写本身已失败且上锁也失败，保留最先遇到的错误结果。现有 CAN 故障查询 `CAN_GET_ERROR`（参数号 `0x4D`）可观察运行期保存失败后的 `MotorParam_Error`，不能区分上表的具体存储原因。进入保存模式的命令响应仍表示命令处理，并非新增的“已持久化”确认；上位机需随后核对模式和故障状态，必要时复位回读参数。

## 兼容与边界

- Flash 地址、2384 字节布局、既有 CRC/迁移解析保持不变。Loader 布局启动只读参数，不自动改写；旧布局保留控制启动前的迁移写入，也记录保存结果。
- 保存期间仍全局屏蔽中断，CAN/控制 ISR 不运行。保留现有 HAL 轮询实现，因此不能把此修改解释为新增的独立硬件超时保证。
- 仍是单份参数区：失败或掉电可能留下部分记录，不保证恢复旧参数。本次没有双分区或掉电事务机制。
- 离线跨应用/存储边界使用实际读写函数与保存协调函数验证：两种布局、原 PRIMASK 为 0/1、交叉重入、未关相、相同记录、两页各自失败、全部 298 个双字失败点、解锁/上锁失败、回读不一致及显式重试。离线验证不代表已经执行实机擦写故障注入。

回归入口：`tests/loader/test_startup_parameter_read.py <C编译器> <输出目录>`，也由 Loader 离线测试集调用。
