# YG_MC_HOST v3.0.1 续租计数回退防护

日期：2026-11-11。状态：离线防护完成，原始回退路径尚未复现，实机复测待现场确认。

## 实际故障

用户截图对应v3.0.0会话：速度START收到1/0受理后约119ms，Type118发送计数1，设备回复5/0。
此前同UID成功续租记录至少达到1194，本机续租文件保存上限1280，本次检查仍为1280。
随后STOP先1/1，最终0/0及IDLE回读，主机关闭CAN并保留硬停状态。没有把受理状态当作输出已关闭。

计数相对本机历史发生回退已确认；但旧进程为何未使用已有1280记录，尚无确切证据。
旧进程的APPDATA、LOCALAPPDATA、USERPROFILE与诊断环境一致，不能据此归因到环境变量。
Type118的5/0没有细分拒绝原因，也不能从单次拒绝推断设备是否曾复位或改变运行许可。

## 主机修复范围

- 原实现对缺失的续租文件使用0并从1开始，且首次持久预留在使能之后。此行为不符合现行协议的高水位丢失处理约定。
- v3.0.1对缺失、损坏、零值或本进程已知回退的记录拒绝使能；不创建零值记录，不猜测设备高水位。
- 每次START前持久预留新的256计数区间，成功后才发START；跳过上一运行未发送部分。
- Snapshot携带续租历史不可用原因，右侧使能按钮禁用并提供诊断详情；只读连接与STOP保持可用。
- 日志增加实际状态文件路径、首个计数、预留上限及之前预留；拒绝记录counter、sequence、result/detail。
- 续租被拒或结果未知时继续沿用STOP、核对及断开流程，不重放START、重置计数或自动恢复运动。

未修改固件、协议ABI、500ms租约、参数、标定或其他保护。
没有可信历史的新设备/新主机仍需独立初始化或记录迁移流程，当前GUI不提供盲目建立计数入口。

重连跳过整个预留区间；拒绝5/0保留实际计数并STOP确认，不重试START。
