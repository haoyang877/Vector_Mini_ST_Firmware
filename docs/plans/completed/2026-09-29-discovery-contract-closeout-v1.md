# 设备发现与当前契约收口 v1

日期：2026-09-29。基线：`dac7f77ddaafe2e754d8796af2c54075276a537a`。
状态：本批源码和文档收口，未运行验证；后续统一验证。

## 目标与范围

GET_INFO 复用 APP、Loader 和镜像工具的共同目标清单，消除产品/硬件身份占位。
建立当前协议入口，区分现行实现与 H1 历史快照，明确 schema12 的装载政策。
普通使能、跨模式、版本发布源和参数迁移不在本批实现；不新增无消费者的接口。

## 保持条件与行为变化

- 控制数学、状态规则、参数记录及分区、故障优先级、采样时基不变。
- GET_INFO 仍为 32 B，GET_CAPS 仍为 16 B；产品/硬件字段内容改用 TARGET_PRODUCT /
  TARGET_HARDWARE，与 Loader 和打包工具一致。编译目标身份不是实际板卡自动识别。
- UID 来自平台；APP/Loader 版本及启动身份继续为 0，不伪造发布元数据。
- GET_CAPS 控制模式仍为 0，101 普通使能未决，116 不隐式启动或切换模式。
- schema12 保持拒绝旧记录、不自动回写；不改变现有现场标定数据。
- 用户 `.uvoptx` 与原始工程不修改，不扩大存储缓存或可写全局。

## 实施与接受

1. 阅读目标清单、APP 组合、Loader 运行时、镜像打包和只读编码真实调用方。
2. APP 直接引用已有 shared/targets 头；不增加第二份配置或产品元数据服务。
3. 在既有只读黄金字节夹具补充目标身份向量；只编辑，不执行。
4. 当前发现契约列出真实路由、能力和未知字段；更新文档及计划索引。
5. 旧 H1 内容标为历史，旧 schema11 不变量标明后续 schema12 决策覆盖关系。

依据源码和调用方阅读收口。按用户代码先行要求，不运行测试、构建、lint/format，
不连接硬件、下载、复位、保存参数或命令运动；不记录当前 PASS 或新资源容量。
统一验证时检查目标身份黄金字节、发现路由和 APP 工程输入。

## 回退与限制

本批独立提交可 revert，恢复 GET_INFO 的零占位；不 reset/clean 用户内容。
旧主机如错误依赖 product_id=0，需要改用目标清单身份；线路长度和字段偏移不变。
旧参数现场重新配置/标定和回退约束按当前装载契约执行，本批不迁移。
远程启动仍因 101 语义选择未决而未开放，不能把身份收口当作完整运动通信实现。
