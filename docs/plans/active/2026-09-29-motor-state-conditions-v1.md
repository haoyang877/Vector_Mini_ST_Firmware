# 主状态机条件与职责精简 v1

日期：2026-09-29。基线：ccd8d8a8，目标分支 codex/system-refactor。

## 目标与不变行为

保留九个主状态、全部电机功能、协议与参数 ABI。主流程按状态阅读，自检分为参数、
感测、停机确认；目标数值校验由现有控制模块负责。删除重复事实和完成记录，私有函数
名字明确动作与职责，不增加健康管理层、全局副本或通用框架，不使用 goto。

保持故障/STOP 优先级、请求拒绝结果、500 ms 期限、四拍稳定窗口、未确认或部分标定
可 READY、启相窗口与运行保护区别、任务代际、取消归还、派生保存和最终启相复核。
伪代码说明阅读结构，不据此重排原快慢拍动作顺序。

## 子任务

1. 保存基线源码、真实 owner/规则测试和两种 APP 构建产物。
2. 删除 facts 中由 active_faults 推导的 fault_sources_clear；明确感测有效字段，
   用 rules.tested 保存唯一自检完成资格，稳定计数只表达当前窗口。
3. 自检按感测、参数、停机条件组织；相同数值谓词共用，八个线上诊断位保持。
   同一临界区复用配置验证结果；跨动作和最终启相继续重新采集，不新增长期缓存。
4. 把格式和目标限值校验放入 motor_execution；状态机保留状态、反馈和输出准入，
   保持 INVALID/FAULT/DENIED/OUT_OF_RANGE 的原优先级。更新真实代码测试接缝。
5. 按九状态组织监督进展，拆清派生保存和使能处理，明确结果归还与事件动作函数名。
   故障诊断继续保持原原因优先级，不凭通用失败推断新的错误。
6. 对照基线 owner 日志、归一化规则矩阵及目标边界。旧纯规则夹具允许故障值为零而
   fault_sources_clear 为假的矛盾输入；删除派生字段时必须先让基线按实际 owner
   不变量生成夹具，记录两版相同的新摘要，不仅修改期望值。
7. 完成 format、lint、PR、release、LoaderApp 构建，量化 ROM/RAM、记录产物哈希。
   分阶段提交、合并主线、保存 outputs 证据后归档临时 worktree。

## 验收、回退与限制

同一更新夹具编译真实基线与最终所有者；目标拒绝、状态/故障/输出、任务身份和存储
效果结果必须一致。规则归一化矩阵 262144 组与基线一致；外部诊断位和黄金 ABI 不变。
实际 APP/LoaderApp 无错误和警告，Loader 槽继续满足容量。每批可 git revert。

证据位于 outputs/state-conditions、outputs/runs。只做离线检查和构建，不连接设备、
烧录、修改参数或运动；软件证据不能证明 ISR 时延、栈峰值或物理功率管关断。
