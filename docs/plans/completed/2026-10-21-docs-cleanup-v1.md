# 文档体系清理与对齐 v1

## 目标
整理 `docs/` 的入口、主题索引、计划状态和历史材料，使维护者能快速定位当前约定、操作指南、协议、待办和真实验证证据；合并重复入口，明确过期/被替代材料的状态。文档治理不改变固件、协议或参数行为。

## 基线
- `docs/` 当前约 396 个文件，含约 335 个 Markdown 文件、约 32,453 行 Markdown。
- `docs/plans/active/` 有约 106 个计划文件，索引同时混有当前待办和已完成/历史阶段，难以作为真实工作队列。
- `docs/README.md` 同时承担入口、协议历史清单和报告目录；部分相对链接与历史文件状态需复核。
- `codex/system-refactor` 工作树有用户未提交的架构文档及源文件改动；清理时保留这些改动，不覆盖或回滚。

## 范围与保持项
- 整理根文档地图和各主题入口，明确当前权威文档与历史记录的关系。
- 复核plans/active：真正未结事项保留；范围结束且正文有结果的移至completed；旧基线/被替代/撤回阶段移至archive，保留未完成事实并承接仍有效的缺口。
- 按版本和状态标识协议提案、历史契约与当前契约。
- 保留具有唯一事实/测量/失败原因的实测报告；仅移除有明确替代且无独立证据的重复材料。
- 不修改固件、协议 ABI、参数 ABI、构建输入或硬件配置。

## 验收标准
- 根 `docs/README.md` 能从当前架构、当前协议、操作/发布指南、当前计划和验证证据进入主题索引。
- `plans/active/README.md` 只列当前未结事项；历史计划不再被标为 active。
- 完成计划有可追溯的 completed 入口；过期协议/候选明确标记为 superseded 或 historical，并指向当前替代项。
- 移动/删除前检查引用；仓库本地 Markdown 链接验证通过，或对工具误报留下明确记录。
- 不丢失独立实测证据；无代码/协议行为变化。

## 回滚
用户已授权提交本轮文档清理；提交只选择文档及归档迁移，不包含固件、工程配置或编辑器设置。提交后可用Git revert回滚，不得reset/clean或覆盖用户/并行会话改动。

## 证据
- 整理前后目录与链接审计摘要。
- `uv run python tools/run.py verify --profile quick` 的当前结果。
- 本轮修改限于Markdown、历史文档/补丁的位置和文档路径引用；不改代码、黄金向量或构建输入。
