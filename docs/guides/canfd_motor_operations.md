# CAN FD 上位机角度标定与速度控制

适用：CAN-Link-Test v1.10.0，使用现有APP的160/161/162标定票据、117/116/118运动会话。
当前台架固件为APP v1.8.4 / Loader v2.3.4。标定与速度命令使用CAN；补偿曲线回读需要J-Link。
接线、1M/5M和节点选择见[大包、测试与标定指南](firmware_test_calibration.md)。

## 共用当前电机与导航

顶部“当前电机”是全部页面共用的轴、节点和UID。J-Link识别到已配板或烧录成功后
自动更新，硬件测试、通信、标定、单台升级和速度控制无需再选轴。新板初装仅在
顶部明确选择一次实际类型；之后沿用已确认类型。只接CAN时点击顶部“扫描识别”，
发现单台即自动选择，多台时在顶部选择当前电机。换板或换通道后重新识别；运动
开始前核对绑定UID，避免沿用同节点的另一台电机。

主页面顺序：J-Link烧录、硬件测试、通信测试、角度标定、升级压测、速度控制。
通信压测和原始协议发送位于通信测试子页。通信默认查询当前电机，启用“多轴查询”
后才选择批量节点；五轴验收使用节点3～7。升级默认当前电机，启用“批量升级”后
保留扫描和多选功能。原始协议帧仍按输入内容发送，切换电机不改写手工编辑的帧。

## 角度标定

进入独立“角度标定”页，直接点击平铺的“编码器 / Hall 角度标定并保存”
（kind1）或“电角零位标定并保存”（kind2）按钮，不需要下拉选择功能或标定项。
减速轴PITCH/YAW/Lift由现有固件在kind1中完成联合电角零位。无独立Hall的型号
按固件kind1执行编码器LUT，完整配板流程还需执行kind2。此页不设置机械零位，
也不覆盖型号、限值或PI。

点击对应标定按钮后，程序先核对UID、APP、能力、IDLE和零故障，显示当前
票据阶段；标定过程中电机会旋转。只有本票据phase2、effects2且Flash保存修订回读
匹配，才显示完成。标定受理和IDLE本身不能代替保存成功。

“停止”发取消请求并等待实际终态及关相。启动应答丢失时直接STOP，不重新启动
标定；明确的旧序号拒绝或已结束历史票据才允许有界换号。标定最长100秒。
Flash保存期间前台可能暂时不能应答；标定专用请求期限为500 ms，161只读查询最多三次，
超时后间隔100 ms重查同一票据。启动、取消不按此规则重放；查询仍失败则STOP。
保存完成与应答可靠性分开显示，重查成功也保留全部超时，不能作为零超时验收。
缺能力、票据错误、保存失败和超时分别保留真实失败，不自动清错或继续运动。

### 曲线与按电机编号归档

归档电机类型自动采用顶部当前电机，分别填写样机序列号和测试序列号
（均默认示例0001）。类型与节点联动；两个编号独立保存，均可包含1～32位数字、字母、
短横线或下划线，保留前导零。例如样机P轴电机-0001，测试0002。
同一样机多次测试保持样机号不变，单独填写测试号；两者均不自动分配，也不写生产SN、
板端型号或控制参数。同一测试号再次使用时仍以时间戳分目录，保留旧数据。

APP1.8.4在标定开始前核对J-Link身份及关相，采集现有RTT通道1的2 kHz原码；
标定命令仍走CAN。RTT读取仅消费调试缓冲，不写控制参数，不暂停或复位设备。
RTT通道没有设备时间戳或序号，图中的时间由接收样本序号除以2000给出，不能确认
零丢帧；同时保存主机接收时间、原始字节及帧边界裁剪长度。每帧为八个little-endian
int16，前五槽保留为零，第六槽是Hall校正角mrad，最后两槽是sin/cos原始ADC计数。
主机可能收到半帧，按保留槽和范围唯一同步，不唯一时保留BIN并报错，不猜测数据。

标定保存并确认关相后，自动通过同一只J-Link只读回读补偿表，核对UID、
CAN保存修订及Flash记录CRC。不暂停、复位或改写Flash/控制参数；读取结束解除探针
复位捕获，防止下一次正常升级停在复位入口。成功后自动弹出曲线窗，
也可点“查看本次曲线”重新打开。缺J-Link或绘图失败单独提示，已成功的标定仍保留。
电角零位任务不重新扫描LUT，图中显示已有表并明确注明。

标定记录位于`CAN-Link-Test/calibration/<类型-样机序列号>/测试-<测试序列号>/<时间>/`：

- `angle-calibration.png`：电机编码器和已装Hall的单圈补偿曲线。
- `angle-calibration.csv`：1024点索引、原始角度、固件原始Q15表值及角度补偿值。
- `calibration-parameters.bin`：校验后的完整16 KiB参数页，可保留全部原始字段和扩展。
- `motor-configuration.json`：独立样机/测试编号、固件型号、UID、票据、保存修订及可读电机配置。
- `calibration-manifest.json`：上述文件的长度和SHA-256；其他帧/操作摘要仍保留。
- `calibration-values.csv`：电零位Q15及编码器角坐标、Hall对齐角与标定极值。
- `hall-raw.bin`、`hall-raw.csv`：原始RTT字节及逐帧两路ADC计数。
- `hall-raw-receive.csv`：主机收到每批字节的时间、偏移和长度。

同一张图还显示电零位、Hall对齐角、sin/cos最小最大值、两路原码时域和XY轨迹。
电零位存储的是电角为零时的电机编码器Q15坐标；角度列为Q15乘360/65536，
不能把这个坐标直接称为电角。Hall对齐角为OEN3的phase_rad，属于电机坐标，满足
`motor = direction × gear_ratio × hall + phase (mod 2π)`。两路标定极值由保存的
offset±amplitude恢复，波形图例另外列出RTT接收样本的观测极值，两者采样窗口不同。
kind2不重新扫Hall，显示的是已保存Hall极值；其本次原码只覆盖电零位任务。
原码采集失败独立提示，缺少的波形不以拟合正弦或旧数据替代。

曲线横轴为各传感器自己的原始机械角，纵轴为原始角减校正角，单位度。
峰峰值表示补偿幅度，不表示标定残余误差或静态噪声。CSV Hall原始Q15为固件加法表，
图和角度列取负号以统一“原始角−校正角”。配置JSON保留控制、限值、热模型、
前馈、Hall系数、输出关系等字段；完整精度和未知保留字节以BIN为准。

## 速度使能、更新与停止

进入独立“速度控制”页。目标速度是**电机轴rad/s**，默认0；PITCH为40:1装配，
输出轴速度等于此值除以40。两侧可用输出行程默认360°，按本次实物条件填写。
本机已有UID继续使用计数数据库；首次且明确刚复位可用默认0/0，已有运行历史的
新工位须填真实高水位。

点击“使能速度控制”，发送117 mode2，确认RUNNING/mode2后才下发116目标。
速度上限输入默认30 rad/s，必须为正数；使能前通过参数1写入RAM并回读确认。
不自动保存Flash，重启恢复已保存值；固件仍按已配置轴包络限制上限，越界不启相。
本台架原轴包络4 rad/s已按用户要求单独提升至30 rad/s并保存，所有标定和PI字节保留。
程序读取电流上限，不改变电流或PI增益。使能后可编辑速度，再点“更新速度目标”；
更新只进入同一工作进程的队列，不重新使能或初始化PI。目标不得超过回读速度上限。
界面显示实际速度，`speed.csv`保留目标、反馈、位置和有效Iq。

速度会话保持到点击“停止”、达到行程或出现故障。工作进程持续发送递增118续租；
断联、目标/续租拒绝、反馈失效、界面关闭或主进程退出均停止，不自动重新使能。
停止需要110及状态确认关相。速度会话仍保持500 ms板端失联保护和每请求50 ms应答期限。
硬件功能检测页继续按50 ms验收，标定500 ms期限不改变已有检测阈值。
长会话分别预留续租和目标号，跨块与回绕不回退，也不以只读查询代替续租。

## 记录和验证范围

其他页面与本页共用一个工作进程和一个SDK端口，运行时不能并行烧录、升级或检测。
记录仍位于本机`CAN-Link-Test/<时间戳>/`：`frames.csv`为线路帧，`summary.json`为
票据、保存修订、启停结论和全部通信超时。速度还生成`speed.csv`。
关相确认与相应请求期限的可靠性独立记录；保存修订或实际反馈失败不能显示成功。
使能前失败显示“未发送使能命令”，不误报为曾经启动但无法确认关相。

协议、参数ABI及已有硬件检测阈值未变。具体实现为
[`can_motor_operations.py`](../../tools/bench/can_motor_operations.py)，
GUI仅收集输入、显示结果和管理工作进程。票据及运动语义见[现行协议](../protocols/README.md)。
