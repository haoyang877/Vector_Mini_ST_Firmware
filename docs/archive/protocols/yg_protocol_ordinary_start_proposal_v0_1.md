# 普通控制启动线路提案 v0.1

日期：2026-09-30。状态：**待 Type 编号定版的设计提案；未注册、未实现、未验证**。
当前已实现行为以[单轴线路契约 v1](yg_protocol_motor_wire_v1.md)和
[设备发现 v1](../../protocols/yg_protocol_device_discovery_v1.md)为准。本提案不授权电机动作。

## 问题与最小改动

`116 SET_CONTROL` 只能在已经 `RUNNING` 的相同模式更新目标，不能隐式使能。
`101 enable=1` 的定义是 mode 5 三相低侧导通制动，当前不开放；
不能用它启动普通控制。运行所有者已有 `MotorStateMachine_RequestEnable(mode)`，
但正式 CAN FD 路由没有调用方。建议增加一次性普通启动命令，后续目标继续使用 116，
状态继续使用 108；不建立另一套控制会话或状态机。

## 候选 Type 与载荷

候选 **117 / 0x0075 `START_CONTROL`**。117 原是保留号，尚未获得用户定版，
也尚未登记到公司消息类型表。此次文档更新不把它加入生产注册表。

| 方向 | 统一帧字段 | Payload | 约束 |
| --- | --- | --- | --- |
| 主控→电机 | Type=117；src=0x02；dst=实际电机 Node ID；flags=0x20 | `mode:u8, reserved:u8=0, reserved:u16 LE=0`，共 4 B | 单播，禁止分片；首批候选仅 mode 2 速度 |
| 电机→主控 | 同 Type、同 seq，src/dst 交换；flags=0x10 | `result:u16 LE, detail:u16 LE`，共 4 B | 每个可信请求必须有业务回复，包括拒绝 |

mode 2 显式映射内部 `MOTOR_CONTROL_SPEED`，以 **0 rad/s** 目标启动；
线上 mode 2 不能直接强转为内部枚举值 1。零速闭环也可能产生制动力矩，
不代表无功率输出。mode 0 仍用 101 失能或 110 STOP；mode 1 电流、
3 位置、6 电压留待逐项开放；mode 4 MIT、5 低侧制动不属于普通启动。
位置模式将来开放时须从**当前机械位置**建立初始参考，不得默认为位置零。

结果码沿用现行公共编码：首次受理 `1`；同身份重试查到已经完成的启动可回 `0`；
不支持 `2`、长度错 `3`、字段/陈旧/冲突 `4`、状态不允许或已取消 `5`、
忙 `6`、来源非法 `7`、内部失败 `8`、越限 `11`、故障 `17`。
`0` 是该启动身份曾经完成的**历史结果**，不保证目前仍在运行，更不表示机械到位。
detail 候选仅针对 117：`0` 无附加信息、`0x0101` 陈旧身份、
`0x0102` 同 seq 不同请求、`0x0103` 已取消、`0x0104` 准入未满足、
`0x0105` 状态不允许；这些值须随 Type 一起冻结，不改变现有 Type 的 detail。

## 程序流与所有者

```text
CAN FD → 公司统一帧/CRC 校验 → 117 长度/来源/保留字节校验
→ wire mode 显式映射 → 唯一运行所有者受理带 source+seq 身份的启动
→ 2 kHz 监督拍复查资格，准备、启相、确认 RUNNING
→ 原身份进展回包；108 读取当前状态
→ RUNNING 且 mode=2 后，116 更新速度目标，124 报告应用终态
```

所有者复用现有启动准入：配置确认、标定、编码器、母线、自检、故障、
维护及升级占用。首次 ACK `result=1` 只表示已受理；不能据此发非零目标。
启动进展应独立于 116 的目标应用进展，至少区分 PENDING、STARTED、REJECTED，
并绑定原 source、seq、mode 和实际生命周期代际。
只有原身份代际匹配、状态 `RUNNING`、模式正确且数字输出确认为开启时，
才能记录 STARTED；这仍不是物理栅极或转速验证。
通信层不能直接操作 PWM、HAL、全局电机对象或在回复丢失后重新执行启动。

## 重试、STOP 与跨复位边界

- 主站递增 16 位 seq；同请求重试保留 source、Type、seq 和完整 4 B payload，
  仅置 retry flag 并重算 CRC。按需回复超时上限 1 s、最多 5 次重试。
- 同身份重试只读取原进展；同 seq 不同 payload 拒绝冲突。
  有效但被准入拒绝的请求也消耗身份，条件随后改善不能用旧 seq 重新启动。
  活动启动不可被新的 BUSY 请求覆盖；记录淘汰后旧 seq 必须判陈旧。
- 117 的去重状态独立于现有 116 的 256 槽目标历史；后者没有 Type 键，
  不能直接共用。新启动只能由新的有效身份在 READY 重新受理。
- STOP、101 失能、故障和升级停机撤销未完成启动及待应用目标。
  旧 117 重试不得重新启相；已 STARTED 的原结果只是历史，当前输出另看 108。
- 必须处理 **STOP 先到、旧 START 后到**：主站对启动/停止使用递增序号，
  所有者保存 STOP 序号屏障；旧 START 不得越过屏障。STOP 不因旧序号而拒绝安全停机。
  当前 STOP 窄端口尚未传 source/seq，实施前必须补齐身份接线与原子复核。
- 以上去重记录是易失的；APP 复位后不能仅靠 4 B 请求与 seq 防止跨复位旧帧。
  当前 `boot_id=0` 及升级交接票据不能冒充普通控制代际。若产品要求跨复位防重放，
  需单独冻结真实启动代际和请求字段，本提案不声称已满足。

## 速度控制示例（候选字节，非黄金向量）

本轮台架发现主控 Node ID 为 `0x02`、电机实际配置 Node ID 为 `0x01`。
使用发现的地址，不改写保存的节点参数；历史 `0x03～0x07` 是公司分配/多轴示例。
请求 priority 2，29 位 CAN ID `0x08EF0102`；回复 priority 3，ID `0x0CEF0201`。
CAN FD 29 位扩展帧、BRS；仲裁 1 Mbit/s、数据 5 Mbit/s。
应用数据区是 16 B 头 + payload + 2 B CRC16；不足 DLC 的尾部补零不参与 CRC。
所有多字节字段小端。CRC8 poly `0x9B`/init 0 覆盖头 0～14；
CRC16 poly `0xBAAD`/init `0xFFFF` 覆盖头及 payload，均不反射。

117 速度启动，seq `0x1001`，payload `02 00 00 00`，CAN FD DLC 24：

```text
5A A5 01 20 02 01 75 00 01 10 04 00 00 00 00 82
02 00 00 00 99 F6 00 00
```

117 首次受理回复，`result=1, detail=0`，DLC 24：

```text
5A A5 01 10 01 02 75 00 01 10 04 00 00 00 00 8E
01 00 00 00 20 12 00 00
```

主站随后查询 108，只有新鲜 `state=6 RUNNING`、`mode=2` 且无故障，
并确认原启动身份已经 STARTED，才发送 116 非零速度目标。
例：30 rpm 约等于 `3142 mrad/s`，116 的 20 B payload 是
`02 00 00 00 00 00 00 00 46 0C 00 00 00 00 00 00 00 00 00 00`。
116 的同 Type 回复、关联 124 与 110 STOP 沿用现行线路契约。
上述 117 字节按现有算法计算，**尚未进入正式黄金向量或测试**，禁止当作设备支持证据。

## 定版与实施条件

先决定是否将 117 从保留号定版，以及首批是否只开放 mode 2；
确认能力发现位和旧固件识别方式，再同步主机与固件。
当前 GET_CAPS `supported_modes=0` 不变，不擅占 features 位。
旧固件没有 117 路由，新主机不能假定一定收到“不支持”业务回包，
也不能回退到 101 制动或 116 隐式启动。
定版后按仓库规则补版本化线路契约、正常/拒绝/重试黄金向量和离线测试；
实机安全验收另按明确台架场景执行。五轴 1 kHz 的组目标与精简反馈是独立工作，
本提案不宣称单轴 116/124 已满足其带宽或同步要求。
