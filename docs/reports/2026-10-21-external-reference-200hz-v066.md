# 外部参考 200 Hz 接收与插补兼容 v0.6.6

本轮保留节点3、自研11位标准帧ID、目标1mrad编码、原有查询与反馈单位，不增加保活命令。修改外部位置参考时间处理，默认点到点入口及控制增益不变。

## 行为变化

- 正常会话取消 `interval_ms >= 5` 的硬拒绝。合法新序号允许4/6、3/7、1/9ms抖动和同毫秒合并；逆序时间仍拒绝，uint32毫秒回绕仍支持。
- 压缩接收的步长预算至少为一个5ms周期，仍受原有角度范围、速度及量化裕量约束，不取消目标有效性检查。
- 正常插补时间为实际接收间隔限制到5～40ms；速度估计分母与插补段时长一致，同毫秒到达不发生零除。新会话仍以实测位置/速度播种，并保留20ms首段。
- 100ms失效、重复序号不刷新、目标越界拒绝、预测角度上限及真实速度反馈保持原语义。不放宽电流、热、母线电压或其他保护。

版本唯一配置更新为 `firmware/app/firmware_version.h` 的v0.6.6/build0；`0x36F`回复`00060600`。版本向量同步更新，历史v0.6.5准入向量保留，新回归使用v0.6.6向量。构建工具接受`external-200hz`，与原外部参考开关对应，不改变默认构建。

## 实机结果与限制

固定J-Link序列号602722271、UID `2d00470010504e4831303320`的roll已由v0.6.5更新到v0.6.6。写入范围仅APP和版本记录页；Loader、保留页及标定参数区逐字节校验一致。母线相关保护参数没有修改。

复位使RAM-only最大位置速度从0.74rad/s回到Flash保存值0.52359879rad/s，已通过原CAN命令恢复0.74rad/s并查询确认；不写Flash参数。主控当前量化规划上限为0.6rad/s。

主控v0.48.0成功核对两源擎5ms配置，10秒三轴核心反馈约200Hz。五轮±20°轨迹在约23秒后因共用电源异常中断：roll报码9（`Under_Voltage`），独立查询母线约3.67V，两台源擎同时失去心跳、PDO和SDO回复。

本轮不能记为完整运动验收通过。中断前观察到前两轮全部端点在±0.5°内；后续轮和最终持位未完成。roll最高观测速度35.52°/s，两源擎约21.41/23.59°/s，均低于45°/s。控制平均约199.90Hz，但出现3个跳过周期、最大SYNC间隔18.382ms，不能声称硬实时或零卡顿。

主控服务已停止，roll反馈模式0失能；源擎失能命令已发送，但无回复，不能把“无通信”当作“已确认失能”。需现场恢复供电并重新检查状态后，才可继续运动验收。完整证据位于主控工作树`outputs/three_joint_200hz_v0480/`。


## 恢复供电后的五轮复测

恢复后roll母线约25.79V，三轴均确认失能；仅清除已经恢复的欠压锁存。两源擎重新配置并读回5ms。使用相同主控v0.48.0与roll v0.6.6执行完整五轮±20°，最终保持3.21秒，控制与核心反馈约200Hz。

整体运动验收仍失败：roll第3～5轮负端目标-325mrad，原始CAN最近实际位置均为-316mrad，误差0.5157°，略超±0.5°。原始反馈复核排除了客户端刷新漏采；未放宽判据。最终位置误差三轴均在±0.5°内，原始最高速度roll32.09°/s、pitch23.05°/s、yaw24.84°/s。3个跳过周期及最大17.81ms SYNC间隔保留为实时性限制。

本次测试结束后三轴均通过真实回复确认失能且错误0，主控服务已停止；最新状态覆盖此前掉电后源擎失能未确认的历史状态。没有继续运动或修改增益，后续需针对roll负端点收敛分析。证据位于主控工作树`outputs/three_joint_200hz_v0480/hardware-summary-resume3.json`。
