# 重构远端整合与单节点验证

将本地已实测的 CAN 配置与本次抓取的远端重构代码合并。基线分别为 `36625947` 和 `8d3e9334`。保留两端已有调用、AT32 默认 1M/5M、G431 固定 500K/2M，以及各自的参数与升级兼容契约。

离线核对两板构建、升级包、主机与寄存器配置。按本次台架范围，在单独连接的 AT32 节点上仅验证仲裁 1M、数据 5M。验收包括保存参数、复位回读、APP 通信、完整 CAN 下载和再次复位确认。回退依据为两个父提交、测试前的整片双读备份和已校验的原整机包。

## 离线结果

远端 23 个提交已纳入合并，10 个冲突文件全部处理。保留 v3.1.3 上位机的自动扫描、参数工作台与 SWD 维护入口，同时支持两段独立的 CAN 速率。USB-CAN 适配层兼容两端已有的仲裁速率关键字。参数工作台收录 AT32 的 0x71，按 kbit/s 显示仲裁/数据，遇到整批均不支持该参数的旧固件时保留上一批有效修订。SWD 关相检查继续核对通道、主输出与两个 GPIO 端口。

| 板型 | APP / Loader | 默认仲裁 / 数据 | CAN APP 长度 |
| --- | --- | --- | --- |
| AT32F456 | v1.7.0 / v2.3.3 | 1M / 5M，两段均可配置 | 88,512 字节 |
| STM32G431 | v1.6.3 / v2.2.0 | 固定 500K / 2M | 81,472 字节 |

AT32 APP 版本在远端 v1.6.5 基础上按兼容新增接口递增。G431 APP 为本次共用固件与板级配置分配独立修订号。两个 Loader 的重建 BIN 均与上一份本地整机包逐字节相同。

- 六个 Keil 目标重建均为 0 错误、0 警告。两板的 FULL HEX 已核对加载地址和参数区边界，CAN 包核对了描述符、CRC、默认速率及跨板拒绝。
- 96 项 CAN、升级、SWD 和装配专项测试通过。生产 BSP 加厂商 SDK 在内存寄存器模型上通过 12 档验证，5 份原始参数备份完成 60 组 APP/Loader 兼容回放。
- Rust 常规测试 89 项通过，另行在解压后的便携包上通过 1 项内存探针测试。此项以替身执行备份、安装和回读。CAN-Link-Test v1.6.3 的窗口启动及内置镜像校验通过。
- PR 与 release 各有 195/197 项单元测试通过，21 项集成测试和 46 组原生回归通过。两个单元失败分别来自文档链接汇总和旧 Keil 目录。120 个失效链接在父版本中已有。暂存合并及既有未跟踪目录也使 release 的干净源码检查失败，release 跳过构建、清单未获通过。上述 Keil 构建由独立构建入口执行。

调试包为 `VectorMini-AT32F456-v1.7.0-STM32G431-v1.6.3-Tool-v1.6.3-merge-offline-debug-20261112.zip`，SHA-256 为 `5282dd72d88c6f005804ba652a1718cf65bd1f8d3811f1c7d977e5d7b00965b3`。包内含双板固件、CAN-Link-Test v1.6.3、此次合并构建的 YG_MC_HOST v3.1.3 便携包、随包升级客户端及校验清单。两种主机工具与外部固件的嵌入载荷分别核对。验证使用的暂存树为 `86e28e9f25163fbccfc5261ed812fcea61545f7e`，生成证据位于 `outputs/refactor-remote-validation-1794495172222`。

## 节点 7 的 1M/5M 实测

CAN-Link-Test v1.6.3 在 USB-CAN 通道 1（驱动索引 0）扫描到一台 YQ-5708。用 J-Link 双读现场 Flash 后安装本包 AT32 FULL HEX。工具识别到 APP v1.7.0、Loader v2.3.3，电机空闲且无故障。

| 操作 | 实测结果 |
| --- | --- |
| 在工具中保存同档参数 `0x71` | RAM 与 Flash 均回读 `0x03E81388`，保存修订为 1。复位后两者仍为 1000/5000 kbit/s。 |
| CAN 升级时读取实际寄存器 | APP 和 Loader 的 ACTIME 均为 `0x2C2C0085`，FDTIME 均为 `0x08080019`。LBTCFG 的位时序字段均匹配 1M/5M 黄金向量。 |
| 用工具内置的 APP 做 CAN 升级 | 88,512 字节，1,230 个写块全部应答，写块重试 0 次。工具总耗时 9.49 秒，CRC32 为 `62eca8f5`。再次复位后，节点身份、版本、CRC、持久确认标志和 16 KiB 参数区均通过回读。 |
| 升级后用工具执行常规查询 | 节点 7 的 1,000 次状态查询均在首次应答窗口内通过。实测 50.05 笔/秒，超时、应用层重试和适配器错误帧均为 0，P99 为 3.533 毫秒。 |

首次升级时，外接 J-Link 捕获了 APP 交接引发的复位。CPU 停在 Loader 复位入口，工具身份查询超时，当次写入 0 字节。解除调试器的复位捕获后，在相同固件与速率下重新执行完整升级并取得上表结果。

测试后按备份恢复了 55 个变化的 Flash 页。整片 262,144 字节与测试前逐字节一致，SHA-256 为 `687491a558906f5a9eafb4876cbb7899c744b595cc6c5439b3f80ac10814525c`。工具再次识别到原现场 APP v0.6.2、Loader v2.2.0，节点 7 在 1M/5M 下空闲且无故障。

本次整机包的其他 11 档波特率与 STM32G431 仅完成离线验证。单板原始记录位于 `outputs/can-fd-single-1m5m-1794497799106`。交付包内的 `summary.json` 记录合并提交与镜像哈希，`verification/at32f456-single-1m5m.json` 记录本次实测结果。
