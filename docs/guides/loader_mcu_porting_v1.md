# Loader 更换 MCU 适配指南 v1

更新：2026-10-20。适用对象：后续新 MCU 或新控制板的 Loader 适配。
当前尚未选定新型号；本文是实施和验收依据，不表示已经支持第二款 MCU。

## 使用方法

先填写本文末尾的任务卡，再按“资料确认 → 差异分析 → 代码适配 → 离线验证 →
实机验收 → 交付”的顺序推进。每一步记录完成情况、证据和未解决事项。
未知信息写“待确认”，不要用 G431 的值替代新芯片资料。

开发者或编码助手可以据此修改代码、生成工程、构建和运行离线检查；硬件接线、
功率隔离和真实断电需要现场配合。资料不足时先做不受影响的工作，列出缺项，
不靠猜测完成驱动，也不为未来型号预先增加空实现。

“通用 Loader”指多目标复用升级流程，每个目标分别编译。一个目标由 MCU、板卡、
存储布局和通信配置共同确定，同一 MCU 的不同板卡也可能需要不同固件。
本指南不选择芯片，不改动现有参数单份存储政策，不新增 USB 功能。
CAN FD 为优先通信方式；UART 必须单独实现和验收，不能因更换 MCU 自动标为支持。

## 开始前需要提供的资料

### 能够开始离线适配的资料

| 资料 | 需要具体到什么程度 | 用途 |
| --- | --- | --- |
| MCU 身份 | 完整订货型号、封装、容量版本；已知硅版本 | 避免同系列不同容量、外设或勘误混用 |
| 板卡身份 | 板名、硬件版本；原板换芯片或整板更换 | 区分芯片差异和板级差异 |
| 芯片文档 | 官方数据手册、参考手册、勘误及版本 | 核对 Flash、复位、时钟、CAN 和调试行为 |
| 电路资料 | 原理图或相关完整电路页、引脚表 | 确定电源、晶振、复位、调试、CAN 和功率控制连接 |
| 功率关闭方式 | 驱动器型号、使能有效电平、PWM 空闲电平、上下拉及硬件保护 | 定义从上电开始可验证的安全状态 |
| 存储信息 | Flash/RAM 起址与容量、擦除单位、最小编程单位、bank、ECC、缓存、写保护 | 确定分区、写入方式和异常读取处理 |
| 时钟与通信 | 晶振频率、CAN 内核时钟来源、控制器能力、收发器型号、目标速率 | 计算时序并建立可通信端口 |
| 开发环境 | 工具链与版本、厂商 SDK、启动文件、最小可构建工程及 Flash 下载算法 | 建立可复现的独立构建 |
| 配套 APP | 待移植 APP 的源码版本、参数格式、资源需求及已有平台端口 | 完成启动、交接、确认和兼容检查 |
| 产品约束 | 是否继承现有协议和参数、必须保留的数据、后续容量余量 | 确定兼容范围和迁移方式 |

如果尚无完整 APP，可先验证 Loader 启动和下载；临时测试 APP 必须单独标识，
其通过结果不能替代真实配套 APP 验收。不能仅凭“引脚兼容”认定芯片可直接替换。

### 接板前补齐的资料

| 资料 | 确认内容 |
| --- | --- |
| 接线与供电 | MCU/CAN 如何单独供电、电机功率如何物理隔离、共地与终端电阻 |
| 测试设备 | 调试器类型、USB-CAN 类型、设备身份和通道，避免只写容易混淆的 CAN 编号 |
| 台架占用 | 设备由本次测试独占；其他软件和测试任务已释放对应连接 |
| 原始状态 | 原固件、全片备份、参数和生产身份、保护配置及恢复步骤 |
| 现场配合 | 可以确认隔离、随时断电；计划中的断电不会伤及其他设备 |

设备序列号、工作站路径和备份只放在本机台架配置与 `outputs/` 证据中，
不写入通用源码或本文。连接失败先排查设备选择、供电和占用，不自动切换另一块板。

## 先识别当前实现的限制

当前已实现并验证的目标是 G431 + CAN FD。应以当前源码、目标配置及
[实机记录](../reports/2026-10/loader_storage_optimization_20261020.md)为依据，
早期[通用框架设计](../architecture/loader/d_loader_portable_framework_20260917.md)中的规划不代表已经实现。

| 当前实现 | 新目标适配时要做什么 |
| --- | --- |
| [镜像内核](../../shared/image/image_transfer.c)要求每次编程 8 字节，三个启动标记也按该单位写入 | 核对新 Flash 编程规则；若不兼容，连同标记布局、CRC 归一化、故障恢复和配套工具一起设计 |
| 镜像内核把 APP 槽上限限制为 128 KiB | 更大 APP 要检查并调整内核、打包工具及边界测试；这不是芯片总 Flash 容量上限 |
| [目标配置](../../shared/targets/vector_mini_st_g431.json)是单一 G431 目标 | 新建独立目标，不能覆盖 G431 配置或沿用它的兼容身份 |
| 工程生成、打包和客户端已接入显式目标选择，现有真实目标仍只有 G431 | 新增目标时提供芯片端口和完整构建输入；生成工具不会自动实现驱动 |
| [运行入口](../../loader/runtime/main.c)通过生成的 `loader_target.h` 选择目标 | 由目标清单生成；不要手工替换已验证目标的头文件 |
| [客户端](../../host_app/upgrade_client.py)支持 `--target`，省略时保持 G431 | 契约随工具部署；未知目标和不兼容能力在操作前拒绝，不能取消匹配检查 |
| UID 通路目前使用 12 字节，打包检查使用当前 ARM 启动向量规则 | 核对新芯片 UID 编码和启动架构；不直接截断身份，不套用不适用的向量检查 |
| G431 使用保留 RAM 邮箱及特定复位、ECC 和看门狗处理 | 核对新 MCU 的真实行为，不能只替换寄存器地址 |

协议、描述符、参数或身份编码发生不兼容变化时，更新相应版本、文档、黄金向量及测试，
明确拒绝旧目标的方式。新增 MCU 本身不等于必须改线协议；兼容时保留已有协议。
不改变格式时，也要为新目标登记准确的 MCU、产品、硬件和布局信息。

## 已完成的公共边界收口

2026-10-21 已将平台接口放入 `loader/ports/include/`，芯片实现留在
`loader/ports/stm32g4/`。依赖检查覆盖核心、组合层、产品层、端口和板级，
核心不能直接包含厂商头、芯片私有头或目标配置。

`loader/product/parameters.c` 负责现有参数格式和 CAN 节点解析；平台只提供有界只读访问，
拒绝读过参数边界进入生产身份页。`loader/boards/vector_mini_st/board.c` 同时拥有
关相动作和关闭状态核对。此次保持原有寄存器条件、节点策略及存储格式。

目标来源统一到 `shared/targets/`，通过 `target_contract.py` 读取并检查。
构建信息记录芯片宏、CPU、工程模板、源文件、输出目录和选择头目录；
固件只编译一个选定目标，不增加运行时目标注册表。

以下命令只生成工程或检查本地文件，不接触设备：

```powershell
uv run python loader/tools/generate_target.py --target vector_mini_st_g431
uv run python tools/build/generate_loader_app_project.py --target vector_mini_st_g431
uv run python tools/build/check_project_layout.py --target vector_mini_st_g431
uv run python host_app/upgrade_client.py inspect --target vector_mini_st_g431 --package outputs/配套包/app-package
```

`package_image.py`、`keil_loader_app.py` 和 `build_loader_bundle.py` 也接受 `--target`。
参数可以是目标名称，或明确的目标 JSON 文件路径；省略时保持 G431。
不存在的显式目标不会回退为默认目标。配套构建前会只读重算并核对目标头、选择头、
Loader/APP 工程和两份链接脚本；有任何过期输入，先重新执行两个生成命令再构建。
不要直接修改生成工程来绕过检查，应修改目标清单或模板后重新生成。
`build.defines` 用于 Loader；`build.app_defines` 用于配套 APP，未填写时采用前者。
新目标需要明确填写 APP 的芯片宏和板级产品宏；G431 保留 6 毫欧采样电阻宏。
APP 工程移到新目录时，生成器会重新计算模板源文件和头文件目录的相对路径。
APP 工程的后处理继承目标选择，配套构建传递同一份契约并核对其哈希。

Qt 主机构建通过 CMake 的 `YG_LOADER_TARGET_FILE` 选择目标，默认仍为 G431。
所选头文件、内嵌校验资源、部署契约及启动的 Python 客户端保持一致。
CMake 配置时会核对选择头及目标常量；目标 JSON 改过而头文件未重新生成时拒绝构建。
独立部署需包含 `target_contract.py` 和 `contracts/<目标名>.json`；仅复制客户端脚本不够。
生产身份工装仍为 G431 专用，不能因为升级客户端支持目标选择就用于其他芯片。

本轮没有放宽 8 字节编程、128 KiB APP 上限、Cortex-M 向量及 12 字节 UID 约定。
不同存储几何和启动架构仍需按下面步骤设计、测试，不能通过修改目标名称绕过限制。

## 分步适配

### 第一步：冻结基线，形成差异表

1. 从确认的重构主线建立隔离工作树，保存基线提交和现有 G431 检查结果。
2. 在 `docs/plans/` 建立该目标的版本化实施计划，引用填好的任务卡。
3. 逐项比较 Flash、RAM、CPU 启动、复位、看门狗、CAN、UID、功率关闭和工具链。
4. 对每项标记“可复用、只改配置、重写端口、需要修改契约、资料不足”。

通过条件：每项差异有资料出处和处理决定；明确哪些工作影响 APP、主机或协议。
不要承诺 G431 的时序和资源数字会在新芯片上保持不变。

### 第二步：确定分区和目标配置

建立 Loader、APP、参数、生产身份和 RAM 邮箱的布局。每个区域写明起址、容量、
对齐、所有者及读写权限；检查擦除块是否跨越区域边界。

当前 G431 的分区为 Loader 16 KiB、APP 96 KiB、参数与身份共 16 KiB，
仅作为已实现参考。新目标根据实际擦除几何、构建体积和余量重新确定。
参数继续单份保存；升级过程不得顺带清除参数、SN、电机类型或 CAN ID。

三处必须一致：目标清单、Loader 链接布局、APP 链接布局。主机读取相同的目标契约。
RAM 邮箱应避开普通数据、堆栈、启动清零和下载算法的工作区；验证所需复位类型下的保留行为。
硬件不支持该方式时，另行设计并记录交接机制。

通过条件：布局不重叠、不跨擦除边界；镜像与启动标记能够按新芯片规则写入和校验。
Flash 不同 bank、非等长扇区或执行限制不能用一个“页大小”常量掩盖。

### 第三步：实现 MCU 和板级端口

建议新增以下位置，名称以实际 MCU 系列和板卡确定：

```text
loader/ports/<mcu_family>/       Flash、CAN、时间、看门狗、复位和跳转
loader/boards/<board>/          时钟源、引脚、收发器和功率关闭
loader/targets/<board_mcu>/     构建输入、链接配置、启动文件引用
shared/targets/<board_mcu>.json  目标和兼容配置
```

复用 `loader/core/` 中的升级事务和 `shared/` 中适用的契约，硬件差异放在端口及板级层。
同系列 MCU 能复用端口时不复制整套实现。厂商代码遵循其来源管理规则，
CubeMX 生成区只按仓库允许的方式维护。

| 端口 | 必须保证的行为 |
| --- | --- |
| 功率关闭 | 尽早进入板级安全状态；读取真实引脚和外设状态验证，不能只返回软件标志 |
| Flash | 写域限于 APP；检查边界、对齐、保护和错误；擦后及写后读回；处理缓存和 ECC |
| 计时 | 单调计时包含 Flash 停顿；超时不能因中断暂停而无限延长 |
| 看门狗 | 处理上电已启用的情况；喂狗与有界工作配合；记录真实复位时间范围 |
| CAN FD | 正确设置时钟、速率、过滤器、收发队列；处理溢出、错误和总线关闭 |
| 发送完成 | 区分入队与线上发送完成；完成事件绑定原消息，不能把复用槽位当成旧消息成功 |
| 复位与跳转 | 核对复位原因；停止本端外设和中断；按目标架构校验并移交 APP 执行环境 |
| 设备身份 | 读取芯片身份和生产记录；无效生产记录报告无效，不能编造 SN |

当前 G431 CAN FD 使用仲裁速率 1 Mbit/s、数据速率 5 Mbit/s。
新目标必须重新计算并验证时序，不能照抄分频参数；改变速率时同时记录主机配置。
没有原生 CAN FD 的芯片需要另行确认通信硬件方案，普通 CAN 不能直接接收当前 FD 帧。

### 第四步：接通配套 APP 和主机工具

APP 从自己的分区启动，并采用与 Loader 一致的描述符、参数兼容信息和邮箱约定。
正常升级链路应完整保留：

```text
APP 停机并等待维护操作结束
  → 交接回复真正发送完成
  → 请求复位进入 Loader
  → 下载、读回、整包校验和激活
  → APP 首次试运行
  → 健康条件满足后确认
```

不能通信或不能通过健康检查的未确认 APP，必须能够通过复位回到 Loader。
已确认 APP 后续故障的救援也需要验证：主机预先等待启动窗口，现场复位后建立新下载会话。
主机按设备身份、目标、布局和镜像校验结果判断成功，不能凭最后一帧发送成功判断升级完成。

首次部署新布局通过受控调试器安装配套 Loader 和 APP；不能用旧地址 APP 直接试运行。
普通 CAN 升级仍只更新 APP。新 MCU 的整体电机控制移植是配套工作，
Loader 验收不替代电流采样、PWM、编码器或闭环性能验收。

### 第五步：离线验证和构建

从仓库根目录使用统一入口：

```powershell
uv sync --locked --extra dev
uv run python tools/run.py format --check
uv run python tools/run.py lint
uv run python tools/run.py verify --profile pr
uv run python tools/run.py verify --profile release
```

这些命令不下载固件、不操作电机。改动固件、协议或测试必须通过 PR 检查；
改动链接、启动、构建输入或台架实现还要通过 release 及适用的实机程序。
当前 release 工具面向现有目标；接入新目标时必须使其能单独构建并报告新目标结果，
不能拿只构建 G431 的通过结果代替新 MCU 构建。
生成工程后先审核并提交目标修改，再从干净工作树执行 release 验证。
当前目标选择和公共边界的用法见下一节；目标可选择不等于已支持其他芯片。

新增并核对：地址越界、整数溢出、擦写边界、镜像不完整、错误 MCU/板卡/布局、
CRC 错误、错误启动入口、过期会话、重复请求、超时和启动标记半写场景。
修改通用代码时同时运行 G431 回归，避免新增 MCU 破坏已有目标。

通过条件：Loader、配套 APP 和主机可独立使用；新目标构建无错误、无警告；
Flash/RAM 和预留栈有明确预算；配套包、合并包、清单与镜像描述符一致。
记录实际体积，不把“链接成功”当成栈峰值已测量。

### 第六步：执行实机验收

先完成独占、接线、隔离、身份核对和双次备份读回。每次运行绑定源提交、
目标、工件哈希和设备，日志放入独立目录；不覆盖失败记录。

任一意外失败立即中止该轮。无法确认 STOP 或功率输出关闭属于硬失败，
必须现场物理干预并重新确认后才能继续，不能自动恢复下一轮。
恢复原机也属于写操作，仅在能够确认安全的情况下执行。

## 实机验收标准

| 项目 | 如何验证 | 通过标准 |
| --- | --- | --- |
| 安全启动 | 冷启动、软件复位、看门狗复位，观察功率控制引脚和外设 | 输出保持规定安全状态；没有意外运动 |
| 初始部署与发现 | 安装配套固件，分别从 Loader 和 APP 查询 | 同一设备身份正确，角色、版本、布局和参数兼容信息正确 |
| 正常升级 | APP 交接、下载、激活、试运行、确认 | 全链路完成；实际 Flash 与预期镜像一致；状态为已确认 |
| 连续升级 | 默认执行连续 20 轮完整升级 | 每轮通过；轮间不靠调试器重刷或人工复位帮助通过；记录耗时和协议内重试 |
| 中断恢复 | 下载中断链或主机停止发送，另做 MCU 复位 | 不启动残缺 APP；旧会话不能继续写；新会话完整下载后恢复 |
| 真实断电 | 按目标 Flash 行为覆盖擦除、写入、激活和确认等关键阶段的断电/重新上电 | 不启动未完整提交的镜像；Loader 可救援；参数和身份不变 |
| 故障 APP | 合法镜像但不能通信/不喂狗或不能通过健康确认 | 不获得确认；在该目标约定期限内回到 Loader，随后能完整恢复正常 APP |
| 已确认 APP 救援 | 模拟已确认 APP 无法交接，主机等待救援窗口后现场复位 | 捕获 Loader 窗口并重新下载；不把超时当成功 |
| 错误镜像与边界 | 错目标、错布局、坏 CRC、越界和非法启动入口 | 拒绝启动或写入；不触及 Loader、参数和身份保护区 |
| 通信和 Flash 错误 | 总线错误/恢复、发送失败、读写错误；支持 ECC 的目标覆盖其异常路径 | 撤销写会话并安全驻留，不错误激活；重新下载按新会话处理 |
| 数据保留 | 升级前后比较 Loader、参数、SN、电机类型、CAN ID 及保护配置 | 没有计划外变化；允许变化的镜像标记按规则单独核对 |
| 资源与时间 | 构建报告及代表性最坏场景测量 | Flash/RAM 不超预算，栈余量足够；擦写、通信和看门狗满足目标计划 |
| 收尾恢复 | 按约定保留新固件或恢复原状态 | 读回及哈希符合约定；记录最终固件、参数和功率输出状态 |

20 轮是本指南的默认连续验收目标。若出现意外失败，保留记录，修复后以新批次重新计数，
不能把失败前后的成功次数拼成连续通过。协议允许的重传单独统计，不隐去。
真实断电不能用软件复位、下载中断或模拟器替代；故障注入和具体断电操作在接板前设计。
若关键项目因条件不足未测，结论写“部分验证，未测项见清单”，不能写“适配验收通过”。
故障恢复只保证能够重新下载；当前单 APP 槽设计不保证恢复已被擦除的旧 APP。

Flash 读回应排除调试器和 CPU 缓存影响。镜像存在可变启动标记时，按描述符规则比较或
归一化这些字段，同时单独核对其状态，不把整包 CRC 不变理解为每个字节永远不变。
看门狗期限来自新目标的设计与实测，不直接采用 G431 已测到的等待时间。
调试器读取也可能延长通信间隔，不能在消息分片之间插入长时间阻塞；
性能记录应说明调试检查开销，避免把整轮时间当作纯 CAN 总线耗时。

## 完成状态与交付物

| 状态 | 允许给出的结论 |
| --- | --- |
| 资料齐全 | 可以实施，有差异表和未决事项 |
| 构建通过 | 新目标能够生成配套工件，尚不代表在硬件上可用 |
| 离线验证通过 | 协议、边界和模型验证通过，实机行为仍待确认 |
| 部分实机验证 | 仅列出已经通过的项目和未测项 |
| 适配验收通过 | 适用验收项目全部完成，有匹配工件的实机证据 |

交付至少包含：新目标及端口源码、配套构建方式、分区/权限表、兼容和参数迁移说明、
Loader/APP 单件工件、CAN 升级包、整机调试器烧录包，以及带哈希的清单和测试记录。
详细命名遵循[固件发布规范](firmware_release_standard.md)。
验收通过不自动等于正式发布，是否发布仍按发布流程处理。

`summary.json` 应关联源提交、工具链、目标、工件哈希、每项结果、失败/未测项和收尾状态。
生成数据放在 `outputs/`，长期结论在 `docs/reports/` 登记。
回退使用事先核验过的匹配固件和备份；保护状态不明时不自动擦除整片。
