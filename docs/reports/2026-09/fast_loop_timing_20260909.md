日期：2026-09-09。分支：`codex/optimize-20khz-loop`，从 `f092e3d` 创建。

分析对象是创建分支时的**实际工作区**，包含原先未提交的参数、阻抗控制等修改；不是干净的 `f092e3d` 镜像。本次保留这些修改。用户连接J-Link后先做只读检查，随后明确授权下载和启动校准；已烧录新HIL镜像并测量停机路径，没有发送使能/运动命令。以下“历史实测”不能当作新镜像测量结果。

- 每周期50 μs，8500 CPU cycles；1 μs = 170 cycles。
- 速度、模式3位置伺服、位置阻抗环配置2 kHz，每10个快环周期更新一次。

- HIL命令邮箱10 kHz；温度换算与监督任务1 kHz。

## 2. 实际执行路径

```text
TIM1中心对齐PWM / CC4触发
  → ADC2顺序转换 Ia、Ib、Ic、Vbus
  → ADC1_2_IRQHandler
  → 按ISR/IER检查事件 → HAL_ADC_IRQHandler
  → HAL_ADCEx_InjectedConvCpltCallback
  → FOC20kHzIRQHandler
      Vbus_Update + Current_Cal / 快速保护
      HIL相电流观察（HIL构建）
      Encoder_Update：同步SPI等待 + LUT + 角度 + 分频测速
      HIL邮箱/命令派发（隔周期）
      Fluxobserver_Update（模式3跳过；其他模式仍执行）
      编码器离线、配置有效性检查
      模式分派
        模式3：构造配置 → PositionCascade_Update
          每周期检查配置、目标变化和分频
          每10周期：轨迹 + 摩擦/保持逻辑 + 位置/速度控制
        FOC_Current
          Clarke/Park → dq PI → 电压限幅/抗饱和回算
          逆Park（含速度角度补偿）→ SVPWM → CCR1/2/3
      模式/故障变化、功率级启停、状态发布
      RTT采样、编码和非阻塞写入（错峰2 kHz）
  → HAL清完成标志 → IRQ统计 → 异常返回
```

入口见 `Core/Src/stm32g4xx_it.c`，调度见 `Foc/foc_task.c`，模式3适配器见 `Foc/foc_run.c::Task_Position_Mode`，算法见 `Foc/foc_algorithm.c::FOC_Current`。

### 采样事件与PWM截止时间

原 `System/board_config.c` 启用ADC2的JEOC，而ADC2配置4个注入rank。JEOC代表单个rank完成，JEOS才代表整个序列完成。中断/HAL开销可能使后续转换在读数据前恰好完成，也可能合并事件；既不能断言必然80 kHz，也不能证明整组数据一致。**优化减少入口耗时后，更可能暴露此前被延迟掩盖的采样竞态。**

本轮先改成JEOS，并在回调再次检查序列完成标志；保留HAL的事件/错误分派与清标志行为。

配置ADC时钟为170 MHz/4 = 42.5 MHz；前三个rank采样6.5周期，第四个12.5周期。按12位转换12.5周期估算，序列转换成本为 `(3×19 + 25)/42.5 ≈ 1.93 μs`，未计触发同步、模拟建立等额外延迟。这是配置推算，不是实测。

TIM1配置中心对齐、ARR=4250、CCR4=4240、RCR=0。中心对齐下更新事件与半周期相关，CCR预装载不能简单理解为“50 μs内任意写入都一样”。采样位于计数顶点附近；若目标是在紧接的下一个有效半周期更新点生效，可用计算时间可能只有约23 μs量级。**具体触发边沿、实际UEV和三相CCR生效时刻必须示波器验证**，不能据此直接给出已确认的deadline或改变RCR。

硬件语义参考：[ST RM0440：ADC和高级定时器章节](https://www.st.com/resource/en/reference_manual/rm0440-stm32g4-series-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)。本仓库HAL在注入回调返回后清JEOC/JEOS，参见 `Drivers/STM32G4xx_HAL_Driver/Src/stm32g4xx_hal_adc.c`。

## 3. 热点与优化优先级

以下按源码可见成本和风险排序；没有分段实测，不将此表当作已测耗时排名。

| 优先级 | 问题/可确认成本 | 方案与约束 |
|---|---|---|
| P0，本轮已改 | 四rank使用JEOC，无完整采样保证 | 改JEOS并防御性检查回调；上板验证每PWM周期一次控制、数据同期 |
| P0，需测量 | 只量IRQ函数内部，未确认PWM deadline | 记录入口间隔、采样序号和PWM提交时刻；示波器同时看触发、IRQ、PWM |
| P1 | SPI2分频32，同步传输两个16-bit字且忙等 | 若SPI时钟为170 MHz/32，32bit线速时间约6.02 μs，占周期12.05%，另有CS/周转/处理成本。优先考虑提前启动异步事务、在快环取完成帧；必须保留时间戳/序号、坏帧处理并补偿采样年龄。不能仅把SPI频率翻倍或直接降采样率 |
| P1 | `Task_Position_Mode`每20 kHz构造整份配置，核心分频前还做memcmp/有效性及目标检查 | 改成模块拥有经验证的配置快照；参数改变时验证并发布版本，快环检查版本、目标和安全边界，完整2 kHz计算按原相位执行。不要仅将分频判断提前，漏掉当前周期非法参数/目标变化处理 |
| P1 | RTT虽然不阻塞，但编码、浮点缩放、复制仍在最高优先级ISR | 快环仅发布有界快照，主循环或低优先级服务编码发送；先落实发布/消费一致性和RAM预算。保持丢帧可见，不在ISR等待读端 |
| P1，本轮已改 | `fast_sqrt`通过位重解释和两轮Newton迭代使用两次浮点除法 | 保留原小值截止，使用标准C `sqrtf`；本目标反汇编确认VSQRT.F32，移植目标由编译器实现 |
| P2 | HAL通用ADC分派成本 | 先分段测量占比，再在HAL Port实现直接事件处理，保持所有已启用错误事件语义；不能在FOC中引入ADC寄存器 |
| P2 | 编码器有界spin的实际时长随编译变化，失败路径可能更慢 | 在sensor_bus的Port中实现以时间为界的超时，测正常/超时路径。340次循环不能直接解释为340 cycles |
| P2 | 非模式3仍每周期执行无感观测器 | 按控制模式真正依赖梳理；有些标定和无感切换需要预热，不能简单“有编码器就关闭” |
| P2 | Park与逆Park分别求sin/cos | 可以优化配对计算，但电流环逆Park角是 `phase + phase_vel*Ts`，**不能直接复用前一个角的sin/cos而删掉相位补偿** |

快环、编码器、utils、位置/轨迹等主要文件已有单文件高优化等级与速度优化设置；普通工程使用ARMCC 5.06u7、Cortex-M4单精度FPU。不要再将“开启O2/O3”当作主要尚未实施的收益。也不建议用全局激进浮点选项换速度而破坏finite检查。

推荐性能目标：在确认PWM生效点后，先保证采样完成至PWM提交小于真实deadline并有明确余量；整IRQ含异常成本建议以不超过35 μs作为第一阶段工程目标，进一步向25～30 μs优化。它们是待验证目标，不能覆盖更短的PWM提交deadline。

## 4. 本轮落地与计时口径

1. `System/board_config.c`：关闭JEOC，启用JEOS；不改ADC采样时间、PWM频率和硬件参数。
2. `Core/Src/stm32g4xx_it.c`：注入回调仅在ADC2整序列完成时进入FOC；保留原IRQ派发，新增HIL内部计时总和、计数、最短区间和入口间隔范围。
3. `System/utils.c`：`fast_sqrt`保留 `<1.19209290e-7f` 返回0的原有行为，改用sqrtf。去掉float/long别名访问及32位long假设。正无穷现在按sqrtf返回正无穷；不把这当作非法输入保护的替代。
4. 测试覆盖实际启动函数的中断选择、实际ADC回调对不完整序列的拒绝，以及实际sqrt函数的数值范围。

没有修改既有控制增益、保护阈值、轨迹时序、编码器协议、采样频率或Flash数据布局。

新增HIL符号（均为IRQ文件私有static，不向控制算法暴露DWT）：

- `hil_profile_total_cycles`：64位累计测量区间cycles。
- `hil_profile_count`：该累计对应的IRQ数量。
- `hil_profile_min_cycles`：最短测量区间。
- `hil_profile_interval_min_cycles/max_cycles`：相邻IRQ入口间隔范围。
- 原 `hil_irq_last_cycles/max_cycles/histogram` 保持原名称与四档格式。

同一测量窗口：`平均区间μs = Δtotal_cycles / Δcount / 170`。入口间隔范围可揭示重复事件或延迟，但受屏蔽中断、调试暂停和故障影响，不能自动归因为“丢PWM周期”。原主机工具清零旧统计不会清零新增累计；应使用两次一致快照之差。64位读不是原子的，需在安全停用/暂停状态取一致快照，或在主机增加序列一致性读取；跨调试暂停的interval结果无效，应开启新统计窗口。count约59.6小时回绕，测试窗口应远短于此。

计时仍不包含C函数入口前的异常进入、全部编译器序言、最后统计和异常退出。新增入口间隔统计本身在被测区间内，也增加调试成本；对比必须使用同样的插桩。它不能证明完整WCET，更不包含完整采样到PWM输出延迟。

## 5. 仓库与架构边界摘要

本轮扫描确认：

- 工程目标：普通APP `MDK-ARM/Vector_Mini_ST.uvprojx` 与HIL调试APP `Vector_Mini_ST_HIL.uvprojx`，共享核心。没有发现独立Loader target和PRODUCT/FACTORY/DEBUG正式三variant构建体系。
- APP入口：`Core/Src/main.c`，初始化 → Board_Init → 主循环USB/CAN发送和参数保存。20 kHz/1 kHz分别来自ADC/TIM7中断。
- IRQ：ADC1_2、FDCAN1_IT0、TIM7、USB_HP/LP、DMA1_Channel1、SysTick及内核异常。ADC优先级0，CAN1，TIM7为3；仍须检查全局关中断窗口和最坏异常路径。
- CubeMX：根目录 `Vector_Mini_ST.ioc`，生成代码 `Core/`；SDK在 `Drivers/CMSIS`、`Drivers/STM32G4xx_HAL_Driver`，USB等中间件在 `Middlewares/`。
- BSP/设备：`Bsp/`混合板级资源、TLE5012B协议/采样、Flash、LED/RGB；`System/board_config.c`混合启动适配。未发现独立多PCB构建矩阵。
- 全局状态：`MotorControl`、`FOC`、`PI_Speed`、`OnBoard_Encoder`、`Fluxobserver`、`SensorlessStartup`、模式/错误历史仍跨模块共享；位置控制器已有私有static状态。
- 通信：`Communication/interface_can.c`、`interface_usb.c`与环形缓冲，尚非独立transport/protocol/command-router体系。
- NVM：`Bsp/flash.h`保存页地址，参数从page56开始，主循环关中断写参数。未建立目标架构要求的统一flash_layout与独立Loader升级链。

主要已有耦合：FOC直接写TIM1、sensing直接读ADC、encoder同时处理SPI/GPIO寄存器和传感器协议。建议迁移方向：FOC纯算法→`software/motor`；同步采样/PWM→`hal/api/motor_hw`及对应Port；TLE5012B协议→`software/drivers/encoder`，总线→`sensor_bus`；板资源→BSP；DWT→`time_hw`对应Port/Profiler。

第一步推荐小范围建立“完整采样→计算→一致提交PWM”的motor_hw契约，再迁移硬件实现；不是一次性重排整个仓库。本轮没有新增跨模块全局状态，也没有将新的DWT/ADC对象放入算法。

另外，过压确认计数每次超限路径又清零、功率级Break/死区配置等既有风险应专项核查；这次耗时优化和主机测试不代表完整安全验收。
