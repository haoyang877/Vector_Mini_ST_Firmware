## 批准的状态关系

| 当前关系 | 本批关系 |
| --- | --- |
| INIT／IDLE 的 STOP 可能进入 STOPPING、推进代际并重置控制 | 主状态保持，仅撤销排队请求；通信 STOP 序号屏障保持；没有活动控制便不做控制器复位 |
| STOPPING 按 tested 返回 IDLE／INIT | 只有 STARTING、RUNNING、MAINTENANCE 进入 STOPPING；停止完成仅返回 IDLE，故障仍进 FAULT |
| FAULT 清错后重新 INIT | 保留现有显式 CLEAR 入口；源恢复、基础健康、输出关闭及取消完成均确认后直接 IDLE，不重新初始化或恢复旧目标 |
| 图中 FATAL→INIT 复位箭头 | FATAL 没有普通软件出口；整程序复位后从程序入口构造 INIT，图中不画 FATAL→INIT 状态迁移 |

STOPPING 自身执行关相、撤销及取消收尾；下一拍需要等待的是实际取消／保存工作归还，
不再由图中文字形成额外状态。保留真实数字输出回读与借用结束确认，不能提前复用内存。
STARTING→RUNNING 保留控制准备及实际输出开启确认，图中直接写“准备完成、输出已开启”。
去掉“实际静默模式”和“全局出口”框，各状态的故障去向直接标明。

## 保持行为和简化

删除 tested、返回 INIT 的分支、enter_initialization 及 SELF_TEST 重启动作。
就绪资格由当前已完成初始化的状态与本次健康事实推导；CLEAR 在 FAULT 内核对八项
基础健康和既有源恢复条件后直达 IDLE。INIT 只在整程序初始化时建立，原零点与期限保持。
不加恢复等待布尔、第二状态机、框架或旧头。任务与 SAVE 仍独立票据及结果，
维持原自动保存种类、迟到结果／实际提交效果、STOP 屏障、参数与载荷 ABI、算法、
保护阈值、快慢环顺序、Loader 接入和数字输出验证。

源码只在独立托管专项树修改；其他任务差异保持未提交，不整文件提交导入功能。
本批不操作硬件，不构建 MCU／烧录／写参数。停止／取消等待没有新超时或自动续试。
