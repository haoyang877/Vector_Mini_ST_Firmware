## 定位与修复

关相只读查询 Type1/2/108/127，同时读取板端收发队列和 CAN 控制器状态。原时序
两轮1000查询分别13、14次失败；每次板端 RX/TX计数均增加1，软件队列没有丢弃，
但硬件发送终态为 `CAN_TSTAT_DISTURBED`，`KOER=BIT`，等待额外150 ms仍无对应回复。
TX ID、格式、DLC与回复内容也核对过。证据指向发送位错误，而非身份查询未执行或
主机仅仅需要等待更久。

| 临时对照 | 查询数 | 未按时正常应答 |
| --- | --- | --- |
| 仲裁75%、数据75%、SSP28，原设置两轮 | 各1000 | 13、14 |
| 只改SSP18 | 1000 | 17 |
| 仲裁80%、数据75%、SSP28 | 1000 | 0 |
| 同一修正再次验证 | 5000 | 0，最长4.42 ms |
| 恢复原设置，从正常错误计数重新验证 | 1000 | 22 |

另外做过两段均80%的对照，1000次零超时；仅数据段80%、仲裁75%的负对照明显恶化，
因总线错误/error-passive中止，不采用。其他回退恢复阶段的错误记录亦保留，不能与
初始错误计数正常的基线混合统计。最终只修改默认档仲裁段，数据段和SSP保留原值。
这些对照支持本台架的仲裁时序互通问题，未用示波器直接测量具体出错边沿。

APP与Loader共用 `shared/targets/at32f456_can_timing.h`：默认1M/5M的仲裁段从
135+45 TQ（75%）改为144+36 TQ（80%），数据27+9 TQ（75%）、SSP28、分频1不变。
对应 ACTIME=`0x2323008E`、FDTIME=`0x08080019`、LBTCFG时序域=`0x00001C00`。
其他11档、控制器一次自动重传限制、应用重试、50 ms期限及超时失败统计均不变。
协议帧、Type127 v2、layout7、schema14与参数ABI均不变；黄金寄存器向量同步更新。
旧Loader仍使用旧时序，需要用配套FULL同步更新两镜像。
