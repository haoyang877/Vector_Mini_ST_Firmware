## 当前规则

普通 APP 和 Loader 配套 APP 均使用以下八组，只登记实际编译源文件：

| 分组 | 内容 |
| --- | --- |
| `00_App` | 启动组合、运行所有者、状态机、执行、维护、调度和 APP 适配 |
| `10_Motor` | FOC、位置/轨迹、标定/辨识、保护 |
| `20_Services` | 生命周期纯核心、停止服务、参数和遥测快照 |
| `30_Communication` | CAN 接入、端点、协议路由、业务载荷与通信适配 |
| `40_Platform` | BSP、ports、CubeMX main/中断/外设初始化和启动汇编 |
| `50_Shared` | 共用协议/校验；配套 APP 的 RAM 邮箱和 APP 描述符也在本组 |
| `60_Common` | 内存池、CRC、基础计算 |
| `90_Vendor` | HAL、CMSIS 系统初始化与第三方 RTT |

所有 `.h` 仅从工程树和 `.uvoptx` 树缓存移除，不删除磁盘文件、不改 include 路径。
原 `.c/.s` 文件节点整体保留，包括相对路径、逐文件优化和其他编译设置。
组内保留 v1 源文件的相对次序；合并 Platform/Vendor 后，跨组工程遍历次序会改变，
不承诺二进制地址或资源数字完全相同。

主工程树缓存重新编号，保留现有编译文件记录和目标调试设置；默认只展开 APP。
在途 CRC 源已从 common 迁至 shared，其工程源路径保持，树缓存同步该路径。
Loader 配套生成器继承普通工程八组，在现有 `50_Shared` 添加两份启动源码，
不再生成独立启动组或头文件导航项。现有配套工程只整理文件组，不重建目标设置。
