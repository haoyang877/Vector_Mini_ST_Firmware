# Loader 与参数存储优化计划 v1

日期：2026-10-20。基线：`b5c5a36d`。开发分支：`codex/loader-storage-optimize`。

用户明确要求参数保持单份，不增加双备份。本次保留 Flash 分区地址、电机控制行为、
停机检查和升级确认机制，优化参数占位、旧参数兼容与测量方式。

## 实施与验收

1. 参数 schema14 删除已退役的齿槽表，记录从 4352 字节降为 2288 字节；
   基础字段偏移不变。APP 只读兼容 schema12/13，保存时写 schema14。
   schema10 必须显式离线迁移，校验原始快照 SHA256、字段及旧扩展 CRC；不自动写板。
2. 新增保留标定的离线迁移；原清标定命令继续明确清除标定。
   身份页及参数记录之外的字节不得被转换工具改变。
3. 升级客户端分别记录发送、等待回复、重试及阶段耗时。
   先前 20 次升级含逐帧 J-Link 检查，不能作为纯 CAN 下载速度。
4. 检查 Loader 启动和库占用，只有构建数据证明有效的缩减才保留；
   不盲目压缩栈，不删除校验、安全停机或回退逻辑。

验收覆盖旧新布局黄金向量、短记录/损坏 CRC/未知版本拒绝、配置与标定保持、
身份页不变、客户端丢包重试、独立 APP/Loader 构建及 release 验证。
新增 ABI 使用 APP 1.5.0 / Loader 2.1.0 配套包，旧包不假定与新 Loader 通用。

## 边界与回滚

参数只有一份：保存中掉电可能使参数无效，下次启动回退未确认默认配置，必须重写或恢复快照。
这不提供参数自动恢复，也不增加固件 A/B。保持原始快照；回滚旧固件前恢复其匹配参数。
不改动主线其他会话未提交的配置工作。新包离线验收与实机验收分别报告；
旧版本 20 次成功不能证明新版本已经实测。完成后记录实际资源与验证路径。
