# APP 与 Loader 参数管理设计

本页原名《参数所有权与四类配置》。最初版本（2026-09-29，`f6fadad4`）说明硬件、电机、应用和设备参数分别由谁维护，当时的持久格式是 schema12。重构前的版本（`48b127dd`）已改用 schema14，仍把 2288 B 写作固定存储长度。当前这 2288 B 是整轴记录的基础段，输出轴标定另占一个扩展段。历史格式见 [OEN1](../protocols/output_encoder_v1.md)、[OEN2](../protocols/output_encoder_v2.md) 和 [OEN3](../protocols/output_encoder_v3.md)。

当前设计按 `the-system-refactor` 核对，PITCH/YAW 的减速比取提交 `a87bc5ce` 的 40:1 配置。APP 从 Flash 恢复每轴配置，在角度标定结束后自动保存；CAN 命令 120/121/122 读取、修改和保存标量参数，190–193 处理型号配置事务。Loader 独立读取节点，CAN 升级的写入范围限于 APP 镜像槽。

## 参数来源与活动对象

| 类别 | 默认来源 | 活动对象 |
| --- | --- | --- |
| 硬件 | config/board_config.h | 编译期常量，不开放在线写入 |
| 电机 | config/motor_profile_config.h | MotorConfiguration.model：极对数、R/L、磁链、PI、标定电流和热参数 |
| 应用 | config/application_config.h | MotorConfiguration.application：电流/速度包络、外环、前馈和轴记录 |
| 设备 | config/application_config.h 与本次采样 | MotorConfiguration.device：节点、零偏、编码器方向/LUT/零位 |

路径相对 firmware。STM32 使用编译期模型默认值；AT32 产品轴按有效记录的节点及 AXS2 修订 2 匹配已登记的轴预设。[板型与电机配置](../../firmware/config/README.md)

## 所有权与提交

### 以一根 AT32 轴为例：从工装输入到控制限值

轴记录经过三种表示。工装输入可以使用输出轴角度或速度；`InterfaceParam` 以固定 ABI 写入基础记录；`MotorConfiguration` 是本次上电最终供控制器读取的活动配置。数值相同的字段也可能具有不同来源，特别是输出轴单位、记录单位及预设上限。

| 步骤 | 执行者 | 数据如何变化 |
| --- | --- | --- |
| 选定装配对象 | 工装按 node 查 `MotorAxisPreset` | 当前工作树节点 3/4 为左右轮、5 为 ROLL、6 为 PITCH、7 为 YAW。节点决定核对哪套预设，记录还须匹配 AXS2 轴角色和电气模型。 |
| 填写限值 | `make_axis_record` → `Param_CreateAxis` | 若输入选择输出轴单位，工具先乘减速比，换为电机轴单位。创建关节行程、速度包络，检查热参数，再约束最大电流与前馈电流。 |
| 生成可装载记录 | 工装 → `Param_Upload` → `Param_Download` | 工具编码一份 2288 B 基础记录，按固件路径重新解码，核对预设、节点与确认位，再输出文件。首次工装记录可以没有 OEN3；完整整轴记录由后续标定保存形成。 |
| 恢复运行配置 | 板端 `MotorAxis_Init` → `Param_Download` | 校验基础字段，将目标轴预设和持久字段装配为活动配置，再尝试恢复输出扩展。本次电流零偏仍从上电采样建立。 |

例如 PITCH 的减速比为 40:1。工装选输出轴单位并给出 1 rad/s 时，向 `Param_CreateAxis` 传入的是 40 rad/s 电机轴限值。这个数值需通过预设上限检查。协议 116 的速度目标使用电机轴 mrad/s；要请求同一个速度，载荷字段应为 40000。位置方向和输出零位的恢复另由 OEN3 处理。此例用于核对单位换算和限制来源，不代表一次运动请求已经获准。[工装转换](../../tools/build/make_axis_record.c) · [预设与物理包络](../../firmware/parameters/motor_axis_profile.c) · [116 线路单位](../protocols/README.md#control)

### 运行时的读写权限

MotorAxis 单份持有配置和运行对象。生命周期借用配置只读视图与运行状态，
控制算法显式接收配置及输出对象；通信仅调用绑定服务，不取得可写对象地址。
Watch 全局符号只用于观测，不构成跨模块写接口。

- 启动：BspFlash_Read → Param_Download；记录无效则 Param_Return_Default。
- 存储：基础参数和输出轴扩展分别校验 CRC，输出轴扩展还绑定基础记录 CRC。两者共用本轴 `record`，启动装载与停机写入串行复用。
- 零偏：在关相 IDLE 累计本次启动的样本，再发布有效偏置。
- 编码器：转子 LUT/零位位于 `configuration.device.encoder`；输出轴相位及 Hall 修正表各归本轴对应的反馈对象。
- 标定：ADC 安装前台登记的有效 LUT；前台在最终提交前复核会话及数字关相，再调用绑定的写记录函数。结果依赖 BSP 写入和回读。[标定发布](../../firmware/app/motor_calibration.c)

参数候选与LUT标定互斥复用6144字节工作区，候选不占用大型自动栈对象。

## 合法性与硬件边界

参数层校验类型、范围、轴记录、热参数和前馈参数；配置有效不等于已经确认或完成标定。
配置确认、实时采样、母线电压、编码器和故障条件共同参与生命周期准入。
热模型参数仍参与配置校验，运行中未接入绕组热降额调度。

固定区域实际字节读写归 BspFlash。写入要求前台和真实关相，由 BSP 协调采样暂停、
擦写及回读；失败保持关相并报告存储故障。CRC 编码允许中断，Flash 写入处于
会话复核后的临界区内，防止 STOP 与保存交错。
Loader 的参数读取与镜像产品保持独立，不能因 APP 内部结构整理改变共享存储 ABI。

## 整轴参数在 Flash 中的布局

**一次保存写入一份 `MotorAxisRecord`，其中两段数据分别标记自己的格式版本。** 前缀 `motor` 使用 **schema14**，保存电机与应用参数、转子编码器标定和 Hall 幅值/偏置等。紧随其后的 `output` 当前使用 **OEN3**，保存输出轴与电机轴的对应关系，以及一圈 1024 点的 Hall 角度修正表。固件从前缀的 `schema_version` 读取 14，从扩展开头的四个 ASCII 字节读取 `OEN3`。因此，同一份 schema14 基础记录也可以搭配兼容的旧版 OEN1 或 OEN2 扩展。[记录结构与版本识别](../../firmware/parameters/parameter_record.c)

STM32G431 与 AT32F456 的参数区均从 `0x0801C000` 开始，每个擦除页为 2048 B。图中左列是页首的绝对地址，块内数字是实际字节数，宽度未按比例绘制。

```text
Flash 地址    页内布局（地址向下递增）
0x0801C000    ┌─ 第 1 页  schema14 前 2048 B，整轴记录从此开始
0x0801C800    ├─ 第 2 页  schema14 末 240 B
              │           └─ 0x0801C8F0 起为 OEN3 前 1808 B
0x0801D000    ├─ 第 3 页  OEN3 末 276 B，最后一个记录字节在 0x0801D113
              │           └─ 0x0801D114 起为页内余量 1772 B
0x0801D800    ├─ 后续 4 页  参数区余量 8192 B
0x0801F800    ├─ 独立生产身份页 2048 B，保存 SN、电机类型等
0x08020000    └─ 分区结束（此地址不在分区内）
```

**整轴记录共 4372 B，其中 schema14 占 2288 B，OEN3 占 2084 B。** 保存需要擦写时覆盖前三页，第 3 页末尾的 1772 B 会随该页一起擦除。生产身份页位于单独的擦除页。两板分区见 [G431 目标清单](../../shared/targets/vector_mini_st_g431.json)和 [AT32 目标清单](../../shared/targets/yg_esc_v1_at32f456.json)。

| 相对记录起点的偏移（十进制，含两端） | 大小 | 内容 |
| --- | ---: | --- |
| 0–35 | 36 B | 节点、三相电流偏置及电机模型。节点以小端 float32 存储，APP 装载时检查是否为合法整数节点 |
| 36–43 | 8 B | 转子电零位、机械零位、标定标志、方向和保留字节 |
| 44–2091 | 2048 B | **转子编码器**线性化表，1024 个 int16，用于校正电机轴角度 |
| 2092–2135 | 44 B | 电流环 PI、速度及位置环整定和限值 |
| 2136–2167 | 32 B | 配置确认、基础 CRC、标定与运行限值、保留槽。CRC 在 2140–2143，schema 在 2160–2163，magic 在 2164–2167 |
| 2168–2207 | 40 B | 兼容槽、采样分流值和位置串级增益；2188–2207 保存 Hall 正余弦偏置、幅值与状态 |
| 2208–2239 | 32 B | 轴配置记录（AXS），AT32 产品轴装载时检查身份和行程等字段 |
| 2240–2287 | 48 B | 绕组热模型参数与速度前馈配置，至此结束 schema14 基础段 |
| 2288–2291 | 4 B | OEN3 版本标记，Flash 字节为 `4F 45 4E 33` |
| 2292–2295 | 4 B | `motor_crc32`，保存同次基础记录的 `record_crc32` |
| 2296–2315 | 20 B | 输出轴减速比、相位、机械零位、方向和状态 |
| 2316–2319 | 4 B | Hall 修正表的标定状态 |
| 2320–4367 | 2048 B | **输出轴 Hall** 角度修正表，1024 个 int16，在幅值与偏置归一化后校正输出轴单圈角 |
| 4368–4371 | 4 B | OEN3 自身的 CRC32 |

读取时先校验基础记录。其 CRC32 覆盖偏移 0–2287，跳过存放 CRC 的四个字节。基础记录通过后，再校验 OEN3：扩展 CRC32 覆盖偏移 2288–4367，且 `motor_crc32` 必须等于刚验证的基础 CRC。这样，即使一段旧 OEN3 自身完整，只要基础参数已经改变、两份 CRC 不匹配，APP 也会保留已装载的基础参数，跳过旧输出轴关系。基础记录本身无效时，APP 回退到默认配置并跳过扩展恢复。[基础存储契约](../../firmware/parameters/README.md#storage) · [OEN3 字段与兼容规则](../protocols/output_encoder_v3.md)

## 旧记录如何恢复

读取时先按 schema14 校验前 2288 B，再看偏移 2288 处的四个字节，按扩展版本选择长度和 CRC 位置。基础段内的转子线性化表与扩展段内的 Hall 修正表属于不同传感器；从 OEN2 升到 OEN3，改变的是后者的采样点数。

| 扩展标记 | 扩展 / 整轴长度 | 扩展 CRC 的整轴偏移 | 当前 APP 如何恢复 |
| --- | --- | ---: | --- |
| 无可识别标记 | 有效基础段 2288 B | — | 保留有效基础配置和输出轴初始化结果。直驱轴可从有效的基础机械零位初始化输出零位。 |
| OEN1 | 32 / 2320 B | 2316 | 恢复减速比、方向、相位和零位；Hall 修正表置零。 |
| OEN2 | 292 / 2580 B | 2576 | 有效成功表在 RAM 中从 128 点周期插值到 1024 点，包含末点回到首点的区间。 |
| OEN3 | 2084 / 4372 B | 4368 | 成功表校验后按原 1024 点恢复。当前保存路径统一生成此格式。 |

上电读取旧格式只恢复 RAM。下一次实际完成标定保存时，`Param_StoreOutputEncoder` 生成 OEN3。零位、方向和相位依赖实际传动关系；如果减速比与当前轴不同，即使 CRC 正确也会拒绝恢复。[轴初始化](../../firmware/app/motor_axis.c) · [版本识别与兼容读取](../../firmware/parameters/parameter_record.c)

### 从 Flash 转储判读一次 OEN3

以仓库的 OEN3 黄金向量为例。下表地址从参数区基址换算，每行字节按 Flash 地址升序排列。向量只包含扩展段，基础 CRC 是测试桩提供的绑定值。[黄金向量](../../tests/fixtures/protocol/output_encoder_v3.json)

| Flash 地址 | 样例字节 | 解码结果 |
| --- | --- | --- |
| `0x0801C8F0` | `4F 45 4E 33` | ASCII 为 OEN3，按 2084 B 读取扩展 |
| `0x0801C8F4` | `78 56 34 12` | 期望的基础 CRC 为 `0x12345678`。在真实转储中应与地址 `0x0801C85C` 处已校验的基础 CRC 相等 |
| `0x0801C8F8` | `00 00 00 41` | 小端 float32 为 8.0，即样例减速比为 8:1 |
| `0x0801C8FC` | `00 00 80 3E` | 电机轴相位偏移 +0.25 rad |
| `0x0801C900` | `00 00 C0 3F` | 输出轴机械零位 +1.5 rad |
| `0x0801C904` | `FF FF FF FF` | int32 为 −1，输出方向反向 |
| `0x0801D110` | `79 56 B6 98` | 扩展 CRC 为 `0x98B65679`；对扩展头到 LUT 末字节重算得到同一值 |

**为什么读出了 OEN3，仍然恢复不了输出轴位置？** 假设传动已从 8:1 改为 40:1。当前 PITCH/YAW 按 40:1 初始化，而样例保存的是 8:1。即使基础段有效、绑定正确且扩展 CRC 通过，`gear_ratio == encoder->params.gear_ratio` 仍会失败。基础参数继续生效，旧输出相位与零位不装载。即使有效扩展恢复成功，首次取得输出位置还需等待合格采样并完成定位，随后才置 `ready`。[恢复检查](../../firmware/parameters/parameter_record.c) · [输出轴定位](../../firmware/motor/feedback/output_encoder.c)

## 上电恢复与失败处理

检查 `g_app.axis.configuration` 时，应同时读取 `configuration_source`、`configuration_confirmed` 和 `application.axis_profile_valid`。来源说明哪条装载路径产生了活动对象，确认位说明保存的配置是否仍适用于当前采样比例，轴配置有效性参与运动准入。单看记录 CRC 或来源字段无法判断是否能启相。

| 装载时读到的事实 | `Param_Download` 的处理 | 调试时优先核对 |
| --- | --- | --- |
| magic 和 schema 都是擦除值 | 返回默认配置，来源为 DEFAULTS | 参数区是否为空。另有硬件读取失败路径也会调用 `Param_Return_Default`，看到 DEFAULTS 时仍须区分读取结果。 |
| magic/schema 不匹配且非空；或 AT32 预设、轴角色、电气模型不匹配 | 回退默认值并标记 UNSUPPORTED | 固件和记录是否配套，节点、AXS2 修订、极对数、R/L 与磁链是否匹配。 |
| 长度或基础 CRC 错；节点非法；最终配置校验失败 | 回退默认值并标记 CORRUPT | 先验证基础段，再核对字段合法性。此时没有持久基础配置可供 OEN 扩展绑定。 |
| 基础记录与轴匹配，但采样分流值已变 | 标定电流和活动电流限值按当前配置重新取值，再受预设上限约束。若最终配置合法，来源仍可为 STORED，确认位置为 false | 比较记录的 `current_sense_shunt_milliohm` 和板级分流值。旧模型确认不能直接授权变更后的电流尺度。 |

两板的空白板表现不同：G431 默认采用配置的节点 1；AT32 产品 APP 的默认节点为 UINT8_MAX，轴配置无效，通信端点会拒绝注册该广播地址。Loader 则可以使用救援节点，按它自己的规则读取参数。因而“Loader 可发现但 APP 无有效产品节点”与“CAN 物理链路失效”需要分开诊断。[装载与默认行为](../../firmware/parameters/parameter_record.c) · [协议初始化](../../firmware/communication/yg_protocol.c)

| 记录或输入 | APP 的处理 | 生效范围 |
| --- | --- | --- |
| 基础参数 | `MotorAxis_Init` 读取整轴记录，`Param_Download` 校验 schema14、magic、CRC、节点和字段；AT32 产品轴还要核对预设与 AXS2 身份 | 装载有效活动配置。读取失败或基础记录被拒绝时应用默认配置，运行准入仍按本轴条件判断。 |
| Hall 与输出轴扩展 | 基础记录成功装载后，按本轴预设恢复 Hall 系数，并尝试恢复输出轴扩展；检查扩展版本、CRC、与基础记录的绑定及值域 | 接受兼容的 OEN1/OEN2/OEN3。无效扩展保留初始化所得的输出轴状态，基础记录单独生效。 |
| 电流偏置 | 每次上电重新在关相 IDLE 采样；保存的兼容字段不能授予本次控制资格 | 供当前上电周期的电流测量与准入使用。 |
| CAN 节点 | Loader 独立检查参数区是否可读、记录外形和节点编码，识别失败沿用救援节点 | 该检查不执行 APP 的整记录 CRC。G431 的坏 CRC 记录可能导致 APP 回退到节点 1，交接后 Loader 仍使用记录中的节点。 |

装载顺序见[轴初始化](../../firmware/app/motor_axis.c)，兼容条件见[记录解码](../../firmware/parameters/parameter_record.c)，Loader 节点策略见[参数只读识别](../../loader/product/parameters.c)。

## 标定保存与掉电边界

1. ADC 完成标定任务、关相并读回。需要安装转子 LUT 时，前台登记原会话，ADC 在读角前复核并安装。带 Hall 的联合标定可在原会话继续电零位。
2. 前台先调用 `Param_Upload` 编码基础记录。带 Hall 的轴再由 `Param_StoreLinearHall` 写入本次幅值、偏置和状态，并更新基础 CRC。最后 `Param_StoreOutputEncoder` 复制此时的基础 CRC，写入输出轴关系及 Hall 表，再计算扩展 CRC。这一顺序把同次保存的两段数据绑定起来。
3. 最终提交检查 `epoch`、标定类型、STOP、故障及实际关相；中途取消的候选不写入。完整扫圈但 Hall 不合格时保留诊断结果，随后报告相应故障。
4. BSP 擦写并回读。正常标定在保存成功后通知状态机收尾，写入失败锁存存储故障。Flash 为单份轴记录，写入期间掉电可能使下次装载时 CRC 失效。

PI 积分、当前目标与故障状态留在 RAM。保存与回读行为见[标定保存用例](../../tests/unit/native/test_calibration_save.py)。

## 参数设计变更的验收条件

### CAN 型号配置保存（v1）

AppMotorConfiguration 在前台拥有待重启配置，与活动 MotorAxis.configuration 分离；
新型号通过 Param_CreateAxis 生成，沿用 schema14/AXS2，不从生产身份 motor_type 推导。
型号与节点配对、热参数、修订、IDLE 和近零速通过后，状态机永久锁定本次上电的启动/标定。
随后复用轴记录编码并清除转子、Hall 和输出轴标定，BSP 仅写参数区并回读核对。
活动配置直到软件复位仍保持旧值；保存失败保持锁定，显式重启只接受已验证保存的修订。
Flash 仍是单份记录，掉电不承诺回滚；新配置生效后必须重新标定。
命令和缩放以[型号配置协议](../protocols/README.md#parameters)为准。

后续若调整记录布局、轴预设或恢复策略，先在本页提出变更场景。例如“同一固件要接收此前保存的 8:1 记录，但设备已换为 40:1 传动”。先确定旧基础参数、Hall 系数、相位、机械零位各自应保留还是失效，以及何时允许再次出力，再选择版本号、字段和实现。下表是当前行为的比对基线。

| 输入或事件 | 当前可验证的结果 |
| --- | --- |
| 工装输入输出轴速度 1 rad/s，选择 40:1 PITCH 预设 | 电机轴速度限值应为 40 rad/s。工装基础记录经固件解码后保持预设、节点与确认位一致。 |
| 基础记录 CRC 错，扩展自身 CRC 对 | APP 回退默认配置，跳过输出扩展恢复。Loader 确定 CAN 节点时使用独立的只读规则。 |
| 基础记录有效，扩展自身 CRC 对，但绑定值属于另一份基础记录 | 保留基础参数，输出轴维持初始化结果。 |
| 两个 CRC 和绑定均通过，Hall 表标为成功，但修正后相邻角度出现折返 | 拒绝该扩展。OEN3 须检查全部 1024 段，最后一段也要与第一个表项相接。 |
| 基础和扩展有效，传动比及字段合法 | 恢复输出关系。对减速轴，运行层还需用转子角和有效 Hall 角完成首次辨圈。 |
| 擦写过程中掉电 | 没有第二个可自动回滚的记录槽。重启分别检查基础和扩展，只恢复实际通过验证的部分。 |

读写兼容与输出轴定位可运行[两板输出轴原生测试](../../tests/unit/native/test_output_encoder.py)。若变更擦除页数或提交顺序，还应明确掉电时点、预期重启结果和对应的板级验证。
