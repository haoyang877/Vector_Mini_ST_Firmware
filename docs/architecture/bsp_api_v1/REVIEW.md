# BSP接口设计审核 2026-10-26

本报告正文记录修订前问题；修订2的处理对照见文末。当前契约见[入口](README.md)与[执行约定](EXECUTION.md)。

审核范围：本目录十个头文件、[总体设计](../bsp_interfaces_v1.md)、
[用户职责约定](../bsp_design_rules.md)，以及当前AT32F456/STM32G4实现和实际调用。
本次不修改接口签名、固件、工程、SDK或板上镜像。

结论：分层方向基本符合目标，尚不能冻结接口进入整批实现。发现5项P1设计缺陷和3项P2问题。
这些是待实现设计的缺陷，不能据此宣称当前运行固件出现了对应故障。
此前24组头文件编译及Doxygen检查只证明声明和包含关系合法，不能证明业务流程与安全等价。

## 目标符合情况

| 设计目标 | 判定 | 依据 |
| --- | --- | --- |
| 两板同一套公开功能契约，应用不见SDK/寄存器 | 基本满足 | 十个头文件不依赖厂商或板私有类型 |
| 时钟、外设初始化归BSP，应用只装配和调度 | 方向满足，流程待落实 | Init/Start存在，但分阶段标定与失败处理仍需接线图 |
| 按板配置资源和功能，不以文件是否存在表示能力 | 部分满足 | 沿用能力机制的方向正确，新增信号/颜色/通道配置尚未完整对应 |
| 采样/标定流程可完整迁移 | 不满足 | R1、R2、R3阻断现有数据和调用链 |
| 保留输出保护及存储失败语义 | 未闭合 | R4、R5缺少可执行的所有权与收尾约定 |

| 通信提供通用传输功能，协议在上层 | 部分满足 | R6仍把当前协议及消费方式写入通用接口 |

## R1 [P1] 母线电流标定缺少原码输入，流程无法闭合

位置：[bsp_adc.h](bsp_adc.h)，ReadRawCurrent、SetBusCurrentOffset、ReadChannel。

ReadRawCurrent只返回三相原码。ReadChannel(BUS_CURRENT)返回物理量，缺校准又必须返回
NOT_CALIBRATED。应用拥有母线电流零偏标定，却无接口取得用于计算零偏的原码；
SetBusCurrentOffset有写入入口但没有完整的输入链。

现有证据：firmware/app/runtime/bus_current_feedback.c:108读取辅助原码，随后检查轨限、
连续序号、128个样本和稳定窗口，再得到零偏。仅凭新接口无法保留这些检查。
MCU温度原码/VREF/VDDA诊断也未在新接口中明确迁移。

建议：增加一个按逻辑通道读取原码的窄接口，包含原码域、序号、时间和有效性；
或者明确保留必要的辅助原码快照。标定和滤波仍归应用，BSP负责采集与物理转换。
不得把标定偷偷塞回ADC模块或写死2048以绕开问题。

## R2 [P1] 电流未标定会同时屏蔽有效母线电压

位置：[bsp_adc.h](bsp_adc.h)，BspAdcFastSample与ReadFast。

ReadFast把三相电流和母线电压作为一次全量成功的输出；缺电流零偏返回NOT_CALIBRATED且
输出不变。辅助枚举又没有BUS_VOLTAGE，原码结构也无母线电压。
因此上电标定阶段无法只取得已经有效的母线电压；关闭相电流而保留电压的目标同样未定义。

现有证据：firmware/app/runtime/motor_axis.c:219先更新本拍母线电压和电压额度，
:223才采集/完成相电流零偏。firmware/motor/foc/foc_sensing.c:98的电压更新不依赖零偏完成。

建议：保留同拍快照，但用清晰的字段有效性表示“电压有效、电流待标定”；或提供从同一缓存
读取母线电压的独立入口。必须保持帧一致性，不能为拆接口触发第二次转换或伪造电流为0。

## R3 [P1] 零偏提交限定前台，与现有快中断标定不相容

位置：[bsp_adc.h](bsp_adc.h)，SetPhaseOffsets、SetBusCurrentOffset。

新契约规定仅前台调用；现有三相零偏在快中断完成，并在同一拍立即执行电流换算。
母线电流标定目前由2kHz监督路径推进。直接替换调用会违反上下文约束；改由前台提交则
新增交接延迟，应用的calibration.complete也可能先于BSP实际偏置生效。

现有证据：firmware/app/runtime/motor_axis.c:58-71、:223；
firmware/platform/bsp/mcu/at32f456/system.c的TMR6_DAC_GLOBAL_IRQHandler。

建议：只对“提交已计算偏置”允许受控的关相ISR短操作，或设计明确的前台交接和生效确认。
不增加隐式排队；应用标定完成、BSP偏置生效和第一帧有效电流必须同一个清楚的时序约定。

## R4 [P1] Flash中断所有权与时间保证不成立

位置：[bsp_flash.h](bsp_flash.h):34-36、[bsp_system.h](bsp_system.h):45；
总体设计4.8称不要求长临界区包住整个公共函数。

现有AT32写入明确要求PRIMASK非零，真实调用也将整个写入置于临界区内；新头文件只要求
前台/配置独占，同时公共临界区契约禁止包住Flash等待。尚未说明由谁接管完整写入期间的
中断屏蔽、采样暂停、看门狗预算和失败后的状态，按现有后端接线会直接拒绝写入。

两板Flash源码都说明同bank取指可能停止，循环次数上限不是墙钟期限；新注释却写
“可按原有界时限阻塞”，容易被当成不存在的最坏执行时间保证。源缓冲与擦除区域重叠时
如何拒绝也没有明确写入新契约，AT32当前有这项检查。

现有证据：firmware/app/runtime/motor_parameter_transaction.c:97-102；
firmware/platform/bsp/mcu/at32f456/flash.c:10-12、:69-78；
firmware/platform/bsp/mcu/stm32g4/flash.c:16-20。

建议：选定一个完整硬件操作所有者，明确进入/退出及失败锁存路径；首轮保留已验证的
屏蔽和采样恢复次序。不承诺墙钟上界，区分软件轮询上限和硬件复位兜底，明确源缓冲限制。

## R5 [P1] 功率窗口移到应用后，禁用事件与许可消费尚未闭合

位置：[bsp_pwm.h](bsp_pwm.h):65-75、总体设计7.3。

当前每次Enable都在共同入口检查窗口，每次Disable都会消费活动窗口。新契约只是要求
调用方先检查窗口，Disable没有定义如何通知应用消费窗口。硬件故障从BSP内部关相后，
应用窗口可能仍为ACTIVE；若未同步消耗许可，再次Enable就不能证明满足原不可复用规则。
这不是要求把测试策略永久放回BSP，而是现有设计缺少等价的事件和所有权约定。

现有证据：firmware/platform/bsp/bsp_pwm.c:14-35、:73-94；
firmware/app/runtime/pwm_power_window.c:49-54；
firmware/platform/bsp/mcu/at32f456/system.c:91-105还包含快拍到期关相和速度边界。

建议：明确唯一的应用功率准入所有者、所有启相路径、任何关相后的许可消费，以及BSP硬件
关断如何向该所有者可靠反馈；保持原快拍/毫秒双截止。补齐正常关闭、故障关闭、部分启相、
到期与重放请求的时序，再决定是否需要一个最小的状态/事件接口。

## R6 [P2] CAN把当前协议限制和中断消费方式固化进通用接口

位置：[bsp_can.h](bsp_can.h):68、:88。

当前发送契约要求扩展ID、FD、BRS，这是当前应用协议的选择，不应永远成为电机板BSP的
通用能力定义。Receive还限定在RX回调消费，但现有AT32基础台架在前台轮询同一个API。
如果直接按新注释实施，会逼台架改调度或重新出现第二套收发入口。

现有证据：tests/bench/at32f456/main.c:105之后的前台循环。

建议：硬件帧格式能力由板配置说明，当前协议继续在上层限制；首轮不启用新帧型。
Receive按配置选择单一消费者，可为ISR或前台，禁止两者并发，而不是必须新增两个接口。

## R7 [P2] 编码器结果冗余，台架便利函数留在核心API

位置：[bsp_encoder.h](bsp_encoder.h):29-33、[bsp_pwm.h](bsp_pwm.h)的ForceHighSides。

angle_counts与angle_rad表示同一原始角度；现有控制用计数先执行方向、LUT和电零位处理，
提前计算rad没有真实消费点，会增加快路径计算和字段一致性负担。
ForceHighSides可完全表达为SetDuty(1,1,1)，当前引用只见台架/测试。

建议：编码器选一种规范输出，优先保留现有计数以避免精度变化；需要rad的上层在合适位置换算。
保留两个输出必须说明实际消费者及性能收益。ForceHighSides可放台架私有辅助函数，
不因删除便利包装而删除台架功能。SetPhaseDuty有实际台架需求，可单独评估是否属于核心契约。

## R8 [P2] UART“受损片段”的边界和错误清除语义没有定义

位置：[bsp_uart.h](bsp_uart.h):45-46。

字节流BSP不知道业务帧边界，无法仅凭“丢弃受损片段”实现两板相同的恢复行为。
发送错误与接收错误还共享ERROR状态，Read只描述接收错误的消费；发送异步失败后如何
观察和恢复没有闭合。当前没有硬件绑定，也没有真实消费者可验证这些选择。

建议：明确到字节位置/整个RX缓存的丢弃规则和上层重新同步责任，区分发送完成/失败与
接收错误；也可将这些细节列为待定，等真实接入时再实现，不扩展通用状态机填补假想需求。

## 还需补齐的设计输入

- Init失败后的安全状态、必要时的BootHw早期调用、各外设启动依赖和最终共用main的顺序。
- 快采样中断、监督中断、前台三种上下文的职责表，尤其是温度推进、LED刷新、功率保护、
  诊断与看门狗健康计数。无需预先新增Bsp_Process；先决定现有工作各归哪里。
- 能力配置到每个接口/通道的对应关系，以及未支持/未启用/未启动时的统一返回语义。
- 固定ADC范围、极性、饱和及新鲜度限制，Flash可写容量和串口缓冲容量由何处明确提供。

## 建议修订顺序

1. 先解决R1/R2/R3，把上电采样、标定、有效电流发布的链路走通。
2. 再解决R4/R5，冻结存储与功率保护的状态和所有权；修订时不改现有硬件行为。
3. 修正R6，精简R7，将R8未证实的细节保持待定。
4. 补一个可审查的main与三上下文调用图，再把修订后的契约交给双板实现和回归。

本轮审核不以编译通过代替以上流程证明，未修改现有接口设计以免混淆问题与修复。

# 修订5补充审核（2026-10-26）

下方原审核保持历史记录。本补充对应用户要求的五类问题，当前只修订接口设计。

| 类别 | 修订结果 | 后续实施要求 |
| --- | --- | --- |
| PWM | 定义三相同事件生效、首写前截止检查、超时关相；Enable失败由BSP先关断 | 对照原输出时点和ADC相位；单独验证异常路径增强，不宣称已与旧实现等价 |
| 编码器 | 控制样本仅角度/序号；独立读取带结果和有效位的诊断快照；保留六槽兼容映射 | 迁移旧诊断消费者，保持线上数值，不增加SPI事务 |
| LED | 使用枚举选择当前码；明确重设、清零、共享灯覆盖和独立灯带 | 保持原5Hz/20Hz波形及颜色映射；BSP不接管应用故障判定 |
| CAN | 溢出一次报告并保留幸存帧；坏帧后继续有界消费，IO失败不自旋 | 核对两控制器标志清除竞态、预算和队列处理 |
| UART | 配置有界发送期限，一次终态、迟到事件隔离，无法静止则禁止新发送 | 未绑定硬件前不创建空驱动；真实接入后验证TC与超时竞态 |
