# G431 Loader 16 KiB 分区迁移

日期：2026-10-17。用户决定将 Loader 分区缩至 16 KiB，把释放的 4 KiB 分配给 APP。
本决策替代此前保留 layout 5 的容量计划；历史构建与台架记录保持原样。

## 目标与边界

| 区域 | 新地址 | 容量 |
| --- | --- | ---: |
| Loader | `0x08000000..0x08003FFF` | 16 KiB |
| APP | `0x08004000..0x0801BFFF` | 96 KiB |
| 参数与身份 | `0x0801C000..0x0801FFFF` | 16 KiB，不变 |

只改 G431 配套构建的分区和版本；CAN FD 升级协议格式、参数 ABI、身份页和电机控制行为不变。
共同目标清单、两端链接工程、描述符、打包器、客户端和上位机必须使用 layout 6。
旧 layout 5 包继续作为历史证据，不能与新 Loader 或 APP 混装。

当前冻结 Loader 为 15,108 B；若重链后仍为此大小，16 KiB 分区只余 1,276 B。
构建时以真实链接跨度为准，任何超限都停止，不截断镜像或占用 APP 页。

## 验收与回退

1. 生成工程输入；检查两端 scatter、Keil 工程和共享常量完全一致。
2. 新旧布局的黄金向量、拒绝旧包测试和主机检查通过；`format --check`、`lint`、
   `verify --profile release` 通过，确认 Loader 和 APP 链接范围、RAM 与产物哈希。
3. 实机迁移只在独占台架、关相及物理隔离确认后执行。必须通过 SWD 一起安装新 Loader
   和新址 APP，保留参数及身份页并逐段回读；随后再验证启动、CAN 与升级链路。
4. 当前 20 KiB 布局板上出现 APP 启动后留在 Loader 的未解释现象。在安全根因和停机状态
   未确认前，不把新布局包下载到该板，也不宣称实机通过。

回退到冻结的 layout 5 配套包时，同样经受控 SWD 一起恢复 Loader 与 APP，恢复备份的
参数和身份页，再核对 UID、Flash 哈希与关相状态；不得只恢复其中一个镜像。
