# AT32 Loader 压测前置复测

日期：2026-11-03。沿用用户明确确认的AT32新板、隔离电机动力、仅逻辑供电、
USB-CAN和SWD独占上下文；本轮用户要求继续压测Loader。

结论：**SWD备份稳定性未通过，Loader安装及100轮CAN升级均未开始。**
本轮没有调用Flash写入，没有发送CAN帧，不修改固件、通信协议或参数。

## 当前实测

| 项目 | 结果 |
| --- | --- |
| 独立连接后完整256 KiB双次备份 | 前9轮通过，第10轮双次内容不一致，立即停止安装流程 |
| 通过轮次的Flash内容 | 全部与此前可信完整备份一致，SHA256为`0726b2b56bb8ddd071fc88baea217612dbdd5a1ac13e1517b8909eaa708b44a8` |
| 暂停CPU并冻结WDT后的读取对照 | 首对完整回读仍不一致；第一份匹配参考，第二份有1,449字节差异 |
| 暂停对照的逐块状态 | 每笔4 KiB前后CPU均暂停、WDT冻结位均有效，DWT周期计数保持不变 |
| 差异形态 | `0x0802C8A0..0x0802CFFF`；从首个差异所在字到该4 KiB块倒数第二个字，坏数据精确对应参考数据后移4字节 |
| 退出状态 | 恢复CPU运行和原WDT调试冻结位，复核六路输出关闭，关闭SWD连接 |
| 参数迁移、Loader安装、CAN升级 | NOT_RUN，Flash写入调用为0，升级完成0/100轮 |
| Keil本体导出对照 | NOT_RUN，打开编辑器后遇到Windows锁屏，停止界面操作，等待用户解锁 |

读取使用1 MHz SWD、每笔最多4 KiB，并关闭J-Link的Flash和内存缓存。
每轮只有两份完整物理Flash相同才接受，不挑选重试结果；第10轮失败使整个稳定性批次失败。
前9轮成功不能替代整批通过，也不能证明后续写入校验可靠。

暂停对照中仍复现读错，不支持把本次异常解释成APP运行或短WDT导致的复位。
现有证据也不能确定是探针、DLL、USB/SWD传输或其他原因，暂不指定硬件根因。
此前32/64位DLL及不同访问宽度均出现过不一致，不能单凭DLL位数下结论。

## 工件与后续

本轮复核配套构建包的所有工件哈希及目标契约，Loader为14,808 B，APP为62,632 B。
与历史release冻结源比较，MCU代码内容未改变；换行差异单列，实质变化仅为此前维护工具、
对应测试及两个目标的J-Link设备名称元数据。历史release结果不冒充本轮实机通过。

继续执行前，先在解锁后的Keil中对齐实际读取范围、CPU状态和缓存设置，导出完整Flash对照；
可靠的完整备份及回读验证恢复前，不执行迁移或安装，不绕过现有保护门槛。
