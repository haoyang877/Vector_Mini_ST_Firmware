# Loader 多目标边界收口 v1

日期：2026-10-21。基线：`f199f7d4`。仅离线开发，不接触 CAN、调试器或电机。

## 目标和不变项

按用户确认的顺序补齐 Loader 分层检查、贯通目标配置到构建/打包/主机校验，
再分离板级安全检查与产品参数解析。只保留真实 G431 目标，不新增虚构 MCU 驱动。
协议 v3、参数 schema14、Flash/RAM 布局、单槽流程、启动标记和 G431 安全行为保持不变。
暂不实现不同 Flash 编程粒度、非 Cortex-M 启动、UART 或第二种实际 MCU。

## 实施与验证

1. 将平台公共接口与芯片实现分开，加入 core/runtime/product/port/board 的依赖检查及反例测试。
2. 以显式目标清单贯通工程生成、APP 后处理、打包、主机检查；默认 G431 向后兼容。
   目标选择及运行包中的契约均需校验，未知目标、错误镜像和不支持能力不得静默回退。
3. 功率关闭与关闭状态核对归板级；参数格式解析归产品层，芯片层仅提供有界只读接口。
   保持读取范围、错误返回、默认节点及旧格式兼容行为。
4. 执行格式、lint、PR、release 和两端配套构建；原生模型覆盖边界、启动、确认及参数。
   比较基线与结果的 ABI/黄金向量、状态行为、参数读取、资源、镜像和构建输入。
   若二进制因函数位置变化而不同，记录差异与实际资源，不宣称逐字节相同。
5. 更新适配指南和结果记录，再合并重构主线，保留主线未提交修改。

## 基线、验收和回退

基线配套构建：`outputs/delivery/mcu-boundary-baseline-20261021/summary.json`，固定 token=7，
用于比较镜像身份和资源。全流程不得放宽 16 KiB Loader 分区，也不修改版本号掩盖兼容变化。
G431 默认命令与显式目标命令都需通过；离线结果不替代新固件实机验收。
所有新检查必须能拒绝违规示例，同时接受真实 G431 构建输入。

每阶段以提交为回退单位，必要时回退本轮提交并重新生成基线工程。
不得重置主线用户修改、擦除旧测试输出或把未测硬件行为写为通过。
最终检查路径、资源和剩余限制在完成时补充。
