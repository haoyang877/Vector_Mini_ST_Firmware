# 经典 CAN 电机控制与状态反馈示例

基于 motor_protocol_v1.md 的 1.2.1 / 200 Hz / 单帧反馈 设计。以下是假设数据和参考编码，未向硬件发送。

主机地址 0x02，电机地址 0x03；29 位扩展数据帧，经典 CAN，DLC=8，小端。假设已申请控制，session_id=0x10203040、lease_tag=0x1234，设备未使能且无故障，活动参数 revision 已读取为 7。示例数值必须位于实际设备支持范围。

顺序：设置速度模式 → 暂存最大 Iq=3 A → 保存参数 → 预装零速度 → 使能 → 每 5 ms 下发速度目标 → 接收位置、速度、Iq 反馈。管理请求停等，必须收到业务 OK 后继续；TP EOMA 仅表示传输完成。

## 6. 运行目标与周期反馈

以下假定零目标只使用了 seq=1，运行目标下一序号为 2；若准备期间已发多条零目标，应使用实际下一序号，详细状态查询回显实际已应用序号；合并反馈不携带序号。等待管理事务期间仍维持所需周期目标；正式目标必须等使能业务 OK 后发送。后续 5 ms 周期继续发送目标，即使值不变也递增序号。

| 方向 / 消息 | CAN ID | 8 B 数据区 | 解码 |
| --- | --- | --- | --- |
| 主机 → 电机，速度目标 | `0x08EF0302` | `68 02 34 12 10 27 00 00` | type=104，seq=2，lease=0x1234，10000×0.001=10 rad/s |
| 电机广播合并反馈 | `0x0CFF7C03` | `22 06 00 00 1C 25 B0 04` | type=124 由 PGN 映射：位置 1.570 rad、速度 9.500 rad/s、Iq 1.200 A |

一条反馈为 200 Hz，三项从同一快照读取。字节 0～3 为 position:i32，字节 4～5 为 speed:i16，字节 6～7 为 iq:i16，小端。速度、电流保留 0.001 单位，有效范围分别为 ±32.767 rad/s、±32.767 A；i16 无效值为 0x8000。PGN=0x00FF7C 为 PDU2 广播，0x7C 不是主机地址。模式、故障和已应用序号在下方 GET_MOTOR_STATE 响应中获取；状态/故障变化另由心跳格式的事件消息报告。设备必须公布 GET_CAPS.features 位 12，旧三帧接收器不能直接解码本帧。

经典 CAN 紧凑实时帧无额外应用 CRC，使用 CAN 硬件 CRC；管理报文保留公司 CRC8/CRC16。

## 力矩字段的边界

本版没有 N·m 单位的力矩反馈或力矩目标命令，type=124 的最后两字节明确定义为 Iq，不能改名为力矩。若需要增加力矩信息，必须先定义电机轴/减速器输出轴、转矩常数及其电流口径、标定有效性、估算/实测标识、单位与无效值，再评审新增字段或消息编号，并重新核算带宽。本示例不假设实际电机的转矩常数。
