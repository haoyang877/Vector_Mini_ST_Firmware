# CAN 参数回复交接补充 v1

日期：2026-10-16。状态：离线回归及普通/HIL 构建通过，尚未进行本轮通信台架验证。

本补充修复参数回复竞争、参数 CRC 重算和运行改号丢失通信。命令编号、数值编码、
参数 Flash 布局及协议查询版本保持不变，不新增通信指令。
黄金向量见 `tests/vectors/can_reply_handoff_v1.json`。

## 回复所有权

CAN RX 中断是唯一生产者，主循环是唯一消费者，共用一个最多 16 字节的回复槽。
接收时冻结完整回复 ID 和载荷；UID/参数 CRC 请求先冻结 ID 与 nonce。
槽占用期间拒绝新回复，保留先到的完整回复并增加诊断计数。

主循环准备 UID 或 CRC 后将槽置为 READY，再单次尝试提交硬件。硬件忙或失败时保留
同一帧，下次主循环再尝试；参数 CRC 对每个已接受请求只计算一次，不跨请求缓存。
只有硬件接受帧后才释放槽；这表示入队成功，不表示已收到总线 ACK。

普通回复仍为 2/4 字节大端参数值，UID 回复为 nonce4＋UID12，CRC 回复为
nonce4＋大端 CRC32。所有回复仍采用标准 CAN-FD、BRS。发送参数未改变。
周期状态是可丢弃的低优先级帧；回复优先，BOOT 交接优先于普通和 UID/CRC 回复。

主机应逐条查询并核对 ID、长度；维护查询还必须核对 nonce。忙拒绝不另发 NAK，
超时后可以重试读操作。已有设置命令不会因回复槽忙而统一被阻塞，因此设置后应查询
确认；不得把没有收到回复直接等同于设置未执行。STOP 和 BOOT 不因槽忙被阻挡。

## 节点改号

`SET_NODE_ID=0x08` 仅接受有限整数 0～7，且要求当前模式、上一模式都为 STOP，
三相输出已关闭。不自动停止正在运行的电机，不挂起运行中的改号请求。

在 CAN RX 中断内先更新硬件过滤器，成功后才发布 `CANMsg.node_id`，并沿用原有按
节点收紧速度上限的行为。该 HAL 在 READY/BUSY 状态下更新标准过滤器，只写一个
32 位 Message RAM 字；不停止 FDCAN、不等待、不屏蔽 ADC。同一 CAN RX 中断不可重入。
硬件更新失败时保留旧节点和旧过滤器；相同节点的停机请求幂等，不重复写过滤器。

保留旧 SET 不自动 ACK 的行为。例如从节点 4 改为 3：

1. 确认 STOP 和关相，向 `0x408` 写入 `40 40 00 00`（float32 的 3）。
2. 向 `0x309` 发 4 字节零，成功回复为 `0x309 / 40 40 00 00`。
3. 更新成功后再通过新节点执行已有保存流程；改号本身不写 Flash。

如果失败，旧节点 `0x409` 仍可查询为 4。已经入槽的旧请求仍按原 ID 回复；不会因为
改号变成新节点回复。改号后排队的旧地址请求由软件地址检查拒绝。
`CANMsg.node_id` 是已生效节点的调试镜像；直接用调试器写 RAM 不属于此事务接口，
不能保证同时改动过滤器。本补充不改变启动时合法 Flash 节点优先于轴身份的策略。

`GET_CAN_BR=0x29` 现在通过同一 `0x29` 回复波特率，修正原来误用心跳查询 `0x2B`
的错误。依赖错误回复 ID 的主机需要修正；心跳查询 `0x2B` 的含义不变。

## 可观测诊断

只读 RAM 符号 `CAN_Diagnostics` 可通过 J-Link 查看，无新增 CAN 查询号。每项独立
单写者，启动清零，计数达到 UINT32_MAX 后饱和；不要在运行中由外部清零。

| 字段 | 含义 |
| --- | --- |
| `rx_rejected` | RX 入口拒绝的格式/保留哨兵，以及参数分派拒绝的非有限/整数溢出或未知命令 |
| `reply_busy` | 回复槽占用导致新回复被拒绝的次数 |
| `tx_busy` | 主循环提交回复时硬件忙或返回失败的次数；不是丢帧数 |
| `node_rejected` | 改号数值非法，或当前模式/上一模式/三相关断条件不满足 |
| `node_filter_failed` | 硬件过滤器提交失败，软件节点未改变 |

不将这些诊断塞入电机故障码，避免改变已有故障协议和运动行为。

## 验证与范围

协议层 `interface_can.c` 负责命令编码、回复槽、节点与保活策略；现有
`comm_hw` / `comm_status_stm32g4.c` 端口负责过滤器、外设启动、接收通知和波特率寄存器。
初始化仍先复位状态帧服务，再启动硬件，最后发布默认 1000 kbit/s。波特率切换仍由
1 kHz 监督任务每 100 ms 检查，值未变化时不重配；数据段超过 1000 kbit/s 时仲裁段
仍固定为 1000 kbit/s，其他档位两段同速。本次只迁移职责，不改变调度或时序公式。
初始化或切换的 HAL 失败仍进入既有 `Error_Handler`：关闭中断并停止软件调度，
该函数不保证主动关闭 PWM。运行中切换失败的输出处置属于后续应用错误策略，本次未改变。

既有 `run_can_status_tests.py` 入口增加真实收发/参数分派与平台端口组合测试，覆盖
发送中 RX 抢占、CRC 中 UID 请求、CRC 单次计算、2/4/8/16 字节 DLC、忙/失败重试、
BOOT 抢占、回复 ID 冻结、停机改号、硬件失败、非法节点和波特率查询。
平台配置回归覆盖 8 个节点范围、9 档速率、初始化/重配顺序、同值不重配及 7 处 HAL 失败。
热参数通信夹具同步使用新槽，热算法和参数存储不变。

本补充不重构旧波特率切换调度，不增加队列，不改变默认速率或控制环。
回退时需要同时回退收发逻辑、2 字节平台端口支持和相应测试，避免只回退单方所有权。
