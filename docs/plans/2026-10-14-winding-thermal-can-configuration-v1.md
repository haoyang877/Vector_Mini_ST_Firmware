# 绕组热参数通信配置 v1

日期：2026-10-14；集成修订：2026-10-15。原独立候选现集成至 `codex/ovp-36v` v0.6.0，不下载硬件。

目标：仅保留连续电流和升温时间常数两个电机标定量。峰值电流作为运行限制，四个热动作门限作为策略参数，均可通过现有CAN协议读写并通过mode 9保存。单相持续电流自动取连续电流÷√2，冷却常数自动取max(120 s, 升温常数)。默认行为仍为3 A / 2.121 A / 7 A、65.985 / 120 s、80% / 70% / 100% / 50%。

## 实现约束

- CAN扩展使用0x80～0x8D的七组SET/GET，0x8E查询扩展版本2。沿用标准ID `(node << 8) | command`、4字节大端float32；门限在线路上以百分数表示。
- 仅mode 0且三相已高阻关闭时接受写入。先整体校验候选配置，失败回复−1且不修改任何参数；成功回复对应GET ID及接受值。
- 连续电流不得超过峰值，冷却常数不得小于升温常数；门限满足`0 ≤ 恢复 < 降额退出 < 降额进入 < 停机 ≤ 100%`。
- 通信上下文预计算系数，单槽请求由下一次关相快拍应用；快环不计算指数或存储CRC。未消费请求禁止启动带电模式，STOP和保存仍可用。
- 参数修改不清热量、不解除故障锁存。降低持续电流时按平方比例放大对应H，增大时不降低已有H；降低停机门限立即重新判断锁存。保留有效窗口中已累计的电流平方。
- Flash追加MTH1/v1独立40字节记录，总长2384字节，既有2344字节前缀及schema10保持；旧全零/擦除尾部采用默认值，非空损坏或不支持的记录禁止参数准入。只保存配置，不保存运行热历史。
- mode 8保留独立热标定配置和热历史；需要恢复热默认值时逐项通过CAN写入。上电热初值仍为0，参数放行仍默认为1，采样周期和安全监督不开放通信修改。

## 验收与回退

使用真实C模块验证可配置门限、完整配置拒绝、热历史保留、锁存保留、停机准入及单槽请求。执行生产CAN收发函数的黄金帧测试，验证大端编码、ID和非法载荷；执行参数上传/下载测试，覆盖旧尾部、CRC破坏、存取一致及旧字段不变。随后运行现有热保护、参数、外环及CAN回归和普通Keil构建；这些操作均不连接硬件。

参数CRC仅合并同一文件中PVF1、PSP1及MTH1的小端字计算，既有算法、记录长度和黄金向量不变；原PVF1/PSP1黄金及逐位损坏测试作为行为保持验收。配置发布复用现有共享电机数据屏障，不添加平台寄存器或新调度机制。

回退删除此扩展提交即可恢复编译固定热参数。旧固件忽略MTH1尾记录；旧固件保存时可能擦除此尾记录，再升级采用默认热参数，须重新核对配置。

## 集成差异

为保留速度前馈0x70～0x7B及Loader查询0x7C，热协议迁移至0x80～0x8E并将能力版本改为2。MTH1在FSL1、SFF1之后追加，偏移2344、总长2384。离散系数改为三阶有界近似，避免引入指数库；精度扫描和热模型解析曲线验证其误差。
