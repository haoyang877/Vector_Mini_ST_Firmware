# RTT 模式3位置伺服遥测

## 当前格式 v2（2026-09-10）

前9路按下表排列。位置单位为0.01°，速度为0.01°/s，电流为1 mA。
例如位置原始值1234表示12.34°，速度原始值−2500表示−25.00°/s，电流原始值1000表示1 A。

| 通道 | 信号 | 每个计数的单位 | 来源 |
|---|---|---|---|
| data0 | 目标位置 | 0.01° | `MotorControl.posRef`，最终目标 |
| data1 | 参考位置 | 0.01° | 轨迹规划位置 `position_reference` |
| data2 | 反馈位置 | 0.01° | 编码器连续机械位置 `theta_mech` |
| data3 | 位置误差 | 0.01° | 参考位置−反馈位置，在浮点域计算后编码 |
| data4 | 参考速度 | 0.01°/s | 轨迹规划速度 `trajectory_speed_reference` |
| data5 | 反馈速度 | 0.01°/s | 实际供闭环使用的滤波速度 |
| data6 | 参考电流 | 1 mA | 限幅后的 `MotorControl.iqRef` |
| data7 | 前馈电流 | 1 mA | `iqRef - feedback_current`，实际参与合成的前馈余量 |
| data8 | 反馈电流 | 1 mA | FOC 实测 `Iq` |
| data9 | PI控制电流（诊断） | 1 mA | 速度PI反馈控制输出 |
| data10 | 保持积分电流（诊断） | 1 mA | 速度PI积分项，已包含在data9内 |
| data11 | 状态字（诊断） | 位域 | 阶段、有效性、故障、丢帧和格式版本 |

data4是规划速度，并非加入位置纠偏后的最终速度命令。data3是轨迹跟随误差；
最终目标误差可用data0−data2观察。data8是实测电流，不能与data9的PI控制输出混淆。
电流合成关系约为 `data6 = data9 + data7`，存在逐通道量化误差。

保持上行通道1、12个有符号int16、每帧24字节、2 kHz和非阻塞SKIP发送方式。
最后3路用于保持既有诊断能力。两个 `.lksscope` 工程已同步顺序、图组和单位。
角度及角速度编码比例均为 `18000/pi`，电流比例为1000，截断小数部分。
位置不再单圈回绕，超出−327.68～327.67°时饱和；速度范围为−327.68～327.67°/s，
电流范围为−32.768～32.767 A。非有限值编码为0。量化单位不代表实际机械测量精度。

v2状态字置bit14、清bit8；v1置bit8、清bit14。其他状态位沿用下方历史定义：
bit0～1阶段，bit2到位，bit3限流，bit4前馈非零，bit5故障，bit6上一帧丢失，
bit7遥测有效，bit9～13为控制诊断。无效或非模式3时信号通道清零且bit7清零。

`tools/rtt_control_frame.py`根据版本解码为具名物理量。保持噪声、运动噪声、
定位统计、自动验收和主机回放已接入v1/v2解码，拒绝混合版本或未知有效帧；
原始采集TSV及二进制不转换单位。HIL采集记录同时保存观察到的版本标签。
固定历史报告脚本仅接受v1，避免重算历史报告时错误解释新版数据。

下面的旧通道表和滤波演进记录仅用于解释历史v1采样，不适用于当前v2。

## 历史 v1 文档


RTT上行通道1只用于模式3位置伺服调试。采样频率为2 kHz，每帧固定12个有符号`int16_t`，共24字节、48 kB/s。通道采用`SEGGER_RTT_MODE_NO_BLOCK_SKIP`，调试器来不及读取时宁可丢帧，也不会阻塞20 kHz电机快环；下一帧状态字的bit6会报告前一帧未完整写入。

## 固定通道布局

| 通道 | 信号 | 编码 | 控制含义 |
| --- | --- | --- | --- |
| `data0` | 轨迹位置参考 | 单圈signed-Q15 | jerk轨迹的`q_ref` |
| `data1` | 机械位置反馈 | 单圈signed-Q15 | 编码器`theta_mech` |
| `data2` | 轨迹位置误差 | raw = rad × 10000 | `q_ref - theta_mech`，使用连续多圈值 |
| `data3` | 轨迹速度参考 | raw = rad/s × 10000 | jerk轨迹的`w_ref` |
| `data4` | 最终速度命令 | raw = rad/s × 10000 | `w_ref + Kp*e_pos + Kd*e_vel` |
| `data5` | 控制用速度反馈 | raw = rad/s × 10000 | 模式3使用的连续窗口测速＋软件低通结果 |
| `data6` | 总Iq参考 | raw = A × 1000 | 限幅后交给电流环的Iq |
| `data7` | Iq反馈 | raw = A × 1000 | FOC测得的Iq |
| `data8` | 反馈控制电流 | raw = A × 1000 | 模式3速度PI输出 |
| `data9` | 实际总前馈电流 | raw = A × 1000 | 总Iq减去抗饱和回写后的反馈电流 |
| `data10` | 保持积分电流 | raw = A × 1000 | 速度PI积分项`Ui` |
| `data11` | 模式3状态字 | 位域 | 阶段、到位、限流、故障和遥测状态 |

signed-Q15角度解码为`angle_rad = raw × π / 32768`。`data0`和`data1`只显示单圈角度，在±π处会跳变；`data2`由未回绕的连续多圈位置直接计算。速度、电流和位置误差超出`int16_t`编码范围时饱和，不会整数回绕；非有限值编码为0。

模式3的电流关系近似为：

```text
data6 = clamp(data8 + data9)
data8 = 速度PI比例电流 + data10
data9 = 限幅后实际使用的加速度前馈电流 + 摩擦前馈电流
```

`data10`已经包含在`data8`内，不能再次加到总电流。`data9`使用`Iq_ref - feedback_current`发送实际参与合成的前馈余量，因此总电流限幅时仍能与`data8`正确对应。目前加速度前馈增益尚未标定且为0，所以`data9`实际主要反映摩擦前馈。由于电机转矩常数尚未确认，RTT只发送电流，不把电流伪换算为N·m。

## data11状态字

| 位 | 含义 |
| --- | --- |
| bit0～1 | 阶段：0=`MOVE`，1=`SETTLE`，2=`HOLD`，3=无效 |
| bit2 | 已连续满足到位条件 |
| bit3 | 总Iq请求或前馈合成触发电流限幅 |
| bit4 | 总前馈电流的编码值非0 |
| bit5 | `MotorControl.ErrorNow`不是`No_Error` |
| bit6 | 前一帧RTT数据未完整写入 |
| bit7 | 模式3控制器遥测有效 |
| bit8 | 帧格式版本1 |
| bit9 | 实际位置/速度触发了落点摩擦前馈卸载 |
| bit10 | 前馈静摩擦脱困（SETTLE或MOVE着陆停顿恢复） |
| bit11 | 已捕获到位窗口，正在进行HOLD迟滞确认 |
| bit12 | 本周期轨迹期望速度受到软跟随误差约束（默认关闭） |
| bit13 | 本周期施加了附加静止纠偏积分（计入data10） |

bit9和bit10表示互斥的前馈阶段：远离目标的脱困运动只置bit10，进入实际制动包络后清除bit10并置bit9。bit10也可在MOVE期间因着陆后停住而置位。若两位同时出现，应检查控制状态切换。bit11置位后，位置噪声可在保持进入窗口与退出窗口之间波动；连续确认完成后bit11清零、阶段切换为`HOLD`并置bit2。bit12表示参考治理正在作用，不是故障或硬误差限制。bit13表示在尚未捕获窗口、持续静止且同向目标/参考误差超过进入窗口时，已有速度PI积分获得受总电流余量约束的额外增量；它与前馈脱困bit10独立。bit13为0不代表普通速度积分被冻结，也不代表电机已运动。

2026-09-08本次优化保持12通道布局和单位，但`data5`改为实际供模式3闭环使用的连续滤波速度；旧记录`03_串级PID_3`的`data5`仍是含硬零速阈值的旧编码器输出。比较新旧波形时必须保留这一语义区别。

非模式3运行时，`data0`～`data10`固定为0，状态字阶段为3且bit7清零。因此上位机必须检查bit7，不能把全零数据解释成电机已经到位。

2026-09-10 HOLD降噪版本：`data5`继续表示实际参与控制的速度。在HOLD阶段，
它包含新增的10 Hz速度低通；MOVE/SETTLE仍为原连续窗口测速＋40 Hz低通。
HOLD退出判断使用新增滤波之前的反馈，因此退出瞬间不能仅凭`data5`推断判定依据。
12通道布局和编码不变，比较历史记录时必须同时保存固件版本和
`POSITION_SERVO_HOLD_VELOCITY_FILTER_HZ`配置。该宏设为0可关闭新增滤波。
诊断依据、实机验证要求见 [静止保持噪声分析](position_hold_noise_20260910.md)。

同日后续运动降噪版本将基础测速低通默认从40 Hz改为20 Hz，HOLD附加低通仍为10 Hz。
因此最新镜像的MOVE/SETTLE `data5`为连续窗口测速＋20 Hz低通；HOLD再叠加10 Hz。
HOLD阶段判断也使用基础20 Hz反馈，独立的编码器速度保护及电流保护未改。
HIL命令10仅允许停机时选择0=编译默认、1=默认一半；其数值不是绝对Hz，
分析记录时必须结合镜像版本：早期运动对比镜像默认40，最终镜像默认20。
现场听感及定量对比见 [运动噪声验证](motion_noise_20260910.md)。

同日最终按用户要求统一为单个10 Hz软件测速低通：MOVE/SETTLE/HOLD的`data5`
共用基础10 Hz输出，HOLD额外低通默认0（关闭）。原编码器窗口测速仍保留。
2 kHz更新下系数为 `alpha = (2*pi*10*0.0005)/(1+2*pi*10*0.0005) ≈ 0.030459`。
当前HIL命令10的0/1分别对应10/5 Hz；命令9不会在默认额外截止频率为0时新增滤波。
历史镜像的同一命令值必须按其编译默认解释。

## 推荐观察组合

- 位置跟踪：`data0`、`data1`、`data2`，观察跟踪误差、超调和稳定时间。
- 阻尼效果：`data3`、`data4`、`data5`，判断速度修正是否过强或不足。
- 电流环能力：`data6`、`data7`、`data11.bit3`，区分外环限流与内电流环跟踪问题。
- 前馈效果：`data6`、`data8`、`data9`和`data11.bit9～10`，确认接近目标时原方向前馈被卸载，以及停在窗口外时脱困前馈能够介入。
- 到位维持：`data2`、`data7`、`data10`和`data11`，确认进入`HOLD`后积分电流能够维持位置。

配套的`pro_lks.lksscope`已经按上述12个通道分组并命名。改变帧字段数量、顺序或类型时，必须同步修改`Core/Src/main.c`中的JScope格式字符串、该Scope工程和本文档。

## 实机采集时序

模式3外环与RTT帧编码错开：若本次正好执行2 kHz外环，RTT延后一个50 μs快周期；随后恢复标称2 kHz帧率。实际频率应根据实测时钟校核。HIL文件另外记录主机时间、下发目标和快中断计数，帧本身仍不包含时间戳。一次只能有一个RTT消费者；自动采集时关闭Scope连接。专用HIL镜像使用 `pro_lks_servo_hil.lksscope`。
