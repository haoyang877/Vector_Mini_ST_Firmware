# APP 分步优化 v1

日期：2026-10-16。基线：`codex/ovp-36v` 的 `1c3daf32`。

## 目标与边界

先完成已验证的内存整理，随后按用户最新要求重点整理功能逻辑与模块边界，
优先 CAN 通信和参数保存；暂停快环三角函数、观测器等耗时微优化。
每一步独立提交并保留验证记录；本轮只执行离线测试与普通/HIL 构建，不连接台架。
用户现有 Keil 会话、示波器布局及 Pitch 分析资料不纳入提交。

不改变电机参数、Flash 记录布局、CAN 数值编码、LUT 点数和精度、控制周期、
热保护与限流规则。保留模式编号。涉及通信生效时序的修复另附兼容说明和黄金向量。

## 基线

该提交配套构建的普通版 ROM 为 93,896 B，RW/ZI 为 27,984 B，CCM 代码 1,960 B；
含 32 B 启动邮箱的实际 RAM 为 29,976 B。固定 APP 区容量 98,304 B。
上轮完整原 C 中断处理函数测量峰值为 37.118 μs，不含硬件异常入退；
本轮离线验证不能更新该实测值，也不作完整 IRQ 小于 40 μs 的新保证。

## 分步实施

1. 标定计数与候选 LUT 复用内部存储；Flash 参数用独占固定缓冲替代通用堆。
   核验 mode 5/13、失败、STOP、重入、旧记录读取与原 ABI。
2. CAN 回复固定完整帧交接，忙时不覆盖；每条参数 CRC 请求只计算一次。
   修复波特率查询回复 ID 和节点号/硬件过滤器生效一致性。
3. Flash 保存逐次检查擦写结果、回读校验、相同内容跳过写入；停机保存结果明确可查。
   保留停机与关相条件，不直接放开擦写期间中断，不改变参数区布局。
4. 整理 CAN 的协议/硬件边界及参数保存的应用/平台边界：让硬件配置留在平台，
   应用负责停机协调和故障发布，功能模块持有自己的请求与结果。
   保持现有命令和模式入口，不引入通用消息框架，不只按文件长度拆分。

旧 mode 4、UART 以及快环微优化本轮暂不实施，先解决功能模块耦合。
已完成的 SPI 流水、热计算展开、
RTT 延后和 CCM 放置继续保留，不压缩栈。

## 验收与证据

- 固定参数记录 2384 B、LUT 1024 点、Flash ABI 及旧记录兼容保持。
- 每一步运行相关原生 C/集成测试；最后执行全部已有离线测试及普通/HIL 构建。
- 工程变更检查链接输入、RAM/CCM 不重叠、Loader APP 记录和镜像哈希。
- CAN 测试覆盖重试、请求中断插入、突发请求、节点切换和错误处理。
- 快环候选覆盖边界、非有限输入、启动/交接/停机状态，不以删除校验换性能。
- 该旧工作树尚无新 `verify --profile`、`format`、`lint` 命令；使用其现有
  `tests/run.py`、项目结构检查和双目标构建，并记录工具缺口。
- 生成证据位于 `outputs/app_optimization_20261016/`，报告位于 `docs/reports/`。
  资源收益以本轮 map 差值为准，运行时间待后续授权台架 A/B 验证。

## 回退

每项使用独立 Git 提交，可逆序 revert。内存优化回退时恢复原缓冲和工程输入；
通信/保存修复回退时同时回退对应文档与测试。没有参数迁移和硬件写入需要恢复。
