# yg_protocol 单板 CAN FD 实机验证 2026-09-28

## 结论与范围

STM32G431CB 实板通过失能状态下的协议回归：24 项检查通过，约 1 kHz 的 1000 条
116 请求对应 1000 条 ACK 和 1000 条 124 反馈，无缺帧。结束时 STOP 返回 0，
TIM1 三相六路输出使能位均关闭，参数区未改变。

用户明确确认已断开电机三相线、板卡仍供电。本轮没有启动电机，没有验证已运行模式的
目标应用、闭环运动、带载安全、低侧制动或五轴同步。失能态 116 返回 5 是预期拒绝，
不能据此宣称位置控制已完成。

## 验证结果

| 范围 | 实测结果 |
| --- | --- |
| 1 GET_INFO / 2 GET_CAPS | 32B / 16B payload，寻址、序号及 CRC 正确；控制能力为零 |
| 108 状态查询 | 空请求返回 45B 全量状态；非空请求返回结果 3，保持全量布局 |
| 110 STOP / 101 失能 | 返回 4B payload、结果 0；结束再次确认 |
| 101 使能 | 结果 2，未开放远程使能 |
| 116 模式 1/2/3/6 | 失能状态返回 5；每条有同 Type ACK 和一条关联 124 |
| 116 模式 4/5 | 结果 2，不支持；仍有对应反馈 |
| 长度、未用字段、使能字段错误 | 分别拒绝；116 错误也对应一条反馈 |
| 未授权控制源 | 源节点 9 返回结果 7，并报告失能状态 |
| 同序号重试 | 相同内容返回原结果；改变 payload 返回 4 |
| CRC8 / CRC16 错包 | 各观察 50 ms，无业务回复 |
| 124 主动反馈 | flags=0，独立帧头序号；payload correlated_seq 对应 116 |
| 软件关断证据 | 上电后及测试后 TIM1 CCER 均为 `0x00001000`，`CCER & 0x0555 == 0` |
| CAN 通道诊断 | 两项 SDK 读取均成功；错误码、REC、TEC 为零 |

一次有效状态快照：位置 1899 mrad、速度 0 mrad/s、Iq 0 mA、母线 32.81 V、
母线电流 0 mA、MCU 温度 43.92 °C、状态 idle、控制模式 0、故障码 0、有效位 `0x01FF`。
电机温度、Vq/Vd 无真实测量源，保持无效位和 `INT16_MIN` 哨兵。
这些是固件采样读数；未进行仪器精度校准。

所有请求在失能态拒绝，结果均为 5。延迟由 PC 收发时刻计算，包含 Windows 调度和

样本约 1 s，不代表长期稳定性、总线满载或五轴同时运行结果。

## 发现与后续边界

1. 板上旧镜像 STOP 返回不支持，三相输出使能位仍开。按 AGENTS.md 停止动力试验，
   用户人工断开三相线后才下载新镜像；没有自动恢复原试验。
2. Keil 脚本使用 `-j1` 时本机启动阻塞；恢复官方批处理选项 `-j0` 后通过完整 release。
   该选项控制 GUI/交互消息，不是并行编译数量。
3. 首轮主机校验器把 124 当成 ACK，误拒 flags=0；保留失败记录，修正校验器后通过。
   未修改固件反馈行为。
4. 实板存储 Node ID 为 1，与当前文档规划的电机 3～7 不同。后续确认板卡身份与节点分配，
   本轮没有为了测试更改用户参数。
5. GET_INFO 的 UID 为零、版本等字段仍为固定占位值。实际镜像身份靠构建清单和读回验证，
   后续应接入真实设备 UID 和可追溯版本。
6. 101 使能、mode 5 波形/退出与静止判断、跨模式启动仍需实现与台架验证。
   当前 STOP 只由软件输出使能位交叉确认，未测真实六路栅极或相电压波形。
