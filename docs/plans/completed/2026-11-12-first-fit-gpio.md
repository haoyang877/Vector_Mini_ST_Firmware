# 空白 AT32F456 的 J-Link 初装

v1.4.0 在 GPIO 和 TMR1 时钟关闭的空板上读取引脚失败，尚未写入 Flash。修复桌面初装入口，在确认空白程序区后按板级定义建立并验证六路关相，再执行原有备份、写入和保护区回读。已装板仍按现有流程检查输出。

本次交付以桌面 EXE、五轴模拟初装及真实空板的只读诊断为验收。现场操作员执行实际初装，选择左轮节点 3 并核对备份、型号参数、复位后的身份和十次电机状态。离线覆盖时钟关闭、实际引脚持续高及非空程序。可回退前版上位机，芯片原始内容以 UID 对应的首份备份为准。

v1.4.1 已交付。实板双读 262144 字节均为擦除态，GPIOA/B 与 TMR1 的时钟使能都为零。旧版在备份前误报输出高，写入尚未开始。修复后只有空白程序区会进入 GPIO 初始化，仍会检查引脚输入电平、PWM 通道及主输出。20 项 J-Link 专测、13 项设备维护和 18 项升级客户端测试通过；从交付 EXE 提取的工作进程对五种角色分别完成了模拟写入、复位、参数回读及 11 项 CAN 查询。实板写入和现场 CAN 验证由操作员执行。

交付 EXE 的 SHA-256 为 `e5ecf37ab5952f888a8b7115ba860520cdba1a7d3c5613e47c67ae537f8790de`。本轮实板只读证据及打包校验记录分别在 `outputs/can-upgrade-stress-20261112/blank-readonly.json` 与 `packaged-verification.json`。

交付后的操作员实测记录 `20261112-153853-539588` 显示左轮 HT8115-4、节点 3 通过空板关相、写入、固件与保护区回读及复位。启动后的参数与预期一致。复位后 USB-CAN 通道 1 在 50 ms 内没有收到节点 3 的身份回复。再次识别读到节点 3，第二次烧录已跳过实际写入，CAN 查询仍超时。此次验证覆盖真实初装与启动，CAN 通信尚待独立核实。
