# 看门狗修复的 AT32F456 设备验证

日期：2026-11-17。状态：本轮台架验证结束；看门狗子场景通过，完整安全验收未通过。

## 目标与边界

用户已明确要求将修复下载到当前 J-Link 连接的 AT32F456 验证。
基线为 `2a7cbf52` 加当前工作树，保留已有 Keil 与 `main_ticks` 调试修改。
修复契约及离线结果见[实现记录](2026-11-17-watchdog-runtime-health.md)。
APP 版本由目标清单升级为 v1.8.26；Loader 仍为 v2.3.4，布局及参数 ABI 不变。
仅更新 APP 槽，禁止写入 Loader、参数、身份或其他 Flash 区域；不发送运动命令。
设备 UID、探针编号及原始数据只保存在忽略的 outputs 证据中。

## 验收与回退

1. 核对 MCU、UID、Flash 容量、实际关相及唯一探针；双读备份完整 Flash。
2. 校验当前构建的 AXF/BIN/HEX 与清单，确认 APP 范围后按扇区下载并回读。
3. 比较完整 Flash，确认 APP 与新镜像一致且所有 APP 槽外字节不变。
4. 正常通过 Loader 启动，连续观察至少 120 s：三项任务推进、未再次复位进 Loader、
   普通 FAULT 下已关相且通信可用。未自然复现故障时如实记录，不绕过状态机强行启相。
5. 执行 release 档检查，记录已有失败，不将本次 debug 台架当作正式 release 通过。

失败时保持关相并保留现场；需要回退时仅恢复本轮备份的 APP 槽并再次验证保护区。
未确认镜像、真实任务停滞及关相失败的危险注入仍以离线回归为准，不在此台架强行制造。

## 结果

已完成当前节点 7 的 256 KiB Flash 双读备份、APP 分区写入和回读。
96,272 B 的 v1.8.26 镜像与回读一致，APP 槽外所有字节保持不变；
Loader、参数、身份及未使用物理 Flash 区域未被更新。

设备正常进入 APP，最终运行时间为 135,494 ms，仍处于过压 FAULT，
零偏计数保持 5 且未完成，快环、监督和外环计数继续增长，
看门狗调试冻结为 0，CFSR/HFSR 为 0。14 次 CAN 查询均成功，
身份返回 APP v1.8.26 / Loader v2.3.4，故障状态没有被清除。
本次验证了已确认 APP 在该故障下不会再因零偏未完成而自动复位。

完整安全验收未通过：计划的 120 s 定时观测被六路输出检查失败中断。
TMR1 相通道和主输出均为关闭，但 GPIOB 的 PB0/PB1 偶尔读为高电平；
在 1 MHz、100 kHz SWD 以及 CPU 暂停而定时器仍运行时均复现。
不能把后续确认的 135.5 s APP 运行时间写成完整 120 s 安全观测通过，
也不能据通道关闭将引脚异常解释为正常。根因尚未确定。

结束时通过 CAN 56 交接到 Loader，确认 Loader 运行、六路 GPIO 低电平，
APP 内容和保护区仍保持一致；设备保留 v1.8.26 APP，未回滚。
未发送电机运动命令，未清错、重新标定或写参数。

`release2` 档检查仍因非干净源码、已有 `main_ticks` 格式及入口抽取问题、
历史文档缺失证据链接而失败。已独立重建目标且零错误、零警告，
但本次不构成正式 release 通过。
