# APP 前台与标定交接精简

基线为 `c83fcd9`。两块板共用五个核心模块。目标是去掉空闲前台的遥测工作，将同一轴的标定交接阶段集中表达。

- CAN 108 查询和 116 产生的 124 反馈在形成回复时读取所属轴，每帧只采一份快照。保持单位、舍入、有效位、哨兵、序号和错误回复。目标重发继续按会话去重。
- 取消 APP 常驻遥测副本，通信给每帧设置无效初值，APP 填写当前状态和有效测量。Loader 使用事务标识判断有无登记，交接时读取轴的实际节点号。
- STOP 的 4 字节回复只传结果和明细，删除没有生产读取方的内部 STOP 令牌。保留 160 标定任务号和 56 Loader 发送票据。
- ADC 发布、前台保存、监督拍收尾使用互斥阶段。保留原会话和关相复核、屏障、STOP 与故障优先级、两段联合标定、Flash 写失败行为。板级绑定、RTT、Loader 试运行窗口与交接时序保持原约定。
- 对照当前启动失败路径，离线验证空闲和批量 CAN 帧、双实例嵌套、标定、停机、Loader 及 PR 档。三种 APP 镜像重建并比较静态资源。本次不操作硬件。
- 记录原生和构建结果、既有门禁失败及未测边界。可整笔回退本次源码、夹具和文档到基线，协议与参数无迁移步骤。

## 实现与验证

普通 APP 的五个模块各自保留独立职责。前台依次建位置轨迹、发布标定、处理 CAN。外环先更新编码器反馈，再取得工作快照、计算和复核提交。ADC、前台和 Loader 锁定停机共用撤销启相许可的顺序。

- 反馈只占用当前回包的局部对象。原生回归经实际收发队列验证空转零采样，同一轮查询、写目标、再查询及错误请求共取四次快照，发送忙重试不会再次取样。目标受理后若被停机抢占，同序号重发拒绝旧会话。
- 标定关相后只可能等待前台发布或等待监督收尾。联合标定发布 LUT 后可以在同一会话继续电零位。参数写入前仍复核会话、故障与数字关相。
- 基线和本次源码使用相同的可观察事件夹具，比较两板普通与 Loader 配置的四组启动、身份页、健康及交接轨迹，结果一致。AT32 的 Loader 配置仅为宿主夹具，实物移植不在本次范围。
- APP 与通信生产 C 源码及头文件合计净减 78 行。三个 Keil 镜像全量构建均为零错误、零警告，链接符号与反汇编中未发现双精度运算。相对基线的静态资源变化见下表。ROM 按 Code、RO-data、RW-data 合计，RAM 按 RW-data、ZI-data 合计。
