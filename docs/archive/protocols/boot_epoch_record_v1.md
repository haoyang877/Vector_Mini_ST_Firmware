# APP 本次启动身份记录与页所有权 v1

日期：2026-10-08。独立实现候选，未进行设备写入；ROOT审查后才接入最终工程。
本契约在layout5的既有16KiB参数／身份区域内划分所有权，不改总边界、RAW或身份格式。

## 固定地址和权限

| 地址范围，右端不含 | 页 | 唯一写入者 |
| --- | --- | --- |
| 0x0801C000..0x0801D800 | 56..58，6KiB | RAW参数存储，当前实际记录4304B，schema12 |
| 0x0801D800..0x0801E800 | 59..60，4KiB | 保留；本实现不读作自由区、不写、不擦 |
| 0x0801E800..0x0801F800 | 61..62，4KiB | 本次启动epoch provider；每页2KiB |
| 0x0801F800..0x08020000 | 63，2KiB | 既有生产身份；本实现不改其64B格式或写权限 |

地址单一输入为 shared/targets/vector_mini_st_g431.json 的新增常量。
TARGET_PARAM_BASE、TARGET_PARAM_BYTES、TARGET_IDENTITY_BASE、TARGET_RAW_BYTES、
TARGET_LAYOUT、参数ABI及槽地址均保持。generic flash_write_param只允许1..6144B，
不再允许历史0x3800B范围，防止参数擦页覆盖保留区、epoch或身份。
当前APP唯一参数写调用由param_store_write传入sizeof(InterfaceParam)=4304B。
Loader只写APP槽，生产工具只操作身份页；历史代码宽写能力不构成可复用空间证明。

在现用代码中未找到61/62页的其他写入者，不代表现场数据已空白。
第一次分配必须完整读取两页，只接受全空白或本格式有效序列。
旧journal、其他非空数据、未知版本、撕裂和损坏一律不可用，不自动擦除或迁移。

## 32字节记录

所有字段显式小端；STM32G431为小端。每页64条，页内无额外头部或尾部。

| 字节偏移 | 宽度 | 内容 |
| --- | --- | --- |
| 0 | u32 | magic=0x31455042，字节42 50 45 31 |
| 4 | u32 | version=1 |
| 8 | u64 | 非零单调epoch，低32位先存 |
| 16 | u64 | epoch逐位补码 |
| 24 | u32 | 标准反射CRC32，复用Crc32_Compute(record,24,0)，覆盖偏移0..23 |
| 28 | u32 | commit=0x314D4F43，字节43 4F 4D 31 |

按偏移0、8、16、24顺序各写一次8B双字，CRC和commit处于最后双字。
写入前目标32B须空白；写入和完整读回验证成功后才发布RAM中的epoch。
失败即本次不可用，同次BootEpoch_Init不重试、不再分配。
[黄金记录向量](../../protocols/boot_epoch_record_v1_vectors.json)与生产核心的离线检查共同核对格式。

## 扫描与分配

两页均扫描完整64条。每页有效记录必须从首条连续排列，计数相邻增加1；空白后非空、
补码/CRC/commit错误或未知字段均拒绝。不能忽略无效尾部后继续复用地址。
两页均有数据时，较旧页必须满64条，较新页第一计数必须是旧页最后计数加1；
重复、倒序、重叠、缺口或溢出均拒绝。

从最大有效计数加1。当前页未满则追加；满页后使用另一页：空白不擦，
有效旧页才擦除且整页读回为空，最新页保持不动，直到新记录完成。
最高计数已经为UINT64_MAX时不再写、不回绕，返回EXHAUSTED和零身份。

在合法写入模型下，已经成功发布的记录一直留在当前页或较新的页。
完整新记录即使还没返回调用方，也被下一次扫描计入；中断发生在首次写前或完整擦除后，
允许重新分配尚未发布的下一计数。任意非空撕裂记录则停止分配。
这保证不会重用已发布epoch，但不承诺每次掉电后都能继续运行。

## 初始化和失败边界

provider只在关相确认后、采样中断和CAN启动前初始化；之后只读，无CRC、Flash或等待。
读取失败、未知记录、写入失败、读回不一致和耗尽均返回零身份。
BSP读前／后检查ECCC/ECCD，不清未知错误；ECCD触发既有NMI死循环，
因此可能停在初始化而不能发送诊断，不能宣称可在线诊断或自动恢复。
依据见[STM32 RM0440](https://www.st.com/resource/en/reference_manual/dm00355726.pdf)的Flash ECC章节。

受控维修和记录迁移策略尚未实现。**不能为了恢复而清掉两页，从1重新开始**，
这会复用主机已见过的身份。全片擦除、未受限旧固件或外部写坏页不在连续性保证内。

## 备份恢复和分域验收

恢复历史整片镜像或完整16KiB参数／身份备份，也可能把61/62页计数回滚到较小值。
历史记录即使格式、补码和CRC均正确，当前实现也无法知道更大的编号曾经发布过，
随后可能重用旧epoch。本方案**没有抵抗全片或计数页回滚的硬件保证**。

| 核对域 | 正常变化和恢复边界 |
| --- | --- |
| RAW参数56..58页 | 按4304B schema12核对参数与标定内容，不把epoch页合并为同一参数记录 |
| 生产身份63页 | 单独核对既有身份；普通参数保存和本provider均不写此页 |
| 启动计数61/62页 | 程序重新启动时合法追加或轮换；正常计数变化不算标定破坏，不要求与旧备份逐字节相等 |
| 保留59/60页 | 本轮不触碰，不把非空未知内容自动回收 |

备份可以保留完整现场，但恢复旧固件或参数时不得不加区分地覆盖epoch页，
也不得通过擦页回到1来恢复可用。现有计数需保持连续，参数和身份按各自明确写域核对。
安全维修、历史计数回滚识别和恢复工具的分域执行策略尚未实现；发现计数被回滚时，
不能继续声称跨复位唯一性仍成立。具体恢复操作须另行审定，本轮不提供自动修复机制。

## 接口兼容

GET_DEVICE_STATUS仍为原16B，完整u64在偏移8；有效位在偏移6。
APP有效时采用provider身份，普通APP阶段为CONFIRMED_APP，LoaderApp阶段仍取
BootHw_IsConfirmed的真实试运行确认状态；身份有效不等于镜像试运行已确认。
不可用时result=6、epoch=0、有效位=0、阶段UNAVAILABLE，按原编码器规则输出。
GET_INFO的u32 boot_id不代替该值；Loader nonce/升级session、UID/SN、参数revision与任务epoch不混用。

H新增两条START线路须匹配可信非零本次epoch；本provider本身不验证远程来源、
重试或租约，不代表所有旧开发命令已防跨复位重放。现有开发模式和控制数学保留。
零身份使新线路unsupported且对应能力位为0；协议适配由H负责，不把它变成算法或
本地所有者的隐藏准入依赖。旧117、旧单项维护及Watch仍为debug兼容路径，
正式生产对旧功率线路的注册和权限策略需独立闭合，尚未实现全产品防重放验收。
现场下载前须核对本项接线、真正关相和目标页内容；本轮仅离线证据。
