初始日期：2026-10-24。状态：范围对齐草案；2026-10-26同步已落地的目录归属。
已明确的用户约束按本页执行；尚待讨论的共用行为变化单列，不因已有代码或测试记录自动纳入。
本轮仅整理文档，不修改固件、下载、复位或运行电机。

## 1. 适配目标与覆盖对象

保留Vector Mini ST旧板，在同一份重构框架中适配YG-ESC_V1.0新板。
两板共用APP、状态机、电机控制功能、参数管理和通信业务；
板卡差异由平台实现和板级配置承担，电机差异由独立型号/装配配置承担。

| 板卡 / MCU | 适配电机与装配 | 范围及当前限制 |
| --- | --- | --- |
| Vector Mini ST / STM32G431 | HT8115-4，无阻尼环、有阻尼环 | 保留旧板支持，覆盖两种配置的构建和受影响功能回归 |
| YG-ESC_V1.0 / AT32F456 | YQ-5708，8:1 | 新板当前集成与验证的主要组合；完整产品验收尚未完成 |
| YG-ESC_V1.0 / AT32F456 | YQ-5740，40:1 | 纳入型号配置与后续逐型号验收；除型号和减速比外沿用5708输入 |
| YG-ESC_V1.0 / AT32F456 | YQ-8116 | 纳入扩展范围；现用HT基线为暂定数据，详细参数和对应验收待补 |

本表表示适配对象，不表示所有组合已经实机通过。其他板卡/电机组合后续明确后再加入。
硬件资源和电机数值统一引用[资源与型号表](../hardware/board_resource_registry_v1.md)，本页不重复维护。
既有型号标签不自动选择运行模型，新增型号不自动继承旧设备的LUT、电零位或实测参数。

## 2. 本适配范围内允许的改动

| 位置 | 允许内容 | 必须保持的边界 |
| --- | --- | --- |
| `projects/stm32g4/application/`、`projects/at32f456/application/` | 各板main入口、初始化和中断调度接线 | 调用同一套App四入口，不另建控制算法或主状态机 |
| APP装配与目标选择 | 必要的目标身份和模块装配，目标为一到两个装配/选择文件 | 不扩展到runtime或状态机行为；超出时先列清原因和影响 |
| `platform/bsp/`各板实现 | 时钟、中断、ADC、PWM、SPI/编码器、CAN、时间、存储等接口实现 | 按同一公共契约提供真实硬件能力，不向共用功能层暴露寄存器或厂商类型 |
| `platform/config/boards/` | 引脚/采样链输入、能力和固定板级限制 | 配置与外设实现分离；电路量程不等同于可安全运行电流 |
| `firmware/app/config/targets/`与`projects/`内的启动/链接及Keil工程 | 目标组合、工程源清单、芯片启动、各板地址布局和测试目标装配 | 兼容性变化明确记录，保持旧板普通APP和Loader配套APP可构建 |
| `motor/profiles/`及配置选择入口 | 电机与装配参数、统一1kHz电流环默认值 | 电机与板卡独立选择；不因改默认值自动覆盖已有有效人工PI |
| 离线测试、验证工具和文档 | 对应的路径、目标矩阵、接口替身、边界及证据维护 | 测试入口不自行下载或启相；定向通过与完整验收分别报告 |

旧板main迁入projects/stm32g4/application属于入口位置统一，迁移本身保持初始化顺序和行为。
两板各自保留真实main且模板相同，共用app_startup.c不定义main。
早期platform_app.c装配已被后续BSP重构替代，当前硬件初始化归MCU system.c；以[BSP架构总图](bsp_architecture_v1.md)为准。
新板平台优化应留在对应平台内；旧板驱动优化不是新增AT32驱动的必需步骤，须单独列项。
本范围的功能验证重点是外设采样、MT6835、电机开环、电流环和速度环，
最终运行路径接入共用APP；独立foundation台架仅作定位和阶段验证。

## 3. 冻结边界与共用改动规则

| 冻结对象 | 原则 |
| --- | --- |
| BSP公共API | 函数签名、类型/布局、单位、有效性、失败语义、执行上下文、时序和所有权保持一致；允许分离板级配置数据 |
| APP运行逻辑与主状态机 | 纯适配不改变命令准入、状态转换、任务完成/取消、STOP、保存及故障恢复行为 |
| 电机功能实现 | 纯适配不改变FOC、控制器、角度估计、标定和保护的计算或执行流程 |
| 参数与通信业务 | 共用参数校验、记录转换、协议和命令语义；现有存储字段、CRC、权限及兼容读取保持 |
| 时基与通信速率 | 控制快环20kHz、监督2kHz、CAN仲裁段1Mbit/s和数据段5Mbit/s保持 |
| 旧板支持 | 保留构建和功能路径；共享修改须同步验证旧板，不能只用新板结果代替 |

修改配置数值属于配置变更，仍须说明单位、来源、作用目标和存储覆盖规则。
状态机、任务调度、保护策略或数据写入所有权的变化属于共用功能/架构变更，
即使接口签名不变、两板仍引用同一文件，也须先单独讨论。
讨论材料包括问题证据、最小方案、影响文件/两板行为、验证办法与回退范围；
明确结论后再实施，新增请求不得以“顺便适配”为由扩大改动。

已存在于当前代码中的下列改动登记为独立评审项，本页不自动确认保留或要求回退：

| 独立评审项 | 需要明确的边界 |
| --- | --- |
| LUT关相后台发布 | 标定任务、状态机、Axis与工作区的提交/释放顺序 |
| 启动配置校验的临界区调整 | 启相准入、配置一致性、STOP/故障优先级及中断时序 |
| SAVE后测速重建 | 暂停采样后的速度有效性、重建过程及遥测含义 |
| MCU温度可选策略 | 测试例外与正式保护要求，自检、跳闸及恢复行为 |
| PA4母线电流接入APP状态 | 实测与估算来源、有效性及APP装配扩展边界 |
| 旧板PWM启动优化 | 与原HAL路径的等价性、两板适配必要性及旧板回归 |

以上已有记录和测试证据继续保留；文档整理不擅自删除代码或恢复历史实现。
正式接受的比较基线仍需明确，当前工作树和历史试验镜像不自动成为已认可的产品基线。

## 5. 交付与验证边界

每次代码任务先记录实际源码快照、板卡/电机/装配、构建目标、改动清单及冻结对象，
未提交源码也纳入哈希记录；功能范围确认与“是否测试通过”分别维护。

- 构建：旧板普通APP和Loader配套APP，新板本次相关的共用APP目标；HT两种装配及新增型号核对各自配置。
- 离线：接口/架构、控制和状态行为、故障/STOP、参数/协议兼容及资源时序等受影响项。
- 等价性：目录或配置搬迁应比对源码/配置、实际加载字节、资源和构建选项；差异必须解释。
- 实机：按具体镜像、组合及授权条件单独验收；共享行为变化同时覆盖新旧板的受影响路径。
- 结果：区分配置可编译、离线通过、关相实机通过、带功率通过和产品验收，未测明确保留。

两个工程“正常跑”须对应具体版本、工况和功能结果，编译成功不能替代运行验收。
后续变更本范围时记录用户决定、版本和影响，不以历史计划或一次试验记录默认为范围扩展。
