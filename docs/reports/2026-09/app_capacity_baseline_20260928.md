# 新 APP 容量基线与占用分析（2026-09-28）

本报告完成“先编译新 APP、分析原因”的阶段，不表示容量适配、功能回归或发布完成。
所有操作均离线，没有烧录、复位、写入设备参数或发送电机命令。

## 1. 源码与构建口径

集成基线为 `7280e257c0a0e411b15638f9436799e9a5b682f7`，工作分支
`codex/capacity-fit`。本次测量包含以下构建前置修复，不能称为未经修改的集成提交：

- CubeMX `main.c` 的 USER CODE 包含区补入 `control_config.h`，修复 RTT 描述符宏缺失。
- 协议枚举使用合法显式初值及无符号上界校验；共享镜像代码消除条件内赋值警告。
- 维护内存池从 7168 B 改为 6272 B，保留最大 6144 B 编码器工作区及 128 B
  管理余量。启动参数加载、背景保存、标定的借用互斥关系已核对；参数记录仍为
  4304 B，齿槽记录仍为 2064 B。最大借用、写满边界和释放合并的原生容量检查通过。
- 各借用大小增加编译期约束。3072 B 启动栈、512 B C 库堆和控制功能均保留。

原配置在补齐头文件后仍有 RAM 链接错误；内存池前置修复用于取得可测量镜像。
它没有解决 APP 的 Flash 缺口。

正式项目保持 ARM Compiler 5.06 update 7 build 960 和原有逐文件配置。
全局为 O1、空间优化，若干快速环/状态机文件单独使用 O3，函数分段保持开启。
此前 O3 和 ARM Compiler 6 的尝试已归档为实验；本报告基线不采用它们。

## 2. 当前尺寸

KiB 按 1024 B 换算。Flash 地址跨度包括必须保留的地址间隙；容量验收采用跨度。

| 工程 | ROM 有效数据 | Flash 地址跨度 | 静态 RAM（含声明栈/堆） | 实际区域 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 普通 APP | 112016 B / 109.39 KiB | 112016 B | 32080 B | Flash 112 KiB；RAM 32 KiB | 0 错误、0 警告；Flash 余 2672 B |
| Loader 配套 APP | 120448 B / 117.63 KiB | **120488 B** | 32312 B | Flash **79872 B / 78 KiB**；RAM 32736 B | 正式链接失败；跨度超出 **40616 B / 39.66 KiB** |
| 独立 Loader | 20036 B / 19.57 KiB | 20036 B | 5152 B | Flash 28 KiB；RAM 32736 B | 0 错误、0 警告；Flash 余 8636 B |

普通 APP HEX 范围为 `[0x08000000, 0x0801B590)`，没有进入从 `0x0801C000`
开始的参数区。Loader HEX 范围为 `[0x08000000, 0x08004E44)`。
两份 HEX 已校验记录校验和、地址跨度及冲突。

Loader 配套 APP 的真实工程发生 `.ANY` 区域容量错误，没有生成可用镜像。
为分析额外占用，使用同一批编译对象进行一次**仅测量链接**：虚拟增大 Flash
链接上限，保留 APP 基址、描述符位置和真实 RAM 上限；不改变正式布局。
临时文件均以 `NONDEPLOYABLE` 命名，不导出 HEX，不可用于烧录或升级。
测量地址跨度到达 `0x08025EA8`，已超出物理 Flash。

该测量还暴露正式 `app.sct` 的另一处缺口：描述符与代码执行区指定了执行地址，
没有指定 `FIXED` 加载地址。向量表实际只有 472 B，距离 512 B 描述符偏移有
40 B 间隙，链接器会压紧加载内容，导致自覆盖及根区域错误。测量脚本中固定
这两个区后取得完整 map；正式生成器与链接脚本尚待下一批修复，不能只扩容绕过。

普通 APP 的 `Code=106032`、`RO=5968`、`RW=476`、`ZI=31604`。
链接器把 RW 初始化内容压缩成 16 B，因此实际 ROM 为
`106032 + 5968 + 16 = 112016 B`，不能直接加 476 B。
调试信息、AXF 文件体积、map 文件体积都不计入 MCU Flash。

RAM 在普通 APP 中余 688 B；配套 APP 保留顶端 32 B 邮箱后只余 424 B。
这些数字是链接资源余量，不是实测栈水位或动态时序证据。

## 4. 缩减顺序与边界

1. 固定本报告基线，修复描述符加载地址；每次调整比较 map、镜像范围及工具链输入。
2. 先验证现有编译器各模块的空间优化、内联和库配置。保留浮点有限性检查与快速环
   语义；编译器迁移单独评估，不能以告警或行为差异未解释的实验直接替换工程。
3. 按上述大对象处理重复代码和被错误保持可达的路径。主状态机和维护适配保留唯一
   所有者、STOP/FAULT/取消守卫；位置控制和标定不得静默删除功能或保护检查。
4. 正弦表可尝试精确对称压缩：原表 1024 点、两个端点为正零，不能直接替换成另一
   采样方式的四分之一表。首先逐点验证 float 位模式，再考虑约 2 KiB 的节约。
5. 硬件驱动只在平台边界优化实际使用路径，保留 CubeMX 生成区规则。HAL 有实际
   初始化/中断调用，不能把所有 HAL 都当作未使用代码删除。
6. 最后复核 Loader 实际余量与布局预算。即使回收其全部 8636 B 余量，仍不足以
   解决 40616 B 缺口；布局变化还要求 Flash 页对齐和版本化契约，不能作为唯一方案。

当前没有采用 Flash 优化或修改目标布局；本报告提供下一批工作的测量依据。
保留 16 KiB 参数区、schema11 4304 B 记录、20 kHz/2 kHz 调度及现有控制功能。
