# 电机状态机最小核心拆分 v1

## 目标与不变行为

按用户要求保留全部功能，把状态条件、迁移和功率安全留在核心，将请求身份、维护、
保存收尾及运行编排拆开。保留八状态、公共函数签名、协议与参数 ABI、快慢环顺序、
STOP/故障优先级、代际校验、取消归还和启相最终复核；不改变控制算法或保护阈值。

## 基线与回退

基线是开始实施时的工作区，包含用户尚未提交的其他重构。相关源、工程、测试及文档
保存于 `outputs/state-core-minimal-20261030/before/`，哈希清单为同目录上级的
`baseline-hashes.json`。回退只恢复本轮改动，不重置或覆盖其他工作。

基线原生状态机夹具编译失败：没有指定 BSP_BOARD，且仍使用已删除的
EncoderState.bad_frame_streak / ENCODER_BAD_FRAME_OFFLINE_COUNT。
证据在 `outputs/state-core-minimal-20261030/baseline/`。

## 实现约束

- 运行上下文仍只有一份，Watch 身份保留；拆分函数显式传递上下文，不跨模块 extern
  可变对象、不创建第二套状态机或隐式初始化顺序。
- `motor_state_rules.c` 的确定性迁移规则保持原样；核心只汇总事实、提交规则、执行动作。
- 请求身份和进度、维护任务与保存结果有独立实现文件；外部接口通过薄入口保持兼容。
- 保留短临界区边界与动作次序，尤其是关相先于取消、发布载荷先于标志、快环最终启相检查。
- 所有新增生产源进入两板现有工程和原生测试；不触碰生成区，不接触硬件。

## 验收

1. 对照冻结源的状态、故障、请求/保存结果、功率动作轨迹和迁移规则输出。
2. 覆盖快环抢占、迟到结果、重复请求、取消与保存提交效果；更新夹具定位以编译真实拆分源。
3. 两板离线编译并记录对象尺寸；明确区分源级证明与未实测的 MCU 时序、栈、镜像差异。
4. 运行格式、lint、架构边界、相关专项及 PR profile；记录既有失败和新增失败。

## 结果

源码拆分完成。原 `motor_state_machine.c` 从2074行缩为526行，状态规则文件字节不变。
`motor_state_requests.c` 接管请求、序号和启动/目标进度；`motor_state_maintenance.c`
接管维护、结果邮箱、取消、保存及后台认领；`motor_state_runtime.c` 持有唯一上下文、
公共兼容入口和监督编排。维护叶任务及Flash实际写入仍沿用原模块。

### 对照与资源证据

- `source-equivalence.json`：85个原函数中83个在仅替换上下文传参和内部函数名后相同。
  其余两个变化是将取消动作和维护完成记录移动到维护模块；已逐语句核对调用位置和顺序。
  上下文字段、布局和规则实现保持不变，没有增加常驻状态。
- `scenario-comparison/summary.json`：34个场景逐个运行，拆分前后返回、轨迹和断言结果完全
  一致；28个通过，6个原有失败保持相同。覆盖启动/停止、远程重放、目标准入、维护保存、
  LUT发布、取消、快环结果及抢占窗口。纯规则262144个用例输出完全相同。
- 对照夹具使用明确的有效热参数；当前缺失默认配置不视为有效测试输入。数值关节配置
  的未调用解析分支使用失败即终止的测试替身，未覆盖该功能，也未更改生产参数。
- `parameters/`：真实参数事务与保存后台夹具通过；`status/`：快慢环快照、回绕和有界重试通过。
- 架构边界新增检查：核心不拥有通信历史或后台保存实现，唯一上下文不跨文件extern，
  四个应用工程完整编译所有拆分文件。每个新文件继承原状态机的板型编译选项。
