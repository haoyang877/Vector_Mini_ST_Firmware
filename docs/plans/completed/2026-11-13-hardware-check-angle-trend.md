# 硬件检测旋转趋势判据与 CAN FD 上位机复测

基线：`the-system-refactor` 提交 `7e1f9e45`，APP v1.8.0。用户已接受现有原始
角度曲线的整体趋势，明确要求不以单拍角增量波动幅度判失败，继续跑完测试并集成、
验证 CAN FD 上位机。历史失败报告保留原判据与原结论，不覆盖为新版本通过。

目标：APP v1.8.1 将动态角度展开后按连续 50 ms 窗口均值观察趋势；至少三个窗口后
辨识位移，比较双向整体旋向，保留趋势停滞和明显往返的检测。短时单拍波动仅作
原码诊断，不作速度连续性验收。每段净位移须可辨，且至少 2/3 的可辨窗口增量与整段方向一致；不比较局部折返
幅度。停稳使用电机角窗口均值，霍尔保留独立测项，不阻断其他项目。

不变项：八项静态原码判据（母线 RMS <50 cnt）、CRC/状态、霍尔原码范围、
电压/温度、运动租约、行程、故障、采样丢失、STOP 和超时；Type127 v2 载荷和参数
ABI 不变，电流 PI 不改，正常台架模式10、3 A。用户随后明确不需现场参照：电机角须与三相开环命令符号对应，霍尔不作安装方向关联。

设计：修改只在板端检测统计，窗口状态随本轮会话维护；复用原角度展开与趋势轨迹，
新增一个私有窗口类型表达累加生命周期，不另拆文件或新增跨模块抽象。上位机沿用
现有硬件页与串行工作线程，增加新判据说明、匹配内置固件及版本显示。

验收：单拍高频波动与短时扰动可通过趋势；趋势明显逆行、停滞、同向去回仍不能
通过；CRC/范围/超时/STOP 回归不变；PR/release、当前台架静态和双向检测、打包 GUI
实际操作验证。每项记录通过、异常和未测，命令/编码器方向自动比较，原始观测仍不伪填为人工观察。
趋势异常仅锁存本项失败，继续收集其他项；硬件保护立即中止。中间零频保持改为 500 ms。
回退：旧 v1.8.0 调试包和本轮下载前整片备份；产物与证据归 `outputs`，旧包不覆盖。

## 结果

已实现 APP v1.8.1 和 CAN FD 工具 v1.7.1，冻结固件提交 `62dab971`，
208单元、21集成、47原生及六工程构建的 release 档通过。
当前台架3 Hz、6 Hz完整双向均确认电机正命令角度增加、负命令角度减少；
打包 GUI 另完成静态和3 Hz双向验证，不需现场旋向。九项正常，霍尔动态异常；
50ms首答存在超时，重试不清除可靠性失败。8 Hz目标 ACK 丢失后已STOP，不计通过。
实际关相、CPU运行，保存参数和保护区不变。详见[当前报告](../../reports/2026-11/hardware_check_v1_8_1_20261113.md)。
本轮功能集成及测试范围结束，剩余独立异常转入[HWCHECK-001](../tech-debt-tracker.md)。
