# 启停与标定核心语义 v1.5

2026-10-30：按用户要求继续删除非核心逻辑，同时保留编码器线性化、电气零位和机械零位标定。

- 117保持零目标启动，110保持实际关相确认，清错后仍须重新启动。
- 普通目标下发116不再绑定APP控制端口，返回UNSUPPORTED。没有目标邮箱或命令进度。
- 启动资格明细参数0x4F..0x51不再提供，返回UNSUPPORTED；实际启相仍执行全部必要检查。
- 运行反馈只提供状态、控制模式及故障；测量有效位恒为零，不将清零字段解释成真实测量。
- 标定继续通过APP接口受理和执行；完成后关相返回空闲，LUT发布仍校验原代际。
- 保存和通用维护任务协议继续不支持。参数Flash格式不变，运行修改仍只影响RAM。
- 升级票据只在组合层维护。生命周期只提供不可撤回的停机锁和实际停止查询；复位前再次复核。

启动请求不等于已启相，主机须读取RUNNING状态。旧主机不能再依赖116或测量字段进行控制，
也不能把测量有效位为零的样本当作有效反馈。帧长度、消息编号与错误码不变。

GET_CAPS当前为features=0x1C00、supported_modes=0，不再声明普通目标控制能力；CAN FD、分片和状态帧能力仍保留。
页0负载：`00 1c 00 00 00 00 40 00 2e 00 00 00 00 00 00 00`。
错误负载和当前能力页登记见[黄金向量](yg_protocol_motor_state_v1_5_vectors.json)。
