# 重构工作树与 CAN 波特率功能集成

## 范围与基线

在 `feat/configurable-can-bitrate` 接纳 `the-system-refactor` 工作树的全部开发改动。两者起点均为 `76e91dc3`，后者的未提交内容是本次输入。已提交的波特率接口、AT32 Loader 接收过滤和 CAN-Link-Test v1.6.1 随功能分支交付。其他工作树各自独立。本轮只在功能分支提交，留给维护者统一处理。

## 实施与验收

冻结原工作树的路径、文件哈希和 Git 基线。逐项核对 G431 的 APP、Loader、CubeMX、调试工程、测试工具和台架记录，登记退役工程与本地工作树元数据的来源。适配跨板接口时分别核对 AT32 的 1M/5M 默认档、G431 的 500K/2M 固定档、节点地址和参数 ABI。

在干净提交上构建双板固件，重新冻结 AT32 的 Loader、APP、CAN 升级包和 Windows 测试工具。复核 SHA-256、HEX 地址、参数区、桌面内置载荷和 ZIP 解包结果。比较重构基线与仓库默认分支的 Git 合并结果，运行对应的 PR 和 release 检查，分别记录既有失败与集成回归。

独立单节点实测覆盖仲裁 500K、1M 与数据 500K、1M、2M、3M、4M、5M 的全部组合。在 1M/5M 识别实物，记录 UID、原版本、参数和回退镜像。每组保存配置、重启，以新速率查询 APP、进入 Loader、完成 CAN 下载和持久确认。结束时恢复 1M/5M 和现场状态，区分设备、适配器与离线验证结果。
