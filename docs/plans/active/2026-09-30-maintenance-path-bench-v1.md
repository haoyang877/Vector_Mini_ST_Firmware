# 轮电机维护标定通路验证 v1

日期：2026-09-30。分支 `codex/system-refactor`，候选源码与镜像按各轮输出哈希固定。

## 目标与边界

按顺序验证齿槽转矩、相电阻、摩擦辨识三项维护任务的受理、执行、结果、取消/停止和
资源释放。轮电机架空无负载，33 V、电源 3 A、相电流上限 6 A、最高 300 rpm、6 mΩ。
之前角度 LUT 与电零位已保存；不把速度闭环的单次通过当作摩擦辨识的资格证明。

## 当前差距及最小实现

- 当前 CAN 160 只映射 LUT、电零位、齿槽。相电阻与摩擦的算法和主状态机所有权已存在，
  但没有 CAN 启动入口。用连续 kind=4（相电阻）、kind=5（摩擦）扩展同一 160～162
  协议，不增加任务状态机或直接写控制变量的入口。
- 更新版本化线路文档、黄金向量和离线测试；未知 kind 仍拒绝，同票重试、原 ticket
  查询/取消与 STOP 屏障语义不变。相电阻结果只在活动 RAM 中，摩擦只生成候选，不
  自动保存或应用。
- 用已冻结镜像先测试齿槽通路；新映射构建后下载并核验参数区保持，再分别测相电阻和
  摩擦。齿槽全表需双向 2048 点，理论合格窗口至少 409.6 s；若只做短时启停，必须
  明确标成通路冒烟，不能报“标定完成”。

## 验收和失败处理

每项核对 UID、镜像、参数、READY/零目标/关相/资源、偏置完成及轮电机配置；仅通过
CAN 维护所有者启动。监控编码器样本、故障、母线/相电流/速度及读取时延。原 ticket
的终态、STOP、NONE 零目标、三相关闭和资源释放分开核验；不以 ACK 或部分进度冒充
成功。不能确认 STOP/关相即要求现场断电，禁止继续下一项。

代码改动通过 PR 验证与 Keil 0 错误/0 警告构建；dirty 调试镜像不冒充 release PASS。
每轮保留完整报告、Flash 备份、源码/工具/镜像哈希；不覆盖旧失败证据。新的持久化
结果必须回读记录及 RAM 一致性；不改变已有 LUT/电零位。
