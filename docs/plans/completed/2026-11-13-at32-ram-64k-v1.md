# AT32F456 APP 64 KiB RAM 优化

基线：`f5a4ef7a`，独立分支 `codex/at32-ram-64k`。

目标：两种 AT32 APP 的 SRAM 代码、数据、8 KiB 栈和32 B邮箱合计不超过
65536 B，数据紧邻热代码；保留板端独立联合标定、2048组样本和1024点LUT。
原基线为 ER_FAST 32660 B、RW+ZI 59168 B，总计91828 B（不含邮箱）。

不变项：原码区间均值、浮点运算次序、构表/拟合、采样频率、保护阈值、Flash布局、
参数schema和CAN线路格式不变。不连接硬件，不改原工作树。

实施：12位Hall均值无损打包；复用标定样本、参数记录、检测采样队列的互斥存储；
保留检测报告；统一检查维护存储所有权；缩短RTT缓冲；逐函数收敛SRAM代码。
禁止把同时使用的电机标定工作区与输出轴采样重叠，不依靠缩栈达标。

验收：采样打包全值域、原算法逐字节对照；标定/检测/参数冲突、取消和重新进入；
PR全套、六目标Keil构建、64KiB链接断言。源码干净后执行release档。
时序迁移需要后续明确台架授权后验证最坏快环耗时；离线通过不代表实机时序通过。

回退：独立分支保留基线；不烧录，原分支及其产物不变。
证据统一位于本工作树的`outputs/ram64/`和`outputs/runs/`。

## 离线实施结果

两种AT32 APP均达到64 KiB预算，保留8 KiB栈、板端标定、全部样本及LUT。
配套APP：ER_FAST 18092 B、RW 72 B、ZI 43976 B、区域间对齐4 B、邮箱32 B，
总预留62176 B（60.71875 KiB），距65536 B余3360 B。独立APP总预留62104 B。
基线分配91828 B，含108 B区域空洞和32 B邮箱为91968 B；按同口径减少29792 B。
APP BIN由94400 B降至94064 B。Flash分区、schema14和协议版本不变。

输出轴存储保持完整int32连续计数，两个12位Hall均值由4 B压为3 B。
参数记录移入`MotorCalibration.storage`，检测仍保留128组队列，借用同区的5120 B；
检测统计和结果独立保留。所有使用记录的参数入口及标定入口检查检测占用。
8 KiB栈未缩小。RTT波形缓冲4096→512 B，容忍主机暂停时间缩短，仍满时丢整帧。
SRAM代码按函数收敛，初始化/参数维护及4 kHz外环回到Flash；ADC采样、FOC、编码器、
无感标定和所需内存库保留在SRAM。两种链接布局都包含64 KiB预算断言。

## 验证与限制

- 全部16777216种Hall整数对及完整int32随机计数往返无损。
- 冻结`f5a4ef7a`算法与新实现两板各62次结算比较，完整输出结构、状态、方向、
  相位及1024点Hall LUT逐字节相同；脚本及日志在`outputs/ram64/`。
- 参数/型号配置与检测冲突、标定BUSY、检测报告保留、超时/溢出释放及重新进入有原生回归。
- 六个Keil目标零错误、零警告。最终release档状态以本工作树最新summary为准。
- 前两次PR发现新增回归夹具未链接参数模块，已移入实际APP实例测试；新worktree缺失的
  历史outputs引用通过复制原证据/只读用途目录联接恢复，没有削弱检查或伪造证据。
- 没有连接硬件或烧录。Flash执行的4 kHz路径、ADC中新增有界队列复制及整体中断嵌套
  仍需目标板最坏时序和栈水位复测；保持debug候选，不作量产或实机精度验收结论。
