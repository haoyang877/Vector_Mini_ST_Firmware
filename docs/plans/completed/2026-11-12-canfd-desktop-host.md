基线为 ac153baa，测试端沿用五轴脚本和 50 ms 首答时限。桌面工具提供通道、位速率、节点勾选、定速查询、阶梯压测、五轴验收及手动原始帧发送。启动界面不访问硬件。使用独立采集进程和正常 CAN 发送模式。

## 实现与对照

界面沿用通信压测和协议发送两个页签，压测由独立进程调用同一个五轴 CLI 收发函数。适配器以正常模式发送，请求在应用层只提交一次。旧版上位机的单次发送模式在对照中共 1,000 笔收到 554 笔，正常发送 1,000 笔均收到应答。节点 7 的 SWD 队列计数对照中，单次发送的 50 笔有 26 笔缺少应答，这 26 笔均未进入电机软件接收队列。正常模式的 50 笔均进队并返回。证据位于 `outputs/gui-can-loss-diagnosis/`。

默认定速模式从打包后的 EXE 运行，五台各 1,000 笔状态查询，总速率 50.01 笔/秒，5,000 笔均在 50 ms 内通过，P99 为 3.071 ms，最大 6.912 ms。此次上位机未写入固件或参数。

离线验证覆盖发送模式、BRS、设备索引、通道选择与释放，3 项适配器测试通过。手动报文的 ID、长度边界、六个快捷查询和置信门槛检查通过。整仓 release 的格式、lint、工程布局、架构、接口和 hygiene 通过。文档检查与上一轮 release 的输出相同；Python 测试仍有文档断链与旧平台目录两项失败，工作树未清洁，固件发布清单未通过。本次整仓记录为 `outputs/runs/20261111T184436066470Z-ac153baa/summary.json`。
