# CAN FD 连续二十次升级实测

日期：2026-10-20。结论：**20 次连续升级全部通过，整轮失败 0 次，整轮重跑 0 次**。
使用 Loader v2.0.0 / APP v1.4.2，固件源码为重构分支的 `903f71fa`。
完整 release 验证及单轮修复背景见[首次联合升级报告](loader_layout6_upgrade_20261020.md)。

## 方法与结果

开始时通过 SWD 安装配套固件一次，之后连续运行二十轮：APP 发起升级请求、完成停机交接、
Loader 擦写 APP、整包校验与激活、新 APP 通信并完成持久健康确认。轮间没有通过 SWD
重刷、人工复位、补写确认标记或跳过失败帮助通过。CAN0 使用 ISO CAN FD，仲裁 1 Mbit/s、
数据 5 Mbit/s；每轮传输 80,360 B APP。

每轮均核对同一 UID、版本和 CRC，记录实际 APP、Loader、新 APP 角色变化；随后两次
回读 Flash，检查完整 APP、Loader、参数、身份和 Option。二十轮事务 nonce 均不同，
升级后的整片 Flash 哈希在二十轮中完全一致。没有发送电机使能或运动命令。

升级过程平均 **37.335 秒**，最快 36.254 秒、最慢 39.242 秒。
整个台架流程为 771.117 秒，包含首次安装、逐轮回读和最终恢复。

客户端有界重发保持启用。成功回复中，状态查询累计发生 24 次重发，激活后的身份查询累计
发生 20 次重发；没有出现 APP 数据写入请求重发。这不等于零丢帧，也不属于整轮失败后重跑。
APP 运行阶段探测 Loader 状态的无回复不计入这项成功回复统计。

## 恢复和证据

本轮重新备份了测试前的 128 KiB Flash，没有借用旧快照覆盖现场状态。结束后恢复原程序；
参数和身份区未被升级改写，Option 保持一致。恢复后的完整 Flash 连续两次读回与本轮原始
备份逐字节相同。最后一次探针观察为 CPU 暂停、六路主动低电平且相位输出关闭，随后释放设备。

证据位于本工作树 `outputs/bench/loader-layout6-repeat20-20261020/`：

- `summary.json`：连续计数、耗时、最终恢复及结束状态。
- `round-01.json` 至 `round-20.json`：各轮协议回复、角色变化、回读和输出状态。
- 各轮 `*-can.jsonl`：原始 CAN 收发记录。
- `prepare.json`、`flash-before.bin`、`restore.json`：本轮备份与恢复证据。
- `verification.json`：独立核对二十轮计数、唯一事务身份、相同镜像及恢复哈希。

原板 schema 10 参数保留，测试 APP 使用当前默认配置及救援节点 1，没有进行参数迁移或
电机校准。二十轮测试覆盖正常升级；真实掉电、故障 APP 救援和运行中总线错误仍需独立用例。
