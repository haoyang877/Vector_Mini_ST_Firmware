# BSP接口执行与配置约定（修订6）

状态：接口已接入两板，离线构建、回归和干净快照release通过；按用户要求，统一实机验收后置。
与[头文件入口](README.md)共同构成契约。第2节明确记录相电流零偏收尾的调度调整，不能将其称为原草案时序逐拍不变。
下列步骤定义所有者和先后条件，不允许新增空转发层来照抄步骤。

## 1. 入口及三个执行上下文

两板使用同一main流程模板，MCU启动汇编和SDK仍按目标编译。
BootHw_Init由Bsp_Init调用一次，应用仅用BootHw_IsAvailable读取缓存结果，不二次初始化。

| 阶段 | 归属与执行内容 | 必须保持的边界 |
| --- | --- | --- |
| Bsp_Init | BSP：先安全输出，BootHw早期交接，时钟及各启用模块准备/硬件校准 | BootHw在HAL/开中断前；失败保持关闭并锁存，不在本次启动重试 |
| App_Init | 应用：参数、控制对象、通信对象、一次性窗口和健康计数初始化 | 不再启动ADC/PWM或写寄存器；新上电零偏仍未完成 |
| Bsp_Start | BSP：开放采样、DMA及原监督时基 | 可以立即进入应用回调，应用必须已就绪；不启相 |
| BspCan_Start | BSP：按原目标时点开放CAN | 接收对象已就绪；轮询/IRQ按目标选一种 |
| BspWatchdog_Start | BSP：仅有应用看门狗的目标显式启动 | 保留原时点/重装值；Loader继承看门狗不重复初始化 |
| 前台循环 | 应用处理协议、参数任务、诊断及健康判定 | 达到全部健康条件才Feed；不增加无工作内容的Bsp_Process |

启动函数失败后只走既有的关相/故障终止路径，不忽略BspResult继续执行。

| 上下文 | BSP负责 | 应用负责 |
| --- | --- | --- |
| 快采样IRQ | 确认/校验原硬件帧，发布快照，按原故障行为关断，再调用OnFastSample | 编码器流水、电压与电流检查、上电零偏、控制计算、窗口快拍截止；顺序沿用现有实现 |
| 监督IRQ | 保持原节拍并调用OnControlTick | 原慢估计、辅助数据处理、保护和状态机提交；唯一温度处理点调用UpdateAuxiliary再ReadChannel |
| 前台 | 原有硬件动作封装和有界状态查询 | 参数保存、CAN TX完成消费、协议、诊断、健康喂狗；不直接读DWT/寄存器 |

AT32的现有快拍预算和故障关相仍在BSP IRQ包围应用回调的原位置；快/慢进度计数可由应用
回调所有者维护。已有FastLoopProfile诊断接口继续保留，不用TimeUs冒充周期精度。
BspAdc_UpdateAuxiliary统一取得完整快照、按序号去重并调用McuAdc_ConvertTemperature纯换算；
STM32在换算后、缓存发布前调用McuAdc_ContinueTemperature，未取得帧时也继续推进空闲ADC。
AT32保持DMA自动采样；禁用和忙碌判断仍归MCU实现。
BspAdc_UpdateAuxiliary接在原Temperature_Poll的位置，保留读取上一帧、换算、触发下一帧的
顺序。不能把转换启动任意挪到监督回调末尾，也不能每次Read都启动硬件。

## 2. 上电采样与零偏生效

1. Bsp_Start后，快帧sequence随硬件完成推进；尚未完成各自零偏时对应电流组无效，但BUS_VOLTAGE_VALID可独立置位。
2. 应用按原顺序读取本拍电压并更新保护/电压额度；不使用无效电流字段。
3. 快中断读取ReadRawCurrent，按原20k帧数量累计整数原码；满窗后冻结，不再累加。
4. 2kHz监督任务计算均值并验证原范围；在短临界区重新确认关相和控制模式后调用SetPhaseOffsets。
5. 只有提交返回OK才同时发布配置偏置和应用complete；下一快拍进入原Current_Cal/过流检查。
6. BSP的Setter仍支持关相ISR原子提交；提交本身不推进采样sequence，随后读取同一缓存可得到有效物理量。

实施差异：原草案要求在满窗快拍内完成均值与提交。AT32实测发现该一次性收尾超过原快环预算，
因此保留原样本数、计算结果、范围和启动准入，将应用收尾移至监督任务。正常调度下增加至多一个
监督周期的启动等待；原草案的“同拍应用完成”不作为当前行为保证。此项不是修改BSP函数签名，
也不能宣称应用时序逐拍等价。最终AT32关相及CAN查询实测最大6574周期（约36.52µs），
原9000周期和PWM窗口保护不变；只覆盖该镜像与关相场景，
见[实测报告](../../reports/2026-10/bsp_private_at32_hil_20261026.md)。

母线电流原码来自PWM快帧的bus_current_counts，也可通过统一ReadRawChannel读取同一缓存。
它使用独立BUS_CURRENT有效位和独立零偏，不能借用相电流偏置或增益。
应用可保留原监督节拍的标定/滤波，保持128个监督样本的时间窗口、轨限和中点校验；
SetBusCurrentOffset成功后才发布标定完成。快采样改变后，监督读取的快序号正常跨多个快周期，
不能再用相邻监督读取的sequence差为1判定连续，更不能无说明改成128个快样本缩短标定时间。
MCU温度原码仍包含同帧VREF，缺出厂校准只影响物理温度，不影响原码诊断。

ReadFast返回OK的含义是取得新鲜完整硬件帧；每个功能组的valid_mask分别决定物理字段能否使用。
未使能、未校准或转换无效的组不置位，字段为NAN；传输不完整/超龄则整个调用失败且不改输出。
ReadChannel对三相电流、母线电流、母线电压使用同一快帧缓存；ReadRawChannel同样读取相应快原码。
单独调用不保证同拍，控制仍使用ReadFast，同拍电流原码仍使用ReadRawCurrent。
共用ADC的采样发布只在最高优先级且不可抢占的ADC完成上下文执行，不再嵌套临界区。
读取与零偏修改仍保留原同步：最多两次无锁复制，连续冲突时第三次短临界区兜底。
单通道读取只处理所选通道，并从同一副本取得原码、序号和时间戳；仅请求物理值时施加零偏和单位换算。
原码读取不执行电流、电压或温度物理换算。物理读取直接填充BspAdcValue，不再经临时原码结构转存；
慢通道在原短临界区内只复制调用方所需字段，不先复制整份缓存。辅助和温度序号由各自的发布函数分配并返回，
删除先查询下一序号的步骤；AT32正余弦使用辅助发布返回的同帧序号，STM32不再另有温度计数器。
辅助快照携带原码、发布序号和原发布点时间；换算后不得重新读取全局序号或用当前时间刷新样本年龄。
AT32记录DMA完成发布时刻；STM32记录消费JEOS完成帧并发布的时刻，不宣称精确采样保持时间。
温度与VDDA在一次纯换算中共用VDDA计算结果，但分别返回有效性和错误分类：
温度缺校准或无效仍为NOT_CALIBRATED，VDDA独立保留NOT_CALIBRATED/IO_ERROR/OK。
电机NTC保持自身算法和SENSOR_FAULT；原码读取不受对应物理量换算失败影响。
只有完整帧实际发布才推进序号；重复读取、无完成事件和失效不推进，失效后也不重置计数。
慢通道缓存只为电机温度、MCU温度、VDDA和硬件版本保留槽位，不重复缓存五个快通道。
Axis在每个快拍的原电压采样位置只调用一次ReadFast，将该局部只读样本同时传给电压与电流处理；
处理器不再次访问BSP。读取失败以NULL传递，沿用原NAN及故障路径，不缓存为下一拍的旧样本。
完整通道、单位、原码来源及两板能力见[覆盖表](COVERAGE.md)。
已有VDDA温度诊断通过ANALOG_SUPPLY_VOLTAGE提供V单位，原mV遥测在应用边界转换，线上单位不变。

## 3. 功率窗口与关相事件

窗口时长、一次性规则和运行策略仍由应用拥有，固定在现有电机状态机的功率准入所有者。
其它应用模块不能直接调用BspPwm_Enable。BSP不保存窗口、时长或业务模式，只保存硬件状态及
每次关相推进的disable_sequence。GetStatus单次读回状态和序号，不在BSP内屏蔽中断或重试。
快环为最高优先级、不可抢占的唯一占空比提交者；前台需要一致快照或执行启停时，由调用方保证互斥。
应用功率准入保留原短临界区，前台功率契约检查在同一短临界区读取输出与窗口状态。
初始化在采样中断开放前完成，并只在此时缓存PWM换算周期，运行中不改变周期。
占空比换算后调用一次MCU提交；MCU检查期限并写比较寄存器，超时返回后由公共BSP统一关相并锁存。
故障处理按原路径先关相。

| 事件 | 应用唯一功率所有者的动作 |
| --- | --- |
| ARMED首次请求 | 同一短临界区检查现有模式/故障/武装期限，读GetStatus，尝试Enable；成功记录该序号为active_disable_sequence并进入ACTIVE |
| ACTIVE重复请求 | 同一短临界区先比序号，再检查原毫秒/快拍期限；序号不等即消费为DONE并拒绝，不能取新序号重新延长窗口 |
| 正常Disable | 立即硬件关闭，BSP推进序号；调用方同时将ACTIVE窗口消费为DONE |
| BSP故障/硬件保护关闭 | BSP先立即关闭并推进序号；应用最迟在下一次准入检查或原快拍窗口检查时消费，不能因当前又为ON就漏掉历史关闭 |
| Enable拒绝/部分开启 | BSP在失败返回前统一Disable并核对关断；应用消费本次请求，不重试或重装窗口，按原故障流程收尾 |
| 快拍/毫秒到期或原速度边界 | 在原检查点立即Disable，窗口EXPIRED；保留两种时间来源及原速度界限 |

关键顺序：EnterCritical → GetStatus → 检查序号/应用准入 → Enable或拒绝 → ExitCritical。
这一段不能包含等待、协议、Flash或算法循环。主状态机已经有功率提交位置，改在那里落实，
不再新增一个通用电源管理对象。窗口记录的序号只在首次成功启相时建立，不能在重放请求时刷新。
ARMED阶段的关相不会凭空消耗尚未启动的窗口；仍按原武装超时和应用故障准入规则处理。
BSP的所有软件关断及硬件保护ISR均进入统一记录路径；不得绕过它直接清使能位。

## 4. Flash事务边界

应用先取得现有配置保存独占权并准备稳定记录；BSP负责整个硬件事务：

1. 拒绝ISR调用、非法长度、指针加长度溢出、源缓冲与目标擦除区重叠。
2. 保存原中断屏蔽状态并屏蔽中断；在屏蔽后再次确认实际关相与控制器资格。
3. 保持原ADC/DMA暂停、擦除、编程、回读及恢复顺序；两板原本不同的必要动作留在各自实现。
4. 硬件安全且操作完成后才恢复采样，再恢复进入前的中断状态；成功不恢复功率。
5. 状态不明/忙超时锁存写禁止，不继续擦写或盲目恢复采样；保持原故障/看门狗兜底。

调用方移除仅为Flash寄存器事务设置的外围长临界区；应用任务/参数独占仍保留。
普通BspSystem临界区只用于短状态操作，Flash是BSP内部拥有的特殊完整屏蔽事务。
软件轮询计数不保证墙钟上界；同bank取指停止时CPU可能无法继续轮询，不能依赖IRQ时钟保证超时。
读取容量与可写RAW区域容量分别沿用现有布局，不把生产身份或其他记录页并入擦除范围。

## 5. 能力与目标配置对应

本表已接入现有config体系，不创建第二套运行时能力对象；未绑定功能保持关闭。

| 功能 | 硬件配置 | 目标选择/应用要求 |
| --- | --- | --- |
| 三相电流/母线电流/母线电压 | PHASE_CURRENT、BUS_CURRENT、BUS_VOLTAGE各自资源、比例、极性 | 三组独立ENABLED/REQUIRED；ReadFast按组标有效，未提供组不参与快帧收齐条件 |
| 温度/VDDA/硬件版本 | 对应实际接线、采样周期、最大年龄、极性/比例、校准来源 | 复用已有功能开关；补硬件版本及VDDA能力；原码和物理值用同一使能，不伪造默认数据 |
| PWM/编码器/LED | 真实通道、器件型号、时序、可用颜色、灯是否共用 | 目标使能与必需条件；PWM提交窗口和最坏预算需验证；颜色无能力则拒绝或沿用明确映射 |
| CAN | 控制器实际支持的经典帧、FD、BRS、远程帧能力 | 单一RX_OWNER为IRQ或POLL；现有APP继续限定扩展FD+BRS，台架按原配置使用 |
| UART | 实际实例/引脚、波特率、帧格式、DMA、TX/RX容量 | 当前未绑定且禁用；接入时校验TX期限及前台服务间隔，不选猜测引脚 |
| Flash/身份 | 固定读区域、RAW写区域及容量 | 保持现有参数/Loader布局，应用记录大小必须在编译期验收 |

未支持或未启用返回NOT_SUPPORTED；已启用但未启动返回NOT_READY。非法参数与硬件未提供同时
发生时不依赖错误检查优先级做业务判断。关相、查询及零长度操作的特殊语义以各函数注释为准。
必需功能缺失在编译期报错；不是增加运行时探测或依靠源文件存在性判断。

### 快母线电流的硬件迁移条件

AT32母线电流已从TMR6触发的普通序列迁入ADC2的PWM同步注入采样；按同一PWM周期收齐，
不沿用2kHz辅助结果并赋予新的快序号。触发/rank与错误收尾已有离线回归，模拟建立时间和实际
最坏耗时仍须实测。STM32没有独立传感器，不增加虚拟采样。ReadFast中母线电流是否有效由真实
能力、当拍结果和自身零偏决定，硬件改动已实现不等于实测验收通过。

## 6. UART错误与完成

UART只提供字节流：发送接受后保留一个完成槽，最后停止位完成或传输失败后产生一次终态；
TakeTxResult消费终态并释放槽，RX错误不会覆盖TX结果。没有自动业务重发或第二层应用队列。
发送活动期间，TakeTxResult同时推进期限检查；超时先收尾，再一次报告TX_TIMEOUT。
不能确认TX静止时报告TX_ERROR并锁存发送禁止，即使终态被消费也不能再次提交；细节见第12节。
RX发生错误后冻结接纳并锁存错误；下一次非零Read原子丢弃整个接收缓存、报告错误并恢复接纳。
此后由上层寻找协议帧头，BSP不识别“损坏业务帧”。新错误再次锁存，不因取TX结果而清除。

温度和VDDA共享内部参考采样时，硬件序列需求按两者使能的逻辑或计算，通道有效性分别判断。
温度/VDDA的共享资源条件已接入两板配置；没有自动开启未绑定的UART或硬件版本采样。

## 7. 设计级验收场景

| 场景 | 必须能用公开接口表达的结果 |
| --- | --- |
| 上电未标定 | ReadFast为OK且仅电压有效，ReadRawCurrent可采标定数据 |
| 母线电流未标定 | 快原码帧该组有效，快物理帧该组无效；ReadChannel为NOT_CALIBRATED，其它快组不受影响 |
| 母线电流快结果未按期完成 | 不发布冒用旧样本的新快帧，按既有采集故障策略处理 |
| 无独立母线电流传感器 | 两个快帧的母线字段NAN且清有效位，单通道读取NOT_SUPPORTED |
| 零偏提交 | Setter成功后同一序号读取可有效；应用由监督任务发布完成，下一快拍开始使用，失败不置complete |
| 中途关相又收到启相重放 | 旧ACTIVE序号不符，拒绝并消费，不能续期 |
| 参数保存 | 调用方不操作寄存器；BSP独占屏蔽/暂停/擦写/恢复，失败锁存且不启相 |
| CAN轮询台架 | 不启用RX回调，前台单消费者使用同一Receive，无第二套CAN接口 |
| UART TX失败同时RX溢出 | 分别通过TakeTxResult和Read消费，互不覆盖，不伪造发送成功 |

这些是契约场景，不是硬件运行通过的声明。后续实现必须用现有原生测试、双板构建和授权台架
验证实际状态、采样值、故障、参数ABI和时间预算，不能只检查函数存在。

## 8. PWM提交窗口与失败收尾

三相SetDuty是一个逻辑提交：全部参数先校验，按原舍入换算，再一次暂存，三相必须在同一
既定硬件更新事件生效。不能让A相使用本次值而B/C相还使用上次值；OK只表示完整暂存。

| 场景 | 约束和结果 |
| --- | --- |
| 正常快环提交 | 唯一快环写入者在采样后的原提交点调用；生效事件沿用该目标原事件，不额外延迟一拍 |
| 截止前安全提交 | MCU实现根据计数方向、计数值、有效更新事件及最坏写入预算，在首写前确认余量；短临界区防止软件抢占 |
| 已错过窗口/余量不足 | 不写三相预装载；BSP执行统一关相并返回TIMEOUT，应用按原截止故障路径处理且不得重试 |
| 非法占空比 | NaN、无穷或范围外均拒绝，三相不写、不自动截断；应用不能忽略错误继续运行 |
| 关相预置 | 与快环写入互斥，并在启相前保证预装载已完整生效；不得借强制更新改变采样相位 |
| 单相台架 | SetPhaseDuty仅由台架唯一写入者使用，按原台架窗口生效，与三相控制不能并行 |

AT32的TMR1 CH2/3/4与STM32的TIM1 CH1/2/3负责三相；各自的采样比较通道不得被提交修改。
软件关中断不能停止硬件更新。禁止用强制UG、重置计数器或随意屏蔽更新事件补救窗口，避免
改变PWM/ADC相位。两板已实现提交窗口检查并通过原生寄存器/HAL回归；不能只依据中心对齐模式认定已经同步。
有效更新边界、重复计数影响和实际最坏提交耗时仍需统一实测，确认新判定不会拒绝正常控制路径。
若目标不能保持原生效事件且保证同次生效，先报告时序冲突，不能悄悄改控制延迟。

Enable仅在实际六路和总输出读回完整开启时返回OK。存在PWM硬件时，任何失败返回前由BSP
统一关断、推进disable_sequence并复核关闭；不再等待应用做首次关断。关闭读回仍不完整时
锁存故障并进入既有致命路径，GetStatus保留真实INCOMPLETE状态，绝不伪报OFF。
应用仍消费本次功率许可，禁止重试；额外防御性Disable可以重复，但不是接口安全成立的前提。

## 9. 编码器控制样本与诊断

Begin/BeginReadback/Complete保留原三段重叠，不新增SPI访问。Complete成功只向控制层返回
angle_counts和成功sequence；方向、零位、LUT与速度计算仍属应用。
同次Complete独立发布BspEncoderDiagnostics，ReadDiagnostics只原子复制缓存。

- 每次取得所有权的Complete，包括失败和空输出收尾，都推进attempt_sequence；无事务不覆盖缓存。
- sample_result记录这次收尾的结果；仅OK时sample_sequence可与控制样本sequence配对。
- valid_mask表示原始字实际取得，不代表CRC正确；未读字段清位并填0，不能借上次字补齐。
- crc_checked仅表示确实计算了CRC。为false时不能把sample_result为OK解释为CRC已经通过。
- 两个读取之间可能有新中断，诊断消费者必须检查序号；不匹配则放弃配对，不能拼接两拍。

| 器件 | frame_word | safety_word | 正常成功时的诊断有效性 |
| --- | --- | --- | --- |
| TLE5012B | 原0x8021读取的16位响应字 | 现有事务不读取，填0 | FRAME有效，SAFETY无效，crc_checked为false |
| MT6835 | 沿用原响应前两字节的16位角度表示 | 沿用响应第3/4字节组成的状态/CRC字 | FRAME和SAFETY有效，crc_checked为true |

MT6835校验失败但已完整收到响应时可以提供本次原始字，sample_result必须为CRC_ERROR或
SENSOR_FAULT；传输超时不提供不完整字。不得为了填满诊断字段新增TLE安全字读取或更改18位换算。
迁移应用原frame_word/safety_word遥测时使用这份快照，保持原数值、线上字段和刷新节拍。

配置诊断仍是固定六槽兼容接口，不是通用寄存器读写入口。GetType决定下表的解释；前台同一
所有者串行执行CaptureConfig与ReadConfigWord。取得总线后旧六槽失效，逐槽标记本轮结果；
部分失败时只允许读到本轮成功槽。BUSY表示未取得总线，不影响旧缓存或正在采样的事务。

| index | TLE5012B原请求/读取字节数 | MT6835原请求/读取字节数 |
| --- | --- | --- |
| 0 | 0x8001 / 2 | 0x3007 / 1 |
| 1 | 0x8061 / 2 | 0x3008 / 1 |
| 2 | 0x8081 / 2 | 0x3009 / 1 |
| 3 | 0x8091 / 2 | 0x300A / 1 |
| 4 | 0x8011 / 2 | 0x300D / 1 |
| 5 | 0x8001 / 2，与槽0相同的独立读取 | 0x3011 / 1 |

这些数值来自现有协议描述，不能把TLE槽5擅自解释成不同地址，或让两器件共用寄存器含义。

## 10. LED选择、资源重用和节拍

SetCode(channel, count)是替换当前显示码，channel是MODE或FAULT，不是分别缓存的两个优先级层。
应用仍按原状态机在有故障时提交故障码，解除后提交当时的模式码；BSP不分析故障也不恢复旧请求。
有效码沿用实际目标的现有编号表，表外参数拒绝且不改变显示；迁移不得重排线上故障编号。

| 操作/条件 | 明确行为 |
| --- | --- |
| 重复相同channel/count | 不重启闪烁；应用可以每个监督周期重复提交 |
| channel/count发生变化 | 下一5Hz显示拍从熄灭起始重新计数，保持原闪烁相位、次数和周期算法 |
| count为0 | 停用闪烁，输出是否显示颜色由资源关系决定，不表示清除应用故障 |
| SetColor重复或改变颜色 | 只更新颜色目标，不推进/重启呼吸；OFF关闭颜色角色，不清闪烁码 |
| 20Hz刷新 | BSP按原步进4及100..-40包络推进一次呼吸，即使被闪烁遮蔽也继续；DMA保持原节拍 |
| 共用输出且count非0 | 闪烁覆盖颜色，闪烁熄灭间隔保持熄灭；count清零后显示当前颜色/呼吸相位 |
| 独立输出 | 状态灯闪烁与灯带颜色同时运行，互不清除 |

AT32的PC13/PC14属于共用输出；颜色映射沿用红/黄→红灯，绿/蓝/青→蓝灯，紫/白→双灯。
STM32的状态GPIO与TIM2 CH3灯带独立，支持原颜色映射。差异只由板级资源共用关系和颜色表表达，
不能靠不同API或调用先后来争抢GPIO。现有专用关相诊断覆盖的优先级仍保留，不加入常规SetCode。

SetColor只更新目标，呼吸步进已归入原20Hz位置；不增加频率、不停掉被遮蔽的呼吸，
重复SetColor不改变速度。DMA缓冲仍由BSP持有并保证发送期间不被改写。

## 11. CAN接收异常与有界消费

BSP采集并锁存本控制器的接收丢失/溢出标志；唯一接收所有者先消费一次OVERFLOW，再取幸存帧。
返回OVERFLOW不写输出、不额外弹出有效帧、不清应用队列。硬件覆盖掉的帧不能恢复，序号缺口和
业务处理由上层协议决定。多个尚未消费的溢出可以合并，但不得把持续故障重复伪造成新事件。
采集、确认和清除硬件标志须防丢失新事件；清除后再次出现的标志必须重新锁存。

| 事件 | Receive结果与后续 |
| --- | --- |
| 溢出，队列仍有幸存帧 | 先OVERFLOW，后续调用按硬件原顺序取帧 |
| 溢出但没有帧 | 报一次OVERFLOW，再次调用NOT_READY，不产生空中断循环 |
| 取到损坏硬件帧 | 只消费该帧并返回FRAME_ERROR，后续好帧仍可取 |
| 被既有目标过滤规则排除 | 有界跳过，保留原过滤，不冒充传输失败或新增协议格式 |
| 硬件读取本身失败 | IO_ERROR；不能作为空队列成功，也不能无界立即重试 |

IRQ和前台仍只能选择一个接收所有者。每次取帧/跳过/报告异常都计入原ISR工作预算，达到预算
且仍有可处理帧或待报告事件时按原机制续挂；消费循环不能在第一次OVERFLOW/FRAME_ERROR就永远
停止处理。持续IO_ERROR而无前进时停止本轮重试，交回既有错误恢复路径，不持续自挂造成活锁。
应用ISR只搬移有效帧及记录链路异常，不在该上下文执行协议指令或参数写入。

## 12. UART截止、收尾及迟到事件

UART当前无板级绑定，本节是接入前的合同，不引入空实现。TX期限由目标配置
BSP_UART_TX_TIMEOUT_US给出，范围为1..INT32_MAX；必须大于最大帧线时长加最坏中断及前台服务
裕量。线时长按容量×每字符位数/波特率向上取整，字符位数包含起始、数据、校验和停止位。
若以后启用流控，必须重新给出有界等待规则，不能将可能无限等待代入当前合同。

接受非零发送时记录单调TimeUs起点，时间差用uint32_t无符号减法。发送所有者在每次前台服务拍
调用TakeTxResult，服务最大间隔必须小于配置期限并纳入验收；未服务时不能承诺准时硬件关断。
不可在活动TX期间进入无法满足该服务预算的阻塞任务；参数Flash写入前须等本次发送完成收尾。

| 状态/事件 | 收尾与终态 |
| --- | --- |
| 截止前确认TC | 记录TX_OK，停止本次DMA/发送中断并释放硬件占用；记录只被消费一次 |
| 只有DMA搬完，无TC | 仍活动，不报告成功；TakeTxResult继续检查期限 |
| 达到期限，无及时TC确认 | 有界停止本次DMA/发送中断、清隔离本次挂起标志，确认TX静止后记录TX_TIMEOUT |
| TC在期限后才被观察且无之前及时确认记录 | 保守按TX_TIMEOUT；不能据此声称远端一定未收到 |
| 硬件故障或收尾无法确认TX静止 | 记录TX_ERROR；无法静止则锁存TX禁止至复位，不把终态消费当成硬件空闲 |
| 迟到DMA/TC中断 | 清除并忽略旧事件，不覆盖终态；下一笔提交前须确认旧硬件和挂起事件已隔离 |
| 消费终态 | 正常收尾才释放逻辑发送槽；锁存TX禁止时保持拒绝新的非零发送 |

活动事务、终态消费、IRQ和超时检查使用同一短状态保护，只有一条路径能从活动转为终态。
按最终确认先后仲裁成功与超时，不能既返回OK又返回TIMEOUT。停止TX不重置整个UART，不清RX
缓存和错误；若所选硬件无法独立完成，须在接入评审中报告限制，不能暗中丢接收数据。

## 13. 修订5验收与实施差异

| 类别 | 设计验收场景 | 正式实现所需证据 |
| --- | --- | --- |
| PWM | 截止前/后、非法占空比、部分启相、关断读回异常 | 双板三相同时生效、原ADC相位和正常控制延迟、失败关断及序号、最坏快环预算 |
| 编码器 | 成功/CRC错/超时、无安全字、并发快照、部分配置捕获 | 原采样流水/诊断数值及协议ABI、错误计数、无新增SPI字节、20kHz预算 |
| LED | 同值重设、切码、零码、故障解除、共享/独立输出 | 两板原闪烁/呼吸波形与节拍、颜色映射、DMA寿命、应用调用次数无关 |
| CAN | 溢出有/无幸存帧、连续溢出、坏帧后好帧、IO不前进 | 两板原过滤和顺序、一次错误报告、接收继续推进、ISR预算和恢复行为 |
| UART | TC前/后截止、无TC、迟到IRQ、收尾失败和RX同时出错 | 有真实硬件后验证配置线时长、服务间隔、一次终态、隔离和RX保留 |

记录行为差异，不能伪称纯重命名或异常逐位等价。正常控制、保护阈值、诊断线上数值和参数ABI
