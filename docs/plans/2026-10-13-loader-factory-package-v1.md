# APP + Loader 初装包方案 v1

## 目标

从分别链接的Loader和APP生成一个带地址的HEX，提供指定J-Link的烧录脚本。
现有CAN协议、参数ABI、电机控制行为及三个固件分区地址不变。

## 决定

- 用`loader/tools/loader_factory.py`的`pack`、`flash`两个显式入口，不增加依赖框架。
- 复用APP向量校验及CRC，实现共享契约规定的48 B有效记录。
- HEX包含Loader页0～5、有效记录页6、APP页8～55；页7及参数页56～63不包含。
- 不生成跨保留页的连续BIN，避免烧录工具将填充FF误当成擦除保留数据的请求。
- 烧录前校验包、绑定探针serial和芯片UID、确认关相、两次读完整Flash并备份。
- 先使记录无效，再写Loader与APP；完整回读含保护区正确后才提交有效记录。
- 禁止mass erase。失败保留诊断且不复位；默认验证成功后仍暂停，`--run`显式复位并复查关相。
- 实机发现探针关闭会再次暂停已启动MCU；成功的`--run`设置关闭时保持运行，默认及失败路径保留暂停。
- 空板参数区保持空白；电机身份和个体标定按原配置流程另行保存。

## 验收

离线验证HEX地址/校验和、旧APP基址拒绝、记录被真实C解码、包篡改拒绝、
探针替身写入顺序、错误UID无副作用、参数损坏及写入失败不提交/不启动。
独立APP和LoaderKeil构建0错误0警告，生成候选包及匹配哈希。
实机烧录需要已授权的台架上下文，前后保护区逐字节相同且固件全区与期望一致。
离线替身通过不等同于实机烧录通过；没有当前summary和哈希不作发布声明。

## 回退与证据

备份、包、构建日志、Flash回读及summary全部放在`outputs/`。
回退使用相同布局的Loader/APP/记录，不覆盖参数和保留页；未知旧固件不能直接平移BIN。
详细操作见[初装烧录指南](../guides/loader_factory_package_v1.md)。
