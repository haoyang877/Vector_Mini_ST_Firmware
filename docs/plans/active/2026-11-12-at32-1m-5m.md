# AT32F456 五轴恢复 CAN FD 1M/5M

从重构分支 ac153baa 及现场 500K/2M 工作树开始，仅恢复五台 AT32 的 CAN 位时序。沿用独立 Loader 2.2.0、APP 0.6.2、协议、参数及身份布局。180 MHz CAN 时钟按原 1 分频、仲裁 135+45、数据 27+9、SSP 28 配置。

验收包括两端初始化专项测试、Keil 重建、合并 HEX 每条记录和擦除页边界复核。逐台以既有 UID 和节点绑定，双读备份 256 KiB、按页下载并回读全部镜像及保护区。五台重新启动后在 1M/5M 共线上逐节点查询版本和状态。各台记录保存在 outputs 下本次独立批次。回退时使用各台备份或上批统一 500K/2M 包，沿用相同保护区核对。

## 离线交付和待验项

APP 真实初始化、Loader 端口、基础平台及 USB-CAN 适配器替身测试通过。五轴只读脚本和 v1.1.1 桌面工具默认使用 1M/5M；旧 500K/2M 测试结果只适用于原批次。输出见 `outputs/at32-1m-5m-20261112` 和 `outputs/jlink-1m-5m-20261112`。

节点 4 使用桌面工具完成实机刷写和回读。重启后参数一致，CAN 读到对应 UID、APP 0.6.2 和 Loader 2.2.0。单轴 50 Hz、50 ms 截止、零应用重试的首轮收到 979/1000 笔正常应答，另有 21 笔只收到带 ERR 标志的应答。随后另一项台架验证将同一节点更新为 APP 0.7.0 / Loader 2.3.0。首次测试及随后版本变更的记录见 `outputs/jlink-cmd-result-20261112/node4-events.json`。

经用户确认，节点 4 最终写回本批 0.6.2 / 2.2.0。重启后的 31 次身份、能力及状态查询全部通过。相同 50 Hz 工况复测 1,000/1,000 通过。另在目标 200 Hz 下连续发出 32,000 次状态查询，32,000 笔全部在 50 ms 内收到唯一有效回复，应用层重试为零。USB-CAN 未报告异常帧。逐笔复核得单侧 95% 失败率上限 0.009361%，P99 延迟 2.232 ms，最大 48.065 ms。结束后 SWD 双读 256 KiB 全片与烧录后快照一致，TEC、REC 均为零。此次验收限右轮单节点，其他四台待各自测试。证据见 `outputs/jlink-cmd-result-20261112/right-fixed-131418/verification.json` 和 `outputs/jlink-cmd-result-20261112/restore-131153-217984/after_can.json`。
