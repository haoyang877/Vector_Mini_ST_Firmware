# 单处使用的协议辅助函数合并 v1

将启动模式、使能位和进入 Loader 的载荷解析放入各自的命令处理函数。
前台解码直接校验 CAN 元信息，目标反馈在处理目标命令时准备，标定回复就地检查任务类型。
共享的解析、完整的命令分发、业务回调以及队列和握手边界各自由原所有者负责。

验收以现有线路字节、错误优先级、业务调用次数、反馈顺序和 Loader 票据行为为准。
修改前快照保存在 `outputs/protocol-inline/baseline/`。前后运行相同的协议请求对照，
检查三套 APP 的 Keil 构建和资源，并运行完整 PR 离线检查。回退仅恢复本次修改的对应片段。

## 结果

六个辅助函数已合并。两个实现文件从 1363 行减至 1289 行。
117 直接读取模式、构造命令并调用电机回调。测试覆盖三个保留字节分别非零和载荷过短的回复，
并检查这些请求没有触发启动回调。101 的黄金帧在命令分发入口验证回复。

128,592 组请求的业务调用、编码帧和队列计数前后一致。两项电机原生回归的日志也逐字节一致。
三套 Keil 工程前后均为 0 错误、0 警告。按 Code+RO+RW 计，AT32 APP 增加 8 B，
STM32 APP 和 LoaderApp 各减少 160 B，三套工程的 RW+ZI 均持平。未测量实机时延。

`outputs/runs/protocol-inline-20261104/summary.json`。
